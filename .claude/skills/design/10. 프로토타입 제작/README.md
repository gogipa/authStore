# design-prototype

06 UI시안·08 컴포넌트토큰·09 모션사양·04 토큰을 묶어 **실제 제품과 거의 구분되지 않는 고충실도
인터랙티브 프로토타입**(클릭·입력·전환 동작) + 사용성 테스트 시나리오 + 자가점검 리포트를 만드는
디자인 시리즈 10단계 생성·검증 스킬. 컴포넌트화(08)·인터랙션모션(09)과 반응형(11)·QA(12) 사이.

## 동명이역 주의 (기획11 prototype-design vs 디자인10)
둘 다 "프로토타입 제작"이지만 **충실도·목적·입력이 정반대**다. 기획11 `prototype-design`은
**저~중충실도**(grayscale·글리프 금칙)로 "플로우 구조가 맞는가"를 싸게 검증하고 버린다. 디자인10은
**고충실도**(확정 컬러·타이포·컴포넌트·모션)로 "이 인터랙션이 자연스러운가, 사용자가 막히는가"를
감각·디테일 수준에서 검증한다. 충실도 단서 없는 "프로토타입 만들어줘"는 **06 고충실도 시안 입력 존재
여부**로 분기 판별한다.

## prototype-design(기획11)을 호출하지 않는 이유
시나리오 설계 규율은 기획11에 잘 정의돼 있으나 **Skill로 호출하지 않고 규율만 내장 계승**한다
(`design-consistency-review`가 `design-review`를 푼 선례). 호출 시 ①산출물이 기획 폴더
`11_프로토타입`에 떨어져 폴더 제약 위반 ②이중 게이트 ③디자인 입력·S-ID 인계 제어 불가. 계승: 비유도형
과업·성공기준·관찰포인트·S-ID 매핑표·SUS·표본 5명·미정값 라벨·08-2 플래그 3종. **계승 제외**:
grayscale·글리프 금칙·"하이파이 위임 금지"(충실도 정반대).

## frontend-design 위임 반전 (핵심)
09 `design-motion`·11 `prototype-design`은 frontend-design을 "시각충실도 미상승·직접 HTML 기본"으로
묶었지만, 디자인10은 **고충실도가 목적이라 하이파이를 환영**한다(정반대). 스코프락은 유지하되 **축을
반전**: 시각충실도 억제가 아니라 **04/06/08/09 충실(BMD·임의 컬러/폰트/수치 발명 금지)** 충실도 락으로
건다. 기본 경로 = frontend-design 내장 invoke 직접 코드 프로토타입.

## Figma Make / v0 / Stitch (옵트인 dead-end)
원본이 Figma Make를 "1순위"로 두지만 **MCP 도구가 아니라 유료 Full seat 패널 기능**이라 Claude가
자동 실행할 수 없고 외부 웹이라 마스킹 가드가 안 걸린다(dead-end). → **기본 경로 비계승**, 게이트1에서
사용자 명시 선택 시에만 붙여넣기 프롬프트(마스킹+경고 배너)로 강등. v0.dev/Stitch도 외부 웹·붙여넣기
프롬프트만·생성 즉시 마스킹. 회사 Figma 1급 도구 전제상 경로는 보존한다.

## 09 핸드오프 계약 수령
`design-motion`(09)이 "09 사양→프로토타입 통합 계약은 디자인 프로토타입 스킬이 빌드될 때 확정한다"며
명시 위임 → **본 스킬이 확정자**. `09-1_모션사양표.md`가 모션 SSOT(09-2 HTML은 보조). 09-1 사양표
행(트리거+duration+easing+속성)을 프로토타입 CSS/JS transition으로 **1:1 전사**하고 관련 케이스ID 열을
S-ID 매핑표 키와 교차. 09 규율 승계: `prefers-reduced-motion` 필수·transform/opacity만·값은 초안.

## Figma MCP (read는 Figma 링크일 때만 · write 기본 금지)
06 시안이 Figma 링크일 때만 READ(get_design_context/get_screenshot/get_variable_defs·nodeId 필수).
미연결 시: `claude mcp add --transport http figma https://mcp.figma.com/mcp` 후 `/mcp` 인증. WRITE
(use_figma 등)는 회사 파일 오염·민감정보로 기본 금지. (SKILL 본문은 mcp add를 하드코딩하지 않는다 —
README 전용.)

## Playwright MCP (선택 · 정적 점검이 기본)
자가점검 기본은 정적 grep(python3 — macOS grep `-P` 미지원). Playwright 연결 시 핵심 경로 자동순회 +
스크린샷 + 의도적 깨뜨리기 보너스. 미연결 시:
`claude mcp add playwright npx '@playwright/mcp@latest'`. dry-run·미연결 시 생략(도구 0개로도 산출물
손실 없음).

## Lottie / Rive (에셋 제작은 디자이너)
09가 분리 판단한 복잡 모션의 **임베드만**(09-4 입력). 에셋(.json/.riv)은 디자이너 HITL 제작, Claude는
통합 스니펫만(CDN URL=placeholder·reduced-motion 분기). 못 만든 걸 만들었다 하지 않는다.

## BMD · 정책 수치 권위
토큰값=04, 모션 수치=09-1, 정책 수치·케이스ID=기획06/기획12가 진실. SKILL 본문·산출물에 HEX/px/ms
재기재 금지(인용만). **정책 수치 권위는 기획06/10/12이지 06 시안 HTML이 아니다**(고충실도 시안 카피는
placeholder일 수 있음). 예외 분기마다 출처 케이스ID 코드 주석, 근거 없는 분기는 `[확인 필요]`.

## 충실도 함정 · 사용성 테스트는 사람
고충실도라 함정(과한 완성도→참가자 비판 위축·일정 기대 부풀음)이 기획11보다 크다 → 진행자 미완성 고지·
"출시 일정 아님"·"확정 디자인 아님" 배너. **사용성 테스트는 사람이 5명 내외 관찰**·AI 산출물은 준비물이지
결과 아님·Playwright는 동작 통과만 본다(사용성 대체 아님·자가점검은 전제조건). 모션 체감은 디자이너가
프로토타입을 직접 만져 보정한다(값은 초안).
