# 퍼블리싱·구현물 디자인 검수 (Implementation Visual QA)

개발이 시안을 코드로 구현한 뒤, **빌드된 화면이 시안과 픽셀·간격·컬러·타이포·반응형 거동까지 일치하는지**
검수한다(구현물 visual QA). **12=시안 자체 검수(Figma 안) / 14=빌드 구현물 검수(브라우저·스테이징 빌드).**
같은 '검수'지만 대상이 다르다. Playwright로 빌드 화면을 일관 조건으로 캡처 → Figma 시안 원본·04 토큰·12
baseline과 **시안-토큰-구현 3자 대조** → 이탈을 심각도별 리포트로 검출 → 수정 요청 → 재검수 루프. **검증·검수
스킬(읽기 전용).**

## 빌드 전제 — 11·12와 degrade 모델이 정반대 (1급 규율)

- **14의 검수 대상 = 빌드된 화면(스테이징/로컬 URL).** Playwright 빌드 캡처가 **검수 입력의 1급 원천**이라, 11·12의 "Playwright 미연결 → 정적 분석으로 손실 없이 완성"을 **절대 계승하지 않는다**(정반대). **빌드(URL)가 없으면 단계 자체가 성립 불가** — 시안만으로 "구현이 시안대로 됐나"를 판정할 수 없다.
- **빌드 URL 부재(dry-run·미배포 포함) → 중단이 아니라 명세까지 degrade**: 0단계 검수 매핑표 + Step 1 캡처 조건 명세 + 기대 토큰값 표**까지만** 산출하고 **실 검수(캡처·비교·수치대조)는 미발동**. ⚠️ **시안만으로 가상 비교는 가짜 캡처·가짜 이탈을 낳으므로 절대 금지.** 인덱스에 "빌드 미배포라 명세까지가 산출물·빈손 미완 아님·빌드 도착 후 실 검수 발동"을 명기(13 빈손 분기 동형).
- **빌드는 있으나 Playwright 미연결** → "검수 완료"가 아니라 **수동 캡처 가이드 + 캡처 조건 명세 산출 → 사람이 캡처를 채워야 비교 발동**.
- **degrade 우선순위**: **빌드 URL 부재 > dry-run(도구 실호출 생략) > Playwright 미연결**. 빌드 부재면 dry-run·연결 여부 무관하게 명세까지만(실 검수 미발동).

## design-review를 호출하지 않는 이유 (이탈 분류 규율만 내장)

원본 Step5·AI표가 "design-review 스킬로 이탈 분류"라 하지만 **Skill로 호출하지 않고 규율만 내장**한다(07·12·13 선례). 비호출 4사유:

1. **출력경로 고정** — design-review는 기획 폴더 `13_디자인리뷰`에 쓴다(디자인14 산출물 오염).
2. **대조 축 불일치** — design-review는 시안↔기획(10/12/06) 대조이지 **시안↔구현물이 아니다**.
3. **이중 게이트** — 자체 게이트 2개.
4. **토큰 월권 배제** — design-review는 토큰 미준수 지적을 '월권'으로 배제하므로 **14 핵심인 토큰 수치 대조를 무력화**한다.

→ **계승**: 검출=후보·수정요청/질문/제안 분리·근거 값 인용 강제·심각도(상/중/하)·심각도 하 묶음·AI 자동 칭찬 금지(잘된 점은 사람 직접)·약관/결제/법적 고지 화면 `[사람 직접 검수]`. **계승 제외**: design-review의 '토큰 지적=월권' 규율(14는 토큰 수치 대조가 1급). 원본의 "design-review 스킬로" 문구는 **"내장 이탈 분류 규율로"**로 읽는다.

## 핵심 원칙

- **BMD: 색·간격·폰트·터치 타깃 값의 진실 = 04/08 `tokens.css`·`scripts/out/color.json`(SSOT).** SKILL 본문·산출물에 임의 hex/고정 px 리터럴 재기재 금지(검출 결과표에만 04 인용으로 현재값 기록). 원본의 색차·간격 예시값은 '차이 검출 메커니즘 설명용 예시(실제 토큰값 아님)'·silent 계승 금지. 터치 타깃 최소 크기는 04 인용 또는 WCAG 2.5.5 출처 인용.
- **토큰 대조 3자 = (1) 04/08 tokens.css 정의값 ↔ (2) 시안 적용값(`get_design_context` 스펙·`get_variable_defs` 보조) ↔ (3) 빌드 computed style.** `get_variable_defs`는 **보조**(selection 한계·하드코딩 거짓통과·미바인딩 후보는 인스펙터 확인)이고 진실 판정 기준 아님. **책임 소재**: (a) 구현이 토큰 안 씀 = 개발 수정요청(14 본업) / (b) 시안이 토큰 안 씀 = **12로 환류**(시안 결함은 12 소관·14에서 처음 발견 시 12 회귀·개발에 떠넘기지 않음) / (c) 04 토큰 자체 공백 = 04 환류 후보(기재만·직접 편집 금지).
- **빌드 computed style은 `browser_evaluate(() => getComputedStyle(el)...)`로 추출**(`browser_snapshot`은 접근성 트리·텍스트·구조용이지 **CSS computed style을 반환하지 않는다**). `browser_evaluate`가 없으면 한계(인스펙터 또는 `get_design_context` 스펙값)를 degrade로 명시.
- **검출 = 후보이지 판정 아님.** 개발의 의도적 조정(로딩 스켈레톤 추가·접근성 대비 강화)을 이탈로 오검출할 수 있다 → 게이트2 사람 재분류 전엔 '후보'로만·그대로 개발에 던지기 금지.
- **스크린샷 픽셀 비교 한계.** 렌더링 엔진·안티에일리어싱·서브픽셀 차이로 1~2px 차이는 진짜 이탈 vs 렌더링 차이가 섞인다 → **캡처 단독 판정 금지·`get_design_context` 스펙값(정의 px) + 빌드 computed style 병행 판정**·심각도 하 묶음.
- **시각 품질은 사람 몫.** 미감·위계·균형은 디자이너 영역·AI는 정량 사실(같다/다르다·몇 px/어떤 hex)까지. `get_screenshot`/Playwright 캡처는 사람 시각 확인 보조이지 AI 시각 판정 입력 아님.
- **Playwright 빌드 URL 안전.** 대상 URL 확인(staging/test/dev 아닌 운영/결제 의심 도메인 경고·기본 차단·게이트에서 사람 확인 후만 캡처)·테스트/스테이징 계정 한정·운영 데이터 조작 금지·비밀번호 런타임 입력(평문 금지)·스크린샷 입력칸/세션/실고객 정보 마스킹·Notion 발행 전 민감정보 더미.
- **시안 부재 브레이크포인트는 11-1 반응형스펙(거동 규칙)으로만 판정·AI 추정/발명 금지**(시안 부재임을 리포트에 명시). ⚠️ **11-1 거동 규칙도 `[확인 필요]`(시안/기획09 의도 부재로 placeholder 도배)면 14도 판정 불가 → 같이 `[확인 필요]`로 라우팅·AI 거동 발명 금지**(11-1이 실제 채워졌을 때만 판정 가능). 브레이크포인트(레이아웃 분기점·04 SSOT·360/768/1280·11 인용)와 **캡처 뷰포트**(디바이스 실폭 스크리닝·375 등·04 미환류·14 검수 파라미터)는 다른 축. 뷰포트 px는 04/11 인용(`@media`는 `var()` 불가 BMD 예외=04 값+인용 주석).

## 파이프라인 (Stage 0~5, 게이트 1·2)

### Stage 0 — 검수 매핑표·입력 수령·실존 probe·degrade
- 슬러그 해소(`디자인/리서치/` 1개 자동/복수 게이트/0개 위치 질문 후 중단·한글경로 Glob/Read만). 번호 혼동([[15]])·단일 키 가시화.
