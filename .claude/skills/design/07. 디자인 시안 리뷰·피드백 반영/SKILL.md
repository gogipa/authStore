# 디자인 시안 리뷰·피드백 반영 (Design Consistency Review)

06 완성 시안을 개발 핸드오프(13)에 넘기기 **전에 디자인 팀 내부**가 자기검증한다. 받는 사람은 개발자가
아니라 **디자인 팀 + 옆자리 기획자**다. 두 축으로 본다: ①**기획 정합성**(시안↔10 화면설계서·12 기능명세·
06 정책) ②**디자인 일관성**(시안↔04 토큰·컴포넌트·접근성). **생성이 아니라 검증·리뷰 스킬이고, 읽기
전용이다**(시안은 디자이너가 리포트를 보고 직접 고친다). 1급 산출 = ①디자인 리뷰 리포트 ②용어집(★하류 재사용).

## design-review와 다른 점 (왜 별도 스킬인가)

- **design-review(기획 시리즈)는 "기획↔시안 정합성"만 보고 토큰을 "월권"으로 배제**한다. 본 스킬은 그
  반대로 **②디자인 일관성(토큰 이탈·컴포넌트 미사용·WCAG 접근성)을 1급으로 끌어올린다** — 이게 분리 근거.
- **design-review를 호출하지 않는다**(아래 §). 05(design-wireframe-review)처럼 규율만 내장 계승한다.
- **차별화 대상(시점 아님)**: design-review=기획↔시안 정합성만 / 본 스킬=+토큰·컴포넌트·접근성(디자인
  시스템 준수). design-wireframe-review(05)=와이어프레임(시안 前) / 본 스킬=완성 시안(시안 後).

## design-review를 호출하지 않는 이유 (규율 내장 계승)

원본 가이드는 "design-review 스킬을 진입점으로 호출"한다지만 실제로는 **위임 불가**다: ① design-review
출력경로가 `기획/리서치/<주제>/13_디자인리뷰/`로 고정 → 호출하면 산출물이 **기획 폴더**에 떨어져 07 디자인
폴더 경로계약을 깬다. ② design-review가 자체 게이트 2개를 가져 호출 시 **이중 게이트**가 된다. ③ Skill
도구는 서브에이전트 독립 실행이라 중간 산출을 '07 경로로 인계'할 제어점이 없다. → **design-review 규율
(검출=후보·수정요청/질문/제안 분류·근거 인용·다층충돌·자기대조 가드·약관 플래그)을 내장 계승하고 호출하지
않는다.** ①기획 정합성 축도 전부 07 자체 Stage로 구현한다.

## 핵심 원칙 (어기면 헛 리포트가 나간다)

- **검출 = 후보지 판정이 아니다.** 디자이너가 의도적으로 개선한 부분(화면설계서 드롭다운→바텀시트)을
  "불일치"로 오검출할 수 있다 → 그대로 던지지 말고 의도적 변경은 **"질문" 또는 "기획서 역업데이트 필요"로
  분류**한 뒤 공유.
- **시각 품질은 판단하지 않는다.** 정렬·여백·위계·심미성의 좋고 나쁨은 디자이너 영역. 07은 **명세·토큰 대비
  사실 확인 + 접근성 정량 점검까지로 한정**.
- **읽기 전용이다.** Figma `use_figma`·`create_new_file` 등 write 금지 — 수정은 디자이너가 직접. 단 ②축이라
  `get_variable_defs`·`get_design_context` 등 **read는 적극 사용**(design-review와 달리 토큰 read가 1급).
- **토큰 값의 진실은 04 산출물이다(재계산 아님).** WCAG 대비비는 `04/scripts/out/color.json`의 `wcag_combos`
  표가 SSOT, 07은 시안이 쓴 색조합을 그 표와 **대조**할 뿐 재계산하지 않는다(수록분 한정).
- **04 환류는 기재만, 직접 편집 안 한다.** 시안이 04의 공백(semantic alias 부재 등)을 드러내면 07-3에 **환류
  후보로 기재**하고, 04 파일 편집은 디자이너/04 재실행에 위임(읽기전용 정합).
- **리포트 톤이 팀 분위기를 좌우한다.** 심각도 하 항목은 묶어 전달, **잘된 부분 언급은 사람이 직접**(AI 자동
  칭찬 금지). 리포트는 도구이고 합의는 사람이 한다.
- **마크다운 = SSOT, Notion = 옵트인 미러.**

### 중단조건 (단일 트리)
1. **시안 부재 → 즉시 중단**(리뷰 대상 없음).
2. 시안 존재 & **04·10 모두 부재 → 중단**(양축 무효).
3. 시안 존재 & 04·10 **중 하나라도 존재 → 해당 축만 degrade**(04 부재=②축만 비활성·①축 존속 / 10 부재=②축만).
   ⚠️ 04 없는 07은 design-review에 수렴하므로 게이트1에서 가시화 경고.

### 슬러그 해소 (Stage 0, 1급)
`스터디/AI 스터디/자동화/디자인/리서치/` 하위 → 1개 자동 채택 / 복수 게이트1 택1 / 0개 위치 질문 후 중단.
같은 슬러그로 `기획/리서치/`도 확인. **한글 경로 Glob/Read만**(Bash ls/find 금지).

### 시안 소스 2분기 (design-review 동형)
- **(a) Figma 링크**: `whoami`→`get_metadata`→`get_design_context`→`get_screenshot`→`get_variable_defs`,
  nodeId 필수(`^\d+[:-]\d+$`·추측 금지).
- **(b) 06-2 HTML**: DOM 파싱(`var(--token)`·`.canvas`·`.btn-primary`·`.card` 등). **(c) 둘 다 없음=중단.**

### 화면ID·귀속 (리터럴/파일명 단정 금지)
- **화면ID** = `S\d+`(무하이픈). **09-1 화면목록에서만 확정.** HTML 화면귀속은 **파일명 sanitize를 불신하고
  (06-3 규칙↔예시 모순 상존) DOM 내 S-ID 마커/주석을 단일 진실로**(예 `10 S6-[n]`), 마커 부재 시에만 09-1
  화면목록 fallback. Figma 모드도 프레임명이 아니라 `S\d+` prefix로 매핑. **항목 단위 마커가 누락된 경우**(화면은
  귀속되나 특정 항목 `[n]` 토큰 부재)는 **10 구성요소 순서로 fallback + `[확인 필요]`**(항목 건너뜀 방지).
- **06-3 표기만 있고 HTML 미생성인 화면**(예 S9·S11)은 **'시안 미생성' 별도 계상·검출 제외**(리뷰 대상 부재).

### dry-run 분기
dry-run = **Figma probe·Figma READ MCP(get_*) 생략** / **로컬 HTML 파일 Read는 1급 수행**(06-2 HTML이 리뷰
대상). **표준 배너 문구**(전 산출물 머리에 동일): `> ⚠️ dry-run — Figma READ 미호출, 06-2 HTML DOM 파싱 1급. 가상 검증.`

## 파이프라인 (Stage 0~6, 전부 07 자체 구현)

### Stage 0 — 입력·시안소스·범위·ID·dry-run·degrade
- 슬러그 해소(위). 시안 소스 2분기(a/b/c). 중단조건 단일 트리. ID·귀속(위)·미정값 수집(`[확인 필요]` +
  06-4 잔존 4건). **약관·결제·해지고지 화면은 `[사람 직접 검수]` 플래그**(텍스트 추출 한계).
- 검토 범위 = 플로우 단위(상한 4~6장·**실재 시안 수에 종속**). dry-run 분기.

### 🚦 게이트1 — 리뷰 범위 + 시안 소스 확정 (사람, 필수·블로킹)
AskUserQuestion(AI 추천 1안, **응답 전 미진행**). 범위(실재 시안 수)·소스(a/b). **04 부재 시 '②축 비활성→
design-review 수렴' 경고 가시화.** ⚠️ **04가 있어도 semantic alias 커버리지가 빈약하면**(실측 6개뿐·에러배경/
border 부재) **②축 토큰 검증이 제한적임을 함께 경고**(alias 충분성 기준, 04 파일 유무만 보지 말 것). Figma면
프레임 nodeId. 검수 대상=시안 존재.

### Stage 1 — 기획 정합성 → `07-1`
- 내장 계승. 누락(화면설계서에 있고 시안에 없음)·추가(시안에만 — 디자이너 의도일 수 있어 분리)·문구 불일치
  (12 확정 메시지 항목만·정책/화면설계서 문구 **그대로 인용 비교**). 확신 없으면 "확인 필요".
- **다층충돌 양방향**: 기준이 `[확인 필요]`/미정이면 차이를 "질문"으로. **RF-04 등 `[법정기준 placeholder]`
  잔존 항목은 '문구 불일치'가 아니라 '정책 확정 대기(질문)'로 분류**.
- **자기대조 가드**: 06 HTML이 10 디스크립션을 카피 출처로 썼을 수 있다(자기대조 함정) → 경로 문자열 비교로
  같은 출처면 대조에서 제외. **출처 역할 분리**: UI 메시지=12 / 정책·도메인 용어=06 / 화면 요소명=10.

### Stage 2 — 상태 커버리지 → `07-2`
- **재사용 우선순위 = 06-3 Stage5(시안 분기판정 a/b/c) > 05-2(분모) > 12(둘 다 부재 시)**. 5종 라벨=로딩/빈
  데이터/에러/권한 없음/입력 검증(권한=10 5종만·빈값/형식=인라인 검증 분리·화면분모 제외).
- **05-2 '상태 추가 요청'은 09→10 추가분 톤**이라 **분모만 가져오고 판정은 06 시안 기준 재평가**(05-2의 ❌를
  완성 시안 누락으로 격상 금지). ❌ = 디자인 추가 작업 목록(예외 케이스ID 근거).

### Stage 3 — ★ 디자인 일관성 (07 고유) → `07-3`
- **토큰 이탈**: HTML 시안은 06-4가 hex 전수 검출 완료(hex 0건·전부 var) → 07은 **재검출이 아니라 06-4
  `[확인 필요]` 4건을 귀속 단계로 라우팅**한다:
  - `1px` border-width·`min-height`·캔버스 치수 등은 **space 토큰 대상 제외 화이트리스트**(06-4 px 거짓양성을
    07에서 닫고 04/06 환류 후보로만 기재).
  - primitive 직접 사용은 **자리별로 04에 그 자리를 커버하는 semantic alias가 존재하는지 먼저 확인**해
    2분기한다: **(가) alias가 있는데 안 씀 = 진짜 토큰 이탈(수정 요청)** / **(나) alias 부재(에러배경·border·
    surface 단계 등 04에 6개뿐)로 불가피 = 이탈 아님 → 04 환류 후보**. ⚠️ 둘을 한 바구니에 담으면 ②축 토큰
    검증이 '항상 통과'로 무력화되므로 **반드시 alias 커버리지를 자리별로 판정**한다.
  - **Figma 모드**: `get_variable_defs`는 selection의 *사용된* 변수만 반환(거짓통과 함정)이라 **보조**, 미바인딩
    후보는 **디자이너 인스펙터 확인 플래그**(토큰값=실제값이어도 바인딩 안 된 것 vs 의도적 토큰 밖 값 구분 불가).
- **컴포넌트 미사용/detach**: HTML엔 detach 개념 없음 → 06-4 ③(컴포넌트 일관) 인용 + 동일 역할 다른 클래스만
  보강. **detach/인스턴스 검출은 Figma 모드 전용**.
- **접근성(1차 거름망·재계산 아님)**: 시안 alias→활성 테마(06-3 라이트 확정) **resolve 후 해당 theme 행의
  `wcag_combos`만 대조**(수록분 한정). 다크는 미선택→탈락조합(white on primary-400=2.83 등) 미승격(06-3 계승).
  ⚠️ **시안 핵심 조합이 wcag_combos에 미수록인 경우가 흔하다**(실측: text-muted=neutral-600 on white·에러배너
  danger-600 on danger-50 둘 다 미수록 — 04가 primitive 조합표만 산출하고 alias 실제 조합을 안 담음). → 미수록
  조합은 ① `[확인필요: 미수록→디자이너 대비 수동 확인]`으로 두되 **그 조합이 시안 핵심(본문 텍스트·에러배너 등)
  이면 심각도 상(上)으로 승격**, ② **'04 wcag_combos에 alias 실제 조합 추가 필요'를 04 환류 후보로 기재**(접근성
  거름망이 핵심 조합을 못 거르는 구조적 구멍 방지). + 색-단독 상태표시·터치 타깃. **스크린리더·포커스 순서·
  실디바이스 등 동적 접근성은 디자인 12(디자인 QA)로 위임.**

## 주의

- **검출은 후보** — 의도적 변경은 "질문"으로.
- **시각 품질 판단 안 함** — 정렬·여백·위계·심미성은 디자이너. 07은 명세·토큰 대비 + 접근성 정량까지.
- **읽기 전용** — Figma write 금지, 수정은 디자이너. 단 토큰 read는 1급.
- **토큰 진실은 04** — WCAG는 wcag_combos 대조(재계산 아님). 04 공백은 환류 후보 기재만(직접 편집 금지).
- **텍스트 추출 한계** — 이미지 글자·외부 컴포넌트 내부 텍스트 미포착 → 약관·결제·해지 화면 사람 직접 검수.
- **토큰 이탈 오탐** — 토큰값=실제값이어도 미바인딩 vs 의도적 토큰 밖 값 구분 불가 → 인스펙터 재확인.
- **리포트 톤** — 심각도 하 묶음·잘된 점은 사람이(AI 자동 칭찬 금지).
- **접근성 1차 거름** — 동적 접근성(스크린리더·포커스)은 디자인 12 디자인 QA.
- **프레임 단위로 끊어** — 파일 전체 한 번에 가져오면 뒷부분 대조 품질 저하.
- **편집 범위** — 기획·이전 디자인은 읽기만, 쓰기는 `<출력루트>` 안에서만(`자동화/` 하위·볼트 루트 금지).
