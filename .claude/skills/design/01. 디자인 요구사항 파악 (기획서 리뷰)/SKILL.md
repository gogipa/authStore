# 디자인 요구사항 파악 (Design Requirements)

디자인 프로세스의 첫 단계. 디자이너가 시안을 그리기 전에 **확정된 기획 산출물을 디자이너
관점으로 다시 읽어** "그려야 할 화면·그 화면이 만족해야 할 조건"으로 **번역**한다. 화면은
화면설계서에, 상태는 기능명세 예외표에, 문구·규칙은 정책에, 화면 간 연결은 유저플로우에
흩어져 있다 — 이를 화면 단위로 합쳐 **디자인 요구사항**으로 만들고, 그 과정에서 기획서에
답이 없는 곳을 **질문 리스트**로 골라낸다. **생성이 아니라 번역·추출·사전 점검 스킬.**

## 핵심 원칙 (어기면 시안을 다시 그린다)

- **이 단계의 1급 산출물은 질문 리스트다.** 가치는 "정답(요구사항 표)을 만드는 것"이 아니라
  **"물어야 할 것을 골라내는 것"**에 있다. 요구사항 표는 질문 리스트를 담는 그릇이다.
- **추측으로 메우지 않는다.** "적절히 안내"·"필요 시 노출" 같은 표현을 그럴듯한 화면
  요구사항으로 **자동 확정 금지** → 질문 리스트로 뺀다. 모든 추출 항목에 **근거 ID 동반**.
- **정책 해석은 단정 금지.** 환불·해지·연령 표시는 법무 검토 영역. 정책→UI 변환표는 "초안",
  강제 여부·문구는 기획자(정책 담당)와 확인 후 확정.
- **시각 디자인은 판단하지 않는다.** 여기서 다루는 건 "무엇을 그려야 하는가"(요구사항)이지
  "어떻게 보여야 하는가"가 아니다. 톤·레이아웃·컬러는 02·03 단계.
- **용어 불일치는 발견만, 통일은 보류.** 충돌 목록까지가 이 단계 산출물. 통일은 04(디자인
  시스템)·08(컴포넌트·토큰)에서.
- **마크다운 = SSOT, Notion = 옵트인 미러.** 볼트 마크다운이 원본. 갈라지면 다툼이 생긴다.
- **AI 정리는 초안이지 확정이 아니다.** 기획서가 비어 있으면 그 공백을 그대로 옮긴다 —
  화면 목록·상태 추출은 디자이너가 직접 "이게 정말 다인가" 확인.
- **design-review를 호출하지 않는다**(아래 §design-review 참조). 시안 부재 시 중단되기 때문.

## design-review를 호출하지 않는 이유 (정합성 로직 내장)

원본 가이드는 "design-review 스킬을 시안 없이 당겨 쓴다"고 하지만, **design-review의 입력
계약은 "시안(Figma 또는 HTML) 또는 10 없으면 중단"**이다. 시안이 없는 이 단계에서 호출하면
즉시 중단된다. 따라서 동일 효과(시안 착수 전 정합성 점검)를 **시안 축 없이 기준 문서 간
대조로 Stage 4에 내장**한다. design-review에서 차용하는 것은 **다층충돌 권위순위 · 자기대조
가드 · 출처 역할분리**뿐이고, 상태 추출은 wireframe-design, 예외 케이스ID 교차는
screen-spec-design 알고리즘을 따른다.

## 입력

- **입력 루트 = `<입력루트>`** (읽기 전용). 기획 가이드 문서(`기획/10. 화면설계서 작성.md`
  등)는 **설명문이지 산출물이 아니므로 입력에서 제외** — 산출물 폴더만 1급.
- **출력 루트 = `<출력루트>`** (쓰기). 입력(기획)과 출력(디자인) 루트가 다르다. **기획 폴더에
  쓰지 않는다.**
- **필수**: `<입력루트>/10_화면설계서/`. **없으면 중단**.
- **강권장**: `12_기능명세`(상태 근거) · `06_정책정의`(UI 제약). 부재 시 degrade(아래).
- **보조**: `07_정보구조`(IA) · `08_유저플로우`. 부재 시 degrade.

### 슬러그 해소 (Stage 0, 1급)
`스터디/AI 스터디/자동화/기획/리서치/` 하위 디렉토리 목록 → **1개면 자동 채택 + 가시화** /
**복수면 게이트1에서 택1**(AI 추천 = 최근 수정) / **0개면 위치 질문 후 중단**.

### 문서 탐색 3형태 (하드코딩 금지, glob)
한 단계가 다음 셋 중 어느 형태로든 존재할 수 있다 — **한쪽만 읽어 누락 금지**:
- (a) 가이드 단일 `.md`,
- (b) `NN_단계명/` 평면 (`12-1_기능목록.md` 등),
- (c) **`NN_단계명/<재중첩>/*.md` + `NN-부속점검.md`** (예: `10_화면설계서/화면설계서/S*.md`
  + `10_화면설계서/10-예외처리_점검.md`, `12_기능명세/기능명세/F*.md`).
- **제외**: `_`로 시작하는 파일(`_템플릿_*`·`_검증체크리스트.md`)은 산출물이 아니므로 입력에서 제외.

### ID 네임스페이스별 감지 (리터럴 단정 금지)
ID 표기는 볼트마다 다르므로 하드코딩하지 말고 **네임스페이스별로 분리 감지**한다(하이픈·패딩
유무는 환경마다 다름 — 실측 화면ID는 `S6`처럼 하이픈 없음):
- **화면ID** = 화면설계서 파일명/헤더의 `S-?\d+`(하이픈 선택). 09 발원·10 계승.
- **기능ID** = 12 발번 `F-?\d+`.
- **정책 케이스ID** = 도메인 prefix형 `(RF|SB|RX|DS|PI)-?\d+` 등(06에서 실제 쓰인 prefix를 감지).
- ⚠️ **07 IA mermaid 내부 노드 라벨(`S7` 등)은 화면ID가 아니다** — 화면ID는 10 화면설계서의
  파일/헤더에서만 확정하고, IA·플로우의 동일 꼴 라벨과 혼동 금지.
신규 발번하는 유일한 ID는 **요구사항ID(`DR-\d+`)**, 나머지는 **참조만**(키 변경 금지).

### 미정값 수집 (Stage 0)
1차 소스의 미정값은 대괄호만으로 표기돼 있지 않다(평문 "기획 결정 필요" 목록·표 셀·⚠️·
"N일"/"N·M" placeholder 등). 다음을 **모두** 수집한다:
- `10-예외처리_점검.md`의 "기획 결정 필요" 섹션(평문 번호목록 포함) + 매트릭스 표 셀의 ⚠️/
  미정/placeholder + per-screen `[확인 필요]`.
- `06-3 정책매트릭스`의 ⚠️미정 · `[법무 확인 필요]` · `[법정기준 placeholder]`.
- 12의 `[확인 필요]`.
**대괄호 `[확인 필요]`로의 단일화는 본 스킬 산출물(질문 리스트)의 표기 규약일 뿐, 1차 소스엔
강제할 수 없다** — 평문 미정값도 grep 외 정독으로 수집해 질문 리스트로 승격한다.

### 부분존재 처리
10 폴더는 있으나 화면 일부만 존재할 수 있다(중단도 단순 degrade도 아님). → **Stage 1 화면
개요 머리에 커버리지 표**(감지 화면 수 / IA·플로우 기준 예상 대비 누락 추정)로 가시화하고
진행한다.

## 파이프라인

### Stage 0 — 입력 감지·슬러그 해소·degrade 판별
- 슬러그 해소(위). 문서 탐색 3형태 glob(`_`-prefix 제외). `10_화면설계서` 0건 → **중단**.
- ID 네임스페이스 감지 1회. 미정값 수집(대괄호+평문). degrade 플래그(12/06/07/08 부재). 출력 루트 확정.

### 🚦 게이트1 — 입력 범위·degrade·슬러그·가상 예시 확인
AskUserQuestion(AI 추천 1안). 예: "감지: 10(O)/12(O)/06(X)/07(O)/08(O). 06 없이 Stage 3을
스킵하고 진행? [추천: 진행 + 06 부재 가시화]". 슬러그 복수면 택1. 가상 예시면 1회 고지.
**응답 전 미진행.**

### Stage 1 — 디자이너 관점 통독 → `01-1_화면개요.md`
- 서비스 한 줄 + 핵심 태스크 3~5개(08 기준) + 그려야 할 화면 목록(화면ID|화면명|소속 플로우
  |한 줄 목적) + 화면 규모(총 화면 수 + 플로우별 화면 수).
- **커버리지 표**(부분존재 가시화): 감지 화면 수 / IA·플로우 기준 예상 / 누락 추정 + 사유.
- 추측 금지(문서에 없는 화면 지어내기 금지), 근거 화면ID 동반.

### Stage 2 — 상태 추출 → `01-2_상태추출표.md`
- 화면별 정상상태 + 필요 상태화면 + 근거 기능ID. 상태 불필요 화면은 "없음" + 이유 1줄.
- **상태 분모 = `10-예외처리_점검.md` 화면별 5종(로딩/빈/에러/권한/검증) 1차, 12 예외 보조.**
  가이드 "한도 초과"는 검증/입력제한 하위로 흡수.
- 모호 → `[확인 필요]`(Stage 4 시드). **degrade-B**: `10-예외처리_점검.md` 부재 시 12로 축소+⚠️.

### Stage 3 — 정책→UI 제약 → `01-3_정책UI제약표.md`
- 디자인에 제약 거는 조항만: [정책조항 인용 | 적용화면 | UI제약유형 | 디자인요구사항 | 정책 케이스ID].
- UI제약유형 = 필수 동의 문구 / 노출 규칙 / 입력값 제한 / 버튼 활성 조건 / 안내·경고 문구 /
  비가역 동작 확인(모달).
- **정책 문구 그대로 인용 · 정책 해석 단정 금지**. 강제 여부·문구는 초안+질문화.
- **degrade-A**: 06 부재 시 이 stage 전체 스킵 + 가시화.

### Stage 4 — 정합성·용어 사전 점검 → `01-4_질문리스트.md` (★ 1급, design-review 미호출)
- **정합성 충돌**: 10 화면 ↔ 12 기능 미물림(기능 있는데 화면 없음 / 화면 있는데 동작 정의
  없음). 단 **상위 커버리지 표에 '차기 명세 대기'로 명시된 화면은 충돌 아님**(거짓양성 방지).
- **누락**: 08 플로우 노드 중 10에 화면 없는 것. ⚠️ 08 노드가 S-ID 미표기(한글 라벨만)면
  화면명 텍스트 매칭으로 대조하고, 매칭 실패 노드는 단정 말고 `[확인 필요]`로 질문화.
- **용어 불일치**: 같은 개념 다른 이름(예 "정기배송"/"구독"/"정기구독") — **발견만, 통일 보류**.
- **모호**: "적절히 안내"·"필요 시 노출" 등 화면 확정에 추가 정의 필요한 표현.
- **다층 충돌(양방향)**: 기준이 `[확인 필요]`/⚠️미정이면 차이를 **"질문"**으로(불일치 단정 금지).
  역방향 트랩: 10 디스크립션이 단언값이어도 06-3 ⚠️미정/10 미정승계면 확정 베이스 금지.
  권위: **06 운영정책 확정본 > 10 디스크립션 > 06-3 placeholder.**
- **출처 역할 분리**: UI 메시지·에러 문구 = 12 / 정책·도메인 용어 = 06 / 화면 요소명 = 10.
- 결과: [번호|유형(충돌/누락/용어/모호)|내용|관련 화면·기능 ID|기획자 질문 한 문장].
  단정 금지 — 디자이너가 임의 결정하면 안 되는 것만 질문으로.
- **degrade-B**: 07/08 부재 시 누락·연결 점검 축소 + ⚠️.

### 🚦 게이트1.5 — MoSCoW 기준 확정 + 질문 리스트 검토 (Stage 5 전)

## 주의

- **요구사항 정리는 초안** — 화면 목록·상태 추출은 디자이너가 직접 "이게 다인가" 확인.
- **모호한 곳은 추측 금지** — 질문 리스트로. 이 단계 가치는 "물어야 할 것 골라내기".
- **정책 해석 단정 금지** — 법무 영역. 변환표는 초안, 강제 여부는 확인 후 확정.
- **시각 디자인 판단 안 함** — 02·03 단계. 1단계에서 비주얼 정하면 요구사항이 흐려진다.
- **용어 통일 보류** — 충돌 목록까지. 통일은 04·08.
- **기준 버전 박기** — 기획이 흔들리면 표에 버전/일자 명시, 갱신 시 영향 행만 재추출.
- **편집 범위** — 기획은 **읽기만**, 쓰기는 **디자인 폴더 안에서만**(자동화/ 하위·볼트 루트 금지).
- 화면ID·기능ID·정책 케이스ID는 **참조 키** — 함부로 바꾸지 마라. 신규 발번은 `DR-`만.
