# design-requirements

확정된 기획 산출물(화면설계서·기능명세·정책·IA·유저플로우)을 **디자이너 관점**으로 번역해, 그려야 할 화면·상태화면·정책 UI 제약을 추출하고, 기획서에 답이 없는 곳을 **질문 리스트**로 뽑아 MoSCoW 디자인 요구사항 표를 만드는 스킬. 디자인 시리즈 1단계(시안 착수 전 사전 점검). **1급 산출물 = 질문 리스트.**

## 설치

`SKILL.md`를 `~/.claude/skills/design-requirements/SKILL.md`로 복사한다.

## 일반경로 치환 포인트 (`<!-- 변경 포인트 -->`)

`SKILL.md` 상단 경로 정의 주석 두 줄을 본인 환경에 맞게 바꾼다. **입력은 기획 산출물에서 읽고, 출력은 디자인 산출물 폴더에 쓴다(기획에 쓰지 않음).**

- `<입력루트>` = 기획 산출물의 주제 폴더 (예: `planning-output/<주제>`)
- `<출력루트>` = `design-requirements-output/<주제>`

본 볼트 설치본은 `<입력루트> = 스터디/AI 스터디/자동화/기획/리서치/<주제-슬러그>`, `<출력루트> = 스터디/AI 스터디/자동화/디자인/리서치/<주제-슬러그>/01_디자인요구사항` 으로 고정돼 있다.

## 입력 전제

- **필수**: `<입력루트>/10_화면설계서/` (없으면 중단).
- **강권장**: `12_기능명세`(상태 근거) / `06_정책정의`(UI 제약) — 부재 시 degrade(해당 stage 축소/스킵 + 가시화).
- **보조**: `07_정보구조` / `08_유저플로우` — 부재 시 degrade.
- 문서 탐색은 하드코딩하지 않고 glob 3형태(가이드 단일 .md / `NN_단계명/` 평면 / `NN_단계명/<재중첩>/*.md` + `NN-부속점검.md`)로 감지한다.

## Notion (옵트인)

산출물 공유는 옵트인. **`claude mcp add`를 SKILL 본문에 박지 않는다**(이미 연결돼 있으면 중복). 미인증이면 스킵 + `/mcp` 안내. 발행 전 parent를 `notion-search`로 확인하고 **민감정보(실 도메인·금액)는 더미 치환**한다. 마크다운이 SSOT, Notion은 미러.

## 출력물

`01-1_화면개요` / `01-2_상태추출표` / `01-3_정책UI제약표` / `01-4_질문리스트`(★) / `01-5_디자인요구사항표`(MoSCoW + 진행/합의 상태 컬럼) / `_검증체크리스트`.

## 다음 소비자 계약

이 단계 산출물(특히 `01-5_디자인요구사항표`)은 디자인 02(레퍼런스·트렌드 리서치)·05(와이어프레임 검토)가 읽는 기준이 된다. 같은 주제에서 기획은 Notion DB, 디자인은 Notion 페이지로 발행처가 갈릴 수 있다.
