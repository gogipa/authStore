# design-responsive

06 시안·08 컴포넌트가 확정된 뒤 **04 디자인시스템의 breakpoint·grid 토큰**을 기준으로 화면이 어떤
디바이스에서도 깨지지 않게 설계하는 디자인 시리즈 11단계 검증·설계 스킬. 브레이크포인트별 거동 규칙표 +
frontend-design 반응형 거동 시뮬 + Playwright 다중 뷰포트 깨짐 검출 + (옵트인) Figma 디바이스 프레임.
프로토타입(10)과 디자인 QA(12) 사이.

## 설치
`SKILL.md`를 `~/.claude/skills/design-responsive/SKILL.md`로 복사.

- `<기획루트>` = `<기획 산출물 루트>/<주제>` (09 와이어프레임=반응형 의도·10 화면설계서 — 읽기 전용)

정규화 폐기(`산출물/`은 스킬 배포 폴더 전용) → `11_반응형/`.

## 반응형 토큰 SSOT = 04 (원본 "08 토큰" 정정)
원본 가이드는 "08 디자인토큰의 breakpoint·spacing"이라 하지만 **실데이터에서 breakpoint·grid는 04에 실재**
(04 `tokens.css`의 `--bp-mobile/tablet/desktop` + 04-2 그리드표). **08 tokens.css엔 breakpoint 0건.** →
09 모션(04 부재→09 신설)과 **정반대로 11은 04를 읽어 쓴다**(신설 금지). 04에 없는 값이 필요하면 04 직접
편집 금지·환류 기재만. 원본 워크플로우 예시 경계값(768-1024/≥1024/1440)은 04 진실(360/768/1280)과 충돌 →
**비계승**(silent 계승 금지).

## 브레이크포인트 ≠ 캡처 뷰포트 (축 분리)
**브레이크포인트**(레이아웃 분기점·04 SSOT·360/768/1280)와 **캡처 뷰포트**(깨짐 스크리닝용 디바이스 실폭·11
자체 검수 파라미터)는 다른 축이다. 폴드(717)·1920 같은 디바이스 실폭은 **04에 환류하지 않는 11 검수
파라미터**(04 SSOT 역방향 오염 방지).

## frontend-design 스코프락 (제3축)
09(시각충실도 미상승 억제)·10(BMD 하이파이 충실도 락)과 또 다르다. 11은 **①06 시안 시각 베이스 재사용
(신규 비주얼 금지) ②04 breakpoint/grid를 `@media`로 1:1 적용 ③반응형 거동만 검증·픽셀 마감/접근성/호환은
비목표(퍼블리싱 14) ④throwaway 배너**. 코드는 거동을 확정하는 throwaway 근거이지 합의물 아님.

## 코드가 진실·Figma가 합의안
반응형 거동은 frontend-design 코드 + Playwright 캡처에서 확정하고, 그 결과를 Figma 프레임에 반영하는 순서.
Figma에서 먼저 그리면 중간 너비 깨짐을 늦게 발견한다. 산출 위계 = ①반응형 스펙(규칙 SSOT) ②Figma 디바이스
프레임(합의·핸드오프 산출물) ③캡처 세트(깨짐 근거).

## 06 모바일 단일 → scale-up degrade
실데이터에서 06 시안·10 인계물이 모두 모바일 단일(360)이라 원본의 "데스크톱→디바이스 재배치" 전제가 깨진다.
06이 모바일 단일이면 **데스크톱 레이아웃을 AI가 발명하지 않고**(BMD), 기획09 와이어프레임 반응형 의도 +
사람 게이트에서 컬럼 확장 규칙만 확정·`[확인 필요: 06 데스크톱 시안 부재]` placeholder.

## Figma MCP (옵트인 · /figma-use 선행 · write 기본 아님)
디바이스 프레임 생성(use_figma)은 코드 확정 후 옵트인(게이트 동의·write 권한·非dry-run). 미연결 시:
`claude mcp add --transport http figma https://mcp.figma.com/mcp` 후 `/mcp` 인증(편집할 파일 쓰기 권한 계정).
`get_design_context`는 06 시안이 Figma 링크일 때만·화면 단위로 끊어 호출. `get_variable_defs`는 토큰 점검
진실 아님(selection 한계·하드코딩 거짓통과·publish 시 인벤토리 보조만). 04 Variables 미publish 주제는
동의해도 베이스 0건이라 HTML+스펙이 사실상 1급. (SKILL 본문은 mcp add를 하드코딩하지 않는다 — README 전용.)

## Playwright MCP (핵심③ · 미연결 시 정적 분석)
다중 뷰포트 일괄 캡처가 핵심이지만 미연결 가능성 높음→정적 CSS 미디어쿼리·overflow 휴리스틱 분석 + 수동
캡처 체크리스트로 degrade(도구 0개로도 손실 없음). 미연결 시:
`claude mcp add playwright npx '@playwright/mcp@latest'`(최초 1회 브라우저 바이너리 설치). dry-run 생략.

## Notion MCP (선택 · 공유)
검수 리포트 공유·반영 추적. 옵트인·사람 검토 후·체크박스 토글. 미연결 시:
`claude mcp add --transport http notion https://mcp.notion.com/mcp`. dry-run·미연결 시 마크다운 1급.

## HITL 경계 (사람 몫)
①시각 품질(여백 위계·균형·미세 정렬)은 스크린샷 평가 불신뢰·디자이너 영역 ②실기기 ≠ 뷰포트 캡처
(100vh 점프·노치/세이프에어리어·폴드 힌지·터치영역은 실기기/에뮬레이터·캡처는 1차 스크리닝) ③자동 검출 =
후보이지 판정 아님(의도적 거동을 깨짐으로 오판 가능·게이트2에서 사람 재분류). 토큰 미사용은 04/08 담당 합의.
