# 와이어프레임 검토 (Wireframe Review)

기획이 만든 와이어프레임(09)을 UI 시안(06)에 올리기 **전에** 한 번 거른다. "이대로 시각
작업에 들어가도 되는가" — 플로우엔 있는데 안 그려진 **누락 화면**, 정상 화면만 있고 빠진
**상태 화면**(빈/에러/로딩/권한), IA·요구사항과 어긋난 **정보 위계**를 검출해 **검토
리포트**로 만든다. **생성이 아니라 검증·검토 스킬.** design-review와 닮았지만 ① 대상이 시안이
아니라 **와이어프레임**(로파이) ② 단계가 시안 後가 아니라 **시안 前** ③ 권위 문서가 10/12/06이
아니라 **08(플로우)·07(IA)+디자인 01-2(상태추출표)**이다.

## 핵심 원칙 (어기면 헛 리포트가 나간다)

- **검출 = 후보지 판정이 아니다.** 기획자가 의도적으로 단순화한 화면(두 상태를 한 화면에 합침,
  프롬프트로만 정의)을 "누락"으로 오검출할 수 있다 → 그대로 던지지 말고 디자이너가 먼저 훑어
  의도적 설계는 **"확인 필요"로 옮긴 뒤** 공유. (design-review "검출=후보, 판정=사람" 계승.)
- **09-1 화면목록이 1급 화면 분모다.** Figma/HTML로 "그려진 프레임"은 09-1의 부분집합일 수 있다
  (실측: HTML 6 ⊂ 09-1 13). 그려진 것만 보면 분모가 줄어 누락을 못 잡는다 → **분모는 항상
  09-1, 그려진 프레임은 '증거'로만**. **프롬프트로만 정의된 화면은 누락(❌)이 아니라 '프레임
  미생성-검토보류'**로 분리(의도적 단순화 오검출 차단).
- **시각 품질은 판단하지 않는다.** 정렬·여백·비례·"예쁨"은 디자이너 영역. 위계 점검은 **"정보
  우선순위가 IA(07)·요구사항과 어긋나는가"라는 사실 대조까지로 한정**.
- **로파이 텍스트는 한계가 있다.** 회색 박스만 있는 와이어프레임은 `get_design_context`로 라벨을
  못 읽는다 → `get_screenshot`(시각) + 09 명세 텍스트 병행, **와이어프레임만으로 라벨 추정 금지**.
- **상태 누락은 단정이 아니라 추가 요청이다.** 누락 화면 책임은 기획자(와이어프레임=기획 산출물).
  디자이너가 임의로 그리지 않고 **리포트로 반영 요청**(디자인은 기획 폴더에 쓰지 않는다).
- **01-2는 하류(10/12) 확정본이다 — 시점 역전 주의.** 01-2에 있고 09(상류·로파이)에 없는 상태는
  '누락' 단정 금지 → "09→10 사이 추가될 상태(보강 요청 or 시안 단계)"로 톤다운.
- **마크다운 = SSOT, Notion = 옵트인 미러.** 갈라지면 다툼이 생긴다.

## design-review와 다른 점 (트리거·권위 분리)

- **wireframe-design**(09 와이어프레임 **"설계"=생성**)의 산출물을 본 스킬이 **"검토"**한다.
  트리거 동사축 분리: 그리기·생성=wireframe-design / 검토·누락 검출·시안 착수 전 점검=본 스킬.
- **design-review**(완성 **시안 後** 리뷰, 권위=10/12/06)와 본 스킬(**와이어프레임 시안 前**,
  권위=08/07/01-2)은 "검출=후보·시각판단 안함·Figma read" 규율을 공유하나 **대상·단계·권위
  문서가 다르다**. design-review는 시안이 있어야 동작하므로 이 단계에서 호출하지 않고 규율만 계승.

### 와이어프레임 소스 2분기 (design-review 시안 소스 분기 동형)
출력 품질은 소스에 비종속:

### ID 네임스페이스 3분 감지 (리터럴 단정 금지)
ID 표기는 볼트마다 다르므로 **네임스페이스별로 분리 감지**한다:
- **화면ID** = `S\d+`(하이픈 없음). **09-1 화면목록의 행에서만 확정한다.** ⚠️ **07-1 IA mermaid의
  `S0~S6` 동일 꼴 노드 라벨은 화면ID가 아니라 IA 내부 식별자**이므로 화면 매핑 금지(실측: 07 S1=구독상세
  vs 09 S1=스플래시로 정면 충돌). Stage 3 IA 위계 대조는 S-숫자가 아니라 **트리 항목명(한글 텍스트)으로 join**.
- **요구ID** = `R\d+`(07/IA 요구사항).
- **정책 복합ID** = `(RF|SB|RX|DS|PI)-?\d+`(08-2에서 실제 쓰인 prefix 감지). **`R` 단독은 정책ID로
  쓰지 않는다**(요구ID와 충돌). ⚠️ `R\d+`(예 R10)은 06 정책 케이스ID이면서 07 요구ID로도 등장해 **출처열이
  둘 다 06이면 문맥 분리가 안 된다** → 같은 셀 `SB-03/R10`은 **SB-03을 1급 정책키로 채택, R10은 `[확인
  필요: 정책ID/요구ID 중의성]`으로 보류**(조용한 누락 방지).

### HTML 화면식별 = `.cap` 텍스트 앵커 (클래스 가정 금지)
`.phone`/`S\d+` 같은 클래스 패턴은 09의 계약이 아니다(실측 `S\d+` 클래스 0건). 식별 규칙:
- **`.cap`/`.label` 등 텍스트 노드에서 `S\d+` + 상태수식어**(empty/error/loading)를 추출하고, **프레임↔ID
  결합은 DOM 인접**으로. **키 = (화면ID, 상태) 복합키**(`S8` 정상 / `S8`+empty를 별도로 — 카운트 혼선 방지).
  ⚠️ 상태수식어는 한글 설명과 한 텍스트에 섞여 나온다(실측 `.cap` = `S8 · 홈 (empty — 구독 0건)`) →
  **영문 토큰(empty/error/loading) substring 매칭**으로 줍고, `S8-empty` 같은 하이픈 표기를 강제하지 말 것.
- `.cap` 등 텍스트 앵커가 없으면 **`09-1_화면목록.md`를 1차 인덱스로 fallback**.
- ⚠️ 09-3 표가 'HTML 7화면'(S8 정상/empty 2장 합산)과 '실생성 6'(고유 화면)을 다르게 셀 수 있다 →
  **복합키로 풀면 카운트 불일치가 리포트에 새지 않는다**(빌드/실행 시 09-3 표와 교차검증).

### Stage 1 — 화면 커버리지 → `05-1`
- **소스 커버리지 4열표**(design-review 13-2식): `09-1 전체(분모) | 그려진 프레임(Figma/HTML) |
  09-2 프롬프트-갈음 | 차집합+사유`. 그려진 프레임 = '증거'로만, 분모는 항상 09-1.
- **프롬프트-갈음 화면은 ❌(누락) 아니라 '프레임 미생성-검토보류'**로 별도 라벨(우선순위 '중'·시안 단계
  생성 예정 — 의도적 단순화이므로 거짓누락 차단).
- 와이어프레임 프레임 ↔ 08-1/08-3 플로우 노드(해피패스+예외) 매핑: `플로우 노드 | 대응 프레임 |
  상태(존재/누락/유사 추정)`. **플로우엔 있고 와이어프레임에 없는 화면 = 누락 목록**(예외 플로우 강조:
  결제실패·추천0건·배송불가). 확신 없는 매핑 = "확인 필요"(단정 금지).
- 08-2 노드가 한글 라벨뿐(S-ID 무)이면 화면명 텍스트 매칭, 실패 노드는 `[확인 필요]`.
- **차집합 0 = 누락 공집합은 정상이다.** 09-2 프롬프트-갈음으로 09-1 전량이 커버되면 '진짜 누락'(분모에도
  프레임에도 프롬프트에도 없음)은 0이 된다 → 이때 검출 가치는 05-2 상태 커버리지로 옮겨감을 리포트에 명시.
  단 **프롬프트-갈음 중 우선순위 '상'인 미렌더 화면은 ⚠️로 강조**(검토보류로 묻혀 디자이너가 가볍게 넘기는 것 차단).

### Stage 2 — 상태 커버리지(빈/에러/로딩/권한) → `05-2` ★ 통합렌즈 핵심
- **상태 분모 = 3겹 통합렌즈**:
  - (1) **01-2를 권위 분모로 재사용** — 01-2가 이미 5종 도출한 화면(실측 S6/S9/S11/S12)은 그 행을
    근거·미정 플래그째 승계. 상태 5종 라벨 = **로딩 / 빈 데이터 / 에러 / 권한 없음 / 입력 검증**(01-2 원문).
  - (2) **01-2 미커버 화면은 08-2 예외표 + 07-1 empty-state에서 재도출**(중복 회피·공백 메움 양립).
  - (3) **09-1 '상태 변형' 셀프선언 열을 1급 축으로 편입** — 09-1이 선언했는데 프레임이 없으면 **최우선
    누락**. 단 09가 08-2 행을 그대로 베껴 선언했고 **그 상태의 프레임이 실재**하는 경우(같은 상류 파생·
    드리프트0)만 '누락'이 아니라 '동일 출처-프레임 실재로 재확인'으로 강등 — **동일 출처라도 프레임이
    부재하면 강등 대상 아니고 일반 상태 추가 요청**으로 둔다.
  - **라벨 매핑(3겹 join 전제)**: 09-1 셀프선언 영문 약어 ↔ 01-2 한글 5종을 고정 매핑한다 — `empty`=빈
    데이터, `error`=에러, `loading`=로딩(09-1엔 권한 없음·입력 검증 약어가 없으니 그 둘은 01-2/08-2에서만
    옴). **글자 일치로 join하지 말 것.**
- **상태 소스 라우팅**: error/loading→08-2(발생 노드 텍스트 매칭), empty→07-1 empty-state, 권한→08-2
  인증/권한행+07. **08-2 '상대방행동(범위 밖)' 행은 분모 제외**. `[정책미정→06 환류]` 케이스에 걸린
  상태는 **누락 단정 금지 → 확인 필요**.
- **시점 역전**: 01-2(하류 10/12)에 있고 09(상류·로파이)에 없는 상태는 '누락' 아니라 "09→10 추가분".
- 각 상태 ↔ 프레임 매핑 ✅/❌/유사추정. ❌ = **상태 화면 추가 요청**(어느 예외 케이스ID 근거인지
  08-2 출처열·01-2 근거열 인용). 커버리지 표: `화면 | 필요 상태(5종) | 프레임 존재 | 근거(08-2/01-2/07)`.
- **문서간 정책상태 상충 dedup**: 같은 케이스ID(예 RF-04)가 01-2(미정)·08-2(확정 3일·2회)로 상반
  기재되면 **케이스ID 키로 dedup**하고 **상류 08-2 확정값을 채택 표기 + '문서간 정책상태 불일치'를
  별도 확인 필요 항목으로 승격**(모순 리포트 방지).
- **누락의 90% = 상태 화면** 원칙: 정상 플로우에 안 보이는 상태를 기계적으로 떨어뜨린다.
- 상태 분모가 08-2·07 어디에도 없는 화면(예 스플래시·동의·일반안내)은 01-2 규율('상태 불필요+이유
  1줄')로 처리하되 **자동 '없음' 단정 금지** → "디자이너 확인" 표기.

### Stage 3 — 정보 위계·레이아웃 점검 → `05-3`
- 핵심 화면 3장 `get_screenshot`(시각) + `get_design_context`(요소 순서·그룹핑, 로파이라 보조).
  HTML이면 DOM 순서. **로파이 텍스트 부실 시 라벨 추정 금지** — get_screenshot + 09 명세 텍스트 병행.
- 07-1 IA 우선순위 + 09-3 세트 명세와 대조: 최우선 정보가 위/크게 있는가 / CTA가 부차 요소에
  묻히지 않는가 / 결정 요소 과밀. **IA 대조는 트리 항목명(한글 텍스트)으로 join**(S-숫자 join 금지).
- 표: `화면 | 위계 이슈 | 근거(IA 우선순위/요구사항) | 심각도(상/중/하)`. **시각 "예쁨" 평가 금지**,
  판단 갈리는 항목 = "확인 필요". 07-2_IA검증리포트 있으면 IA 미결·중복라벨을 근거 보강에 인용.

### Stage 4 — (옵션) 대안 레이아웃 시뮬레이션 (frontend-design) → `05-4` HTML

  실제 카피 없이 회색 박스. frontend-design = 내장 스킬 invoke.
- **Playwright = probe 후 연결 시에만** 모바일/데스크톱 뷰포트 스크린샷. **미연결이면 뷰포트 캡처만
  생략하고 대안 HTML은 산출**(부분 degrade·도구 존재 단정 금지). dry-run 시 생략.

## degrade / 중단 / 게이트 블로킹

- **중단**: 와이어프레임 부재(a·b 둘 다) / **08 전부 부재 AND 01-2도 부재**(상태 분모 완전 소멸) / 슬러그 0개.
- **degrade**:
  - Figma 미인증 → 09 HTML(또는 사람-개입 get_screenshot 단발, 그조차 불가하면 중단).
  - 01-2 부재 → 상태 분모를 08-2/07에서 **전량 재도출** + ⚠️(통합렌즈 자동 폴백).
  - **08 부재 but 01-2 있음** → 01-2 커버 4화면 한정 상태 검토 + 커버리지 대조 축소 + ⚠️(부분 degrade).
  - 07 부재 → Stage 3 위계 점검을 09 명세 우선순위만으로 축소 + ⚠️.
  - get_metadata 부재 → 05-2 "프레임 존재" 열 "추정" 강등.
  - frontend-design/Playwright 미사용 → Stage 4 생략(또는 뷰포트만 생략) — 산출 손실: 대안 HTML/스크린샷.
  - Notion 미사용 → 마크다운 SSOT.
  - **"08(또는 01-2) + 와이어프레임만 있으면 05-1 커버리지 + 05-2 상태로 degrade 완성"**(중단 아님).
- **게이트 블로킹**: 게이트2 Notion parent 미확인 = Notion 발행만 차단 / `[확인 필요]` 미해소 = 완료 보고 차단.

## 주의

- **검출은 후보** — 의도적 단순화는 "확인 필요"로 옮긴 뒤 공유.
- **분모는 09-1** — 그려진 프레임만 보면 누락을 못 잡는다. 프롬프트-갈음은 '검토보류'.
- **시각 품질 판단 안 함** — 위계는 IA 사실 대조까지. 정렬·여백·"예쁨"은 06.
- **로파이 라벨 추정 금지** — 회색 박스는 get_screenshot + 09 명세 텍스트 병행.
- **누락 화면 책임=기획자** — 디자이너가 임의로 안 그림, 리포트로 반영 요청. 기획 폴더에 안 씀.
- **01-2 시점 역전** — 01-2(하류)에 있고 09(상류)에 없는 상태는 '누락' 아니라 추가분.
- **화면ID는 09-1만** — IA mermaid S0~S6는 화면ID 아님. IA 대조는 트리 항목명으로.
- **기준 버전 박기** — 09/08/07이 흔들리면 리포트에 버전/일자 명시, 갱신 시 영향 행만 재검토.
- **편집 범위** — 기획·이전 디자인은 읽기만, 쓰기는 `<출력루트>` 안에서만(`자동화/` 하위·볼트 루트 금지).
