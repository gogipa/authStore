# design-wireframe-review

기획 와이어프레임(09)을 UI 시안(06) **착수 전에** 검토하는 디자인 시리즈 5단계 스킬. 플로우엔
있는데 안 그려진 **누락 화면**, 정상 화면만 있고 빠진 **상태 화면**(빈/에러/로딩/권한), IA·요구사항과
어긋난 **정보 위계**를 검출해 **검토 리포트**로 만든다. **생성이 아니라 검증·검토 스킬.** 디자인
시스템(04)과 UI 시안(06) 사이.

## 설치
`SKILL.md`를 `~/.claude/skills/design-wireframe-review/SKILL.md`로 복사.

## 일반경로 치환 포인트 (`<!-- 변경 포인트 -->`)
- `<기획루트>` = `<기획 산출물 루트>/<주제>` (와이어프레임·플로우·IA를 읽는 곳)
- `<디자인입력>` = `<디자인 산출물 루트>/<주제>` (01-2 상태추출표를 읽는 곳)
- `<출력루트>` = `<디자인 산출물 루트>/<주제>/05_와이어프레임검토`

⚠️ 원본 가이드는 `디자인/검토산출물/` 평면경로를 입출력에 쓰는데, 이 스킬 시리즈에서 `산출물/`은
**스킬 배포 폴더 전용**이고 `검토산출물/`은 임의 경로라 충돌한다 → 출력(대안 HTML·리포트 모두)은
`05_와이어프레임검토/`로.

## 입력 전제
- **필수(검토 대상)**: 와이어프레임 — **(a) Figma 링크** OR **(b) `<기획루트>/09_와이어프레임/`**
  (`09-1_화면목록.md`·`09-3_와이어프레임세트.md`·`wireframes/*.html`). 둘 다 없으면 중단.
- **필수(대조 기준)**: `08_유저플로우`(`08-2_예외케이스표` 포함). 08 전부 부재 **AND** 01-2도 부재면
  중단(상태 분모 소멸). 08 부재지만 01-2 있으면 4화면 한정 부분 degrade.
- **강권장**: `07_정보구조`(`07-1_IA트리`·`07-2_IA검증리포트`) · 디자인 `01_디자인요구사항/01-2_상태추출표`.

## 와이어프레임 소스 2분기
출력 품질은 소스에 비종속이다. **(a) Figma 링크**가 있으면 Figma READ로, 없으면 **(b) 09 HTML**을
파싱한다. HTML 화면식별은 `.cap`/`.label` 텍스트의 `S\d+`+상태수식어를 앵커로 쓰고(클래스 패턴은
09 계약이 아님), 텍스트 앵커가 없으면 `09-1_화면목록.md`를 인덱스로 fallback한다.

## Figma (READ 전용 · /figma-use 불요)
와이어프레임 검토는 **읽기만** 한다 — `get_metadata`/`get_screenshot`/`get_design_context`를 직접
호출하며 `/figma-use`(write 전용 게이트)는 비해당이다. 미연결 시: `claude mcp add --transport http
figma https://mcp.figma.com/mcp` 후 `/mcp` 인증(파일 열람권한 계정). 미인증·view-only면 09 HTML로
degrade. (SKILL 본문은 mcp add를 하드코딩하지 않는다 — README 전용.)

## 상태 분모 3겹 (통합렌즈)
상태 커버리지(Stage 2)의 분모는 ① 01-2 상태추출표가 이미 5종 도출한 화면(권위 재사용) ② 01-2
미커버 화면은 08-2 예외표+07 empty-state에서 재도출 ③ 09-1 '상태 변형' 셀프선언 열을 1급 축으로
편입(선언 O·프레임 X = 최우선 누락) — 세 겹을 합쳐 구성한다. 01-2는 하류(10/12) 확정본이라 01-2에만
있고 09에 없는 상태는 '누락'이 아니라 '09→10 사이 추가분'으로 톤다운한다.

## Playwright (옵션)
Stage 4 대안 레이아웃의 뷰포트 스크린샷에만 쓴다. **probe 후 연결돼 있을 때만** 캡처하고, 미연결이면
뷰포트 캡처만 생략하되 그레이스케일 대안 HTML은 그대로 산출한다(도구 존재 단정 금지).

## frontend-design (내장)
Stage 4 그레이스케일 대안 레이아웃 HTML은 frontend-design 스킬을 내장 invoke한다(probe 불요).

## Notion (옵트인)
검토 리포트의 Notion 미러는 옵트인이다. 마크다운이 SSOT, Notion은 체크박스 토글 미러. 미인증이면
스킵 + `/mcp` 안내. parent는 `notion-search`로 후보 제시 후 확인. 민감정보는 더미로 치환.

## 출력물
`05-1_화면커버리지`(소스 커버리지 4열표+누락 목록) · `05-2_상태커버리지`(3겹 분모 ✅/❌+상태 추가
요청) · `05-3_정보위계검토`(위계 이슈+IA 근거+심각도) · `05-4_대안레이아웃.html`(조건부·그레이스케일) ·
`05-5_와이어프레임검토리포트`(개요+5섹션) · `_검증체크리스트`.

## 다음 소비자 계약
이 검토 리포트가 06(UI 시안)이 무엇을 그려야 하는지의 입력이 되고, 12(디자인 QA)가 상태 커버리지
체크리스트를 재사용한다. **누락 화면 책임은 기획자** — 디자이너가 임의로 그리지 않고 리포트로 반영
요청한다(디자인은 기획 폴더에 쓰지 않는다).
