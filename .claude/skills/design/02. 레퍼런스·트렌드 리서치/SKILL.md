# 레퍼런스·트렌드 리서치 (Design Reference Research)

요구사항을 파악했으면(design-requirements), 그리기 전에 "남들은 이 문제를 어떻게 풀었는가"를
본다. 경쟁/동종 앱의 실제 화면과 UI 패턴을 모으고, 최근 디자인 트렌드(컬러·타이포·모션)를
정리하고, 그것을 **우리 와이어프레임 화면에 적용 후보로 매핑**한다. **수집·분류·구조화
스킬 — 시안을 생성하지도, 취향을 판단하지도 않는다.** 화면을 고르는 안목과 "우리한테 맞는가"는
사람이, 빠짐없이 모으고 출처와 함께 구조화하는 일은 AI가 한다.

## 핵심 원칙 (어기면 시안 착수가 헛돈다)

- **수집은 진척이 아니다. 매핑표가 결과물이다.** 200장을 모으고 우리 화면에 매핑하지 않으면
  시안 착수 때 다시 헤맨다. 이 단계의 1급 산출물은 **우리 화면 ↔ 패턴 매핑표(`02-8`)**.
- **취향·예쁨을 판단하지 않는다.** "어떤 패턴이 더 세련됐나"는 디자이너 영역. AI는 패턴을
  모으고 출처와 함께 사실(빈도·구성·흐름)로 구조화하는 데까지. "어떤 게 더 나아?"의 답을
  컨셉 근거로 삼지 마라(Stage 2·4·5·6에서 반복 적용).
- **갤러리를 AI가 크롤링한다고 가정하지 않는다.** Mobbin·Dribbble은 로그인·동적 렌더링이라
  WebFetch로 본문이 안 잡힌다 → **WebFetch 시도조차 하지 않고**(실패 예정 호출 = 비용·환각),
  사람이 캡처+설명 md를 `<출력루트>/레퍼런스/`에 넣는다(human-in-the-loop, 게이트2).
- **트렌드는 유통기한이 짧고 동조 위험이 있다.** "2026 트렌드"를 그대로 따르면 다 비슷해진다.
  트렌드 산출물 머리에 **조사일을 박고**, 트렌드 따르기와 차별화의 균형은 사람이 정한다.
- **출처·저작권.** Dribbble·Behance는 컨셉(미출시)이 많아 복제 금지 — "패턴을 배우는" 대상.
  캡처 임베드 시 출처 필수, 외부 공유본은 라이선스 확인.
- **마크다운 = SSOT.** 볼트가 원본, Notion은 옵트인 미러. NotebookLM은 소스가 전부 —
  화면 유형별 최소 3~5개 사례를 넣어야 "공통 패턴"이 의미를 갖는다.

- **1급 분모 = `<기획입력>/09_와이어프레임/09-1_화면목록.md`의 전체 화면**(실측 `S1~S13`).

### 경쟁사 (강권장·선택, 약한 가중치)
- market-research 01 산출물이 있으면 1순위. **없으면 폴백** = `<기획입력>/05_비즈니스모델/
  05-2_경쟁사가격정책.md` + `04_상위기획/04-4_가치제안캔버스.md`.
- ⚠️ 폴백은 **검색 기반 가설(degrade 산물)**이고 **가격·가치 신호이지 UI 강점 신호가 아니다.**
  '어디를 집중해 볼지' **보조 나침반**으로만 쓰고, 이 한계를 `02-1_조사범위.md`에 그대로 전파.
  **경쟁사명 하드코딩 금지** — 폴백 파일에서 실제 등장명을 추출. 셋 다 부재 → degrade(가중치
  빼고 우리 화면 09-1/07 IA에서만 화면유형 도출).
- ⚠️ **경쟁사 폴백은 `02-1` 보조 나침반까지만.** `02-8` 매핑표의 근거 칸에는 직접 인용하지
  않는다(매핑 근거 = 아티클·캡처·Figma 시안만). 폴백엔 UI 단서가 거의 없어 빈 근거 칸을
  폴백으로 메우면 약한 출처가 UI 근거로 과대 인용된다.

### 화면ID 감지 (하드코딩 금지)
09-1 `#`열·화면명 셀·01-1 화면ID 열의 **`S-?\d+`만 화면ID**(실측 하이픈 없음 `S1~S13`).
⚠️ **R·RF·SB·US·07·08 prefix는 화면ID가 아니다**(IA 라우트·정책 케이스ID·플로우 — 09-1 한 표에
밀집). 화면ID는 **참조만**(키 변경 금지). 02가 신규 발번하는 유일 네임스페이스 = **패턴ID `PT-\d+`**
(매핑표에서 패턴 식별용, 화면/정책 ID와 시각 충돌 회피).

### 사람 큐레이션 캡처 (Stage 3·5 입력, human-in-the-loop)
정상 경로는 `<출력루트>/레퍼런스/*.{png,md}` **단일**. (원본 가이드의 평면경로 `디자인/리서치/

## 파이프라인

### Stage 0 — 슬러그 해소·화면목록 출처·도구 probe·degrade
- 슬러그 해소(위). 화면목록 = 09-1 1급 + 01-1 오버레이(없으면 09-1만, 둘 다 없으면 중단).
- **도구 probe**(하드코딩 가정 금지): deep-research = 번들 스킬(미탑재 거의 없음, 가벼운 확인.
  저비용/dry-run 모드에선 WebSearch 2~4건으로 바운드 가능) / Figma = whoami 인증 / NotebookLM =
  서버별 분기. **notebooklm-mcp**: `server_info`의 `auth_status`가 `configured`가 아니면
  (stale·not_configured·error 포함) **미인증**으로 처리, 재로그인은 Bash CLI `nlm login`
  (MCP 도구 아님). **레거시 notebooklm**: `get_health`의 `authenticated=false`면 setup_auth·
  공유URL 입력 요청.
- 입력 산출물에 dry-run/가상예시 고지가 있으면 02 산출물 머리에 1회 계승. degrade 플래그.

### Stage 1 — 조사 범위 → `02-1_조사범위.md`

필요 패턴은 "Mobbin 확인 필요" 표기. **비용·시간 경고**(게이트1 동의분).
`02-3`은 **고정 3섹션 템플릿**으로 쓴다(다음 실행자마다 분리 기준이 달라지지 않게):
- `## 시각 트렌드` — 컬러·타이포·모션·레이아웃 각 항목 + 출처
- `## 핸드오프 키워드` — 03(무드보드)·04(토큰)가 떼어갈 키워드(5축 내외)
- `## 대표 썸네일` — `레퍼런스/` 캡처 2~3장 wikilink + 출처
03/04는 이 섹션 단위로 떼어간다.

### Stage 3 — WebFetch 아티클 → `02-4_아티클패턴표.md`

### 🚦 게이트2 — 사람 캡처·Figma 링크
`레퍼런스/`에 캡처+설명 md를 넣었는지 + Figma 커뮤니티 시안의 **드래프트 복제링크(node-id 포함)**
요청. 요청 문구에 절대경로(중첩) 명시. 미제공 시 추천 = "캡처 없이 deep-research+아티클로 매핑표
작성, 캡처 의존 패턴은 [캡처 대기] 표기 후 진행"("캡처 안 함"도 유효 선택).

### Stage 4 — Figma 시안 분해 → `02-5_figma시안분해.md`
get_metadata로 프레임 목록 → 해당 프레임 get_screenshot → 구성요소 분해(플랜 카드 구조·가격
표기·CTA 위치·배송주기 UI). 우리 화면과 비교해 "차용 가능 / 우리 맥락 부적합" 분리. **시각품질
평가 금지.** **Figma 미인증 — 또는 인증됐어도 게이트2에서 복제링크 미제공 — 시 이 stage 스킵 +
가시화**(스킵 사유를 `02-5`에 한 줄로 남긴다).

### Stage 5 — NotebookLM 질의 → `02-6_notebooklm질의.md`
Stage 1~4 산출물 + 캡처 설명 적재 후 출처기반 질의. **소스 3~5개 미달 시 신뢰도 경고.** 질의문에
평가어('우수한/세련된/잘 풀어낸') 금지 → 관찰 사실어(빈도·구성·흐름). 템플릿: "X 화면유형 공통
패턴 상위 N / 특정 UX(건너뛰기·일시정지 진입점) 사례의 공통점, 각 답 근거 소스 표기". 서버 미인증·
레거시 자동생성 불가 → 2단 degrade(자동 / 사람이 노트북 만들고 공유URL 입력 / 스킵).

## 도구 정확성

- **deep-research** = 번들 스킬(MCP 아님). 비용·시간(토큰·5~15분) 경고 + 게이트1 동의. 실패 시
  중단 아닌 degrade. 저비용/dry-run 모드는 WebSearch 2~4건으로 바운드.
- **WebSearch/WebFetch**(내장) = 정적 아티클 원문만. Mobbin·Dribbble 동적 페이지는 시도 안 함.
- **Figma MCP** = get_metadata/get_screenshot로 **구조** 분해(캡처보다 정확). 커뮤니티 원본은
  권한·렌더링 문제 → **본인 드래프트 복제링크(node-id 포함)** 사용. whoami 인증; 미인증·링크 미제공 스킵.
- **NotebookLM MCP**(2서버) = 서버별 분기 probe(위 Stage 0). **claude mcp add 본문 하드코딩 금지**
  (이미 연결됨) — 인증 확인 → 미인증 스킵 + 안내. 소스 기반 RAG(소스 3~5개).
- **Notion MCP**(연결됨) = 옵트인. 로컬 이미지 자동 업로드 안 됨 → 경로+출처만, wikilink는 경로
  텍스트로 변환. 민감정보 더미.

## 주의

- **수집 ≠ 진척.** 매핑(Stage 6)이 결과물. 200장 모으고 매핑 안 하면 시안 때 다시 헤맨다.
- **취향·예쁨 판단 안 함** — 큐레이션은 사람. AI에 "더 나은가" 물어 컨셉 근거 삼지 마라.
  보드 '한 줄 평'은 AI가 비운다(`[사람 큐레이션 대기]`).
- **Mobbin·Dribbble은 사람이 캡처** — AI 크롤링 가정 금지. WebFetch 시도 안 함.
- **트렌드 동조 위험 + 유통기한** — 조사일 박기, 따르기와 차별화는 사람이.
- **출처·저작권** — 컨셉 시안 복제 금지, 캡처 출처 필수, 라이선스 확인.
- **경쟁사 폴백은 약한 출처** — UI 강점 신호 아님(가격·가치), ⚠️ 전파, 매핑 근거 칸 직접 인용 금지.
- **편집 범위** — 기획·디자인 01은 **읽기만**, 쓰기는 `<출력루트>` 안에서만(자동화/ 하위·볼트 루트 금지).
- 화면ID는 **참조 키** — 바꾸지 마라. 신규 발번은 `PT-`(패턴)만. 한글 경로는 Read/Glob만.
