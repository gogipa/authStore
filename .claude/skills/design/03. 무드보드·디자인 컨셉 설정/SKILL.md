# 무드보드·디자인 컨셉 설정 (Design Moodboard)

레퍼런스를 모았다면(design-reference-research), 그 더미에서 **우리 서비스가 가야 할 방향
하나**를 골라야 한다. 이 스킬은 흩어진 인상을 **아트 디렉션 하나로 수렴**시키는 합의 작업이다.
톤앤매너·컨셉 키워드·컬러 무드를 정하고, 그것을 무드보드에 모아 팀이 한 방향을 고른다.
**핵심은 디자인이 아니라 합의** — 무드보드는 예쁜 콜라주가 아니라 **의사결정 도구**다. 06 UI
시안에서 "이건 우리가 정한 톤이 아닌데"라는 되돌리기를 막는 것이 존재 이유.

## 핵심 원칙 (어기면 06 시안에서 갈아엎는다)

- **AI 발산 키워드는 재료지 결론이 아니다.** 발산의 가치는 양·다양성이지 정답이 아니다 —
  수렴 기준(가치제안 부합)은 반드시 사람이 적용해 거른다. AI는 컨셉을 고르지 않는다.
- **멋 ≠ 맞음.** 시각적으로 가장 인상적인 후보가 가장 좋은 것이 아니다. 기획 04 가치제안과
  연결이 약하면 아무리 멋있어도 기각. 선택 기준은 항상 "멋"이 아니라 "맞음".
- **컬러는 무드보드까지만 후보, 정의서는 방향만.** 무드보드/탐색 단계는 hex 후보를 허용하되
  **`확정 아님·04에서 재검토` 라벨을 강제**한다. **컨셉 정의서(04 입력)의 컬러는 온도·채도
  방향만** — 여기서 hex를 못박으면 04의 접근성(대비 4.5:1)·다크모드·브랜드 일관성 검토를
  건너뛴다. (원본 가이드가 무드보드엔 hex를 요구하고 정의서엔 방향만 요구하는 단계 분리 의도.)
- **컨셉 비주얼은 방향 탐색용 러프다.** 완성도 높아 보여도 06에 그대로 가져가면 "AI스러운 룩"·
  저작권·일관성 문제가 생긴다. **후보 비교가 끝나면 비주얼은 버리고 정의서(언어)만 남긴다.**
- **펫(도메인) 클리셰를 경계.** 반려동물 서비스는 과한 파스텔·만화풍 일러스트·발바닥 모티프로
  쏠린다. 경쟁사와 톤이 겹치면 차별성이 사라진다 — 발산부터 `[흔함]` 태그로 의식적으로 피한다.
- **무드보드는 보관용이 아니라 합의용.** 기획·디자인·(가능하면) 클라이언트가 같은 보드를 보며
  한 방향을 골라야 06 되돌리기를 막는 효과가 생긴다.

## brainstorming을 호출하지 않는 이유 (발산→수렴 로직 내장)

원본 가이드는 "brainstorming 스킬로 발산"이라 하지만, **brainstorming은 commit·writing-plans로
끝나는 폐쇄형 대화 워크플로우**라 03의 산출물 계약·게이트(게이트1/2/4)와 양립하지 않는다. 따라서
발산→수렴을 **이 스킬에 로직으로 내장**한다(design-review·design-requirements 내장 선례, 그리고
high-level-planning도 brainstorming을 호출하지 않고 발산→반론→수렴을 내장한다). 발산(Stage 1)과
수렴(Stage 2)을 분리하고, 수렴 기준은 게이트1에서 사람이 확정한다.

### 02-3 핸드오프 섹션 회수 (의미 기반 탐지)
02-3의 "03·04가 떼어갈 트렌드 키워드" 섹션을 **헤더명이 아니라 의미로 회수**한다(02 스킬 규약은
`## 핸드오프 키워드`지만 실제 산출은 `## B. …` 등으로 다를 수 있음). 헤더 텍스트 매칭 실패 시
파일 내용(분위기/컬러/타이포/레이아웃/모션 방향)으로 폴백 회수.
- **회수 단위 고정**: 핸드오프 키워드 **섹션 전체를 통으로 회수**하고, 그 안의 항목(분위기·컬러·
  타이포·레이아웃·모션 방향)을 발산 재료로 전개한다(섹션 vs 불릿 혼동 방지).
- ⚠️ **02 스킬 헤더 규약 불일치는 `[확인 필요]`로 표기 + 02 검증체크리스트로 역피드백**(02가
  `## 핸드오프 키워드` 고정 3섹션을 명시했는데 실제가 다르면, 어느 쪽이 정본인지 02 소유자가
  끊도록 신호를 남긴다). 03은 그동안 양쪽을 의미로 수용한다.

## 파이프라인

### Stage 0 — 슬러그 해소·입력 로드·도구 probe·degrade
- 슬러그 해소(위). 입력 등급별 로드, 02-3 의미 회수, 부재 분기 판정.
- **도구 probe**(하드코딩 가정 금지): Figma = `whoami` 인증(플랜만 반환, edit 권한은 실호출로

  확인 후 선택**(지어내지 않음). 이미지 생성 도구 = 외부 웹(HITL, probe 없음). brainstorming =

### Stage 1 — 시각 컨셉 발산 → `03-1_시각컨셉발산.md`
04 가치제안·컨셉 + 02-3 키워드로 **톤앤매너 키워드 20~30개**를 결을 섞어 발산(감정형·질감형·

양·다양성이 목적, 평가 금지.**

### 🚦 게이트1 — 수렴 평가 기준 확정 (사람, 필수)
AskUserQuestion(AI 추천 1안). 기본 제안: ① 가치제안 부합도(04 원페이저·캔버스 직접 연결) ②

### Stage 2 — 아트 디렉션 수렴 → `03-2_아트디렉션수렴.md`
키워드를 3~5 군집으로 묶고 이름 부여. 게이트1 기준으로 **상/중/하 점수 + 한 줄 근거(04/02 인용,

**컨셉 키워드 맵**(발산→군집 관계, mermaid flowchart) 포함.

### 🚦 게이트2 — 후보 검토 + 2개로 압축 (사람, 필수)
AskUserQuestion으로 3개 후보 제시 → **가치제안 부합도 하위 1개를 기각해 2개로**(멋≠맞음 1차 적용).
**타이브레이크**: ①가치제안 부합도가 동률이면 ②차별성 → ③확장성 순으로 하위를 가른다(동률로 멈추지
않게). **AI는 고르지 않는다** — 사람이 압축. (여기서 최종 1개로 확정하지 않음 — 무드보드를 보고
고르는 게 본질, 게이트4에서 확정.)

### Stage 3 — 컨셉 비주얼 프롬프트 + 컬러 무드 → `03-3_컨셉비주얼·컬러무드.md`
2개 방향 각각:
1. **키비주얼 프롬프트(영문, 이미지 생성 도구용)** — 분위기·소재·구도·광원·질감 + "반려동물 사료
   구독" 맥락. 강아지 클로즈업 클리셰 회피. **AI는 프롬프트만, 후보 이미지는 사람이 Figma Make/
   v0/Stitch에 넣어 뽑는다(HITL).**
2. **컬러 무드** — 메인/서브/포인트. **hex 후보 허용 + `확정 아님·04에서 재검토` 라벨 강제** +
   온도(따뜻/차가움)·채도(차분/생기) 설명.
3. 04 가치제안과의 연결 한 줄.

### 🚦 게이트3 — Figma WRITE 동의 (사람, 필수 / 이 시리즈 첫 Figma 쓰기)

mandatory 절차 선행**.

### Stage 4 — FigJam 무드보드 (degrade 사다리)

**실패/view-only면 degrade**. 보드: 방향별 섹션(컨셉명+문장 / 키워드 스티키 / **컬러 칩(온도·채도
라벨)** / 02-7 썸네일 `upload_assets`(실파일 0개면 호출 안 함) / 비주얼 placeholder — 사람이 채움).

  텍스트 표 사다리. (⚠️ `generate_diagram`은 사분면 미지원 → 무드 축에 쓰지 않는다.)
- **컨셉 키워드 맵**: `generate_diagram` flowchart(사분면 아니라 지원됨).
- **degrade 진입점**: **게이트3 미동의 = Figma 칸을 건너뛰고 mermaid부터 시작**(미동의=시도 안 함,
  "시도 후 실패"와 진입점이 다름). degrade 산출물은 `03-0_무드보드(degrade).md`에 쓰고 정의서에 링크.

### 🚦 게이트4 — 확정 컨셉 선택 (사람, 필수)
무드보드 리뷰 후 AskUserQuestion으로 "어느 방향으로 합의됐는지" 사람이 선택. **AI는 고르지 않음**

### Stage 5 — 디자인 컨셉 정의서 → `03-4_디자인컨셉정의서.md`(★)
1. **확정 컨셉**: 이름 + 한 줄 정의 + 대표 키워드 3개
2. **톤앤매너 가이드**: ~하다 / ~하지 않다 쌍 4~5개 — **부정쪽은 긍정쪽의 과잉·오용 형태**여야
   한다("따뜻하다 / 유치하지 않다", "정돈됐다 / 차갑지 않다"처럼 별개 축). 단순 부정("안 따뜻하다")은
   동어반복이라 무효. 04 토큰·06 시안 판단 기준.
3. **컬러 무드 방향**: 메인/서브/포인트 + 온도·채도(★04 입력, **확정 hex 아님**)
4. **피해야 할 것**: 합의된 금지(만화풍 일러스트 + 펫 클리셰)
5. **근거**: 04 가치제안 연결 + 경쟁사 차별점
6. **무드보드 링크**: FigJam 링크(있으면) / degrade 시 `03-0_무드보드(degrade).md` 경로

## 주의

- **발산은 재료, 수렴 기준은 사람** — AI는 컨셉을 고르지 않는다.
- **멋 ≠ 맞음** — 가치제안 연결 약하면 기각.
- **컬러 hex는 무드보드까지만, 정의서는 방향만** — 04 접근성·다크모드 여지 보존.
- **컨셉 비주얼은 러프** — 후보 비교 후 버리고 정의서(언어)만.
- **펫 클리셰 경계** — 발산부터 `[흔함]` 태그.
- **무드보드는 합의용** — 회의 없이 저장만 하면 의미 없음.
- **편집 범위** — 기획·이전 단계는 **읽기만**, 쓰기는 `<출력루트>` 안에서만(자동화/ 하위·볼트 루트 금지).
- 한글 경로는 Glob/Read만. 신규 발번 ID 없음(컨셉 방향은 이름으로 식별).
