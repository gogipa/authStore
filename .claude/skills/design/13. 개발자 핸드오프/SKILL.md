# 개발자 핸드오프 (Design Handoff · 에셋·스펙 전달)

12 QA를 통과한 시안을 **개발자가 추측 없이 그대로 구현하도록** 에셋·스펙·토큰·컴포넌트 매핑을 픽셀·토큰
단위로 넘긴다. "Figma 링크 던질게요"가 아니라, 개발자가 자를 대고 픽셀을 재고 아이콘을 일일이 export하고
"이 간격이 16인가 20인가"를 슬랙으로 되묻는 일을 없앤다. 4묶음 = ①에셋(아이콘·이미지·모션 참조) ②스펙
(측정값) ③디자인 토큰(→ 코드 변수) ④컴포넌트 매핑(Code Connect) + 화면 관점 엣지케이스 Q&A + 티켓 초안
+ 인덱스. **디자인 시리즈 최대 통합 수령 종착 스킬**(07~12 산출물 수렴). 볼트 원본 + Notion 공유본.

## dev-handoff(기획14)를 호출하지 않는 이유 (규율만 내장 계승)

원본 Step5가 "dev-handoff 스킬로 엣지케이스 Q&A·티켓 생성"이라 하지만 **Skill로 호출하지 않고 규율만 내장**한다(10·12 선례). 비호출 4사유:

1. **출력경로 고정** — dev-handoff는 기획 폴더 `14_핸드오프`에 쓴다. 호출 시 디자인 산출물이 기획 폴더 오염.
2. **이중 게이트** — 자체 게이트 2개로 본 스킬 게이트와 충돌.
3. **인계 제어점 부재** — 서브에이전트 독립 실행이라 디자인13 경로로 인계 불가.
4. **Figma write 정면충돌** — dev-handoff는 Figma write·Code Connect write 전면 금지(Code Connect는 FE/디자인시스템 몫·read만)인데, **이게 디자인13의 핵심(Code Connect 등록)과 정반대**.

→ **계승**: 화면 관점 엣지케이스 Q&A(답있음=명세/정책 case-ID 인용 / 기획·디자인 확인 필요=담당자·결정기한 컬럼·추측 단정 금지)·화면/컴포넌트 단위 티켓(제목·AC 3개 이내·관련 에셋·스펙/토큰·의존성)·🔴 결제/법적 전수 사람 확정. **계승 제외**: API/OpenAPI(14-3 기획14 소관)·기능(FE/BE/공통) 단위 티켓(13은 화면/컴포넌트 단위). 원본의 "dev-handoff 스킬로" 문구는 **"내장 엣지케이스 Q&A·티켓 규율로"**로 읽는다.
- **기획14와 짝**(같은 Notion 트리·**14=시스템 동작 관점 / 13=화면·스펙 관점**·충돌 아닌 협력). 기획 `14-1 엣지케이스`·`14-2 티켓`·`14-4 용어집`이 있으면 **입력 수령해 중복 dedup**.

## 08과의 Code Connect 경계 (1급)

`design-componentize`(08)이 이미 `08-3_CodeConnect매핑.md` 명세표를 1급으로 만들고 `.figma.ts` 작성을 figma-code-connect에 위임했다. 13의 고유 책무는 **명세를 실제 등록(send)까지 격상**하는 것:

- **(a)** `08-3` 명세표 **수령**(재생성 금지·08 판정 신뢰도·prop 매칭 인용 승계·`get_code_connect_map`으로 기존 매핑 조회 후 **diff만**). 부재 시에만 13이 `get_code_connect_suggestions`로 직접 후보 생성(⚠️).
- **(b)** 13 고유 = 08이 명세표로만 남긴 매핑을 **실제 등록(send)**까지.
- **(c)** `.figma.ts` 작성·등록 경로는 08과 일관되게 **figma-code-connect 스킬 위임 1순위**(raw `add_code_connect_map`/`send_code_connect_mappings` 직접 호출은 폴백·동시 사용 금지).
- **(d)** 08의 **4대 하드전제**(published 컴포넌트·코드 레포 실존·Org/Enterprise 플랜·node-id URL)를 13도 **게이트로 강제** — 하나라도 미충족이면 **명세표/신규 구현 필요 목록만 degrade·등록 안 함**.
- **(e)** 신규 프로젝트(레포 컴포넌트 미구현)·**또는 08-3 신뢰도가 전부 미검증(`[확인 필요]`)이거나 등록 가능 매핑 0건**이면 → Stage 4 = **'신규 구현 필요 + 우선순위 목록'으로 완전 대체**(등록 격상은 publish+레포 확인 후 차기로 이연). ⚠️ **이 경우 Stage 4의 등록 부가가치는 0이 정상** — '빈손이라 미완'이 아니라 '하드전제 미충족이라 명세표/신규구현 목록이 산출물'임을 인덱스에 명시(검수자 혼선 방지).

### Code Connect 함수 워크플로우 (도구 사실)
`get_code_connect_suggestions`(read 후보) → **사람 확정 게이트** → `send_code_connect_mappings`(bulk 저장). `add_code_connect_map`은 개별 1건 저장(**'add로 등록 후 send로 반영' 2단계 표현 폐기** — 둘 다 저장 동작). `.figma.ts` 템플릿은 `get_context_for_code_connect`로 properties/variants 받아 figma-code-connect 위임. **확정 전 등록 금지**·`send`는 되돌리기 어려움 경고 + 등록 후 `get_code_connect_map` 검수·**생성≠게시**.

## 핵심 원칙

- **Code Connect write는 정당하다(13=디자인시스템 주체).** dev-handoff(기획14)는 기획자 도구라 read-only지만 13은 디자인시스템/FE 협력 주체라 등록(write)이 정당(같은 트리·역할 분리·모순 아님). write 허용 = **Code Connect 등록 계열로 한정**·`use_figma`/`create_new_file`은 13도 불필요하므로 금지 유지.
- **BMD: 토큰 값의 진실 = 04/08 `tokens.css`·`scripts/out/*.json`(SSOT).** 13은 새 값을 만들지 않고 코드 토큰(CSS var/Tailwind)으로 **포맷 변환만**. ⚠️ **금지 대상 = 시안 색을 '새로' 값으로 재기재**(전수 치환 지옥 → 이름으로 연결). **04/08 tokens.css `:root` primitive 정의 전체를 그대로 편입(`@import`/복사)하는 것은 SSOT 운반이라 허용**(재기재 아님). `get_variable_defs`는 **보조**(selection의 사용된 변수만 반환→하드코딩 거짓통과·미바인딩 누락·인스펙터 확인 플래그)이고 진실 판정 기준 아님. 04가 dry-run 가상값이면 13 산출물에 가상값 배너 전파.
- **다크모드 변형 강제 — 단 환류 대기는 미완 인계.** 04가 정의한 라이트/다크 2테마를 코드 토큰에 포함(`:root` + `prefers-color-scheme: dark` + `[data-theme=dark]` **3블록**·08 Stage4 패턴)·'mode 있으면' 조건부 금지·**LLM이 다크 짝 발명 금지**(04 다크 재매핑 구조 변환만). ⚠️ **04/08이 다크 짝을 `[04 환류 대기]`로 비워둔 토큰**(08 신규 semantic 등)은 다크 강제와 발명 금지가 충돌 → **다크 3블록에서 미정의 주석 유지 + "다크 부분 미완·04 재실행 선행" 인계**(발명 금지 우선·인덱스 '확인 필요'에 다크 미완 의무 기재). 08 확장분도 변환 대상. 토큰 네이밍 = 04 규약 우선·Figma 변수↔04 차이는 **'토큰 차이 목록'으로 빼서 사람 결정**·개발 컨벤션 합의 게이트.
- **에셋 추출 결과는 기계가 진실이 아니다 — 사람 눈 검수 필수.** 추출 직후 매니페스트(파일명·타입·배율·사용 화면 S-ID·원본 프레임명)↔실파일 대조·아이콘 SVG 렌더링 확인·래스터↔벡터 오추출·SVG 마스크/클리핑 잔존 확인.
- **상태 누락 = 12 환류**(13은 처음 발견하는 자리가 아니다). 상태 변형(화면 빈/에러/로딩/권한·컴포넌트 hover/disabled/loading) 누락은 12에서 잡혔어야 함 — 13 신규 발견은 **12로 회귀(시안 보강 후 재핸드오프)**·절대 `[확인 필요]`로 개발에 떠넘기지 않음. 컴포넌트 state와 화면 5종 상태 구분(엔티티 상태머신 ≠ 화면 상태).
- **하드코딩(토큰 미연결) 검출 = 후보이지 판정 아님.** 의도된 일회성 값(프로모션 배너 브랜드 컬러)일 수 있음 → 게이트 재분류 전엔 '후보'. HTML 모드 grep은 `:root`/토큰 정의 블록 화이트리스트·`var()` 미사용 raw값만·1px border/min-height/뷰포트 치수 제외·python3 정규식. 진짜 누락만 04/08 토큰화 환류 후보(직접 편집 금지·기재만).
- **법적·결제·정기결제 고지 화면은 `[🔴 사람 직접 검수]`.** `get_design_context` 추출값 신뢰 금지·패키지 확정 게이트 통과 조건·미해소 시 Notion 발행·완료 보고 차단. 검수 경로 2분기: **Figma 모드 = `get_screenshot`+원본 Figma 사람 대조** / **HTML·dry-run 모드 = 시안 텍스트 + 원본 기획 문서(기획06/10) 사람 대조**(이미지 내부 텍스트·외부 컴포넌트 내부 문구 미포착).
- **티켓 우선순위·스프린트 배분은 사람**(개발리드·PM)·동의어 판별 사람 최종·외부 공유물 "확정 아님·내부 검토용" 배너·잘된 점은 사람이 직접(AI 자동 칭찬 금지).
