# be-architecture-design — 시스템 아키텍처 설계 자동화 스킬

요구사항(01)과 확정 스택(02)을 넣으면 아키텍처 옵션 비교 매트릭스 → C4 다이어그램 → ADR을 생성하는
Claude Code 스킬입니다. 사람은 **아키텍처 스타일 결정 1번**(배포 단위·내부 구조·모듈 경계)만 개입합니다.

> BE 프로세스 03단계 "시스템 아키텍처 설계"를 자동화합니다.
> 역할 분담: AI는 옵션을 빠짐없이 발산·시각화·기록, **선택은 사람**(AI는 거의 항상 유행하는 답을 권함).

## 무엇을 만들어 주나

`backend-output/<주제>/03_아키텍처/`에 생성:

| 파일 | 내용 |
|---|---|
| `03-1_옵션비교.md` | 배포 단위(모놀리식/모듈러 모놀리식/MSA) × 내부 구조(레이어드/헥사고날) 비교 매트릭스 + 권장안(근거·사람 결정 필요 표시) |
| `03-2_C4다이어그램.md` | C4 3단계(Context/Container/Component) Mermaid + 트랜잭션 경계 주석. Figma 공유본 옵트인 |
| `03-ADR-003_아키텍처.md` | ADR(상태=`Proposed` 고정 / Context·Decision·Considered Options·Consequences·재검토 트리거) |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(필수) 01 요구사항분석** — `backend-output/<주제>/01_요구사항분석/`의 01-1 도메인분석·01-2 비기능요구.
2. **(필수) 02 기술스택** — `backend-output/<주제>/02_기술스택/`의 02-ADR 스택 결정.
3. **(권장) 01-3 기획질문리스트·02-1 제약요구표** — 팀 규모·운영 역량·트래픽 가정 입력.

01·02가 둘 다 없으면 위치를 묻고 중단합니다. 02만 있고 01이 없으면 도메인 경계를 추정하지 않고 01 먼저 권장.

## 설치

```bash
cp SKILL.md ~/.claude/skills/be-architecture-design/SKILL.md
```

## 사용법

01·02 산출물을 준비한 뒤:

```
01·02 읽고 포밋 백엔드 시스템 아키텍처 설계해줘
```

1. **옵션 비교 매트릭스 발산** → (옵트인) deep-research 사례 조사
2. **아키텍처 스타일 확정** → 당신이 배포 단위·내부 구조·모듈 경계 결정 (유일한 개입)
3. **C4 다이어그램**(Mermaid/Figma) → **ADR 초안**(상태 `Proposed`) 자동

발동 키워드: `시스템 아키텍처`, `아키텍처 설계`, `C4`, `모듈러 모놀리식`, `MSA`, `헥사고날`, `ADR`

## 주의

- **AI는 거의 항상 "더 멋진" 걸 권합니다.** MSA·CQRS·이벤트소싱을 초기 스타트업에 권함 — "우리 팀
  2~3명이 운영 가능한가"로 깎아냅니다.
- **다이어그램은 합의안이지 진실이 아닙니다.** 큰 구조 변경마다 갱신 책임자를 정하세요.
- **ADR 상태는 `Proposed` 초안.** 팀 리뷰 후에만 `Accepted`로 바꿉니다.
- **핵심 트랜잭션 경계**(주제의 정합성 중요 흐름 — 예: 결제-예약 / 해지-정산)를 다이어그램·ADR에서
  빠뜨리지 마세요 — 08·11단계 비용이 폭발합니다.
- **그림과 ADR은 한 쌍.** 다이어그램만 만들고 ADR을 안 남기면 6개월 뒤 근거가 증발합니다.
