# be-testing — 단위·통합 테스트 자동화 스킬

08 비즈니스로직·09 API 구현 코드를 넣으면 테스트 피라미드(단위 多 > 통합 中 > E2E 少)에 맞춰 테스트 계획 → 단위(JUnit5/AssertJ/Mockito) → 통합(Testcontainers PostgreSQL16/Redis7)·API(REST Assured) → JaCoCo 커버리지 빈틈 보강안을 생성하는 Claude Code 스킬입니다.

> BE 프로세스 13단계 "단위·통합 테스트"를 자동화합니다.
> 역할 분담: AI는 케이스 회수(happy/경계값/예외)·골격, **기대값(정답) 정의·정답 판단은 사람**.

## 무엇을 만들어 주나

`backend-output/<주제>/13_테스트/`에 생성:

| 파일 | 내용 |
|---|---|
| `13-1_테스트계획.md` | 검증항목 × [단위/통합/E2E] 분배 표 + 각 "기대 동작" 1줄(모호 시 `[확인 필요]`) |
| `13-2_단위테스트초안.md` | JUnit5+AssertJ+Mockito, `@Nested`+한글 `@DisplayName`, 상태 전이 `@ParameterizedTest`, 예외 케이스 |
| `13-3_통합테스트.md` | Testcontainers(PostgreSQL16·Redis7) 트랜잭션·캐시 검증 + REST Assured API 관통·계약 검증(외부 PG는 WireMock 목) |
| `13-4_커버리지보강.md` | JaCoCo 미커버 분기 목록 + 운영 버그 위험 상/중/하 + 상·중만 추가 제안 |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(필수) 08 비즈니스로직 + 09 API개발** — `backend-output/<주제>/08_비즈니스로직`(도메인 규칙·상태 전이)·`09_API개발`(컨트롤러·전역예외핸들러). 둘 다 없으면 중단.
2. **(권장) 기획 12 기능명세서의 핵심 도메인 정책** — 상태 전이·수수료/정산 등 기대값 근거(관통 예시=포밋 예약Booking; 본인 주제로 치환 — 예: 구독서비스=해지·정산). 없으면 명세 모호점은 `[확인 필요]` 처리.
3. **(연결) 10 쿼리·11 외부연동·06 개발환경** — 캐시 적중 회귀 검증·WireMock 목 대상·테스트 의존성(build.gradle.kts).

## 사용법

08·09 산출물(또는 대상 코드)을 준비한 뒤(아래 도메인명은 본인 주제로 치환):

```
구독 해지·정산 도메인 테스트 짜줘   # (포밋이면 "예약(Booking) 도메인 테스트 짜줘")
```

1. 테스트 계획(피라미드 분배) 초안 자동 생성
2. **🚦 테스트 레벨 분배 + 기대값(assertion) 확정** → 당신이 OK/수정 (사람 개입)
3. (게이트 통과 후) 단위 → 통합·API 테스트 코드 생성
4. JaCoCo 커버리지 빈틈 보강안(상·중 위험만, 코드는 승인 후) → 검증 체크리스트

발동 키워드: `테스트`, `단위 테스트`, `통합 테스트`, `Testcontainers`, `테스트 피라미드`, `JUnit`, `REST Assured`, `JaCoCo`, `커버리지`

## 주의

- **AI가 짠 테스트는 "통과시키는" 방향으로 기운다.** 모든 assertion을 명세 기준으로 대조하고, 가능하면 구현을 일부러 깨뜨려 빨갛게 되는지 확인하세요.
- **기대값은 사람, 케이스는 AI** — 둘을 섞으면 구현을 베끼는 동어반복 테스트가 됩니다.
- **Testcontainers는 느리고 Docker가 필요** — 컨테이너 재사용·통합 최소화로 관리.
- **커버리지 100%는 함정** — 빈틈 지도로만 쓰고 숫자를 목표로 삼지 마세요.
- **외부 연동은 실제로 때리지 않는다** — 토스페이먼츠·FCM은 WireMock 목 처리(실결제·실발송 금지).
- **한 방 생성 금지** — 도메인 단위로 끊고 매 단계 사람이 검토.
