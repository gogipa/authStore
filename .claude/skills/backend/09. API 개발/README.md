# be-api-development — API 개발 자동화 스킬

05 OpenAPI 명세와 08 도메인 서비스를 넣으면 컨트롤러·요청/응답 DTO·Bean Validation·전역 예외 핸들러를 스캐폴딩하고, 명세↔구현 대조표와 슬라이스 테스트 초안까지 만드는 Claude Code 스킬입니다. 사람은 **구현 범위·명세 모호점 확정 1번**과 마감 검토에 개입합니다.

> BE 프로세스 9단계 "API 개발"을 자동화합니다.
> 역할 분담: AI는 명세→코드 변환·보일러플레이트, **"정말 명세대로인가" 대조와 정책 검증은 사람**.

## 무엇을 만들어 주나

`backend-output/<주제>/09_API개발/`에 생성:

| 파일 | 내용 |
|---|---|
| `09-1_컨트롤러DTO초안.md` | 컨트롤러(얇게·위임만)·record DTO·Bean Validation(근거 주석)·명세↔코드 매핑표 |
| `09-2_전역예외핸들러.md` | `@RestControllerAdvice` 핸들러. 도메인 예외→에러코드표 매핑, **05-2 `ErrorResponse` 스키마와 동일 포맷**(RFC 7807 ProblemDetail이거나 커스텀 스키마 — 05가 정하는 대로), 미커버 에러코드 목록 |
| `09-3_명세대조표.md` | 05 openapi ↔ 구현 대조(엔드포인트·필드·상태코드·에러코드), 불일치 0건 목표. (선택) `@WebMvcTest`+`@MockBean` 슬라이스 테스트 초안 부록 |
| `_검증체크리스트.md` | 사람이 확인할 항목(빌드·테스트·대조 0건) |

## 준비물 (입력)

1. **(필수) 05 OpenAPI 명세 + 에러코드규약** — `backend-output/<주제>/05_API/05-2_openapi.yaml`(엔드포인트·스키마·`ErrorResponse` 포맷) + `05-3_에러코드페이징규약.md`(도메인 에러코드표·페이징 — 예외 핸들러 매핑의 출처). 이 단계 구현의 정답지. 없으면 중단하고 05 먼저 권장.
2. **(필수) 08 비즈니스 로직** — `backend-output/<주제>/08_비즈니스로직/`(도메인 서비스 시그니처·도메인 규칙·상태 전이). 컨트롤러가 위임할 대상과 던질 예외.
3. **(권장) 기획 06 정책 정의** — Bean Validation 규칙의 근거(예약 가능 시간·취소 마감 등). 없으면 명세 제약만 반영하고 "정책 미대조 ⚠️" 표기.

## 사용법

05 명세와 08 도메인 산출물을 준비한 뒤:

```
05 openapi 명세 보고 Booking API 컨트롤러·DTO·예외 핸들러 스캐폴딩해줘
```

1. **구현 범위 + 명세 모호점 확정** → 당신이 OK (유일한 사전 개입)
2. 컨트롤러·DTO 스캐폴딩 → Bean Validation 부착 → 전역 예외 핸들러 자동
3. 명세↔구현 대조표(불일치 도출) → 슬라이스 테스트 초안 자동
4. **마감**: `code-review`로 점검 → `verification-before-completion`으로 `./gradlew test` 통과 + 대조 0건 확인 후에만 완료

발동 키워드: `API 개발`, `컨트롤러 구현`, `DTO`, `Bean Validation`, `전역 예외 핸들러`, `명세 대조`

## 주의

- **AI는 명세에 없는 필드·엔드포인트를 지어냅니다.** Stage 4 대조에서 "여분 필드"를 반드시 확인 — 친절한 추가 필드가 계약 위반 사고가 됩니다.
- **검증을 정책과 대조하지 않으면** 명세만 충족하고 06 정책(취소 마감 등)을 어깁니다.
- **엔티티 직접 노출 금지** — 컴파일은 되지만 운영에서 터집니다(Lazy·순환참조·민감필드). DTO 변환을 규약으로.
- **상태코드·에러 본문은 계약** — 임의로 바꾸지 말고, 바꾸려면 05 명세부터.
- **빌드 없이 "완료" 금지** — `./gradlew test` 통과 + 대조표 0건을 출력으로 확인한 뒤에만 완료.
