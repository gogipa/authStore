# be-external-integration — 외부 시스템·서드파티 연동 자동화 스킬

토스페이먼츠 결제·Firebase FCM 같은 외부 시스템에 우리 서비스를 붙일 때, **외부 장애가 우리 서비스로
전파되지 않게 가두는 격리 설계**(멱등성·재시도·서킷브레이커·타임아웃·웹훅 서명 검증)와 그 격리를 검증하는
WireMock 실패 시나리오 테스트 초안을 생성하는 Claude Code 스킬입니다.

> BE 프로세스 11단계 "외부 시스템·서드파티 연동"을 자동화합니다.
> 역할 분담: AI는 보일러플레이트·격리 설정·스텁 초안 생성, **판단(재시도 가능/불가 구분·시크릿·금액 검증·임계값 확정)은 사람**. 결제는 돈이 오가므로 검토 시간을 줄이지 않습니다.

## 준비물 (입력)

1. **(필수) 08 비즈니스 로직** — `08_비즈니스로직/`의 도메인 규칙·Booking 상태 전이(08-4). 결제 승인 → 예약 확정이 여기 정의된 상태 전이와 이어집니다.
2. **(필수) 09 API 개발** — `09_API개발/`의 컨트롤러/DTO·전역예외핸들러. 외부 호출 결과를 우리 도메인에 반영하는 부분이 09 위에 붙습니다.
3. **(권장) 06 개발환경** — `06_개발환경/06-4_프로파일환경변수.md`의 12-Factor 시크릿 주입 규약. 없으면 ⚠️ 가정 표기.
4. **(권장) 04 데이터베이스** — `04_데이터베이스/`의 Payment 엔티티·멱등 수신 테이블. 웹훅 멱등 수신/멱등성 키 저장의 근거.

## 사용법

08·09 산출물을 준비한 뒤:

```
포밋 결제 플로우 외부 연동 설계해줘 (토스페이먼츠 + FCM)
```

1. 입력(08·09) 로드 + 도구 probe(Context7·docker·python3)
2. **🚦 게이트** — 외부 계약·실패 정책 확정 + 🔴 키·시크릿 더미 확인 (사람 개입). **게이트 통과 전에는 산출물을 만들지 않습니다.**
3. (게이트 후) Context7로 최신 SDK 문서 확인 → 실패 케이스 도출 + 연동 설계 → 어댑터·격리(서킷/재시도/타임아웃)·트랜잭션 경계 초안
4. WireMock 실패 시나리오 통합 테스트 + 웹훅 서명 검증
5. 검증 체크리스트 + 경로 보고

발동 키워드: `외부 연동`, `서드파티 연동`, `결제 연동`, `PG 연동`, `서킷브레이커`, `멱등성`, `재시도`, `웹훅`, `FCM 푸시`, `WireMock`

## 주의

- **AI가 만든 결제 코드도 사람이 끝까지 검토합니다.** 금액·환불·이중 결제는 곧바로 금전 사고 — 재시도 가능/불가 구분, 멱등성 키 규칙은 한 줄씩 확인.
- **시크릿은 코드·프롬프트·로그에 절대 넣지 않습니다.** 환경변수 플레이스홀더만, 산출물 키·금액은 전부 더미. 결제 로그는 카드번호·키 마스킹(15단계 재검수).
- **웹훅은 외부 입력 — 신뢰하지 않습니다.** 서명 검증을 본문 파싱보다 먼저, 검증된 웹훅도 멱등 처리.
- **서킷/타임아웃/재시도 수치는 추정값입니다.** 운영 응답 분포를 보고 사람이 조정 — 기본값을 그대로 올리지 마세요.
- **외부 호출을 긴 @Transactional 안에 두지 않습니다.** 커넥션 풀 고갈로 이어집니다 — 외부 호출은 트랜잭션 경계 밖으로.
