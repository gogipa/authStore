# be-caching-performance — 캐싱·성능 최적화 자동화 스킬

포밋 백엔드의 가장 무거운 경로(지역·날짜 시터 검색 API)를 **측정→캐시→재측정** 순서로 최적화하는 Claude Code 스킬입니다. k6 부하 스크립트·p95/p99 병목 분석·Redis look-aside 캐시 전략(무효화 매핑 포함)을 초안하고, 같은 조건 재측정으로 효과를 입증합니다.

> BE 프로세스 12단계 "캐싱·성능 최적화"를 자동화합니다.
> 역할 분담: AI는 k6 스크립트·캐시 코드 초안·측정 해석, **"어디가 병목인가"·"무엇을 캐싱할지" 판단은 측정값 보고 사람**.

## 주의

- **측정 없이 캐시부터 넣지 마세요.** 측정→병목 확인→적용→재측정 순서. 추측 최적화는 무효화 버그·복잡도만 남깁니다.
- **측정 환경이 곧 신뢰도.** 로컬 소량 데이터 수치는 운영 지표가 아닙니다 — 운영 비슷한 조건에서 측정.
- **무효화 매핑이 없는 캐시는 버그.** "어떤 변경→어떤 캐시 무효화"를 코드 리뷰에서 반드시 확인.
- **캐싱 금지 데이터.** 결제·예약 상태·정산 금액은 캐싱하지 않습니다.
- **AI 제안 TTL·임계값은 출발점.** 운영 SLO로 그대로 박지 마세요.
- **캐시는 반창고가 아닙니다.** 병목이 쿼리면 10단계(인덱스·fetch join)로 원인부터 고칩니다.
