# be-incident-response — 장애 대응·유지보수 자동화 스킬

장애가 났을 때 흩어진 신호(로그·트레이스·메트릭)를 한 타임라인에 모아 원인을 좁히고, 대응
플레이북·blameless 포스트모템·5 Whys 근본원인 분석을 만드는 Claude Code 스킬입니다.
**AI는 분석·정리·초안까지, 복구 실행·롤백 판단·공지 결정은 사람이 합니다.**

> BE 프로세스 18단계 "장애 대응·유지보수"를 자동화합니다.
> 역할 분담: AI는 신호를 모아 가설을 좁히는 분석가, **프로덕션에 명령을 때리는 실행자는 사람**.

## 무엇을 만들어 주나

`backend-output/<주제>/18_장애대응/`에 생성:

| 파일 | 내용 |
|---|---|
| `18-1_대응플레이북.md` | 알림 수신 → 트리아지 → 신호 교차분석 → 17 런북 연결 → 롤백/핫픽스 의사결정 표 흐름 |
| `18-2_포스트모템템플릿.md` | 재사용 blameless 포스트모템 빈 양식(요약·영향·타임라인·5 Whys·액션 아이템) |
| `18-3_근본원인분석.md` | 사례 적용본 — 신호 교차분석 판정표 + 타임라인 + 5 Whys + 포스트모템 초안 + 의사결정 표 |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(연결, 필수에 준함) 14 관측성** — `14_관측성/`의 알림룰·로깅설정·SLO. 어떤 알림이 무엇을
   의미하고 traceId로 어떻게 신호를 꿰는지의 원본.
2. **(연결) 17 인프라 런북** — `17_인프라/17-4_런북.md`. 복구 명령의 정본(RDS PITR·ECS 롤백). 없으면
   의사결정 표 실행 명령 칸이 `[런북 참조 필요]`로 표기됩니다.
3. **(장애 발생 시) 실제 신호 발췌** — payment.log·Tempo span·PromQL 결과·배포 이력. 붙여넣을 때
   토큰·결제·개인정보는 마스킹하세요.

## 사전 요구사항

| 항목 | 필수? | 없으면 |
|---|---|---|
| Claude Code | 필수 | — |
| systematic-debugging 스킬 | 권장 | 실제 장애 분석 시 `/superpowers:systematic-debugging` 먼저 호출 권장 |
| Context7 MCP | 선택 | LogQL/PromQL 쿼리 예시를 내장 지식으로 작성 + "버전 확인 필요 ⚠️" |
| 14 관측성 산출물 | 필수 | 신호 출처를 질의하고 진행 + `⚠️ 14 미작성` (17까지 함께 부재면 중단) |
| 17 런북 산출물 | 권장 | 의사결정 표 실행 명령 칸을 `[런북 참조 필요]`로 표기 |

## 사용법

장애 발생 시(또는 평시 준비로):

```
결제 승인 실패율이 임계값을 넘었어. 장애 대응 플레이북이랑 포스트모템 준비해줘
```

1. (실제 분석이면) `/superpowers:systematic-debugging`으로 증상→가설→증거 절차 시작
2. 대응 플레이북 + blameless 포스트모템 빈 양식 자동 생성
3. **🚦 게이트(🔴)** — 채택 가설·실행 조치(롤백/핫픽스)·공지 여부 **당신이 확정** (유일한 개입)
4. 근본원인 분석(신호 판정표·타임라인·5 Whys·포스트모템 초안) 자동 + 19 개선 백로그 회부 목록

발동 키워드: `장애 대응`, `인시던트`, `포스트모템`, `근본원인 분석`, `5 Whys`, `타임라인 재구성`,
`롤백 의사결정`, `incident response`, `postmortem`, `root cause`

## 주의

- **복구 명령·롤백 결정은 사람이.** AI는 의사결정 표까지, 실행은 온콜 담당자가 17 런북대로.
- **증거 없는 원인은 단정 금지** — 미검증 가설은 '미확인'. 미확정 원인에 기대 롤백하면 새 장애를 부릅니다.
- **타임라인·로그 환각** — 시각·수치·로그는 원본과 대조, 근거 없는 구간은 `[확인 필요]`.
- **로그의 시크릿·개인정보 마스킹** 후 붙여넣기.
- **포스트모템은 blameless** — 비난 표현은 시스템 개선 액션 아이템으로 바꿉니다.
