# be-tech-stack-selection — 기술 스택 선정 자동화 스킬

01 요구사항·비기능요구를 넣으면 **평가 기준 고정 → 후보 비교 매트릭스(deep-research) →
최신 버전 확인(Context7) → ADR(아키텍처 결정 기록)**을 만드는 Claude Code 스킬입니다.
사람은 **스택 결정(가중치·최종 선택) 1번**에 개입합니다(되돌리기 비용이 큰 결정).

> BE 프로세스 02단계 "기술 스택 선정"을 자동화합니다.
> 역할 분담: AI는 후보를 같은 기준으로 조사·정리, **결정은 맥락을 아는 사람**.

## 무엇을 만들어 주나

`backend-output/<주제>/02_기술스택/`에 생성:

| 파일 | 내용 |
|---|---|
| `02-1_제약요구표.md` | 01-2 비기능요구 계승 제약 + 평가 기준 6~8개(가중치는 사람이 매기게 비움) |
| `02-2_후보비교매트릭스.md` | 영역별 후보 2~3개 같은 기준 비교 + 출처 + 트레이드오프 + Context7 검증 버전 |
| `02-ADR-NNN_<결정>.md` | 영역별 ADR(맥락/결정/근거/결과·트레이드오프/재검토 트리거) |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(필수) 01-2 비기능요구** — `01_요구사항분석/01-2_비기능요구.md`(성능·트랜잭션·동시성·보안·운영 NFR).
   없으면 사용자가 제약을 직접 제시(트래픽·팀 역량·운영 여건·일정)하면 그 제약으로 진행.
2. **(연결) 01-1 도메인분석** — 애그리거트·트랜잭션 단위. 강한 일관성 요구 판단에 사용.
3. **(사람이 제시) 맥락** — 예상 트래픽, 팀의 언어/프레임워크 역량, 전담 인프라 인력·예산, 일정.

## 사용법

01 산출물(또는 제약)을 준비한 뒤:

```
01 비기능요구 반영해서 백엔드 기술 스택 선정해줘
```

1. **제약·평가 기준 고정** → 후보 조사(deep-research) → 최신 버전 확인(Context7) 자동
2. 🚦 **스택 결정** → 당신이 평가 기준 가중치 + 영역별 최종 선택 확정 (유일한 개입, 🔴 되돌리기 큼)
3. 결정을 ADR로 기록 → 검증 체크리스트 자동

발동 키워드: `기술 스택 선정`, `스택 비교`, `스택 후보 조사`, `ADR`, `아키텍처 결정 기록`, `tech stack`

## 주의

- **결정을 AI에게 맡기지 마세요.** "뭐가 제일 좋아?"에는 무난한 다수파 답이 나옵니다 — AI는 트레이드오프를 펼치는 데만.
- **벤치마크 출처를 검증하세요.** 조건(버전·하드웨어·워크로드)이 다르면 비교에서 빼거나 단서를 답니다.
- **버전은 빌드로 최종 확인**(06단계). ADR 버전은 "현재 합의"이지 "검증 완료"가 아닙니다.
- **결론부터 쓴 ADR 금지** — 탈락 후보가 왜 졌는지가 들어가야 추적됩니다.
- **재검토 트리거 누락 금지** — "언제 다시 볼 것인가"가 없으면 ADR이 박제됩니다.
