# 접근성·반응형 대응 (Accessibility & Responsive)

08에서 다 그린 화면을 **마우스 없이도 쓸 수 있고(접근성)**, **어떤 디바이스에서도 안 깨지게(반응형)** 전수 검증하고 메우는 단계다. 산출물 = WCAG 점검표(자동 검출 + 수동 검수 체크리스트) → 반응형 거동 명세(디자인 11 계승) → jsx-a11y/axe 설정. **AI는 검출 가능한 위반을 일괄로 잡고(회수율), "스크린리더로 들을 때 흐름이 자연스러운가"·"포커스 순서가 시각 순서와 맞는가" 같은 체감 품질은 사람이 직접 조작해 검수한다.** 자동 도구는 위반의 일부만 잡으므로(통설 30~40%), 자동 통과를 "접근성 통과"로 보고하지 않는 역할 분담이 이 단계 설계의 핵심이다.

## 핵심 원칙

- **자동 검출과 직접 조작을 분리한다(가장 중요).** axe·jsx-a11y가 잡는 정형 위반(레이블·대비·alt 누락)은 AI가 일괄로, "스크린리더로 들었을 때 흐름이 자연스러운가" 같은 체감 품질은 사람이 직접 조작한다. **"axe 위반 0건"을 "접근성 통과"로 보고하지 않는다** — 자동 결과는 바닥선이지 천장이 아니다.
- **자동 검출은 "후보"이지 판정이 아니다.** 장식용 `alt=""`나 의도적으로 다른 반응형 거동(태블릿에서 캐러셀 대신 그리드)을 도구가 위반으로 잡을 수 있다. 그대로 수정하지 말고 **"확인 필요"로 분리**해 사람이 의도를 판단한 뒤 처리(자동 수정 가능한 것만 먼저 패치).
- **상위 산출물 계승, 재발명 금지 — 단 확정 상태일 때만.**
  - **반응형 거동은 디자인 11에서 계승**: breakpoint·거동 규칙(컬럼 수, GNB→햄버거, 테이블→카드)은 디자인 시리즈가 이미 합의한 결정이다. **FE는 새로 정하지 않고** Tailwind 클래스로 충실히 옮긴다. 디자인 11이 없으면 ⚠️(스펙 미대조) + 게이트에서 거동 규칙을 수기 확정받는다.
  - **breakpoint는 04 `screens` 토큰만**: mobile/tablet/desktop의 **분기 px·prefix·이름은 04 `screens`를 읽어 그대로** 쓴다(예: mobile ~767 / tablet 768~ / desktop — desktop 분기점은 04마다 1024·1280 등으로 다르므로 이 문장의 숫자를 정본으로 베끼지 말 것). `800px` 같은 **임의 px 금지** — 04 tailwind `screens`와 일치.
  - **다크모드는 semantic 토큰 분기로 국소화**: 04에서 `:root`/`[data-theme="dark"]`로 분기돼 있으면, 이 단계 일은 "다크에서도 AA 대비를 지키는가" 검증(**토큰 쌍 점검**)이지 화면마다 다크 스타일 재작성이 아니다.
  - **07 컴포넌트 접근성 기본 계승**: focus-visible·ARIA·Radix 위임은 07에서 박힌다. 이 단계는 그게 화면(08)에서 실제로 살아 있는지 검증·보강(컴포넌트 재작성 아님).
- **시안은 스냅샷이고 코드는 연속이다.** Figma 프레임은 390px·1440px의 스냅샷일 뿐 그 사이 모든 너비를 담지 못한다. 반응형 깨짐 대부분은 디자이너가 프레임을 안 그린 **중간 너비(폴드 펼침·태블릿 세로)**에서 난다. 실제 빌드된 화면을 Playwright로 일괄 캡처해 그 구간을 드러낸다(디자인 11이 시안에서 못 본 깨짐을 FE가 빌드에서 잡는다).
- **시맨틱 마크업이 근본 해법이다.** `<div onClick>` 대신 `<button>`·`<a>`·적절한 role. jsx-a11y가 일부 잡지만 처음부터 시맨틱하게 쓰는 게 근본이다.
- **단계별 파일로 끊는다**: WCAG 점검표(14-1) → 반응형 거동(14-2) → jsx-a11y/axe 설정(14-3). 한 방 생성 금지(중간 판단 검토 불가).

### 🚦 게이트 — a11y 기준 + breakpoint·반응형 거동 확정 (사람 개입, 필수)
AskUserQuestion으로 제시 → 사용자가 OK/수정. **이 게이트 전에는 Stage 1~3(검출·코드화)로 넘어가지 않는다**(한 방 생성 방지 — 중간 판단을 검토해야 한다).
- 핵심 결정 항목(사람이 쥐는 판단):
  - **WCAG 목표 등급·jsx-a11y 룰셋** — 기본 WCAG 2.1 AA + `plugin:jsx-a11y/recommended`(또는 `strict`). 어디까지 강제할지(AA가 정본, AAA는 선택).
  - **breakpoint 정본** — 디자인 11 + 04 `screens`를 그대로 쓸지. **분기 px·prefix·이름은 04 `screens` 정본을 읽어 채택**(예시는 mobile ~767 / tablet 768~ / desktop이지만 desktop 분기점은 프로젝트마다 1024·1280 등으로 다르다 — SKILL 본문 숫자를 정본으로 삼지 말 것). **디자인 11이 없으면 거동 규칙(컬럼 수·GNB→햄버거·테이블→카드)을 여기서 수기 확정**(임의 발명 금지).
  - **점검 대상 화면·뷰포트** — 핵심 흐름 화면(예: 포밋 시터 검색→상세→예약→결제) 우선, 6개 뷰포트(아래) 그대로 쓸지.
  - **다크모드 점검 여부** — 04에 다크 분기가 있으면 라이트/다크 양쪽 스캔(없으면 라이트만).

### Stage 1 — jsx-a11y 정적 위반 일괄 검출·수정 → 14-1·14-3
정적 1차 방어선. JSX의 흔한 누락을 커밋 전에 차단한다(런타임 문제는 못 잡음).
- 06 ESLint config(또는 신규)에 `plugin:jsx-a11y/recommended`(필요 시 `strict`)를 명시적으로 켠다(`eslint-config-next`의 jsx-a11y는 일부만 포함이므로 커버리지를 넓힌다). 설정 초안은 **14-3**에.
- `src/features/**`·`src/components/**`의 위반을 **규칙별로 그룹핑**(레이블 누락 / alt 누락 / 비시맨틱 클릭 요소 / 포커스 불가 핸들러 등), 각 위반에 파일·라인 + 수정 방향 한 줄.
- **자동 수정 가능한 것만 먼저 패치**, 판단이 필요한 것(장식용 `alt=""` 등)은 **"확인 필요"로 분리**(단정 금지).
- Context7로 jsx-a11y 최신 권장 룰셋을 확인한 뒤 진행. 결과는 **14-1** 자동 검출 섹션에 기록.

### Stage 2 — axe 런타임 접근성 스캔(화면×모드) → 14-1·14-3
정적 분석이 못 잡는 실제 렌더링 결과(대비비·ARIA 트리·동적 콘텐츠)를 브라우저에서 스캔한다.
- `@axe-core/playwright`로 핵심 화면(게이트 확정 범위)을 **라이트/다크 양쪽**에서 스캔하는 테스트 초안 생성(`e2e/a11y/` 아래). 초안은 **14-3**에.
- WCAG 2.1 A·AA 룰만 활성화: `.withTags(['wcag2a','wcag2aa','wcag21a','wcag21aa'])`.
- 위반을 **impact(critical/serious/moderate)별 집계 + 화면×모드 매트릭스**로 출력. `color-contrast` 위반은 어떤 **토큰 쌍**(예: `--color-text-muted` on `--color-bg`)인지 함께 표기 → **14-1**.
- **양쪽 스캔 강제**: 라이트에서 통과한 토큰이 다크 배경에서 AA 미달이 되는 경우가 잦다(라이트만 보고 넘어가기 방지).

### Stage 3 — 반응형 거동 코드화(디자인 11 계승) + 다중 뷰포트 깨짐 검수 → 14-2·14-3
디자인 11 스펙을 Tailwind 클래스로 옮기고(새 거동 발명 금지), 실제 빌드 화면을 6개 뷰포트로 일괄 캡처해 깨짐을 잡는다.
- **거동 코드화**: 디자인 11 스펙(예: 시터 검색 결과 그리드 desktop 3열→tablet 2열→mobile 1열, 필터 desktop 사이드바→mobile 바텀시트, GNB desktop 가로→mobile 햄버거)을 SitterList·FilterPanel·Header 등의 Tailwind 클래스로.
  - breakpoint·prefix는 **04 `screens` 정본을 그대로** — **임의 px 금지**(예: `tablet`/`desktop` 또는 `md`/`lg`, 분기점은 04가 정한 값. desktop이 1024인지 1280인지는 04에서 읽고 SKILL 본문 숫자를 베끼지 말 것). 모바일 퍼스트(기본 스타일 후 `tablet:`/`desktop:` 등 04 prefix로 확장).
  - 가로 스크롤 나기 쉬운 표(가격 비교·예약 요약)는 모바일에서 **카드형 또는 `overflow-x-auto` 래퍼**로.
  - **터치 타깃 최소 44×44px** 보장(버튼·링크 패딩). 부모 폭 기준 재배치가 더 맞으면 Context7로 `@container` 문법 확인 후 제안.
  - 거동 규칙표는 **14-2**(출처 컬럼: 디자인11 계승 / 신규⚠️).
- **다중 뷰포트 깨짐 검수**: Playwright로 핵심 화면을 아래 6개 뷰포트에서 캡처(`e2e/responsive/{화면}-{뷰포트}.png`), 스크립트 초안은 **14-3**.
  - mobile-fold 360×800 / mobile 390×844 / tablet-portrait 768×1024 / tablet-landscape 1024×768 / desktop 1440×900 / desktop-wide 1920×1080.
  - 자동 검출 항목: **가로 스크롤**(`document.scrollingElement.scrollWidth > clientWidth`) / 요소 뷰포트 밖 잘림·CTA 이탈 / 텍스트 overflow.
  - 가로 스크롤 검출된 (화면, 뷰포트) 조합을 표로 → **14-2**. 캡처는 회귀 검사에 재사용.

### Stage 4 — 키보드·스크린리더 수동 검수 체크리스트(사람 주도) → 14-1
자동 도구가 못 잡는 영역은 사람이 직접 조작한다. AI는 **체크리스트만** 만들고 실제 조작은 개발자가 한다.
- **키보드**: Tab 순서 = 시각 순서 / 모든 인터랙티브 요소 도달 가능 / 포커스 링 보임(focus-visible) / 모달 포커스 트랩·ESC 닫힘 / 바텀시트·드롭다운 키보드 열고 닫힘.
- **스크린리더(VoiceOver/NVDA)**: 예약 상태(`REQUESTED→ACCEPTED` 등) 변경이 읽힘(aria-live) / 폼 에러가 입력란과 연결돼 읽힘 / 이미지·아이콘 버튼에 의미 있는 레이블 / 로딩 상태 안내.
- **터치 타깃·포커스 가시성**: 데스크톱 작은 버튼이 모바일에서 44px 미달인지, `outline: none`으로 포커스 링을 지웠는지(자동 도구가 부분만 잡으므로 수동에 포함).
- 각 항목을 `[화면 / 조작 / 기대 동작 / 통과여부]` 표로, **통과여부 칸은 사람이 채우게** 비워 둔다 → **14-1** 수동 검수 섹션.

### Stage 5 — 검증 체크리스트 + 마무리
- `_검증체크리스트.md` 생성(`<주제>`/`<날짜>` 치환, 아래 본문).
- 산출물 폴더 경로와 "axe 통과 ≠ 접근성 통과 — 키보드·스크린리더 수동 검수(14-1) 미완료면 통과로 보고 금지 / breakpoint는 04 screens·반응형은 디자인 11 계승 / axe·뷰포트 캡처는 15 테스트·16 CI에 편입" 고지를 보고한다.
- 잔존 ⚠️(스펙 미대조·확인 필요)·미해결 위반·수동 검수 미완 항목이 남아 있으면 표시하고 완료 단정을 피한다.

## _검증체크리스트 본문 (Stage 5 생성)
```markdown
# 검증 체크리스트 — <주제> 접근성·반응형 대응 (작성일: <날짜>)

> AI는 검출 가능한 위반 일괄 회수까지. 키보드·스크린리더 체감 품질은 사람이 직접 조작해 판단한다.

- [ ] a11y 기준·breakpoint를 사람이 확정한 뒤 검출·코드화로 넘어갔는가 (한 방 생성 금지)
- [ ] axe "위반 0건"을 "접근성 통과"로 보고하지 않았는가 — 키보드·스크린리더 수동 검수(14-1) 완료 후에만 통과
- [ ] axe 스캔을 라이트·다크 양쪽에서 돌렸는가 (다크 대비 미달 누락 방지)
- [ ] color-contrast 위반에 토큰 쌍이 명시됐는가 (어느 semantic 토큰 쌍이 AA 미달인지)
- [ ] "확인 필요"(장식 alt=""·의도적 반응형 거동)를 자동 수정하지 않고 사람 판단으로 분리했는가
- [ ] 반응형 거동이 디자인 11 계승인가 (FE가 임의 거동 발명 0건, 신규는 ⚠️ 표기)
- [ ] breakpoint가 04 screens 토큰만 사용 (임의 px 0건 — 분기점·prefix는 04 정본 그대로, SKILL 본문 숫자 베끼기 금지)
- [ ] 6개 뷰포트(360/390/768/1024/1440/1920) 가로 스크롤·텍스트 잘림·CTA 이탈 검출 완료
- [ ] 터치 타깃 ≥44×44px, focus-visible 포커스 링 살아 있음 (수동 검수에 포함)
- [ ] 비시맨틱 <div onClick> 패턴이 <button>·role로 교정됐는가
- [ ] axe 테스트·뷰포트 캡처가 15 테스트·16 CI 편입 메모와 함께 남았는가
```

## 도구 정확성 (probe·degrade)
- **Playwright MCP / @axe-core/playwright**(probe) = 런타임 접근성 스캔(화면×모드)·다중 뷰포트 깨짐 캡처. 반응형 검수의 핵심. 없으면 degrade: 테스트·스크립트는 **생성하되 "로컬 실행 필요"** 안내, 자동 뷰포트 캡처·런타임 위반 수집은 생략(정적 jsx-a11y는 계속).
- **Context7 MCP**(probe) = Tailwind 반응형 prefix(`sm:`/`md:`/`lg:`)·컨테이너 쿼리(`@container`)·`next-themes` 다크모드 API·ARIA 패턴(WAI-ARIA Authoring Practices)·jsx-a11y 최신 룰셋 조회(버전·권장안이 바뀜). 없으면 **내장 지식 + "버전 확인 필요 ⚠️"**.
- **frontend-design 스킬**(정본) = 반응형 거동(컬럼 합치기·카드 그리드 재배치·GNB→햄버거)을 동작 코드로 초안화, 다크/라이트·여러 뷰포트 변형 비교. 정적 시안에 없는 중간 너비 거동을 코드로 드러낼 때.
- **pnpm·eslint·@axe-core/playwright**(bash probe) = `pnpm add -D eslint-plugin-jsx-a11y @axe-core/playwright @playwright/test`. 없으면 설정·테스트는 생성하되 "로컬 설치·실행 필요" 안내.
- **Figma MCP read**(probe, 선택) = 디자인 11 스펙·시안 거동 참고만. **write 도구는 사용하지 않는다**(시안 생성·토큰 정의는 디자인 몫). 없으면 사용자 수기 기술 + ⚠️.
- **중단**은 필수 입력(08·07) 부재 시에만. 그 외(디자인 11·04·06·CLI·MCP)는 degrade.

## 주의
(핵심 원칙의 재진술은 줄이고, 실무에서 자주 빠뜨리는 한계만)
- **터치 타깃·포커스 가시성을 빼먹기 쉽다.** 데스크톱에서 예쁜 작은 버튼이 모바일에서 44px 미달, `outline: none`으로 포커스 링을 지워 키보드 사용자가 위치를 잃는 경우가 흔하다 — 자동 도구가 부분만 잡으므로 수동 검수(Stage 4)에 포함.
- **흔한 실수 — 다크모드 라이트만 보고 넘어가기.** 라이트에서 멀쩡한 `--color-text-muted`가 다크 배경에서 대비 미달이 되는 경우가 잦다 — axe 스캔을 라이트·다크 양쪽에서(Stage 2).
- **흔한 실수 — `<div onClick>` 패턴.** 클릭만 되는 div는 키보드·스크린리더로 접근 불가다. jsx-a11y가 일부 잡지만, 처음부터 `<button>`·`<a>`·적절한 role로 쓰는 시맨틱 마크업이 근본 해법이다.
- **경계** — axe 통과 ≠ 접근성 통과(수동 검수 Stage 4 후에만 통과), 자동 검출은 후보이지 판정 아님, breakpoint·반응형 거동은 04 screens·디자인 11 계승(임의 발명 금지). 상세는 「핵심 원칙」 참조. 픽셀 단위 최종 검수는 디자인 14 퍼블리싱 검수 몫.
