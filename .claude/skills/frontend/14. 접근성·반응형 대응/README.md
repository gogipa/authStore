# fe-accessibility-responsive — 접근성·반응형 대응 자동화 스킬

08 화면·07 컴포넌트·04 토큰(screens·다크모드)을 넣으면, 다 그려진 화면을 **마우스 없이 쓸 수 있고(접근성) 어떤 디바이스에서도 안 깨지게(반응형)** 전수 검증·보강하는 Claude Code 스킬입니다. jsx-a11y 정적 위반과 @axe-core/playwright 런타임 위반을 일괄 검출하고, 디자인 11 반응형 스펙을 Tailwind 클래스로 계승해 코드화하며, 6개 뷰포트로 깨짐을 캡처하고, 자동 도구가 못 잡는 영역은 키보드·스크린리더 수동 검수 체크리스트로 사람에게 넘깁니다.

> FE 프로세스 14단계 "접근성·반응형 대응"을 자동화합니다.
> 역할 분담: AI는 검출 가능한 위반 일괄 회수(jsx-a11y·axe·뷰포트), **체감 품질(스크린리더 흐름·포커스 순서)은 사람이 직접 조작**. **"axe 위반 0건 ≠ 접근성 통과"** — 자동 결과는 바닥선이지 천장이 아닙니다.

## 무엇을 만들어 주나

`frontend-output/<주제>/14_접근성반응형/`에 생성:

| `14-2_반응형거동.md` | 디자인 11 계승 거동 규칙표(컬럼 수·GNB→햄버거·테이블→카드, 04 screens·Tailwind 클래스·출처) + 6개 뷰포트 깨짐 검수 결과(가로 스크롤·텍스트 잘림·CTA 이탈) + 캡처 경로 |

## 준비물 (입력)

1. **(필수) 08 화면 구현** — `<루트>/08_화면구현/`(화면 목록·상태 커버리지). 점검·검수 대상 화면의 출처. 없으면 중단.
2. **(필수) 07 공통 컴포넌트** — `<루트>/07_공통컴포넌트/`(focus-visible·ARIA가 박힌 컴포넌트·접근성 점검). 없으면 중단.
3. **(권장) 디자인 11 반응형 스펙** — 컴포넌트별 거동 규칙표. 반응형 코드화의 근거. 없으면 게이트에서 거동 규칙 수기 확정 + ⚠️.
4. **(권장) 04 토큰·06 ESLint·13 CWV** — `screens` breakpoint·다크모드 semantic 분기, jsx-a11y 얹을 config, CLS 연계.

## 주의

- **axe 통과 ≠ 접근성 통과.** 자동 도구가 잡는 건 일부(30~40%)입니다 — "위반 0건"을 완료로 보고하지 말고 키보드·스크린리더 수동 검수(14-1)를 반드시 거치세요. 검출 항목은 후보이지 판정이 아니라, 장식 `alt=""`·의도적 거동은 "확인 필요"로 분리합니다.
- **breakpoint를 임의로 만들지 마세요.** 04 `screens` 토큰의 분기점·prefix를 그대로 쓰세요(desktop이 1024인지 1280인지는 04에서 읽고, 이 문장 숫자를 베끼지 마세요). 반응형 거동은 디자인 11 계승 — FE가 발명하면 시안과 어긋납니다.
- **다크모드 라이트만 보고 넘어가지 마세요** — axe를 라이트·다크 양쪽에서. **터치 타깃 44×44px·`outline: none` 금지**는 자동 도구가 부분만 잡으니 수동 검수에. **`<div onClick>`** 대신 `<button>`·`<a>`·role.
- 픽셀 단위 최종 검수는 **디자인 14 퍼블리싱 검수** 몫, axe·뷰포트 캡처는 **15 테스트·16 CI**에 편입됩니다.
