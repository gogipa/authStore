# fe-performance-tuning — 성능 모니터링·고도화 자동화 스킬

17단계가 켠 관측 파이프라인(Sentry·web-vitals RUM·GA4)이 쌓은 데이터를 넣으면, 화면별 **현장(field)
성능을 p75로 해석 → 회귀 추세·배포 상관 추정 → React/Next 병목 번역 → RICE 개선 백로그 →
Lighthouse CI 회귀 게이트 + 01 회귀(루프 마감)** 를 생성하는 Claude Code 스킬입니다.

> FE 프로세스 18단계 "성능 모니터링·고도화"를 자동화합니다.
> 역할 분담: AI는 분산 데이터 **회수·정리·계산(p75·추세)** 과 백로그 초안, **"이 수치가 아픈가·이번
> 스프린트에 넣을 가치가 있나"는 사람의 판단**입니다.

## 무엇을 만들어 주나

`frontend-output/<주제>/18_고도화/`에 생성:

| 파일 | 내용 |
|---|---|
| `18-1_RUM지표해석.md` | 화면별 LCP/INP/CLS **p75**·표본수(n)·🟢🟡🔴 라벨, 기기군별 분해, 랩(13)↔필드 괴리 표시, n<100 해석 보류 |
| `18-2_성능회귀추세.md` | 7일 이동평균·전주 대비 증감·변곡점 검출 + 의심 배포/PR·대안 가설·확인 방법 (상관≠인과) |
| `18-3_개선백로그.md` | 가설·대상·목표 지표·근거·예상 효과·난이도 + RICE 초안, 기술부채 별도 섹션 |
| `18-4_차기사이클입력.md` | 채택 항목을 FE 01 입력 형식으로 변환 (18→01 루프 마감) |

| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(필수) RUM export 데이터** — `리서치/rum/`(또는 17이 안내한 위치)에 Vercel Analytics·GA4 Web
   Vitals CSV(화면별 LCP/INP/CLS, 가능하면 일자별 시계열·기기군 분포). 대시보드를 매번 눈으로 읽는 대신
   **export → 분석**으로 정형화하는 것이 핵심. 며칠치 데이터가 쌓여야 분석 가능.
2. **(권장) 17 모니터링** — `17_모니터링/`(화면·이벤트·알림 임계 정의 출처). 없으면 CSV 헤더에서 라벨 추출 + ⚠️.
3. **(권장) 13 성능** — `13_성능/`(랩 CWV·번들 분석, 랩↔필드 비교 기준). 없으면 "랩 비교 미수행 ⚠️".
4. **(권장)** gh 배포·머지 타임라인 / 17 Sentry 느린 트랜잭션.

## 사용법

RUM export CSV를 `리서치/rum/`에 둔 뒤:

```
리서치/rum/의 web-vitals CSV 읽고 포밋 프론트엔드 성능 현황·회귀·개선 백로그 만들어줘
```

1. RUM 지표 화면별 **p75** 집계·해석(python3 계산) → 18-1
2. 회귀 추세 + 배포 상관 추정(상관≠인과) → 18-2
3. `/vercel-react-best-practices`로 병목 번역 (없으면 일반 React/Next 점검으로 degrade)
4. RICE 개선 백로그 **초안** → 18-3
5. **개선 우선순위 확정** → 당신이 채택·우선순위 결정 (사람 개입, 18-3 확정 전 다음 단계 진행 안 함)
6. Lighthouse CI 게이트(18-5) + 01 입력 변환(18-4, 루프 마감)

발동 키워드: `RUM 분석`, `성능 회귀 추세`, `개선 백로그`, `Lighthouse CI`, `p75 지표 해석`, `performance tuning`

## 주의

- **p75를 봐야지 평균을 보면 안 됩니다.** 평균은 느린 사용자를 가립니다. 표본 적은 화면(n<100)은 해석 보류.
- **상관을 인과로 단정하지 마세요.** 인접 배포가 범인이라는 보장 없음 — 트래픽 구성 변화·외부 SDK·노이즈를 대안 가설로.
- **숫자는 스크립트가 냅니다.** p75·이동평균·증감률을 LLM이 추정하면 틀립니다 — python3로.
- **Lighthouse 점수 자체를 목표로 삼지 마세요.** budget은 회귀 방지선. 실제 목표는 RUM 사용자 체감.
- **개선 효과는 다음 사이클 RUM으로만 검증됩니다.** "고쳤다"가 아니라 "다음 측정으로 확인".
- 화면 구조·디자인 개선 항목은 **디자인 15**와 조율(FE는 성능·코드 구현 관점, 중복 금지).
