# fe-testing — 테스트 (단위·컴포넌트·E2E) 자동화 스킬

08 화면·10 API연동 산출물을 넣으면 테스트 피라미드 계획 → 컴포넌트 테스트 초안(Vitest+RTL) →
E2E 시나리오(Playwright) → MSW 목 설정을 만들어 **회귀 안전망**을 짜는 Claude Code 스킬입니다.
역할 분담: **케이스 발굴·보일러플레이트·목 핸들러는 AI, 기대값(assert) 확정과 시나리오 검수는 사람**.

> FE 프로세스 15단계 "테스트 (단위·컴포넌트·E2E)"를 자동화합니다.

## 무엇을 만들어 주나

`frontend-output/<주제>/15_테스트/`에 생성:

| 파일 | 내용 |
|---|---|
| `15-1_테스트계획.md` | 테스트 피라미드(단위/컴포넌트/E2E 배분)·레벨별 대상·도구 세팅·커버리지 정책 + 케이스 표(기대값 칼럼 비움) |
| `15-2_컴포넌트테스트초안.md` | 단위(AAA) + 컴포넌트(RTL `getByRole`/`userEvent`) 테스트 초안, 상태 4종(10-3 계승) 검증 |
| `15-3_E2E시나리오.md` | Playwright 핵심 여정 3~5개, route mocking·인증 우회 픽스처·trace (픽셀 비교 금지) |
| `15-4_MSW목설정.md` | `src/mocks/{handlers,server,browser}.ts` 골격(MSW v2), 목 응답은 10 `schema.d.ts` 준수 |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(필수) 08 화면구현** — `08_화면구현/`(검증 대상 화면·`08-2_상태화면커버리지`).
2. **(필수) 10 API연동** — `10_API연동/`의 `schema.d.ts`(목 응답 타입 원천, BE 05 OpenAPI 계승) + `10-3_로딩에러빈상태`(상태 4종 분기).
3. **(권장) 11 폼 / 12 인증가드 / 유저플로우** — 컴포넌트 케이스·E2E 핵심 여정·인증 우회에 반영.

08·10이 둘 다 없으면 중단합니다(검증 대상이 없음).

## 사용법

08·10 산출물을 준비한 뒤:

```
08·10 산출물 보고 테스트 계획이랑 컴포넌트·E2E 테스트 만들어줘
```

1. 테스트 계획(피라미드) + **케이스 표(기대값 칼럼 비움)** 자동 생성
2. **🚦 케이스 기대값 확정** → 당신이 도메인 명세로 채움 (유일한 필수 개입 — E2E 범위·인증 우회·커버리지 하한선도 여기서)
3. 단위·컴포넌트 테스트 초안 → E2E 시나리오 → MSW 목 설정 → 커버리지 점검 자동

발동 키워드: `프론트 테스트`, `컴포넌트 테스트`, `E2E`, `테스트 피라미드`, `MSW 목`, `회귀 테스트`

## 주의

- **AI가 채운 기대값을 그대로 믿지 마세요.** 버그 있는 코드를 "정답"으로 박제합니다 — 상태 전이·금액·검증 기대값은 사람이 명세로 확정.
- **커버리지 숫자는 목표가 아닙니다.** "안 덮인 위험 지점 찾기" 용도. getter·타입 파일까지 덮는 무의미 테스트 금지.
- **E2E는 핵심 여정 3~5개로 제한.** 모든 걸 E2E로 덮으면 CI가 느려지고 플래키해져 결국 `--skip`이 늡니다.
- **시각 회귀·픽셀 검수는 디자인 시리즈 몫.** 이 단계 E2E는 "기능이 동작하는가"만 봅니다(스크린샷 픽셀 비교 금지).
- **MSW는 v2 문법**(`http`/`HttpResponse`), 목 응답은 `schema.d.ts`와 어긋나지 않게.
