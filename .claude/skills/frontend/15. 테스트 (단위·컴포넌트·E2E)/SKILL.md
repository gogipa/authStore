# 테스트 (단위·컴포넌트·E2E) (Frontend Testing)

지금까지 구현한 화면·상태·폼·API 연동·인증을 "손으로 눌러보니 되더라"에서 **자동으로 반복 검증되는
회귀 안전망**으로 바꾼다. 산출물 = 테스트 계획(피라미드) → 컴포넌트 테스트 초안(Vitest+RTL) → E2E
시나리오(Playwright) → MSW 목 설정(10 `schema.d.ts` 계승). **AI는 케이스 발굴·보일러플레이트·목
핸들러 생성(회수율), 각 케이스의 기대값(assert)과 시나리오 검수는 사람** — 한마디로 "케이스는 AI,
기대값은 사람".

## 핵심 원칙

- **케이스는 AI, 기대값은 사람.** AI는 정상/경계/예외 케이스를 사람보다 빠짐없이 떠올린다. 하지만
  "그 입력이면 결과가 무엇이어야 하는가"는 도메인 명세다. **기대값 칼럼을 비워 표로 먼저 제시 →
  사람이 채운 뒤에야 `it()` 코드로 변환**한다(코드에 맞춰 기대값을 채운 "통과용 테스트" 방지).
- **상위 산출물 계승, 재발명 금지 — 단 확정 상태일 때만.**
  - **10 `schema.d.ts`(BE 05 OpenAPI 계승) → MSW 목 응답**: 목 응답 타입은 `schema.d.ts`를 따른다.
    임의 필드 금지(목을 손으로 지어내면 "테스트는 초록·프로덕션은 빨강"). `schema.d.ts`(코드 프로젝트
    생성물)에 접근 못 하면 ⚠️ + **10-1이 인용한 BE 05 OpenAPI 스키마명·enum을 원천으로 타입드**(아래 입력 참조).
  - **10-3 상태 4종(loading/error/empty/success) → 컴포넌트 테스트 케이스**: 10에서 만든 분기를 회수해
    실제 동작하는지 검증(재발명 금지).
  - **08-2 상태화면 커버리지 → 검증 대상 화면 목록**. 08/10에 잔존한 `⚠️`/`[확인 필요]`는 보존.
- **테스트 피라미드로 비용을 배분.** 순수 로직=단위(빠르고 안정), 화면 거동=컴포넌트+MSW, 사용자
  여정만 E2E(비싸고 플래키). 아래가 넓고 위가 좁게. **E2E는 핵심 여정 3~5개로 제한.**
- **사용자 관점 쿼리 강제.** RTL은 `getByRole`/`getByLabelText` 우선, `test-id`는 최후수단. 접근성
  쿼리로 못 잡히면 그건 [[14. 접근성·반응형 대응]]의 결함 신호 → 별도 표기. 구현 세부(내부 state·
  함수 호출 횟수·`className`)는 단언하지 않는다(리팩터링 내성).
- **커버리지는 지도이지 목표가 아니다.** "안 덮인 위험 지점 찾기" 용도. 100%를 위해 getter·타입 파일을
  덮는 무의미한 테스트 금지. CI 하한선(예 lines 70%)은 회귀 방지용, 보강 대상은 위험도로 사람이 정함.
- **경계 — 시각 회귀(visual QA)·픽셀 검수는 디자인 시리즈 몫.** 이 단계 E2E는 "픽셀이 시안과 같은가"가
  아니라 **"기능이 동작하는가"**를 본다. E2E에 스크린샷 픽셀 비교를 넣지 않는다(디자인 14 퍼블리싱 검수).
- **단계별 파일로 끊는다**(한 방 생성 금지 — 코드+테스트 동시 생성은 자기 코드에 맞춘 통과 테스트를 부른다).
  신규 로직·버그 수정은 `test-driven-development` 스킬(RED→GREEN→REFACTOR)로 테스트를 먼저 확정하면 이 함정을 피한다.

## 파이프라인

### Stage 0 — 입력 확인·도구 probe·degrade
- `<루트>/08_화면구현/`·`<루트>/10_API연동/`을 읽는다. **둘 다 없으면 중단**(위치 질의).
- `10-1`의 `schema.d.ts`를 로드(있으면 목 타입 계승 모드, 없으면 ⚠️ + 수기 작성 안내).
- 11(폼)·12(인증)·유저플로우 로드 시도(있으면 케이스·E2E 여정에 반영).
- **도구 probe**: Context7(ToolSearch 존재) / pnpm·vitest·msw·playwright(bash 시도) / Playwright MCP(ToolSearch).
  없으면 degrade(아래 "도구 정확성").

### Stage 1 — 테스트 계획(피라미드) + 케이스 표 → 15-1
- 08·10·11·12 산출물에서 테스트 대상을 **레벨별로 분류**:
  - **단위(多)**: 순수 로직(예 `canTransition(from,to)` 상태머신, 금액 계산, 검증 함수).
  - **컴포넌트(中)**: 화면 거동(검색 폼, 상태 4종 분기, 권한별 UI).
  - **E2E(少)**: 핵심 사용자 여정 3~5개(로그인→검색→예약 등).
- 레벨별 도구 세팅(Vitest+RTL/MSW/Playwright) 명령과 커버리지 정책(CI 하한선·위험도 보강 기준)을 적는다.
- **케이스 표**: 단위·컴포넌트 대상의 정상/경계/예외 케이스를 나열하되 **`기대값` 칼럼은 비워둔다**
  (사람이 채울 자리). 예 — 상태머신: 모든 `(from,to)` 조합 + 같은 상태/종료 상태(COMPLETED·CANCELED)
  전이/존재하지 않는 상태값 등 경계·예외.
- → `15-1_테스트계획.md`

### 🚦 게이트 — 케이스 기대값 확정 (사람 개입, 필수)
AskUserQuestion으로 **15-1의 케이스 표 + 피라미드 배분(어디까지 E2E로 할지)**을 제시 → 사람이 OK/수정.
- 핵심 결정 항목(사람이 쥐는 도메인 판단):
  - **케이스 기대값** — `allow?`/예상 결과 칼럼을 도메인 명세(BE 정본 상태머신·검증 규칙)로 확정.
    AI가 코드 동작에 맞춰 채운 값을 그대로 믿지 않는다.
  - **E2E 범위** — 어떤 여정 3~5개를 E2E로 둘지(비용 배분). 단위·컴포넌트로 충분한 건 내린다.
  - **인증 우회 방식** — 카카오 OAuth 실로그인은 E2E에서 막힘 → 세션 주입/픽스처 중 택.
  - **커버리지 하한선** — CI 게이트 값(예 lines 70%)과 제외 후보(타입·단순 표현 파일).
- **기대값을 사람이 확정하기 전에는 테스트 코드(Stage 2~)로 변환하지 않는다**(한 방 생성 방지 —
  중간 판단을 검토해야 한다).

### Stage 2 — 단위·컴포넌트 테스트 초안 → 15-2
- **단위**: 확정된 케이스 표를 `describe`/`it`로 변환. AAA(Arrange-Act-Assert) 구조. 기대값은 게이트에서
  사람이 확정한 값만 사용.
- **컴포넌트(RTL)**: `getByRole`/`getByLabelText` 우선(`test-id` 최후수단). 검증은 **사용자가 보는 결과**만
  (구현 세부 단언 금지). 각 `it()`에 given-when-then 한 줄 주석. **접근성 쿼리로 안 잡히는 요소는
  "14 접근성 결함 신호"로 별도 표기**.
- **10-3 상태 4종 검증**: TanStack Query를 `QueryClientProvider` wrapper로 감싸 렌더(테스트에선 `retry:false`,
  `gcTime` 짧게 — 플래키 방지). 성공(목록)·빈(`[]`)·에러(500)·로딩(스켈레톤)을 각각 검증(MSW는 15-4).
- → `15-2_컴포넌트테스트초안.md`

### Stage 3 — E2E 시나리오 → 15-3
- 유저플로우의 핵심 여정 **3~5개만** Playwright 시나리오로(`e2e/*.spec.ts`).
- `baseURL`은 `playwright.config.ts`, `webServer`로 `pnpm dev` 자동 기동.
- **외부 의존 제거**(플래키 방지): 카카오 OAuth 실호출 금지 → 게이트에서 확정한 인증 우회(세션 주입/픽스처).
  `/api/**`는 Playwright **route mocking**으로 응답 고정.
- 셀렉터 `getByRole`/`getByLabel` 우선(텍스트는 시안 카피 변경에 약함). 단언 = **기능 동작만**
  (예 "예약 접수" 확인 화면 이동 + 예약 목록에 `REQUESTED` 1건). **픽셀·스크린샷 비교 금지**(디자인 검수 몫).
  실패 시 trace 남기도록 설정.
- Playwright MCP 가용 시 시나리오 시범 실행·관찰에 참고(없으면 코드만 생성 + "로컬 실행 필요").
- → `15-3_E2E시나리오.md`

### Stage 4 — MSW 목 설정 → 15-4
- `src/mocks/`: `handlers.ts`(핸들러) / `server.ts`(node·테스트용) / `browser.ts`(개발용) 골격.
- **MSW v2 문법**(`http.get` / `HttpResponse.json(...)`) — v1(`rest.get`/`res(ctx.json())`) 혼용 금지. Context7로 확인.
- **목 응답 타입은 10 `schema.d.ts` 준수**(임의 필드 금지 — 계약 기반 목). 핸들러별 상태(성공/빈/500)를
  `server.use()`로 테스트별 오버라이드하는 패턴.
- (선택) `pnpm exec msw init public/ --save`로 브라우저용 service worker.
- → `15-4_MSW목설정.md`

### Stage 5 — 커버리지 점검 + 검증 체크리스트
- (가능 시) `vitest run --coverage` 결과를 읽고 **핵심 로직인데 안 덮인 곳**을 우선순위로, 단순 표현/타입
  파일은 제외 후보로 분류해 표로 제시(사람이 보강 대상 확정). **숫자 추종 금지** — 목표는 위험 로직
  (bookingStatus·결제 검증 등)을 덮는 것. (CLI 부재 시 "로컬 실행 필요" 안내 + 정적 점검 항목.)
- `_검증체크리스트.md` 생성(`<주제>`/`<날짜>` 치환). 마지막으로 산출물 폴더 경로와 "`pnpm test`·
  `pnpm exec playwright test` 통과를 16단계 CI 머지 게이트로 건다" 고지를 보고한다.

## 도구 정확성 (probe·degrade)
- **Context7 MCP**(probe) = Vitest·RTL·MSW v2·Playwright 최신 API 확인(메이저 버전 차 큼 — MSW
  v1→v2, RTL `fireEvent`→`userEvent`). 없으면 **내장 지식 + "버전 확인 필요 ⚠️"** 표기.
- **pnpm / vitest / msw / playwright CLI**(bash probe) = 설치·실행. 없으면 **설정·테스트 코드는 생성하되
  "로컬 실행 필요"**(`pnpm create playwright`·`pnpm exec msw init` 등 명령만 안내).
- **Playwright MCP**(probe) = E2E 시범 실행·브라우저 관찰 참고. 없으면 코드만 생성.
- **openapi-typescript / 10 `schema.d.ts` 부재** = 목 응답 타입 수기 작성 안내 + ⚠️(계약 미대조).
- **중단**은 필수 입력(08·10) 부재 시에만. 그 외는 degrade.

# 검증 체크리스트 — <주제> 테스트 (작성일: <날짜>)

> AI는 케이스 발굴·보일러플레이트·목까지. 기대값(assert)과 시나리오 검수는 사람의 일이다.

- [ ] AI가 채운 기대값을 그대로 믿지 않았는가 — 도메인 로직(상태 전이·금액·검증) 기대값은 사람이 명세로 확정
- [ ] 케이스 표를 사람이 확정한 뒤 테스트 코드로 변환했는가 (코드+테스트 한 방 생성 금지)
- [ ] 피라미드 비율 지킴 — E2E 3~5개로 제한, 단위·컴포넌트로 충분한 건 E2E로 안 올림
- [ ] 컴포넌트 테스트: getByRole/getByLabel 우선, 구현 세부(state·className) 단언 없음 / 접근성 쿼리 미탐 요소는 14 결함으로 표기
- [ ] 상태 4종(loading/error/empty/success, 10-3 계승) 각각 검증
- [ ] MSW 목 응답 타입이 10 schema.d.ts 준수 (임의 필드 0) / MSW v2 문법(http·HttpResponse), v1 혼용 0

- [ ] 커버리지는 위험 지점 찾기 용도 — 숫자만 올린 무의미 테스트 없음, CI 하한선 회귀 방지용

## 주의
- **AI가 채운 기대값을 그대로 믿지 마라** — 가장 위험한 실수. 버그 있는 코드를 "정답"으로 박제한다.
  상태 전이·금액·검증 규칙 기대값은 사람이 명세로 확정.
- **테스트가 구현 세부에 묶이면 짐** — 내부 state·호출 횟수·`className` 단언은 리팩터링마다 깨진다.
  사용자가 보는 결과만 단언.
- **커버리지 숫자를 목표로 삼지 마라** — getter·타입 파일까지 덮으면 무의미 테스트만 늘고 위험 로직은 얕다.
- **E2E 플래키 방치 금지** — 고정 대기(`waitForTimeout`)·외부 네트워크·실 OAuth가 간헐 실패 주범. auto-wait·
  route mocking·인증 우회로 외부 의존을 줄인다(가끔 실패하는 E2E는 곧 아무도 안 믿어 안전망이 무너진다).
- **흔한 실수 — 코드+테스트 동시 한 방 생성**: 자기 코드에 맞춘 통과용 테스트를 부른다. 테스트(명세)를 먼저
  확정하거나 기대값을 사람이 별도 검수.
- **흔한 실수 — E2E로 모든 걸 덮기**: CI가 느려지고 자주 깨져 결국 `--skip`이 는다. 피라미드 비율(단위 多·E2E 少) 유지.
- **MSW v1/v2 혼용 주의** — v2는 `http`/`HttpResponse`. Context7로 확인하고 목 응답이 `schema.d.ts`와 어긋나지 않는지 점검.
