# 화면·페이지 구현 (Page Implementation)

07에서 만든 공통 UI 컴포넌트를 라우트(05)마다 비어 있던 페이지에 조립해 "사용자가 실제로 보는 한 장"을 코드로 완성한다. 산출물 = 화면 구현 목록 → 상태 화면 커버리지(빈/로딩/에러/권한) → 페이지 초안. **AI는 골격·변형 초안 생성(회수율), 정보 위계·인터랙션 우선순위·접근성 디테일 판단은 사람.** 이 단계는 목 데이터로 **정적 구조 + 상태 화면의 자리**까지만 완성하고, 실제 페칭·캐싱은 10, 서버/클라 상태 분리는 09로 미룬다.

## 핵심 원칙

- **상위 산출물 계승, 재발명 금지 — 단 확정 상태일 때만.**
  - **07 공통 컴포넌트는 재사용 강제**: Button/Input/Modal/Card/EmptyState 등 07 인벤토리에 있는 컴포넌트를 화면 안에서 "비슷한 걸 다시 만들지" 않는다. **Code Connect 매핑(`get_code_connect_map`)이 있으면 그 코드 컴포넌트를 그대로** 쓴다. 화면 특화 단위(예: SitterCard)만 `features/<도메인>/components/`로 분리.
  - **05 route 맵·layout 계승**: 채울 페이지 경로(`app/.../page.tsx`)·route group·layout 경계는 05에서 확정된 것을 따른다. 임의 라우트 신설 금지.
  - **04 토큰만 사용, 매직값 금지**: 색·간격·타이포는 04 tailwind config·CSS vars 토큰만. 시안의 값을 하드코딩(`#3B82F6`, `margin: 13px`)하지 않는다. 생성 후 매직값을 grep으로 점검.
  - **BE 05 도메인 용어 계승**: props 타입은 BE 05 도메인(`SitterProfile`·`Pet`·`Booking` 등)에 맞춰 선언. 재작명 금지. (이 단계는 타입 선언·목 데이터까지, 실제 페칭은 10.)
- **순서 강제: 분해 → 매핑 → 상태.** "이 시안 만들어줘"를 통으로 던지면 07을 안 쓰거나 happy path만 만든다. 섹션 분해 → 07/Code Connect 매핑 → 상태 4종으로 끊어 각 단계를 사람이 검토·확정한 뒤 넘긴다.
- **상태 화면을 happy path와 같은 작업으로 묶는다.** empty/loading(skeleton)/error/권한은 "나중에"가 되면 영영 빠진다. **한 작업 단위에서 함께 생성하도록 강제**하는 것이 이 단계의 핵심 설계다. 상태는 "있다"가 아니라 "디자인됐다"여야 한다(상태별 설계 규칙은 Stage 2).
- **데이터 연동을 일부러 미룬다.** 이 단계는 목 데이터로 골격·상태 자리까지만. `fetch`·TanStack Query 페칭을 끌어오지 않는다(10의 자리만 TODO 주석). 폼 검증 스키마·제출 로직도 11의 자리만 비운다.
- **서버/클라 경계를 흐리지 않는다.** 화면 전체에 무심코 `'use client'`를 박지 않는다. 상호작용이 필요한 최소 단위(필터 바·CTA)만 클라이언트로, 헷갈리면 Context7로 Next 15 경계 규칙 확인.
- **단계별 파일로 끊는다**: 구현 목록(08-1) → 상태 커버리지(08-2) → 페이지 초안(08-3). 한 방 생성 금지(중간 판단 검토 불가).

## 파이프라인

### Stage 0 — 입력 확인·도구 probe·degrade
- `<루트>/07_공통컴포넌트/`·`<루트>/05_라우팅/`을 읽는다. **둘 중 하나라도 없으면 중단**(해당 단계 먼저 권장).
- 디자인 13 시안 접근 경로 확인(Figma MCP 또는 로컬 스펙). 없으면 degrade 모드(사용자 수기 기술 + ⚠️).
- 04 토큰 사전·01 화면 목록·BE 05 도메인 타입 로드 시도(있으면 사용, 없으면 degrade).
- **도구 probe**: Figma MCP read(ToolSearch 존재)·Context7(ToolSearch 존재)·pnpm/Storybook(bash 시도). 없으면 degrade(아래 "도구 정확성").
- 구현할 화면 범위·우선 패턴(목록/상세/폼)을 게이트용으로 정리.

### Stage 1 — 시안 분해 + 07/Code Connect 매핑 → 08-1
- 시안(Figma `get_design_context`/`get_metadata` 또는 수기 기술)을 **의미 단위 섹션**으로 분해(예: 필터 바 / 결과 목록 / 페이지네이션).
- 각 섹션을 **07 공통 컴포넌트로 매핑**. `get_code_connect_map`에 매핑이 있으면 그 컴포넌트를 그대로 쓰도록 명시(임의 신규 금지).
- 화면 특화 단위만 `features/<도메인>/components/`로 분리(예: `SitterCard`).
- **서버/클라 경계** 컬럼: 목록은 RSC, 상호작용 섹션(필터 바·CTA)만 `'use client'`.
- props **도메인 타입은 BE 05 계약**(`SitterProfile`·`Pet`·`Booking` 등)으로 선언(타입만, 페칭은 10).
- 시안에 있는데 07로 안 떨어지거나 매핑이 모호한 항목은 **"확인 필요"** 표시(억지 매핑·임의 신규 금지).
- 목록/상세/폼 **반복 패턴을 식별**해 "한 화면 확정 후 변주" 대상으로 표시.
- 표: `화면 | 라우트 | 섹션 분해 | 07 컴포넌트 매핑 | 화면특화 | 서버/클라 | 도메인 타입 | 확인필요`.

### 🚦 게이트 — 화면 범위 + 상태 커버리지 기준 확정 (사람 개입, 필수)
08-1 분해·매핑 초안을 AskUserQuestion으로 제시 → 사용자가 OK/수정. **이 게이트 전에는 Stage 2(상태 생성)·Stage 3(코드)로 넘어가지 않는다**(한 방 생성 방지 — 분해·매핑이라는 중간 판단을 사람이 검토한 뒤 넘긴다).
- 핵심 결정 항목(사람이 쥐는 판단):
  - **이번에 구현할 화면 범위** — 모든 화면을 한 번에 vs 패턴 대표 화면(목록·상세·폼) 먼저 확정 후 변주.
  - **상태 커버리지 기준** — 기본 4종(빈/로딩/에러/권한). 화면별로 더 필요한 상태(예: 마감·차단·검증 실패)가 있는지. 4종 중 해당 없는 상태는 "N/A 사유"로 명시(임의 누락 금지).
  - **정보 위계·인터랙션 우선순위** — 08-1 분해에서 무엇이 1급인지, 어느 인터랙션이 우선인지(AI가 못 읽는 의도).
  - **신규 컴포넌트 허용 여부** — 08-1에서 07로 안 떨어진 화면특화 단위를 어디까지 `features/`로 분리할지.

### Stage 2 — 상태 화면 4종 매트릭스 → 08-2
happy path만 두고 넘어가지 않도록, 화면별 비-happy 상태를 강제로 함께 설계한다.
- **빈(empty)**: 결과 0건 등. 사용자 언어 안내 + **다음 행동 CTA 필수**(예: 필터 초기화, 펫 먼저 등록). 07 인벤토리에 `EmptyState`가 **있으면 재사용**. **없으면 07 신규 생성 금지 — `Card`/`Button`+텍스트를 04 토큰으로 인라인 조합**하고, 2곳+ 반복되면 "07로 승격 역질의"로 회부(임의 신규 컴포넌트 금지·07 인벤토리는 도메인 따라 EmptyState가 없을 수 있음).
- **로딩(skeleton)**: 본 컴포넌트 **실제 치수에 맞는** 스켈레톤(CLS 없게 같은 높이/간격). Next `loading.tsx` 활용. 07에 `Skeleton`이 있으면 재사용, 없으면 토큰 기반 인라인(`bg-bg-surface`+`animate-pulse`, 본 컴포넌트와 같은 높이/간격)+승격 역질의.
- **에러**: 로딩 실패. `error.tsx`(`'use client'`)에 **재시도** + 사용자 언어 메시지(**스택트레이스 노출 금지**).
- **권한/조건**: 권한 미허용·마감·차단 등 화면별 조건 상태(예: 위치 권한 미허용 안내, 마감 시 disabled CTA + 안내).
- 각 상태에 **Storybook 스토리**를 매핑(데이터 없이 격리 확인): 예 `SitterListView.stories.tsx`의 Loading/Empty/Error/NoPermission.
- 게이트에서 N/A로 합의된 상태는 사유와 함께 기록. **누락 상태가 있으면 경고**.
- 표: `화면 | 빈 | 로딩 | 에러 | 권한/조건 | Next 파일 | Storybook 스토리`.

### Stage 3 — 페이지·상태 변형 코드 초안 → 08-3
- 확정된 08-1 분해 + 08-2 상태를 근거로 페이지·화면특화 컴포넌트·상태 변형 코드 초안 생성:
  - **목 데이터·props 타입만**으로 렌더. 페칭·캐싱·낙관적 업데이트는 **TODO 주석으로 10의 자리만** 비움. 폼 검증/제출은 11의 자리만 TODO.
  - 04 토큰(Tailwind·CSS vars)만 사용. **매직값 금지** — 생성 후 색상 리터럴(`#`)·픽셀 매직값을 grep으로 점검해 보고.
  - 서버/클라 경계 준수(상호작용 최소 단위만 `'use client'`). 헷갈리면 Context7로 Next 15 App Router 경계 확인(도구 정확성 참조).
  - Booking 등 상태 흐름이 걸린 화면은 BE 정본 흐름(`REQUESTED→ACCEPTED→…`) 그대로, 해당 화면이 어느 진입점인지 주석 명시.
  - 하단 CTA sticky·`aria-label`·포커스 순서 등 접근성 기본을 반영(상세 a11y 점검은 14).
- **frontend-design 스킬**로 화면 코드를 옮기되, 시안 의도(정보 위계·간격·타이포)를 살리고 제네릭 UI를 피한다.
- 패턴 대표 화면 확정 후, 나머지 화면은 같은 분해·상태 규칙을 변주 적용.
- **시안↔빌드 1차 시각 대조**(가능 시): 로컬 빌드 화면과 Figma `get_screenshot` 캡처를 나란히 비교해 **구조적 갭만** 표로(섹션 순서·간격 토큰·타이포 위계·매직값). **픽셀 단위 최종 판정은 하지 않는다**(디자인 14 퍼블리싱 검수 몫).

### Stage 4 — 검증 체크리스트 + 마무리
- `_검증체크리스트.md` 생성(`<주제>`/`<날짜>` 치환, 아래 본문).
- 산출물 폴더 경로와 "상태 화면은 happy path와 같은 작업 단위 — happy-path 단일 PR 금지 / 픽셀 검수는 디자인 14 / 페칭은 10·상태 위치는 09" 고지를 보고한다.
- 잔존 ⚠️(시안 미대조·확인 필요)·매직값이 남아 있으면 표시하고 완료 단정을 피한다.

## 도구 정확성 (probe·degrade)
- **frontend-design 스킬**(정본) = 시안→production-grade 화면 코드. 제네릭 UI 회피·정보 위계 유지. 화면 구현 작업에 적용.
- **Figma MCP read**(probe) = `get_design_context`/`get_screenshot`/`get_metadata`/`get_code_connect_map` 참고만(시안 읽기·매핑 확인·시각 대조). **write 도구는 사용하지 않는다**(시안 생성·토큰 정의는 디자인 몫). 없으면 degrade: **01-1 화면목록·디자인 13 로컬 스펙을 시안 분해의 텍스트 출처로 사용**(시안=HTML·node-id 부재처럼 Figma 파일 자체가 없는 경우 포함), 그래도 부족하면 사용자가 수기 기술. **모두 ⚠️(시안 미대조) 표기·시각 대조 생략.** 시안 미실측 화면의 분해·상태는 "추정"으로 명시.
- **Context7 MCP**(probe) = Next.js 15 App Router 화면 구성 경계(`loading.tsx`/`error.tsx`/`not-found.tsx`·Suspense·RSC vs Client)·최신 표기 조회. 없으면 **내장 지식 + "버전 확인 필요 ⚠️"**.
- **pnpm·Storybook**(bash probe) = 스토리·로컬 빌드. 없으면 스토리/설정은 생성하되 "로컬 실행 필요" 안내(시각 대조 생략).
- **중단**은 필수 입력(07·05) 부재 시에만. 그 외(시안·04·01·BE 타입·CLI)는 degrade.

## 주의
- **시각적으로 그럴듯한 것과 시안 일치는 다르다.** frontend-design 화면은 보기엔 완성돼도 간격·위계가 미묘하게 다를 수 있다. 1차 갭만 잡고 **픽셀 단위 최종 판정은 디자인 14 퍼블리싱 검수**에 맡긴다(FE가 디자인 검수를 자처하지 않는다).
- **04 토큰을 벗어난 매직값을 경계한다.** AI가 시안 색·간격을 토큰 대신 하드코딩하는 경우가 잦다 — 토큰만 쓰도록 명시하고 생성 후 grep 점검.
- **새 컴포넌트를 멋대로 만들게 두지 않는다.** 07 인벤토리·Code Connect 매핑을 컨텍스트로 주고 "신규 컴포넌트 금지, 재사용 우선" 명시.
- **상태는 "있다"가 아니라 "디자인됐다"여야 한다** — 에러 스택트레이스 노출·빈 상태 CTA 부재는 상태를 만든 의미가 없다.
- **흔한 실수 — 데이터 연동 끌어오기**: 화면 만들며 `fetch`·TanStack Query를 같이 넣으려다 구조가 엉킨다. 목 데이터로 골격만, 페칭은 10.
- **흔한 실수 — happy path 단일 PR**: happy path만으로 PR 올리고 "상태는 다음에"로 미루면 그 화면은 미완성으로 운영에 나간다. 상태 4종을 같은 작업 단위로 묶어 끝낸다.
