# fe-page-implementation — 화면·페이지 구현 자동화 스킬

07 공통 컴포넌트·05 라우트 맵·디자인 13 시안을 넣으면, 비어 있던 페이지를 **분해→매핑→상태** 순서로 조립하는 Claude Code 스킬입니다. 시안을 섹션으로 쪼개 07 컴포넌트로 매핑하고, 빈·로딩·에러·권한 상태 4종을 happy path와 한 묶음으로 강제 생성한 뒤 목 데이터로 정적 골격까지 만듭니다.

> FE 프로세스 8단계 "화면·페이지 구현"을 자동화합니다.
> 역할 분담: AI는 골격·상태 변형 초안(회수율), **정보 위계·인터랙션·접근성 판단은 사람**. 데이터 페칭은 10, 상태 위치는 09, 픽셀 검수는 디자인 14로 분리.

## 무엇을 만들어 주나

`frontend-output/<주제>/08_화면구현/`에 생성:

| 파일 | 내용 |
|---|---|
| `08-1_화면구현목록.md` | 화면·라우트·섹션 분해·07 컴포넌트 매핑(Code Connect)·화면특화 컴포넌트·서버/클라 경계·도메인 타입·확인필요. 목록/상세/폼 패턴 식별 |
| `08-2_상태화면커버리지.md` | 화면별 상태 4종(빈/로딩-skeleton/에러/권한) 매트릭스 + 사용자 메시지·다음 행동 CTA·Next 파일·Storybook 스토리 |
| `08-3_페이지초안.md` | 페이지·화면특화 컴포넌트·상태 변형 코드 초안(목 데이터·props 타입, 페칭 TODO) + 시안↔빌드 1차 시각 갭 표 |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **(필수) 07 공통 컴포넌트** — `<루트>/07_공통컴포넌트/`(변형 매트릭스·컴포넌트 초안). 없으면 중단.
2. **(필수) 05 라우트 맵** — `<루트>/05_라우팅/`(route 맵·layout). 채울 페이지 경로의 출처. 없으면 중단.
3. **(권장) 디자인 13 핸드오프 시안** — Figma MCP read 또는 로컬 스펙. 없으면 시안 구조 수기 기술 + ⚠️.
4. **(권장) 04 토큰·01 화면 목록·BE 05 도메인 타입** — 토큰만 쓰기·그릴 화면·props 타입용.

## 사용법

07·05 산출물(과 시안)을 준비한 뒤:

```
시터 검색·예약 요청 화면 구현해줘 (07 컴포넌트·05 라우트 기준, 상태 4종 포함)
```

1. 시안 분해 + 07/Code Connect 매핑 (08-1)
2. **화면 범위·상태 커버리지 기준 확정** → 당신이 OK (유일한 게이트 개입)
3. 상태 4종 매트릭스 (08-2) → 페이지·상태 코드 초안 (08-3) → 검증 체크리스트

발동 키워드: `화면 구현`, `페이지 구현`, `상태 화면`, `빈 로딩 에러`, `스켈레톤`, `page implementation`, `screen states`

## 주의

- **그럴듯함 ≠ 시안 일치.** 1차 구조 갭만 잡고 **픽셀 단위 최종 판정은 디자인 14 퍼블리싱 검수**에 맡깁니다(FE가 디자인 검수 자처 금지).
- **매직값을 경계하세요.** AI가 색·간격을 토큰 대신 하드코딩하는 일이 잦습니다 — 04 토큰만, 생성 후 grep 점검.
- **새 컴포넌트를 멋대로 만들지 않게.** 07 인벤토리·Code Connect를 컨텍스트로 주고 "재사용 우선".
- **상태는 "디자인됐다"여야 합니다** — 에러 스택트레이스 노출·빈 상태 CTA 부재는 의미 없음.
- **데이터 연동·폼 검증은 끌어오지 마세요** — 페칭은 10, 폼은 11. 이 단계는 목 데이터 골격까지.
- **happy path 단일 PR 금지** — 상태 4종을 같은 작업 단위로 묶어 끝냅니다.
