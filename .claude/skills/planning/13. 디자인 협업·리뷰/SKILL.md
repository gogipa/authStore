# 디자인 협업·리뷰 (Design Review)

기능명세까지 확정되면 디자이너가 시안을 만든다. 이 단계 기획자의 역할은 **"예쁜가"가 아니라
"기획과 일치하는가"**를 검증하는 것이다. 화면설계서 요소가 빠지지 않았는지, 기능명세의 예외
케이스(빈/에러/로딩) 화면이 있는지, 정책 문구가 UI 텍스트에 반영됐는지를 화면 단위로 대조한다.
**생성이 아니라 대조 스킬.** 산출물은 **디자인 리뷰 리포트**(수정요청/질문/제안).

## 핵심 원칙 (어기면 협업이 망가진다)

- **대조 결과는 후보 목록이지 판정이 아니다.** 디자이너의 의도적 개선(드롭다운→바텀시트)을
  "불일치"로 오검출할 수 있다 — 기획자가 먼저 훑어 의도적 변경은 **"질문"으로 옮긴 뒤** 전달.
  (이 스킬 자체가 검증 스킬이므로 "검출 = 후보, 판정 = 사람" 규율을 끝까지 지킨다.)
- **수정요청 / 질문 / 제안 분리 + 근거 문서 인용 강제.** 취향 코멘트와 명세 기반 지적을 섞지
  않는다(협업 마찰의 주원인).
- **시각 품질 판단 안 함.** 정렬·여백·위계는 디자이너 영역. **get_variable_defs(토큰)는
  보조·선택**만 — 토큰 미준수 지적은 월권이다.
- **용어 통일은 사용자 결정**(권장안만 제시). 확정 용어집 = 14/15 재사용.
- **문구 검수 한계**: 이미지 글자·외부 컴포넌트 내부 텍스트는 design context에 안 잡힌다 →
  **약관·결제·법적 고지 화면은 `[사람 직접 검수 필요]` 플래그를 무조건 부여**(자동 판정 금지,
  get_screenshot 이미지 + 원본을 사람이 직접).
- **잘된 점·격려는 기획자가 직접 작성**(AI 자동 칭찬 금지 — placeholder만 비워둠). 자동 지적
  수십 개를 그대로 던지면 "기계 검사" 인상을 준다. 심각도 하 항목은 묶어서 전달.
- **프레임 단위(4~6장)로 끊어** 가져오고 리포트는 플로우별 누적(전체 한 번에 금지).
- **마크다운 = SSOT**(정합성/QA/용어/리포트·심각도·근거가 전부 13-1~13-4에 존재), Notion =
  옵트인 부분집합 미러.

## 시안 소스 3분기 (리뷰 대상 = 1급 입력)

생성 스킬과 달리 13은 **시안 자체가 리뷰 대상=1급 입력**이고 기준 문서(10/12/06)가 대조 축이다.
수신자 시안 소스에 따라 (a)/(b) 중 하나가 1급이며, 출력 품질은 시안 소스에 비종속이다.

- **(a) Figma 링크 = 진짜 디자이너 시안 리뷰의 1급(주) 경로.** figma read MCP를 **직접 호출**
  한다(선행 스킬 불필요 — `use_figma` MANDATORY 게이트는 write 전용이라 비해당). 순서:
  `whoami`(인증 확인 1회) → `get_metadata`(프레임 목록) → `get_design_context`(구조·텍스트) →
  `get_screenshot`(레이아웃) → `get_variable_defs`(토큰 보조·선택). **nodeId 필수**
  (`^\d+[:-]\d+$`, URL의 `-`를 `:`로 변환, 빈값·추측 금지). node-id 없는 파일 링크면
  `get_metadata`를 nodeId 생략 호출 → top-level 페이지 목록 → 게이트1에서 리뷰 프레임 nodeId 확정.
- **(b) 로컬 HTML(09 와이어/11 프로토타입) = HTML 파이프라인 팀의 1급(대등) 경로.** HTML 파싱으로
  텍스트·구조 추출. 11 prototype의 09 추출 절차 계승(`.phone` 프레임 / `.cap`의 `S\d+` / 텍스트
  토큰) — 단 이는 11이 09 산출물에 대해 **가정한** 패턴이지 09 SKILL 계약이 아니므로, 클래스
  미존재 시 `09-1_화면목록.md`를 1차 인덱스로 fallback.
- **(c) 둘 다 없음 = 리뷰 대상 부재 → 중단.**

## 입력

- **필수**: 시안(Figma 링크 또는 09/11 HTML) + 기준 문서 `<루트>/10_화면설계서/화면설계서/*.md`
  **+ `<루트>/10_화면설계서/10-예외처리_점검.md`**(둘 중 한쪽만 읽어 누락 금지).
  <!-- 변경 포인트(입력 경로): 본인 설치본은 <루트>=리서치/<주제-슬러그>. 10이 다른 폴더면 수정 -->
- **권장**: `12_기능명세`(인라인 검증 UI·용어) / `06`(문구·정책 용어).
- 시안 또는 10 없으면 **중단**.

## 다층 충돌 (기준 문서 미정 처리 — 양방향)

권위 우선순위: **06 운영정책 확정본 > 10 디스크립션 > 06-3 placeholder.**
1. 기준이 `[확인 필요]`/⚠️미정 → 차이는 **"질문"**(불일치 아님).
2. **역방향 트랩**: 기준 10 디스크립션이 단언값(예 "3일·2회")이어도 그 항목이 06-3 ⚠️미정이거나
   10 미정 승계 섹션이 `[확인 필요]`로 강등했으면 **확정 베이스 금지** → "미정 항목·시안값
   확인(질문)". 확정 판정은 **06 운영정책 확정본으로 해소된 경우에만**.
3. **문구 출처 역할 분리**: UI 메시지·에러 문구 = **12 예외처리표 우선** / 도메인·정책 용어 =
   06 / 화면 요소명·디스크립션 = 10(라벨 확정 아님 주석). **"문구불일치" 판정은 12 확정 메시지가
   있는 항목에만**, 10 디스크립션만 있는 항목은 "문구 미확정→질문" 강등.

## 자기대조 가드

기준 문서가 시안을 소스로 삼아 작성됐다면(예: 10이 와이어 HTML을 "화면 이미지"로 인용) **그 쌍은
정합성 대조에서 제외**하고 12·06과만 대조한다(드리프트 0인 자기대조 함정 회피).
- **실행 절차**: 리뷰 대상 시안이 최종 가리키는 파일 경로(또는 Figma fileKey)를 확정 → 10 각
  화면의 "화면 이미지" 링크 경로/fileKey와 **문자열 비교** → **동일할 때만** 그 (10, 시안) 쌍을
  정합성 대조에서 제외. **와이어 스타일을 베이스로 했더라도 경로가 다르면 정상 대조**(별도 시안).

## 파이프라인

### Stage 0 — 입력·시안소스 판별·범위확정·도구 probe·degrade
- 기준 10(+10-예외처리) 필수(없으면 중단). 시안 소스 3분기 판별.
- **프레임 단위(4~6장) 범위** 확정.
- **[확인 필요] 수집**: 10-예외처리 "기획 결정 필요" 목록 + per-screen `[확인 필요]` + 12 `[확인 필요]` 전부.
- **ID 컨벤션 감지 1회**(`[A-Z]+-?\d+`): 화면ID = S-ID(09 발원·10 계승), 기능ID = 12 발번. 리터럴 가정 금지.
- **약관/결제/법적 고지 화면 식별 → `[사람 직접 검수 필요]` 플래그**. **식별 기준**: 위약금·
  환불금액·청약철회·자동갱신 고지·약관 동의·개인정보 처리방침 등 **법정/계약 효력 문구가 직접
  노출되는 화면**을 대상으로 하고, 단순 결제 금액·결제일 표시만 하는 화면은 제외. 06 매트릭스에
  `[법정기준 placeholder]`/`[법무 확인 필요]` 태그가 달린 케이스ID(RF-03 등)가 등장하는 화면은 자동 후보.
- Figma probe: 대상 fileKey를 `get_metadata` 1회로 접근 확인(**seat 추론 단정 금지**, read 가용은 호출 성공으로만 판별).

### 🚦 게이트1 — 리뷰 범위(프레임) + 시안 소스 확정
AskUserQuestion(AI 추천 1안). Figma면 리뷰 프레임 nodeId 확정.

### Stage 1 — 정합성 체크 → 13-1
- 시안 vs 10/12. 누락 / 추가(디자이너 의도 가능 → 분리) / 문구불일치(문구 그대로 인용 비교).
- **다층 충돌 양방향 적용**(미정 기준은 질문, 문구불일치는 12 확정 메시지 항목만). **자기대조 가드**.
- 의도적 변경 가능성은 질문 후보. 확신 없으면 "확인 필요". **약관/결제 화면은 자동 판정 금지**.

### Stage 2 — QA 체크리스트 + 상태 커버리지 → 13-2
- **상태화면 분모 = 10-예외처리_점검 화면별 5종**(로딩/빈/에러/권한/검증). 12-2 상태머신은
  "전용 화면이 명시된 상태"만 보조 매핑(상태≠화면 주석 강제). 12 6종은 인라인 검증 UI(에러
  문구) 존재 점검으로 분리.
- **중복 라벨 귀속 축 고정**(5종↔6종 라벨 겹침 방지): **권한 없음**은 전용 화면이면 10 5종
  "권한" 열로만 계상(6종에서 중복 계상 금지). 6종의 **빈값/형식**은 인라인 검증(에러 문구) 존재
  여부로만 점검하고 **화면 분모에 넣지 않는다**.
- 프레임 목록(get_metadata 또는 HTML) ↔ 매핑 ✅/❌/추정. ❌ = 디자인 요청 목록(근거 1줄).
- **커버리지 표 4열**: 09-1 전체 N / 10 작성 M / 13 리뷰 대상 / **10 미작성(차기) K + 사유**.
  차기 배치 화면을 그린 시안은 "추가"가 아니라 "상위(10) 미작성-차기"로 별도 표기.

### Stage 3 — 용어 통일 → 13-3 용어집
- 시안 텍스트 ↔ 10/12/06 용어(**출처 역할 분리**: 메시지=12, 정책 용어=06, 요소명=10).
- 불일치 표 + 권장안(근거: 사용 빈도·정책 정의 여부). **사용자 결정**(미확정 상태로 게이트2 회부).

### Stage 4 — 리뷰 리포트 초안 → 13-4
- **개요 헤더**(대상 Figma 링크/프레임·대조 기준 문서 목록+버전·리뷰 일자·범위[플로우명]).
- 수정요청 / 질문 / 제안 + 심각도(상/중/하) + 근거 인용 강제. **시각 품질 판단 금지**.
- 심각도 하 항목 묶음. **잘된 점은 placeholder만**(AI 자동 칭찬 금지). 외부 공유물에 "확정
  아님/내부 검토용" 배너.

### 🚦 게이트2 — 리포트 검토 + 수정요청/질문 재분류(의도적 변경) + 용어 결정
AskUserQuestion(AI 추천 1안). **Stage 4 뒤에 둔다** — 검수 대상(13-4 리포트 초안 + 13-3 용어
권장안)이 게이트 시점에 존재해야 한다. 통과 후 13-4 "확정"·13-3 용어집 확정. **해소 전 Notion 차단.**

### Stage 5 — (옵트인) Notion 공유

## 도구 정확성

- **Figma read MCP**(연결 시): `get_metadata`→`get_design_context`→`get_screenshot`→
  `get_variable_defs`를 **직접 호출**(선행 스킬 불필요, `use_figma` MANDATORY는 write 전용).
  **whoami는 복수 팀 반환**(read는 fileKey 기반이라 seat 무관 — view-only 단정 금지).
  `get_design_context`/`get_variable_defs`는 **concrete nodeId 필수**(추측 금지). write/시각화
  환류가 필요하면 해당 팀(편집 권한) 키로 **사용자 확인 후만**.
- **get_variable_defs = 보조·선택**(토큰 미준수 지적은 월권). 부재 시 산출물 손실 0.
- **Notion MCP**(연결 시) = 옵트인 외부발행·민감정보 더미. 마크다운 SSOT.
- get_design_context 텍스트 추출 한계(이미지/외부 컴포넌트) → 약관/결제/법적 고지는 get_screenshot+사람.

## degrade vs 중단 vs 게이트 블로킹

- **degrade**: Figma 미인증→HTML(또는 사람-개입: get_screenshot 단발/디자이너 수기 제공, 그조차
  불가하면 중단) / 12 부재→13-2 상태커버리지 분모 무효(10 기준 프레임 존재 점검까지 축소+⚠️) /
  06 부재→13-3 권장안 근거 빈도만(정책 근거 ⚠️비움)+13-1 문구불일치 10 대조까지 축소 / Notion
  미사용→마크다운 SSOT / get_metadata 부재→13-2 "프레임 존재" 열 "추정" 강등.

## 주의

- **대조 결과는 후보지 판정 아님** — 의도적 변경은 질문으로 옮긴 뒤 전달.
- **시각 품질·디자인 토큰은 기획자 영역 아님**(월권 금지, get_variable_defs 보조만).
- **약관/결제/법적 고지** — 자동 문구 대조 금지, screenshot + 사람 직접.
- **리포트 전달이 관계를 좌우한다** — 하 항목 묶음, 잘된 점은 기획자가 직접. 리포트는 도구, 합의는 사람.
- **민감정보** — Notion 발행·외부 공유 전 더미 치환.
- 화면ID·기능ID는 **참조 키** — 함부로 바꾸지 마라. 확정 용어집은 14/15 기준 문서.
