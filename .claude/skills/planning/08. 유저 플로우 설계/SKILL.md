# 유저 플로우 설계 (User Flow Design)

07 정보구조(IA) + 03 요구사항(유저스토리·AC) + 06 정책을 받아 **핵심 과업별 유저 플로우 1부**
(시나리오 + 해피패스 차트 + 예외 전수표 + 최종 차트)를 만든다. 사람 개입 게이트는
**핵심 과업 확정 1곳 + 예외 케이스 채택 선별 1곳, 총 2곳**이다.

**AI의 역할**: **시나리오 작도·예외 카테고리 순회까지. 정책 동작 확정·예외 취사선택은 사람.** 예외의 "시스템 동작"을 AI가 그럴듯하게 채우지만 그건 일반론이지 우리 정책이 아니다.

**핵심 원칙**:
- **텍스트(mermaid) = 원본(source of truth), FigJam = 파생.** 수정은 텍스트 한 줄, 공유본은 원본에서 재생성.
- **해피패스/예외 분리.** 한 차트에 다 넣으면 스파게티 — 차트엔 빈도·중요도 높은 분기만, 나머지는 표.
- **예외 도출 = 발상이 아니라 순회.** 카테고리 × 노드 곱집합. 목적은 정답이 아니라 **"검토 후 의도적 제외" 가능한 후보 목록**.
- **AI는 정책을 지어낸다.** `[정책확정:06-케이스ID]`(매핑)·`[정책미정→06 환류]`(06 ⚠️·placeholder 승계)·`[값 환류:케이스ID]`(케이스 존재·값만 미정)를 구분해 환각을 표면화.
- **노드 = 07 화면명/ID 계승.** 같은 화면이 IA·플로우에서 다른 이름으로 갈라지면 안 된다(라벨 드리프트 금지).
- **플로우는 IA와 함께 움직인다.** 플로우에서 발견한 IA에 없는 화면은 07 역반영 백로그.

## 파이프라인

### Stage 0 — 입력 확인 & ID 계승
07(필수)·03/06(권장)·04(선택)을 읽는다. 07 없으면 위치 묻고 중단.
- **ID 컨벤션 계승**: 07/03이 쓰는 화면·요구 ID 컨벤션을 감지해 그대로 쓴다(리터럴 하드코딩 금지).
- **degrade**: 03 없으면 시나리오를 **'과업 골격만(AC 미반영)'**으로 만들고 전 노드에 경고 배너 / 06 없으면 예외표 시스템동작 **전 행을 '정책 필요' 강제**.

### Stage 1 — 핵심 과업 도출
07 IA + 03 유저스토리에서 과업 단위(회원가입·온보딩·첫 구매·해지 등)와 시작/종착점, 우선순위를 **AI 추천 1안**으로 뽑는다.

### 🚦 게이트1 — 핵심 과업 확정 + 07 ⚠️ 화면 처리 (사람 개입, 필수)
AskUserQuestion으로 ① 과업 목록·우선순위·시작/종착을 택1·수정 + ② **07의 `⚠️정책파생`·미배치·Won't·정책-스코프 불일치 화면을 플로우 노드 후보로 별도 표기 → 채택/보류/제외 결정**(채택 시 ⚠️ 플래그 그대로 승계). **확정 전에는 Stage 2로 넘어가지 않는다.**

### Stage 2 — 시나리오(산문) + AC 추적표
**시나리오 산문을 먼저** 쓴다(글이 정확해야 차트가 정확). 03 AC·06 정책 참조.
- **AC 추적표**: 각 과업의 03 AC를 행으로 펼쳐 — **조건/긍정절 = 해피패스 단계, 부정/예외절 = Stage 4 예외 후보**로 1:1 매핑한다. **AC가 어디에도 안 걸리면 경고**(분기형 AC가 산문에 묻혀 빠지는 것 방지).
- **탈락·보류 과업 AC 보존**: 추적 단위는 채택 과업이 아니라 **03 전체 AC**. 게이트1에서 탈락·보류된 과업의 AC는 추적표 말미 "미커버 과업 AC" 섹션에 모아 각 AC를 (a)타 채택 과업이 흡수 / (b)후속 단계 이월 중 하나로 표기한다(증발 방지 — 게이트2의 "제외 보존"과 대칭).
- → `08-1_핵심과업_시나리오.md`

### Stage 3 — 해피패스 mermaid
`flowchart TD`로 해피패스만 그린다.
- 화면 = 사각형, 판단 분기 = 마름모 `{}`, **시스템 자동 동작 = `id["[시스템] ..."]`**(`[시스템]`은 대괄호 충돌이라 **항상 따옴표**), 시작 = 진입 노드, **종료 노드 ID/라벨은 `done`·`exit`**(`end`는 mermaid 예약어라 회피). 라벨 한국어·ID 영문.
- **노드 = 07 트리의 화면명·ID 그대로**(mermaid 노드 ID = 07 화면 ID라야 Stage 6 정합 성립). 플로우에서 새 화면이 필요하면 `⚠️IA없음` 태그 + 07 역반영 백로그.

### Stage 4 — 예외·이탈 전수 도출
카테고리 체크리스트 **①입력 오류 ②인증/권한 ③네트워크/시스템 ④정책 분기 ⑤사용자 이탈 ⑥상대방 행동 ⑦동시성** × 노드 곱집합으로 순회한다.

<!-- 변경 포인트: 예외 카테고리. 도메인에 맞게 교체하세요. 예) B2B 콘솔이면 ⑥상대방 행동 → '권한 위임·승인 대기', 오프라인 앱이면 '디바이스 오프라인' 추가 등 -->

- **곱집합 폭발 사전 제어**: ① 노드유형 × 카테고리 **적용성 매트릭스**로 N/A 셀 먼저 제거(표시전용 화면엔 입력오류 N/A, 입력 없는 노드엔 동시성 N/A 등) → ② **과업별 표로 분할, 한 표 20~30행 상한** → ③ 30행 초과 시 카테고리 우선순위로 상위만 전수, 나머지는 "샘플 점검"으로 로그.
  - **카테고리 행 전체 제거는 신중히**: 셀 단위 N/A는 자유지만, 한 카테고리(예: ⑥상대방행동)를 **통째 제거**할 땐 "상대역/트리거가 구조적으로 부재"함을 **1줄 근거로 머리말에 명시**하라. 삭제 전 도메인 교체(B2B '권한 위임·승인 대기' 등)를 먼저 검토하고, 상대역(결제사·배송기사·CS·가족공유 등)이 실재하면 삭제 금지 — '범위 밖'이면 삭제가 아니라 표 유지로.
- 표 컬럼: `발생 노드 | 케이스 | 시스템 동작 | 사용자에게 보이는 것 | 복귀 경로 | 출처(06 케이스ID)`.
- **플래그 3종 분리**: `[정책확정:06-케이스ID]`(06 정의분을 우선 적용) / `[정책미정→06 환류:케이스ID/태그]`(06의 ⚠️미정·`[법정기준 placeholder]`·`[법무 확인 필요]`를 그대로 승계 — AI가 단정 금지) / `[값 환류:케이스ID]`(06에 케이스는 있고 placeholder 값만 미정 — 흐름은 적되 값은 미확정 표기).
- 머리말에 **전수/채택/제외/정책필요 카운트** 기록. → `08-2_예외케이스표.md`

### 🚦 게이트2 — 예외 케이스 채택 선별 (사람 개입, 필수)
AskUserQuestion으로 빈도·비즈니스 영향도 기준 **채택(차트) / 표 유지 / 정책필요 백로그**를 선별한다. **제외한 결과("검토 후 제외" 목록)도 보존**한다(같은 논의 반복 방지). **확정 전에는 Stage 5로 넘어가지 않는다.**

### Stage 5 — 최종 플로우차트 + (선택) 공유본
채택 예외를 차트에 반영한다.
- 예외 분기 = 점선 `-..->`, 이탈 종료 노드 = 빨강 `classDef`.
- **분리 임계**: 노드(사각형+마름모+시스템) **합계 ≥ 25 또는 분기 마름모 ≥ 6**이면 과업/서브플로우로 분리(스파게티 방지).
- 노드는 **화면 단위까지만 — 화면 내부 인터랙션은 그리지 않는다(→10 화면설계서)**.
- **placeholder 비전파**: `[정책미정→06 환류]`·`[법정기준 placeholder]` 같은 미확정 값은 **차트 노드 라벨로 굳히지 말고** 표·주석으로 둔다(미정이 확정처럼 차트에 박히는 것 방지).
- + 차트 외 예외 처리 표 → `08-3_플로우차트.md`

**mermaid 원본 작성규칙**(로컬 렌더): 따옴표는 선택(단 `[시스템]`·특수문자 라벨은 필수), 이모지 렌더 OK, 줄바꿈 `<br/>`, 분기 마름모·엣지라벨(`-- 예 -->`)·subgraph 기본 렌더.

(선택) **FigJam 공유본** — 게이트2 통과 후 **리뷰·공유가 필요할 때만, 사용자 확인 후** 생성:
- `figma-generate-diagram` 스킬 있으면 선행 로드, 없으면 MCP instructions 폴백 → `whoami`로 **쓰기 가능한 Dev/edit 팀** 확인 → 회사/공유 워크스페이스 쓰기 사용자 확인 후 → 미인증/실패 시 스킵.
- **generate_diagram 내보내기 전처리**(원본엔 적용 금지): **이모지 제거·`\n` 금지·노드 텍스트 따옴표·classNames에 'end' 금지·classDef 빨강은 이탈종료 1종에만**(sparingly). flowchart(분기·점선·클래스) 지원됨.
- 고지: "초안 품질 5~10분 수동 정리 / **사후 개별 편집 불가** / FigJam 수정분은 08-3 mermaid에 **수동 역반영**(자동 반영 안 됨)."

### Stage 6 — 정합성 점검 + 마무리
플로우 ↔ IA 정합(플로우에서 발견된 IA에 없는 화면 = 07 역반영 백로그) + 플로우 ↔ 정책 환류(정책 필요 항목 = 06 백로그)를 점검한다.
- **환류 write-back(표기로 끝내지 마라)**: IA 역반영(`⚠️IA없음` 화면)·정책 필요 항목을 **사용자 확인 후 실제로** 07-1 IA트리의 '미배치/역반영' 섹션과 06의 '⚠️미정' 섹션에 append한다(스킬이 직접 write). 사용자가 거부하면 백로그 표기로 degrade. **편집은 입력 산출물 폴더 내 해당 파일에 한정**(다른 폴더 금지).
- `_검증체크리스트.md`를 작성하고, **미해결(정책필요 잔존·IA 역반영 미해소)이 있으면 ⚠️ 표기 + 사용자 확인 없이 '완료' 보고 금지**(09/10 진입 전제).

`_검증체크리스트.md` 템플릿(`<주제>`/`<날짜>` 치환):

```markdown
# 검증 체크리스트 — <주제> 유저 플로우 (작성일: <날짜>)

> AI가 채운 "시스템 동작"은 일반론이지 우리 정책이 아니다. 06과 대조해 확정하라.

- [ ] 정책 필요 — `[정책미정→06 환류]` 항목을 06 정책 정의로 보냈는가 (08-2, 백로그)
- [ ] 정책 매핑 — `[정책확정:06-케이스ID]`가 06 실제 동작과 일치하는가
- [ ] AC 커버리지 — 03 **전체** AC가 (채택 과업) 해피/예외 또는 (탈락 과업) 이월로 표기됐는가 (08-1, 미커버 과업 AC 섹션 포함)
- [ ] 예외 채택 — 빈도·영향도로 걸렀는가 / "검토 후 제외" 목록을 남겼는가 (08-2)
- [ ] 노드 = IA — 플로우 노드가 07 화면명/ID와 일치하는가 (라벨 드리프트)
```

## 주의
- **AI는 정책을 지어낸다.** "시스템 동작"은 일반론 — 06과 대조하고 단정 불가는 `[정책미정→06 환류]`로 표면화. 이 항목이 06으로 보낼 백로그다.
- **예외 후보를 전부 채택하지 마라.** 발생 확률 극히 낮은 케이스까지 망라된다 — 빈도·영향도로 거르고, 거른 결과도 남겨라.
- **Mermaid 표현 한계**: 노드 40~50 넘으면 렌더가 깨진다 — 과업 단위 분리, 화면 내부 세부 인터랙션은 10단계.
- **FigJam 생성물은 검수 필요**: 라벨 누락·화살표 방향·레이아웃 겹침 빈번. 원본은 mermaid, FigJam은 공유 스냅샷.
- **플로우는 IA와 함께 움직인다.** 없던 화면 발견 시 07에 즉시 역반영(안 하면 두 문서가 어긋난다).
- **노드는 화면 단위까지만** — 화면 내부 인터랙션은 이 단계가 아니라 10단계(화면설계서).
