# 배포·오픈 (Launch Package)

배포·오픈은 QA 통과 제품을 사용자에게 내놓으며 흩어진 비개발 업무(법무·CS·마케팅·운영)를 총괄하는
단계다. 산출물 = **런칭 패키지**: ① 출시 체크리스트(4관점) ② 릴리즈노트·공지·스토어 문구 ③ CS
FAQ·매크로 ④ 롤백 기준. **모두 12 기능명세·06 정책에서 파생(채널별 변환)** 하며, **AI는 초안·누락
방지·포맷팅, 의사결정(완료 확인·롤백 합의·법무 검토)은 사람.**

## 핵심 원칙

- **파생 = 변환(창작 금지)**: 모든 런칭 문구는 12 명세·06 정책에 **1:1 근거**. 명세에 없는 기능·임의
  숫자(버전/출시일/가격) 금지(환각).
- **출시 범위 = 12 기능 집합(release scope)**: 12가 명세한 기능만 출시 대상. **06엔 있으나 12 범위
  밖인 정책은 공지/FAQ/스토어에 쓰지 마라**(원본 1순위 환각 "없는 기능 공지"). 범위 밖 06 항목은
  "차기 출시(범위 외)"로 분리 보관(생성 금지). 범위 baseline은 게이트1에서 고정.
- **출시 메타(버전/출시일/가격)는 외부 입력**: 12/06에 없음 → 게이트1에서 사용자 제공, **미입력 시
  `{{버전}}`/`{{출시일}}` placeholder**(임의 생성 금지). 단일 SSOT로 4채널 문서에 전파·교차 점검
  (자주 틀림). 가격은 05에 근거 있으면 참조값 제시(불일치 시 ⚠️). **단 05 가격이 예시/추정/권고
  출발점으로 표기됐으면 `{{가격}}` 또는 ⚠️추정 병기**(확정 단정 금지 — 메타 헤더에도 적용).
- **(family 16판) 런칭 문구는 12/06 "확정분"만 단정**: 미정은 단정 금지 → **"정책 미정 — 기획 확인
  필요"로 분리**.
  - **reverse-trap(3갈래)**: ① **06 조항ID가 있어도 값/예외가 `[법정기준 placeholder]`·`[법무 확인
    필요]`면 단정 금지**(부분확정 — 한 조항에 확정 절+미정 절 공존 가능, 확정 절만 단정·미정 절은 같은
    답변에서 분리. **역방향도 위반 — 확정 절을 미정으로 뭉뚱그리는 과소단정 금지**, 확정 절은 확정으로
    명시). ② **상위(14-1/15-2) 추천안을 FAQ 확정답으로 격상 금지**(추천 ≠ 확정). ③ **`[법무
    검토 전 초안]`·`[조문 미확인]` 약관을 공지/스토어에 단정 금지**.
  - **확정 화이트리스트** = 06 운영정책에서 마커(⚠️/🔴/`[법정기준 placeholder]`/`[법무 확인 필요]`)
    **없는** 확정 조항만. 그 외는 정책 미정.
- **`[법정기준 placeholder]` vs `[법무 확인 필요]` 분기**: placeholder = `{{법정기준:항목}}`로 문안
  골격 생성 가능(SSOT 전파). **법무 확인 = 문안 생성 금지·검토 의뢰 목록(🔴)**. **둘 다 붙은 조항은
  법무 확인 우선**(더 보수적). **같은 케이스ID가 섹션(운영정책/약관)마다 마커가 다르면 더 보수적 마커
  채택**(법무 확인 우선).
- **법무 항목 = "검토 의뢰 목록"(결과 아님)**: 체크리스트 법무 섹션·🔴 개인정보·약관 고지는 사람(법무)
  확정. AI는 항목 도출만.
- **롤백 임계값 = `[[임계값:합의]]`(개발·인프라 합의)**: 임의 수치 금지. 결정트리 뼈대 + "합의 필요"
  체크리스트. 임계값·실행 절차는 개발·인프라 소관.
- **표기 범례**(혼동 방지): 출시 메타 `{{버전}}`(사용자 입력·게이트1) / 롤백 임계값 `[[임계값:합의]]`
  (개발 합의·게이트2) / 06 정책 미정은 원천 마커(`[법정기준 placeholder]`/`[법무 확인 필요]`/⚠️/🔴)
  **그대로 보존**.
- **스토어 가이드라인은 변함**: 글자수·금지 표현 정적 기본 + **"제출 직전 콘솔·최신 가이드라인 재확인"
  경고**. (옵트인) deep-research로 최신 확인.
- **체크리스트는 살아있는 문서**: D-7/D-3/D-1 리뷰 미팅 안내(발행 후 방치 금지).

## 파이프라인

### Stage 0 — 입력확인·출시메타·범위 baseline·도구 probe·degrade
- 12·06 필수(둘 다 없으면 중단). **출시 범위 baseline = 12 기능 집합**(06엔 있으나 12 밖 = 범위 외).
  15-2/14-1 존재 감지(정책미정 dedup). 05 존재 감지(가격 교차).
- **확정 baseline**(dedup 비활성 대비): 정책 미정 분리는 **06 마커**(⚠️/🔴/`[법정기준 placeholder]`/
  `[법무 확인 필요]`/`[법무 검토 전 초안]`)로 **결정적 판정**. 15-2/14-1은 해결상태 전파를 더할 뿐,
  분리의 필수 입력 아님.
- **도구 probe(종류별 분리)**: MCP(Notion·NotebookLM) = **no-op 호출 성공으로 가용 판별**(ToolSearch
  존재 ≠ 가용). NotebookLM 2서버는 1개 선택 또는 폴백(세션 grounding=`notebooklm.ask_question` / 대형
  소스=`notebooklm-mcp.notebook_query`). 스킬(deep-research) = **번들 가정(항상 존재)**, **실행 여부만
  옵트인**(연결 실패 개념 없음).

### 🚦 게이트1 — 출시 메타 + 범위 baseline + 채널 글자수 (Stage 0 검수 대상만)
AskUserQuestion(AI 추천 1안). **출시 메타(버전/출시일/가격) SSOT** + **출시 범위 = 12 기능 집합 확정**
(06 범위 외 제외) + 채널 글자수 제한. **검수 대상은 메타/체계/범위뿐** — 4관점 항목·D-day 구체 기한은
Stage 1 생성 후 게이트2(검수 대상이 게이트 시점에 존재해야 한다는 원칙).

### Stage 1 — 출시 체크리스트 → 16-1
- 4관점(법무/CS/마케팅/운영) 각 섹션. [ ]+담당 부서+기한(D-7/D-3/D-1/D-Day) 표. **신규 기능에서 파생
  되는 항목 도출**.
- **관점별 시드(라벨만 아닌 내용)**: 운영=모니터링 대시보드·장애 비상 연락망·점진 배포 비율 / 법무=
  개인정보 수집 변경·약관 개정 고지(🔴 검토 의뢰) / CS·마케팅 최소 1~2개. **법무 항목 = 검토 의뢰
  목록(결과 아님)**.

### Stage 2 — 릴리즈노트·공지·스토어 문구 → 16-2
- **출처 2층**: 범위·기능 = 12 / 정책값 = 06. 교차 항목은 출처 병기.
- 사내 릴리즈노트(변경 + 영향 화면 + **알려진 제한사항** = 14-1/15-2 미해결분 연결, 개조식) / 사용자
  공지(친근한 존댓말·이모지 없이·혜택 중심 300자) / 스토어(App 프로모션텍스트 170자, Play 변경사항
  500자, **각 2안 + 글자수 옆 표기**).
- **SSOT 숫자 전파**(버전/출시일/가격) + **환각 0**(12 범위 밖 기능·임의 숫자 금지). 미정 정책은 단정 금지.

### Stage 3 — CS FAQ·매크로 → 16-3
- **FAQ = "12 범위 내 기능 × 06 조항근거" 동시 충족 시에만 생성**. 각 답변에 **06 조항번호 병기**.
  신규 기능 + 기존 변경. **개수(예: 15)는 목표치, 리터럴 강제 아님** — 근거 없으면 채우기 금지·게이트2
  "범위 확인 필요" 회부.
  - **기존 변경 FAQ도 12 출시 범위 교차 통과 필수**: 06 조항이 있어도 **12 미명세 조항(차기 출시
    케이스ID)은 FAQ 제외** — "이번 출시에 변경됐다"는 06 정책변경/03 범위변경 근거가 있을 때만 등재.
    근거 없으면 "기존 변경 없음" 또는 "차기 출시(범위 외) 보류"로(개수 채우려 범위 밖 조항 끌어오기 금지).
- **정책 미정 분리(dedup·단일출처)**: 15-2 있으면 **15-2를 1차 풀로 전건 등재**(FAQ 영향 여부 무관 —
  FAQ 영향 없는 동시성/정산 미정도 등재하되 **처리 채널 컬럼**으로 FAQ vs 롤백(16-4)/합의 구분) +
  15-2가 명시 제외한 14-1 항목만 보강. 15-2 없으면 14-1 1차. 둘 다 없으면 06 마커로 직접 분리.
  **추천안 확정 격상 금지.** python3 자기검산: **15-2는 14-1을 흡수한 상위집합** →
  `distinct = 15-2 전건 + 14-1 제외분`(단순 ∪ 합 아님), **FAQ 노출 부분집합 ≠ 정책미정 풀**(분리 보고).
- (옵트인) NotebookLM grounding은 **조항 위치 찾기 보조**(반환 조항을 06 확정/미정 마커와 in-context
  대조, **미정 마커 인용은 정책 미정으로**).
- **매크로**: 핵심 운영정책 행위별 + **장애 문의 매크로 필수**(도메인 무관 상수). 인사-답변-안내-맺음.

### Stage 4 — 롤백 기준 → 16-4
- 심각도 3단계(즉시 롤백 / 1시간 내 판단 / 모니터링 지속) 결정트리. **트리거 지표 카테고리 시드**
