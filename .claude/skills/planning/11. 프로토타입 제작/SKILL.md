# 프로토타입 제작 (Interactive Prototype)

화면설계서가 "어떻게 생겼는지"라면 프로토타입은 **"어떻게 동작하는지"**다. 정적 화면을
클릭 가능하게 연결해, 이해관계자가 만져보고 사용자가 실제 과업을 수행해볼 수 있는
**검증용** 산출물을 만든다. 목적은 완성도 높은 제품이 아니라 **개발 착수 전에
플로우·인터랙션·정책의 허점을 싸게 찾아내는 것**이다.

산출물은 둘이다. ① **클릭 가능한 인터랙티브 프로토타입**, ② 그것으로 진행할
**사용성 테스트 시나리오·과업 목록**. 후자까지 있어야 "보여주기용"이 아니라 "검증용"이 된다.

## 핵심 원칙 (어기면 프로토타입이 해를 끼친다)

- **프로토타입은 throwaway다.** 검증된 플로우·발견된 문제만 [[12. 기능명세서 작성]]으로
  가져가고 **코드는 버린다**. AI가 만든 HTML/JS는 접근성·보안·성능·아키텍처가 검증 안 됨.
  "이 코드 그대로 쓰면 되죠?"는 금지. 12 진입 전제는 검증된 요구사항이지 코드가 아니다.
- **11의 차별점은 시각 충실도가 아니라 인터랙션/상태연동/검증로직이다.** 09 grayscale
  베이스 위에 JS 핸들러만 얹는다. **고충실도의 함정** — 너무 그럴싸하면 참가자가 비판을
  아끼고 내부 일정 기대치가 부푼다. 검증에 필요한 만큼만 충실도를 올린다.
- **09 글리프 금칙 계승**: 프로토타입 HTML에 **이모지·아이콘폰트·픽토그램·유채색·이미지
  금지**(grayscale 유지). 글리프가 들어가면 검증용 저충실도가 깨진다 — 09가 코드로 박은
  규칙이다. (Stage 2에서 grep로 자동 점검.)
- **정책 수치는 절대 09 HTML에서 읽지 않는다.** 09는 시각 레이아웃 베이스로만 쓴다.
  동작·정책의 권위 소스는 10 디스크립션·예외처리표와 06이다.
- **미정값은 동작으로 굳히지 않는다.** 프로토타입은 "동작"이라 미정값이 확정처럼
  구현되기 매우 쉽다. 미정은 placeholder + 주석으로 노출한다(확정 구현 금지).
- **AI는 정책/엣지케이스를 임의로 메운다.** 프롬프트에 없는 부분(결제 실패 등)을
  그럴듯하게 지어내므로 06과 대조해 임의구현을 색출한다. 정책 없는 분기는 임의 동작 금지.
- **테스트 과업 문장은 비유도형으로.** "구독 버튼을 누르세요/찾으세요" 같은 답을 알려주는
  문장은 테스트를 무의미하게 만든다. 사람이 최종 검수한다.
- **실사용자 데이터 금지.** 더미만. 외부도구 프롬프트는 생성 즉시 마스킹한다.

## 다층 입력 충돌 우선순위 (값의 표면형식이 아니라 "확정 상태"로 판정)

상위 산출물이 서로 다른 값을 말할 때:
1. **10의 "미정 승계(06-3 ⚠️ 교차)" 섹션·예외처리표 출처열 = 단일 권위 소스.** 같은
   화면ID의 09 프레임 텍스트가 아무리 구체적이어도, 10이 `[확인 필요]`/미정으로 표기한
   항목은 프로토타입에서 **무조건 placeholder + 주석으로 강등**한다.
2. **운영정책 확정 > 06-3 미해소 미정(값 미정·A/B 옵션 분기 미정 포함).** 06-3가
   ⚠️미정이어도 `06-운영정책_약관초안`·10 디스크립션·09가 일관되게 확정 동작을 말하면
   확정으로 본다. A/B 옵션이 운영정책으로 택1됐으면 그 택1이 확정이다. **단 10의 미정
   승계가 `[확인 필요]`로 유지한 항목은 예외(강등 유지).**
3. **정책 수치의 권위는 10/06이다 — 09에서 읽지 않는다.** 09 in-frame 텍스트가 확정
   수치를 단언하든 방식만 라벨하든 신뢰하지 마라(09는 시각 베이스).

**회귀 예시(self-check)** — 도메인 예시이니 본인 산출물의 케이스ID로 치환:
- ① 09가 `[정책확정:RF-04] 3일·2회`처럼 **확정 단언** → 06-3 미정·10 [확인 필요]이면 **placeholder 강등**.
- ② 09가 `법정 기준 적용 [값 환류:RF-03]`처럼 **방식만 라벨하고 값은 이미 placeholder** →
  그대로 **placeholder 계승**(09를 '단언'으로 오해 말 것 — 09도 미정 표기).
- ③ **대조** 06-3는 미정이나 운영정책이 확정한 케이스(예: SB-03) → **확정 구현**.
- ④ **옵션 분기 해소** 06-3가 `A/B 미정`이나 운영정책이 한쪽으로 택1한 케이스(예: RF-01) → **확정 구현**.
  (운영정책이 '기본값' 표기일 뿐인 케이스는 미정 유지 — 둘을 구분.)

## 08-2 플래그 3종 처리 (하나도 빠뜨리지 마라)

- `[정책확정:케이스ID]` → 동작 구현.
- `[정책미정→06환류]` → 해당 분기를 placeholder + 주석으로 **비활성**(임의 동작 금지).
- `[값 환류:케이스ID]` → 흐름·UI는 구현하되 **미정 값 위치에만 placeholder**
  (예: `₩— (위약금율 06 미정)`) + 테스트 과업에 "값 미정 상태 사용자 이해" 관찰포인트 승계.
- self-check: "flag 3종 모두 프로토타입 + 과업에 추적됐는가".

## 미정값 라벨 사전 (전 stage 동일)

- `[정책미정]` = 06 근거 부재(분기 비활성)
- `[확인 필요]` = 10 기재 모호(10 원문 질문 그대로 보존)
- `[값 미정]` = 케이스는 확정, 값만 미정(placeholder 값)
- 해소: 게이트에서 `[정책미정]` → `[정책가정@게이트]`(사용자 명시 승인) 또는 범위 제외.
- 10 `[확인 필요]`는 인라인 질문형일 수 있다(`[확인 필요: 내역 화면 존재?]`/`[N값]`/`[분기]`).
  유형별로: **값미정→placeholder값** / **요소·화면 존재미정→해당 네비·화면 미생성+주석**
  (over-implementation 방지) / **분기미정→분기 비활성**.

## 09 단일 HTML 프레임 추출 절차

- 프레임 경계 = `.phone` 단위. 화면ID = `.cap` 텍스트의 `S\d+` 패턴(주석 보조).
  상태 접미사 `(error)/(empty)/(모달)`을 파싱해 상태 변형을 분리한다.
- 09는 화면당 일부 상태만 렌더할 수 있다(예: 한 화면은 error만, 다른 화면은 normal+empty).
  **09에 없는 정상/추가 상태는 09-1 화면목록 상태변형 열 + 10 예외처리표로 보강 생성**한다.
- 09 텍스트 토큰(`[배송]`/`[skip]`/`[pause]` 등)은 하드코딩하지 말고 "대괄호 = 09 작성자
  의미 라벨, 화면별 동작 단서"로 일반화한다. **토큰 → 인터랙션 매핑의 권위는 10 인터랙션 섹션**.
- 09 마크업이 위 구조와 다르면(다른 클래스/마커) 09-1_화면목록.md를 1차 인덱스로,
  HTML은 시각 참고로만 degrade.

## 파이프라인

### Stage 0 — 입력확인 & 검증범위 선정 & 입력소스 판별 & 도구 probe & degrade
- 10 필수 확인(없으면 중단). 06 입력은 `06-3 매트릭스 + 06-운영정책_약관초안` 쌍으로.
- **검증범위 = 핵심 플로우 1~2개만** 선정(전 화면 금지). 08-2 예외 밀집 + 정책미정 플래그
  밀집 구간(=리스크 높은 곳) 우선. 08 없으면 ⚠️리스크근거 미연결로 degrade.
- 입력 소스 3분기 판별(a/b/c).
- **도구 probe**: Playwright MCP(도구 목록 존재 여부) / Figma MCP(read vs write 구분) /
  frontend-design(옵트인). 결과를 게이트1 도구경로에 노출.
- degrade 플래그: 08 없으면 ⚠️리스크근거 미연결 / 06 없으면 ⚠️정책 미대조 / 09 없으면 시각베이스 자체생성.
- 화면ID = **10 S-ID 계승**(프로토타입 화면·11-2 문제목록·11-1 과업/매핑표 모두 단일 키).
  09에만 있고 10에 없는 화면은 `[확인 필요]`로 표기.

### 🚦 게이트1 — 검증범위(플로우) + 도구경로 확정
AskUserQuestion(AI 추천 1안: 08 최고 리스크 플로우 + **직접 HTML 생성**). 다음은 명시 선택 시만:
- **frontend-design 옵트인** — 사용자가 하이파이를 명시적으로 요구할 때만. throwaway·확정
  아님·고충실도 함정 경고를 동반(13 전 단계). 기본은 직접 HTML.
- **외부도구 프롬프트**(v0/Stitch/Figma Make) — 옵션. dead-end(유료 시트)·외부 웹 통제
  밖·민감정보 경고 병기.
- **Figma write 도구**(use_figma 등) — 기본 금지(회사 파일 오염·민감정보). 정 필요하면
  사용자 명시 동의 + 더미 확인 후만.

### Stage 1 — 인터랙티브 프로토타입 생성

## 도구 정확성

- **frontend-design = 하이파이/BOLD** → 09가 코드로 위임 금지. **11 기본은 직접 HTML Write**,
  frontend-design은 명시 옵트인만(경고 동반).
- **Playwright MCP = 미연결 가능성 높음** → 정적 점검이 기본, 자동순회는 연결 시 보너스.
  **도구 0개로도 산출물 0개 손실 없이 완성.**
- **v0.dev / Stitch / Figma Make = 외부 서비스(MCP 아님)** → 붙여넣기 프롬프트만, 자동
  업로드 금지, 생성 즉시 마스킹, 유료 dead-end 경고.
- **Figma Make = 유료 Full seat 필요** → 기본 경로 아님. **Figma MCP write 도구
  (use_figma/create_new_file/upload_assets)는 회사 파일 오염·민감정보 → 기본 금지.**
  Figma **read**(get_screenshot/get_design_context)는 10이 Figma 링크일 때만 허용.
- Stitch는 "시각 베이스(09)도 Figma 자산도 전혀 없을 때"의 degrade
  (프롬프트 출력 → Copy to Figma → Make 연결).

## degrade vs 중단 vs 게이트 블로킹

- **중단**: 10 부재(입력물) / 10·08·06 동시 부재.
- **degrade**: Figma 미인증→마크다운 / 09 HTML 없음→09-1 인덱스+마크다운 / Playwright
  없음→정적 점검 / 06·08·07 개별 부재→⚠️플래그 / 환류 대상 부재→백로그.
- **게이트 블로킹**: 해소 가능한 미정값. 06 자체가 degrade로 없으면 게이트2에서 사용자
  명시 승인 시 `[정책가정]`으로 차단 해제, 미승인 시 해당 과업만 범위 제외.

  요구사항이다.
