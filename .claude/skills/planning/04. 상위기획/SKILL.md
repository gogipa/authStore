# 상위기획 (High-Level Planning)

01~03 산출물(시장·사용자·요구사항)을 받아 **하나의 서비스 컨셉**으로 수렴한다. 산출물의 핵심은
분량이 아니라 합의 — 팀이 같은 그림을 보는 **한 장짜리 원페이저**다. 사람 개입 게이트는
**평가 기준 확정 1곳 + 컨셉 확정 1곳, 총 2곳**이다.

**AI의 역할**: 결정이 아니라 **발산의 폭을 넓히고 수렴의 논거를 구조화**하는 것. 최종 컨셉 선택과 책임은 사람.

**핵심 원칙**:
- **발산 → 반론 → 수렴 순서 엄수.** 발산을 건너뛰고 원페이저부터 쓰면 AI는 검증 없이 미화만 한다.
- **반대 논거를 일부러 시킨다** — AI의 "사용자 선택 지지" 편향을 상쇄.
- **인용은 지어내지 마라.** 캔버스·수렴 근거 인용은 02 원문과 대조 가능해야 한다. 근거 없으면 "근거 부족".
- **원페이저는 1장 엄수.** 길이 제한이 곧 사고의 압축이다.

## 입력

- **필수**: `high-level-planning-output/<주제-슬러그>/` 의 02·03 산출물(앞 단계 스킬 산출물을 이 위치에 두거나 경로를 맞춘다)
  - `02_사용자리서치/03_페르소나.md`, `02_사용자리서치/06_인사이트_리포트.md`
  - `03_요구사항정의/03-PRD초안.md`, `03_요구사항정의/03-3_moscow.md`
- **연결(선택)**: `01_시장경쟁사/03-경쟁사-비교.md` — 포지셔닝 맵 경쟁사 좌표 근거. 없으면 맵 경쟁사 축이 약해지므로 01 먼저 권장.
- **대상 한 줄**: 누구의 어떤 문제인가. 안 주어지면 한 줄로 묻고 시작.
- 02·03이 없으면 위치를 묻고 중단한다.

## 파이프라인

### Stage 0 — 입력 확인 & 페인포인트 요약
02·03 산출물을 읽는다(없으면 위치를 묻고 중단). `01_시장경쟁사/`도 있으면 로드(없으면 포지셔닝 맵에서 degrade).
02·03에서 **핵심 페인포인트·요구를 요약**한다 — 이게 발산의 재료다. 대상 한 줄(누구의 어떤 문제)을 확정한다.

### Stage 1 — 컨셉 발산 (diverge)
- 서로 다른 접근 축으로 **컨셉 후보 8개 이상** 발산한다 (예: 자동화 중심 / 커뮤니티 중심 / 템플릿 중심 / B2B 연동 중심 등 — 축을 일부러 다양하게).
- 각 후보: `한 줄 컨셉 / 핵심 타깃 / 차별점 / 가장 큰 리스크`.
- **아직 평가하지 마라. 발산만 한다.** (익숙한 3~4개에서 멈추지 않게)
- → `04-1_컨셉발산.md`

### 🚦 게이트1 — 평가 기준 확정 (사람 개입, 필수)
AskUserQuestion으로 **수렴 평가 기준**을 제시 → 사용자가 OK/수정.
- 기본 제안(각 1~5점): ① 페인포인트 적합도(02 인용과 직접 연결되는가) ② 차별화 가능성(01 경쟁사가 못 하는가) ③ 초기 구현 난이도(MVP를 빠르게 만들 수 있는가, **낮을수록 고점**) ④ 수익화 명확성.

<!-- 변경 포인트: 기본 4기준을 사업에 맞게 바꾸세요. -->

기준은 사람이 정한다. 확정 전에는 Stage 2로 넘어가지 않는다.

### Stage 2 — 컨셉 수렴 (converge)
- 확정 기준으로 8개+ 후보를 **채점표**로 정리(기준별 점수 + 합계).
- 상위 2개에 대해 **"이 컨셉을 선택하면 안 되는 이유(반대 논거) 3개씩"** 을 쓴다(확증편향 상쇄).
- **점수·논거 근거는 반드시 01~03 문서를 인용**한다. 인용이 원문에 없으면 지어내지 말고 "근거 부족" 표기.
- → `04-2_컨셉수렴.md`

### 🚦 게이트2 — 컨셉 확정 (사람 개입, 필수)
AskUserQuestion으로 상위 후보를 제시 → **사용자가 최종 컨셉을 선택**한다.
**AI는 컨셉을 고르지 않는다.** 채점표는 참고 자료일 뿐이고, 시장 타이밍·팀 역량·의지 같은 결정 변수는 사람이 안다.
확정된 컨셉을 이후 모든 산출물의 기준으로 삼는다.

### Stage 3 — 원페이저 (1장 엄수)
확정 컨셉으로 원페이저를 쓴다:
- 한 문장 컨셉 / 타깃과 핵심 문제 / 솔루션 요약 / 차별점 3개 / **하지 않을 것(Non-goals) 3개** / 핵심 가정과 검증 방법.
- **한 페이지 분량 엄수.** 늘어나면 Non-goals부터 다시 정리한다.
- → `04-원페이저.md`

### Stage 4 — 북극성 지표 · OKR
- **북극성 지표(NSM) 후보 3개**: 각각 "왜 사용자 가치와 비즈니스 성장을 동시에 반영하는가 / 어떤 왜곡 위험이 있는가"를 쓰고 **1개를 추천**. MAU 같은 **허영 지표(vanity metric) 제외.**
- **출시 후 첫 분기 OKR**: Objective 1개 + Key Result 3개. KR은 **측정 방법까지 명시**(예: "온보딩 완료율 40% — GA4 퍼널로 측정"). 17단계(성과 측정)에서 실제로 잡히는 지표인지 연결 고려.
- → `04-3_지표·OKR.md`

### Stage 5 — 가치제안 캔버스 + 포지셔닝 맵
1. **가치제안 캔버스**: `Customer Jobs / Pains / Gains` ↔ `Products / Pain Relievers / Gain Creators`를 표로 매핑.
   - **각 항목 옆에 근거가 된 02 인터뷰 인용을 짧게** 단다(P번호·원문). 리서치와 캔버스의 연결을 유지.
   - 인용을 지어내지 마라 — 02 원문에 없으면 "근거 부족".
2. **포지셔닝 맵**:
   - ⚠️ **사분면(2×2) 맵은 Figma MCP `generate_diagram`으로 못 만든다** — generate_diagram은 graph/flowchart/sequence/state/gantt/ER만 지원하고 **quadrantChart는 미지원**이다. 사분면을 generate_diagram에 넣지 마라.
   - **정밀 2×2 사분면**은 **mermaid `quadrantChart`로 작성**한다(Obsidian이 기본 렌더링). 축: 도메인 X/Y(예: X=신뢰 근거, Y=맞춤 깊이). 배치: **01 경쟁사 + 우리 서비스(강조)** + **빈 공간(white space) 주석**. "경쟁사 좌표는 AI 추정 → 01 대조·보정" 명시. 01 산출물이 없으면 좌표는 가설(degrade).
   - **Figma 공유본이 필요하면**: `figma-use` 스킬 후 **`use_figma`**(generate_diagram 아님)로 Figma 보드에 포지셔닝 맵을 만든다. 팀이 여러 개거나 View 시트면 **생성 가능한(Dev/edit) 팀을 먼저 확인**하고, 회사 워크스페이스 쓰기이므로 사용자 확인 후 진행.
   - (컨셉 구조도·플로우가 필요하면 그때 `generate_diagram` flowchart 사용 — 사분면 아님)
   - → `04-4_가치제안캔버스.md`

### Stage 6 — 검증 체크리스트 + 마무리
`_검증체크리스트.md`를 아래 템플릿으로 생성한다(`<주제>`/`<날짜>` 치환):

```markdown
# 검증 체크리스트 — <주제> 상위기획 (작성일: <날짜>)

> 채점표는 참고 자료다. 컨셉 선택과 그 이유는 기획자가 자기 언어로 쓴다.

- [ ] 컨셉 선택 — AI 점수가 아니라 시장 타이밍·팀 역량·의지로 사람이 최종 결정 (04-2)
- [ ] 캔버스·수렴 근거의 인터뷰 인용을 02 원문과 샘플 대조 (AI 인용 조작 차단)
- [ ] 북극성 지표 — 현재 데이터 스택으로 측정 가능한가 / 조작 가능성은 없는가 (17단계 연결)
- [ ] 원페이저 1장 유지 — 두 장이 되면 Non-goals부터 다시 압축
- [ ] 포지셔닝 맵 경쟁사 좌표 — 01 근거와 맞는지, 축이 유리하게 왜곡되지 않았는지 FigJam에서 보정
- [ ] 민감정보 — Figma/Notion 외부 공유 전 제외 확인
```

(선택) **합의**: Notion MCP가 인증돼 있으면 `04-원페이저.md`를 팀 페이지로 업로드해 코멘트 합의를 진행한다(미인증이면 스킵 + `/mcp` 안내). 코멘트 반론은 원페이저 "핵심 가정"에 반영.

마지막으로 산출물 폴더 경로와 "컨셉 선택·지표 검증은 사람의 일"이라는 고지를 보고한다.

## 주의
- **컨셉 선택을 AI에게 맡기지 마라.** 채점은 입력 문서 표현에 좌우되고, 결정 변수(타이밍·역량·의지)를 모른다.
- **북극성 지표는 사람이 검증** — 측정 가능성·조작 가능성을 직접 따진다.
- **인용 조작 주의** — "인용 달아줘"가 환각을 부른다. 02 원문 대조는 필수.
- **원페이저가 두 장이 되는 순간 실패** — "1장 엄수"를 지킨다.
- **발산을 건너뛰지 마라** — 발산→반론→수렴이 이 단계 자동화의 핵심.
- 포지셔닝 맵 `generate_diagram` 결과는 초안 — 좌표·축을 사람이 보정한다.
