# 요구사항 정의 (Requirements Definition)

원천자료(회의록·슬랙·인터뷰)에서 요구사항을 추출해 유저스토리 → MoSCoW 우선순위 →
(Notion DB) → PRD 초안을 생성한다. 사람 검증 게이트는 **MoSCoW 평가 기준 확정 1곳**뿐이다.

**역할 분담**: AI는 빠짐없이 추출·구조화(회수율), **스코프 확정은 사람**(정밀도).

**핵심 원칙**:
- 모든 요구사항에 **출처**(파일명 + 발언자 + 원문 인용 한 줄). 출처 없는 항목을 지어내지 마라.
- 해석이 갈리면 **"확인 필요"** 태그. MoSCoW는 **"기준 먼저, 분류 나중"**.
- Must를 후하게 주지 마라(과적 경계).

## 입력

- **필수**: `requirements-output/<주제-슬러그>/원천자료/`의 회의록·슬랙·인터뷰 md
- **연결**: `requirements-output/<주제-슬러그>/02_사용자리서치/03_페르소나.md` (있으면 유저스토리 매핑, 없으면 "페르소나 미매핑" 처리 + 02 먼저 권장 안내)
- 원천자료가 없으면 위치를 묻고 중단한다.

> 원천자료 수집·전사는 스킬 범위 밖. 슬랙은 링크가 아니라 **내용을 복사해 md로** 저장해야 읽힌다.

## 출력 위치

결과물은 **`requirements-output/<주제-슬러그>/03_요구사항정의/`** 폴더(현재 작업 디렉토리 기준)에 저장한다:

<!-- 변경 포인트: 다른 위치에 모으려면 이 경로를 바꾸세요. 예) Obsidian 볼트 → "리서치/<주제-슬러그>/03_요구사항정의/" -->

| 파일 | 내용 |
|---|---|
| `03-1_요구사항추출.md` | ID·요구사항·유형·명시/암묵·출처·확인필요 표 |
| `03-2_유저스토리.md` | As a/I want/So that + 인수조건 + 페르소나 매핑 |
| `03-3_moscow.md` | MoSCoW 분류 + 근거 + 논의필요 |
| `03-PRD초안.md` | 배경/목표/스코프/제외/스토리/미해결 질문 |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

- 출력 폴더가 없으면 생성한다. `<주제-슬러그>`는 짧은 kebab-case.

## 파이프라인

### Stage 0 — 입력 확인
`원천자료/`의 md를 모두 읽는다. 없으면 위치를 묻고 중단.
`02_사용자리서치/03_페르소나.md`를 로드(있으면). 없으면 Stage 2에서 미매핑 처리 + 02 먼저 권장.
**민감정보**(슬랙 인사·계약 등)가 보이면 사용자에게 경고한다.

### Stage 1 — 요구사항 추출
- 명시적 요구("~가 필요하다")와 암묵적 요구(불만·우회행동 유추)를 **구분 표시**.
- 각 항목에 **출처**(파일명 + 발언자 + 원문 인용 한 줄). 기능/비기능 구분.
- **출처 인용에 민감정보**(계약 금액·개인 연락처·실명 등 식별정보)가 섞이면 마스킹하거나 `[민감정보 제외]`로 적는다 — 로컬 산출물도 나중에 공유될 수 있다.
- 중복·유사 항목 병합(병합 출처 모두 나열). 해석 갈리면 **"확인 필요"** 태그 + 모호점 기재.
- 표: `ID | 요구사항 | 유형(기능/비기능) | 명시/암묵 | 출처 | 확인필요`
- → `03-1_요구사항추출.md`

### Stage 2 — 유저스토리 변환
- 형식: `As a [페르소나], I want [기능], So that [가치]`
- 페르소나는 **02 산출물에 정의된 것만** 사용. 매핑 안 되면 억지로 끼우지 말고 "페르소나 미매핑" 섹션에 분리.
- 각 스토리에 인수조건(Acceptance Criteria) 2~3개.
- → `03-2_유저스토리.md`

### 🚦 게이트 — MoSCoW 평가 기준 확정 (사람 개입, 필수)
AskUserQuestion으로 **평가 기준**을 제시 → 사용자가 OK/수정.
- 기본 제안: ① MVP 핵심 가치에 직접 기여하는가 ② 없으면 서비스 성립 불가인가 ③ 출시 후 추가해도 UX가 크게 깨지지 않는가

기준 확정 전에는 Stage 3로 넘어가지 않는다.

### Stage 3 — MoSCoW 분류
- 확정 기준으로만 Must/Should/Could/Won't 분류. 각 항목 분류 근거 1문장.
- confidence 낮은 항목(사업 판단 필요)은 **"논의 필요"** 목록으로 분리.
- **Must가 전체 40%를 초과하면 경고**하고 재검토 대상을 제안.
- → `03-3_moscow.md`

### Stage 4 — Notion DB (선택적, degrade)
Notion MCP 인증을 확인한다. 미인증/미설치면 **스킵**하고 `/mcp` 인증을 안내한다.
인증되면: "<주제> 요구사항" DB 생성(속성: ID/유저스토리/유형/MoSCoW/출처/상태/담당자/관련화면)
→ 전 항목 입력(상태 "초안") → MoSCoW 보드 뷰 추가.
**민감정보 점검**: 외부(Notion) 전송 전 원천자료의 민감 내용 제외 확인.

### Stage 5 — PRD 초안 + 검증 체크리스트
`03-PRD초안.md` 생성: 배경 / 목표 / 스코프(Must·Should) / 스코프 제외(Won't) / 유저스토리 목록 / 미해결 질문("확인 필요"·"논의 필요" 모음).

`_검증체크리스트.md`(`<주제>`/`<날짜>` 치환):

```markdown
# 검증 체크리스트 — <주제> 요구사항 정의 (조사일: <날짜>)

> AI는 추출·구조화까지. 스코프 확정은 사람의 일이다.

- [ ] "확인 필요"·인용 어색 항목 원문 대조 (AI가 지어낸 요구사항 차단)
- [ ] MoSCoW는 초안 — 이해관계자 리뷰 후에만 "확정"으로
- [ ] 이해관계자 충돌 항목 조정 (AI는 식별만)
- [ ] Must 과적 재검증 — "없으면 출시를 미룰 것인가"
- [ ] Notion DB 입력 후 항목 수·속성 샘플 원본 대조
- [ ] 민감정보 외부 전송 점검
```

마지막으로 산출물 폴더 경로와 "MoSCoW는 초안 — 이해관계자 리뷰 필수" 고지를 보고한다.

## 주의
- 출처 없는 요구사항을 지어내지 마라. 인용이 어색하면 원문 대조.
- MoSCoW 초안을 그대로 "확정"하지 마라 — 비즈니스 판단은 사람.
- 이해관계자 충돌은 식별만, 조정은 기획자.
- 슬랙 등 민감정보는 외부 MCP 전송 전 제외.
- 한 방 프롬프트 금지 — 단계별 산출물을 파일로 남긴다.
