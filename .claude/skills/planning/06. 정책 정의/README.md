# policy-definition — 정책 정의 자동화 스킬

04 상위기획 + 05 비즈니스모델을 넣으면 **적대적 레드팀으로 엣지케이스 발굴 → 정책 매트릭스 →
타사 약관 벤치마크 → 운영정책·약관 초안**을 생성하는 Claude Code 스킬입니다. 사람은
**정책 영역 확정 1번 + 매트릭스 미정 결정 1번**, 두 번 개입합니다.

> 기획 프로세스 6단계 "정책 정의"를 자동화합니다.
> **AI는 질문 생성·구조화까지. 결정은 사람, 약관은 법무 검토.** AI가 확정한 정책·법조항은 위험합니다.

## 무엇을 만들어 주나

`policy-definition-output/<주제>/06_정책정의/`에 생성:

| 파일 | 내용 |
|---|---|
| `06-1_정책영역인벤토리.md` | 공통 코어 + BM 의존 정책 영역 |
| `06-2_레드팀_엣지케이스.md` | 3역할(악성유저/CS/법무) 각 10개+ → 가능성·리스크 태그 |
| `06-3_정책매트릭스.md` | 케이스별 옵션 A/B + ⚠️미정 + 조합 자체점검 |
| `06-4_약관벤치마크.md` | 타사 약관 비교표 + 차별/추격 3제안 |
| `06-운영정책_약관초안.md` | 운영정책 + 약관 초안 — **게이트2(미정 결정) 통과 후 생성** |
| `_검증체크리스트.md` | 사람이 확인할 항목 |

## 준비물 (입력)

1. **04 원페이저** (필수) — `…/04_상위기획/04-원페이저.md`.
2. **05 비즈니스모델** (필수) — `…/05_비즈니스모델/`(요금제·paywall·환불 전제). 없으면 환불·정산 정책이 ⚠️미정으로 강제됩니다.
3. **(선택) 03 PRD** — 정책 = 비기능 요구의 상세화.

```bash
cp SKILL.md ~/.claude/skills/policy-definition/SKILL.md
```

> 4종 표기: 스킬명 `policy-definition` / 출력 루트 `policy-definition-output/` / 배포 보관 폴더 `06. 정책 정의/` / 산출물 단계폴더 `06_정책정의/`.

## 사용법

04·05 산출물을 준비한 뒤:

```
04·05 산출물로 정책 정의해줘.
```

1. 정책 영역 인벤토리 자동
2. **영역 확정** → 당신이 OK (개입 1)
3. 레드팀 엣지케이스 → 정책 매트릭스(옵션·⚠️미정) 자동
4. **매트릭스 미정 결정** → 당신이 확정 (개입 2)
5. 약관 벤치마크 → 운영정책·약관 초안 자동

발동 키워드: `정책 정의`, `정책 매트릭스`, `약관 초안`, `운영정책`, `환불 정책`, `엣지케이스`, `레드팀`

## 주의

- **AI 산출물은 법률 자문이 아닙니다.** 약관은 전자상거래법·약관규제법·개인정보보호법 적용 — **법무 검토 필수**.
- **법조항 환각** — AI가 조문을 확정하지 않습니다(`[조문 미확인]` 태그). 청약철회·위약금·개인정보 보유기간은 `[법정기준 placeholder]` — 사람이 law.go.kr에서 확인.
- **타사 약관 복사 금지** — 구조·항목만 벤치마크(저작권 + BM 부적합).
- **레드팀 결과 전부 정책화 금지** — 상/중만, '하'는 운영자 재량.
- **⚠️미정을 그대로 넘기지 마세요** — 12단계 기능명세에서 구멍이 됩니다.
- 비한국 서비스면 **관할을 먼저 바꾸세요**(기본값은 한국).
