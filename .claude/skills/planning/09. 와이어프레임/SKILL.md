# 와이어프레임 (Wireframe Design)

08 유저플로우 + 07 IA + 06 정책을 받아 **와이어프레임 세트 1부**(화면 목록 + 화면별 프롬프트 + 실제 와이어프레임 + 세트 정리)를 만든다. 사람 개입 게이트는 **화면 목록 확정 1곳 + 생성 경로·충실도 확정 1곳, 총 2곳**이다.

**AI의 역할**: **초안 대량 생산까지. 무엇이 위에 오고 무엇이 중요한지 판단은 사람.** 요소·순서·우선순위를 프롬프트에 명시하지 않으면 AI가 임의로 채우고, 그 임의 결정이 검토 없이 굳는다.

**핵심 원칙**:
- **와이어 = 빨리 만들고 빨리 버리는 초안.** 완성도가 아니라 논의 베이스 → 우선순위 '상'·분기/정책 화면에 **레이아웃 대안 2~3개**를 만들어 비교(상태변형 empty/error는 대안이 아니다).
- **09-1 화면목록·09-2 프롬프트는 도구 0개로도 항상 완성**된다(순수 텍스트). Stage 3 시각 산출물은 부가물.
- **하이파이의 함정**: AI 시안은 와이어치고 너무 그럴듯하다 → **grayscale·low-fi 강제**, 리뷰 때 "구조만 본다" 선 긋기.
- **정책·엣지는 AI가 모른다**: 06 제약을 프롬프트에 안 넣으면 화면에 안 들어간다 → **06 케이스ID로 주입 + 생성 후 대조**(차기/Won't 제외).
- **상태 변형은 재발명하지 마라**: error/loading = 08-2 예외표, empty = 07 empty-state에서 가져온다.
- **화면 간 일관성**: 같은 세션에서 이어 생성하고 마지막에 일관성 점검. 디테일(문구·필드·예외)은 10단계.
- **세 생성 경로는 동등, 보유 도구 우선.**

## 파이프라인

### Stage 0 — 입력 확인 & degrade 매트릭스
08(필수)·07/06(권장)·03(선택)을 읽는다. 08 없으면 위치 묻고 중단. 07/08 화면명·ID를 계승한다.
- **degrade**: 07 없으면 전 화면 `⚠️IA미반영`(정보 위계·empty-state·스코프 게이트 불가) / 06 없으면 `⚠️정책 미주입` / 03 없으면 요소 우선순위 AI 추정+주의.

### Stage 1 — 화면 목록 추출 → 09-1
- **08-3 노드 필터**: `[시스템]`·`{분기}`·종착(`([...])`) 노드는 **제외**, 화면 노드만 추출. 화면 목록 = **08-3 화면 노드 ∪ 08 IA역반영 백로그 ∪ 07-1 "08 환류" 섹션**의 합집합 → **ID로 dedup**(R10-결과 등).
- **상태 변형 매핑(재발명 금지)**: error/loading = **08-2 예외표 행**(시스템동작·"보이는 것")에서, empty = **07-1 empty-state 표기**에서 가져온다. 그 위에 누락 점검(권한 요청·확인 모달)을 보강.
- 화면별 진입 경로·핵심 요소·우선순위(AI 추천 1안).

### 🚦 게이트1 — 화면 목록·상태변형·우선순위 확정 (사람 개입, 필수)
AskUserQuestion으로 화면 목록·상태 변형·우선순위를 택1·수정한다. 확정 전 Stage 2 미진입.

### Stage 2 — 화면별 프롬프트 → 09-2
화면마다 와이어프레임 프롬프트를 만든다(Stitch·use_figma 공용).
- **요소를 위→아래 순서로** 나열하고 우선순위 명시(07 정보 위계 반영), **grayscale·low-fi 강제**("low-fidelity wireframe, grayscale only, no real photos"), **한 프롬프트 = 한 화면**.
- **06 정책 주입**: 화면별 정책 = **08-2 예외표 '출처(06)' 열의 케이스ID를 수집 → 06-3 매트릭스에서 그 ID의 처리방안을 프롬프트 제약으로 주입**(예: "미인증 시 신청 불가"). **07 Won't/차기 케이스(RX-01/02/03·R6·R7 등)는 주입 금지**(MVP 화면 역오염 방지).

### 🚦 게이트2 — 생성 경로·충실도 확정 (사람 개입, 필수)
**probe 1회**(whoami / HTML 가용 / `stitch-loop` 가용)로 **가능한 경로만** AskUserQuestion에 제시한다(AI 추천 1안). 충실도 = grayscale low-fi. 확정 전 Stage 3 미진입.

### Stage 3 — 와이어프레임 생성 (degrade 사다리)
선택 경로로 생성한다. **사다리: use_figma → HTML → Stitch 프롬프트 → 마크다운 화면명세.**
- **시각화 대상 선정**: 실제 생성 = 우선순위 '상' 화면 전부 + 06 정책ID 주입 화면 + 대표 error·empty 각 1. '중'은 09-2 프롬프트로 갈음. 09-3에 **시각화 커버리지 표(전체 N / 실생성 M / 프롬프트 갈음 K / 사유)** 기록.
- (a) **use_figma**: `figma-use` 스킬 선행 로드 → `whoami`로 플랜(team/organization key) 확인 → **쓰기 가능한 팀의 planKey로 `use_figma`/`create_new_file` 시도, 실패 시 view-only로 판단하고 스킵**(HTML/Stitch로 degrade). whoami는 플랜만 반환하므로 **edit 권한은 실제 호출 실패로 판별**. 복잡한 화면은 **프레임 → 섹션 → 컴포넌트로 잘게** 지시 + 중간 스크린샷 확인. (Stitch Copy to Figma로 들어온 레이어는 프레임명 정리.)
- (b) **HTML**: **09 스킬이 직접** grayscale·박스+라벨 low-fi HTML을 Write한다(`frontend-design` 위임 금지 — 그 스킬은 하이파이·BOLD 지향이라 와이어 의도를 깬다). **이모지·아이콘폰트·이미지·유채색 금지** — 아이콘은 `[달력]`·`▢` 등 텍스트 라벨로, CSS는 #000~#fff 그레이스케일만. `wireframes/` 폴더에 저장, 09-3에 **상대경로** 링크.
- (c) **Stitch**: 외부 웹이라 직접 구동 불가. `stitch-loop` 스킬이 있으면 연동, 없으면 **09-2 프롬프트를 사용자가 stitch.withgoogle.com에 붙여넣도록 안내**(+ Copy to Figma).
- **최종 폴백(셋 다 불가)**: 09-2 프롬프트 + **마크다운 화면명세 표**(요소·순서·상태변형)를 최종 산출로 확정.
- **대안**: 우선순위 '상' + 분기/정책 화면에만 레이아웃 배치 대안 2~3을 만들어 **09-3 '대안 비교표'(화면 / A안·B안 / 추천·이유)**에 정리한다(상태변형은 대안 아님 — 0건이면 미완). 화면 간 일관성 = 같은 세션 연속 생성.

### Stage 4 — 정책·엣지 대조 + 일관성 점검
06 케이스ID를 역추적해 화면이 제약을 반영했는지, empty/error/loading이 커버됐는지, 버튼 위치·네비게이션이 일관적인지, grayscale가 유지됐는지 점검한다. (HTML 경로면 `grep -P '[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]' wireframes/*.html`로 이모지·픽토그램 0건 확인.)

### Stage 5 — 세트 정리 → 09-3 + 마무리
화면별 산출물 링크/경로 + 핵심 배치 결정(왜 이 배치인지) + 정책 대조·일관성 결과를 `09-3_와이어프레임세트.md`에 정리한다(→ 10 화면설계서 입력).
- **환류 write-back**: 와이어 그리다 발견된 IA에 없는 화면을 **사용자 확인 후 실제로** 07-1·08에 append(스킬이 write). 거부 시 백로그 표기로 degrade. **편집은 입력 산출물 폴더 내 한정**(다른 폴더 금지).
- `_검증체크리스트.md` 작성. **미해소(정책 미반영·IA 역반영 미해소)가 있으면 ⚠️ + 사용자 확인 없이 '완료' 보고 금지**(10단계 진입 전제).

`_검증체크리스트.md` 템플릿(`<주제>`/`<날짜>` 치환):

```markdown
# 검증 체크리스트 — <주제> 와이어프레임 (작성일: <날짜>)

> 와이어는 구조 확정용. 컬러·폰트는 디자이너 몫, 디테일은 10단계. 오늘은 구조만 본다.

- [ ] 상태 변형 — empty/error/loading이 08-2 예외표·07 empty-state에서 빠짐없이 왔는가 (09-1)
- [ ] 정책 반영 — 06 케이스ID 제약(미인증 차단 등)이 화면에 들어갔는가 / 생성 후 06 대조 (09-2·Stage4)
- [ ] 차기 제외 — Won't/차기(RX·R6·R7) 화면을 MVP 와이어에 넣지 않았는가
- [ ] 화면명 = 07·08 — 화면명/ID가 IA·플로우와 일치하는가 (라벨 드리프트)
- [ ] 일관성 — 버튼 위치·네비게이션이 화면 간 일관적인가 (09-3)
- [ ] grayscale + 글리프 — 하이파이로 흐르지 않았는가 / HTML에 이모지·아이콘·이미지·유채색 0(grep 확인)
- [ ] 대안 비교 — '상'·분기/정책 화면에 레이아웃 대안 2~3을 09-3 비교표에 올렸는가(상태변형은 대안 아님, 0건이면 미완)
- [ ] 환류 write-back — 발견된 새 화면을 07/08에 실제 반영(또는 확인 후 보류)했는가
- [ ] 민감정보 — Figma/외부 공유 전 제외 확인
```

마지막으로 산출물 폴더 경로와 **"와이어는 구조까지 — 문구·필드·예외는 10 화면설계서 / 발견 화면은 07·08로 환류"** 고지를 보고한다.

## 주의
- **하이파이의 함정** — AI 시안은 너무 그럴듯하다. grayscale·low-fi 명시 + "구조만 본다" 선 긋기.
- **정책·엣지는 AI가 모른다** — 06 케이스ID로 주입하고 생성 후 대조. 차기 스코프는 주입 금지.
- **화면 간 일관성** — 하나씩 생성하면 버튼·네비가 미묘하게 어긋난다. 같은 세션 + 마지막 점검.
- **use_figma 한계** — 복잡한 화면 한 번에 그리면 어긋난다. 프레임→섹션→컴포넌트 잘게 + 스크린샷 확인.
- **whoami는 edit 권한을 모른다** — 플랜만 반환. edit은 실제 호출 실패로 판별(view-only면 스킵).
- **frontend-design은 와이어용이 아니다** — 하이파이 지향이라 09가 직접 grayscale HTML 생성.
- **흔한 실수** — 와이어에서 디테일을 다 채우려는 것. 문구·필드·예외는 10단계. 여기선 구조까지.
- **Stitch는 외부 웹** — MCP 아님. stitch-loop 없으면 프롬프트 붙여넣기.
