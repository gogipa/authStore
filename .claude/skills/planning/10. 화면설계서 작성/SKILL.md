# 화면설계서 (Screen Specification / Storyboard)

09 와이어프레임 + 06 정책 + 08 인터랙션 + 07 화면ID를 받아 **화면설계서 1부**(화면별 구성요소·인터랙션·예외처리·변경이력) + 예외 점검 + (선택)PPT를 만든다. 디자이너·개발자 공용 **Single Source of Truth**. 사람 개입 게이트는 **템플릿·화면ID 확정 1곳 + [확인 필요]·기획 결정 해소 1곳, 총 2곳**이다.

**AI의 역할**: **그림 보고 디스크립션 초안까지. 동작 정의·정책 판단은 사람.** AI는 화면의 의도를 모른다 — 스크린샷만 보고 동작을 단정하면 틀린 스펙이 가장 자신 있는 문장으로 개발까지 흐른다.

**핵심 원칙**:
- **원본 = Figma(또는 09 와이어), 설계서 = 파생, PPT = 출력물.** 마크다운이 원본(AI·사람이 같은 파일). **갱신 비용이 높은 문서는 죽는다.**
- **[확인 필요] 강제.** 불확실한 동작은 추측해서 채우지 말고 `[확인 필요]` 태그. 추정값 기입 금지. 동작 정의는 전부 기획자 검증.
- **예외처리는 별도 패스.** AI는 보이는 것만 쓴다 — 로딩/빈/에러/권한/검증실패는 체크리스트로 들이밀어야 나온다. 06과 연결 = 기획자 판단 영역.
- **09 산출물 계승(재발명 금지).** 09-2 케이스ID 매핑표·08-2 플래그·07/09 화면ID를 1:1 승계.
- **화면 1장 = 파일 1개, 3~5개 배치.** 전 화면 한 번에 돌리면 뒤로 갈수록 품질이 떨어진다.
- **마크다운 설계서는 도구 0개로도 항상 생성**, 시각/PPT는 부가물.

## 파이프라인

### Stage 0 — 입력 확인 & 입력 소스 판별 & degrade
09(필수)·06/08/07(권장)을 읽는다. 입력 위치를 못 찾으면 묻고 **중단**.
- **화면ID 규칙 = 09 S-ID 계승**(신규 발번 금지, 07 R-ID는 매핑표 병기).
- **입력 소스 판별**: (a) 09 `wireframes/*.html` 있음 (b) Figma 링크 — `figma` 스킬 선행 로드 → `whoami` 인증 확인, 실패 시 09 HTML/마크다운으로 degrade(중단 아님; read 전용이라 use_figma/edit-team 확인 불필요) (c) `09-1`/`09-2` 마크다운(항상 존재 = 공통 1차 소스).
- **degrade 플래그**: 06 없으면 `⚠️정책 미대조` / 08 없으면 `⚠️플로우 미연결` / 07 없으면 `⚠️IA미계승`.

### Stage 1 — 표준 템플릿 고정 → _템플릿_화면설계서.md
화면ID·진입경로·관련 정책 위키링크·화면 이미지·구성요소 표(`번호 | 요소명 | 타입 | 디스크립션 | 노출 조건`)·인터랙션(`트리거 → 동작 → 결과`)·예외처리(로딩/빈/에러/권한/검증)·변경이력(`날짜 | 버전 | 변경 내용 | 작성자`)을 포함한다.

<!-- 변경 포인트: 화면ID 규칙. 기본은 09 S-ID 계승. 자체 체계(예: PM-[도메인3]-[번호3])가 있으면 게이트1에서 합의해 교체 -->

### 🚦 게이트1 — 템플릿 + 화면ID 체계 + 대상 화면 확정 (사람 개입, 필수)
AskUserQuestion으로 템플릿·화면ID 체계(09 S-ID 계승, AI 추천 1안)·대상 화면을 확정한다. ID 감지 실패 시에만 합의. (Figma 입력이면 프레임 명명 `화면ID_화면명` 사전 점검.) **확정 전 Stage 2 미진입.**

### Stage 2 — 화면별 디스크립션 초안 (3~5개 배치)
**입력 소스 3분기**: `09-1` 핵심요소 열 + `09-2` 프롬프트 = **전 화면 공통 1차 소스**, HTML/Figma는 **있는 화면만 시각 보강**(렌더 없는 화면도 마크다운에서 설계서 생성, 구성요소 표 미존재분은 `[확인 필요]`로 명시).
- 구성요소는 화면 위→아래·좌→우 순서로 번호. 디스크립션 = **"무엇인가 + 탭/입력 시 무슨 일"** 한 문장씩.
- **추정값 기입 금지 → 불확실한 동작은 `[확인 필요]`**(AI는 화면 의도를 모른다).
- 배치 루프: 배치1 생성 → 검토 → 기준 보정 → 배치2. 화면 1장 = 파일 1개.

### Stage 3 — 예외처리 별도 패스 → 10-예외처리_점검.md
화면별 **로딩 / 빈 데이터 / 에러(서버) / 권한 없음(비로그인) / 입력 검증 실패** 체크리스트.
- **09-2 매핑표를 화면↔케이스 1차 소스로 로드(06-3 전수 재매핑 금지)**, 06-3은 처리방안·미정 플래그 확인용으로만 조인.
- **08-2 플래그 1:1 승계**: `[정책미정→06환류]` → "기획 결정 필요" / `[값환류]` → `[확인 필요]`+placeholder / `[정책확정]` → 디스크립션 반영.
- **06-3 ⚠️미정 교차 점검**: 09가 확정처럼 쓴 값(RF-01 A/B·RF-04 N·M·RF-03 위약금율 등)도 **06-3이 ⚠️미정이면 `[확인 필요]`로 재강등**(HTML 단언 텍스트보다 06-3 placeholder 우선).
- **06 내부 충돌 우선순위**: 06은 매트릭스·운영정책·약관 다층이라 서로 어긋날 수 있다(예: 06-3 매트릭스 RF-01 ⚠️ vs 06 운영정책 게이트2 확정). **우선순위 = 게이트 통과 확정본(운영정책/약관) > 06-3 매트릭스 placeholder.** 단 **둘 중 하나라도 ⚠️미정이면 `[확인 필요]` 유지**. 어느 출처를 따랐는지 1줄 주석.
- 누락은 임의로 채우지 말고 **"기획 결정 필요" 목록**으로 분리.

### 🚦 게이트2 — [확인 필요] + "기획 결정 필요" 해소 (사람 개입, 필수)
AskUserQuestion으로 `[확인 필요]`·"기획 결정 필요" 항목을 사용자가 해소한다(AI 추천 1안). **해소 전 PPT/완료 진입 차단.**

### Stage 4 — (선택) PPT 변환
설계서 md를 읽어 **슬라이드 HTML**을 직접 생성한다: 표지 → 문서정보(버전·작성자) → 화면 인덱스 → **예외처리 종합 슬라이드(화면×상태 매트릭스 — 1급 섹션)** → 화면별 1슬라이드(구성요소 번호·디스크립션 + 하단 예외 표). → **powerpoint 스킬의 `html2pptx.js`로 .pptx 변환**(powerpoint는 md→PPT 자동변환기가 아니라 슬라이드 HTML→pptx 워크플로우).
- 스크린샷 **3-way degrade**: (a) HTML→PNG 캡처 도구 있으면 삽입 / (b) 없으면 스크린샷 생략·구성요소 표 중심 + 09 HTML **상대경로 링크** 갈음(화면당 1파일이면 파일 링크, **멀티프레임 단일 HTML이면 `#<화면ID>` 앵커까지** — 앵커 없으면 `[확인 필요]` + 09에 앵커 부여 환류) / (c) Figma 입력이었으면 `get_screenshot` 단기 URL을 PNG로 받아 삽입.
- **PPT 직접 수정 금지** — 수정은 md에서, PPT는 재생성.

### Stage 5 — 마무리
변경 이력·버전 관리(덮어쓰기 금지 — 화면이 바뀌면 그 화면만 재실행, 이력 표에 추가).
- **환류 write-back**: 발견된 화면 공백 → 07-1(+08), 정책 공백 → 06에 **사용자 확인 후 append**(거부 시 백로그 degrade). **편집은 입력 산출물 폴더 내 한정**(다른 폴더 금지).
- `_검증체크리스트.md` 작성. **[확인 필요]·"기획 결정 필요" 잔존 시 ⚠️ + 사용자 확인 없이 '완료' 보고 금지**(12 진입 전제). 화면ID·구성요소 번호 = 12 기능명세 참조 키임을 안내.

`_검증체크리스트.md` 템플릿(`<주제>`/`<날짜>` 치환):

```markdown
# 검증 체크리스트 — <주제> 화면설계서 (작성일: <날짜>)

> AI는 화면 의도를 모른다. 동작 정의·정책은 사람이 검증. "맞는 말 같은데 우리 정책과 다른 문장"을 찾아라.

- [ ] 화면 커버리지 — 전체 N / 작성 M / 차기 K + **미작성 화면별 사유·차기 트리거 표**(누락 추적 — 12 진입 전)
- [ ] [확인 필요] 해소 — 추측으로 채운 동작이 없는가 / 잔존 시 12로 넘기지 않았는가
- [ ] 예외처리 5종 — 화면마다 로딩/빈/에러/권한/검증이 정의됐는가 / 빈칸은 N/A vs 미점검 구분 (10-예외처리_점검)
- [ ] 정책 대조 — 09-2 매핑표·06-3과 충돌·누락이 없는가 / "기획 결정 필요" 분리했는가
- [ ] 미정 승계 — 06-3 ⚠️미정 값(위약금율 등)을 확정처럼 쓰지 않았는가([확인 필요] 유지)
- [ ] 화면ID = 07/09 — 화면ID·구성요소 번호가 상위와 일치하는가(12 참조 키)
- [ ] 변경 이력 — 덮어쓰지 않고 이력에 추가했는가
- [ ] 환류 — 발견된 화면/정책 공백을 07/06에 반영(또는 확인 후 보류)했는가
- [ ] 민감정보 — 와이어의 실제 데이터를 더미로 교체했는가(외부 MCP 전송 전)
```

마지막으로 산출물 폴더 경로와 **"설계서 원본은 마크다운 / PPT는 재생성 출력물 / 화면ID·구성요소 번호는 12 기능명세 참조 키"** 고지를 보고한다.

## 주의
- **AI는 화면의 의도를 모른다** — 동작 정의는 전부 기획자 검증. `[확인 필요]` 규칙이 그 장치다.
- **그럴듯한 추측을 조심하라** — 빈칸을 일반 패턴으로 채우면 틀린 스펙이 자신 있게 굳는다. 검토 시 "우리 정책과 다른 그럴듯한 문장"을 찾아라.
- **프레임 단위를 정리하고 시작하라**(Figma 입력 시) — 09에서 프레임명을 `화면ID_화면명`으로 맞춰두면 매끄럽다.
- **PPT를 직접 수정하지 마라** — md 원본과 갈라진다. 수정은 md, PPT는 재생성.
- **전 화면을 한 번에 돌리지 마라** — 3~5개 배치, 첫 배치 검토 후 프롬프트 보정.
- **민감정보** — 와이어에 실제 고객 데이터·내부 수치가 있으면 외부 MCP 전송 전 더미로 교체.
