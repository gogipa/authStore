# 화면설계서 (Screen Spec / Storyboard) 스킬

와이어프레임에 **말을 입히는** 단계. 09 와이어 + 06 정책 + 08 인터랙션 + 07 화면ID → 화면별 **구성요소·인터랙션·예외처리·변경이력** 마크다운 설계서 + (선택)PPT를 생성한다. 디자이너·개발자 공용 Single Source of Truth.

## 1. 무엇을 만드나
- `_템플릿_화면설계서.md` — 표준 템플릿(포맷 고정)
- `화면설계서/<화면ID>_<화면명>.md` — 화면 1장 = 파일 1개
- `10-예외처리_점검.md` — 화면별 로딩/빈/에러/권한/검증 + 06 충돌·누락 + 기획 결정 필요
- `_검증체크리스트.md` / (선택) `<주제>_화면설계서_v1.0.pptx`

> **마크다운 설계서는 도구가 없어도 항상 생성**됩니다. 시각/PPT는 부가물.

## 2. 설치
```bash
mkdir -p ~/.claude/skills/screen-spec-design
cp SKILL.md ~/.claude/skills/screen-spec-design/SKILL.md
```
설치 후 `화면설계서 작성해줘` / `스토리보드 만들어줘`로 트리거된다.

## 3. 입력 준비
- **필수** — 09 와이어프레임(09-1 화면목록·09-3 세트·09-2 매핑표·wireframes HTML 또는 Figma 링크).
- **권장** — 06 정책(예외 근거·케이스ID) / 08 유저플로우(예외표) / 07 IA(화면ID). 없으면 degrade(⚠️ 플래그).

## 4. 사람 개입 게이트 (2곳, 스킵 불가)
1. **템플릿 + 화면ID 체계 + 대상 화면 확정** — 기본은 09 S-ID 계승.
2. **[확인 필요] + "기획 결정 필요" 해소** — 해소 전 PPT/완료 진입 차단.

## 5. 변경 포인트
| 무엇 | 어디 | 바꾸는 법 |
|---|---|---|
| **화면ID 규칙** | Stage 1 주석 | 기본 09 S-ID 계승. 자체 체계(PM-[도메인]-[번호] 등)는 게이트1에서 교체 |
| **입력 경로(09/06/08/07)** | `## 입력` 주석 | 각 산출물이 다른 폴더/Figma면 개별 수정 |
| **출력 경로** | `## 출력 위치` 주석 | 기본 `screen-spec-design-output/` → 원하는 폴더 |
| **PPT 파일명·생성 여부** | Stage 4 주석 | PPT 불필요하면 Stage 4 스킵(md로 충분) |
| **입력 소스** | Stage 0 | 09가 HTML/마크다운/Figma 중 무엇이든 1차 소스 = 09-1·09-2 마크다운 |

## 6. degrade
- **09 없음** → 입력물이라 위치 묻고 **중단**.
- **Figma 미인증** → 09 HTML/마크다운으로(중단 아님).
- **HTML 없음** → 09-1·09-2 마크다운이 1차 소스(구성요소 미존재분 `[확인 필요]`).
- **powerpoint 없음** → 마크다운 설계서까지(PPT 생략).
- **06/08/07 없음** → ⚠️정책 미대조 / ⚠️플로우 미연결 / ⚠️IA미계승.

## 7. 주의
- **AI는 화면 의도를 모른다** — 동작 정의는 전부 기획자 검증. 불확실은 `[확인 필요]`(추측 금지).
- **그럴듯한 추측 조심** — 틀린 스펙이 자신 있게 굳어 개발까지 흐른다. "우리 정책과 다른 그럴듯한 문장"을 찾아라.
- **PPT 직접 수정 금지** — md 원본과 갈라진다. 수정은 md, PPT는 재생성. **재생성 비용 최소화 = 문서 생존 조건.**
- **전 화면 한 번에 금지** — 3~5개 배치, 첫 배치 검토 후 보정.
- **민감정보** — 와이어에 실제 데이터·내부 수치가 있으면 외부 MCP 전송 전 더미로 교체.
- 화면ID·구성요소 번호는 **12 기능명세 참조 키** — 함부로 바꾸지 마라.
