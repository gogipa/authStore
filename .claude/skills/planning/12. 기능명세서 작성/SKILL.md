# 기능명세서 (Functional Spec)

화면설계서가 "이 화면이 어떻게 보이는가"라면, 기능명세서는 **"각 기능이 어떻게 동작하는가"**를
기능 단위로 정의한다. 버튼을 눌렀을 때 어떤 입력이 가고, 무엇이 유효하고 무엇이 거부되며,
실패하면 무엇을 보여주는지를 빠짐없이 적는다. 개발자가 "이 경우엔 어떻게 되나요?"라고 묻기
전에 답이 문서에 있어야 한다.

구성: ① 기능 단위 목록(10에서 추출) ② 입력값·유효성·예외처리 표 ③ 상태(state) 정의 + Mermaid
④ API 목록 초안. **마크다운 = SSOT**, (옵트인) Notion = 공유본. "기능명세는 창작이 아니라
구조화" — 흩어진 10/06 정보를 표로 재배열하고 정형 예외를 기계적으로 빠짐없이 나열한다.

## 핵심 원칙

- **AI 추정 유효성 규칙은 무조건 ⚠️.** "비밀번호 8자"가 우리 정책인지 AI 일반론인지는 사람만
  확정한다. AI가 표를 채우고 사람은 ⚠️만 집중 검토. **개인정보·결제·보안 규칙은 격상 마크
  (🔴사람확정)** — 게이트2 통과 조건에 전수 확정.
- **다층 충돌은 "확정 상태"로 판정**(값의 표면형식 아님). 10 per-screen 디스크립션이 확정처럼
  단언해도, 같은 항목이 06-3 ⚠️미정이거나 10 "미정 승계" 섹션이 [확인 필요]로 강등했으면 **12도
  [확인 필요]/⚠️ 유지**. 디스크립션 단언이 이기는 건 **06 운영정책 확정본일 때만**.
- **환각 기능 분리.** 화면설계서에 없으나 동작상 필요한 기능(세션 만료 등)은 "추정 기능"으로
  분리(본 목록과 안 섞음). **기능↔화면 역추적 2회**(Stage 1 화면 기반 + Stage 3 상태머신 발견분).
- **API 초안은 논의용.** 메서드·경로는 추정 — 확정 스펙으로 공유 금지.
- **마크다운 = 원본, Notion = 공유본.** Notion 전 마크다운 검토 완료. SSOT 손실 0 — 담당·진행
  상태·우선순위·매핑이 전부 마크다운에 존재.
- **배치는 내부 청크**(게이트 아님). Must부터 5~10개 단위 생성→검토. **N>40이면 Must/Should만
  개별 파일**, 나머지는 12-1 표 행.
- **민감정보는 외부 전송 전 더미.** Notion 발행·Figma read·Context7 쿼리 모두 외부 경계다.

## ID 체계 (07 정보구조와 동일하게 감지·계승)

- **기능 ID = `F<n>`.** 03 요구사항 ID 열의 스타일(접두/자릿수/하이픈)을 `[A-Z]+-?\d+`로 감지해
  정렬한다(03이 `R1~R16` 무패딩이면 `F1..Fn`, 하이픈+패딩 쓰면 그 스타일). **원본 가이드의
  `F-001`·`P0`는 예시이며 리터럴로 가정 금지.** 감지 실패 시 Stage 0에서 inline 1회 질문(게이트 아님).
- **F 충돌 회피**: 수신자 03이 F계열 접두사를 쓰면 기능 ID는 `FEAT<n>`로 회피.
- **우선순위 = MoSCoW 계승 + P0 병기**: 03 MoSCoW(Must/Should/Could)를 1급 표기로 계승(03→12
  추적성), 개발 편의용 P0/P1/P2 변환표를 12-1에 병기(Must=P0).
- 매핑 표: 기능ID ↔ 화면(S-ID, 10 계승) ↔ 요구사항(R-ID, 무패딩). **복합형 `SB-03/R10`은 슬래시
  분리 파싱**, 케이스ID(하이픈+패딩)는 R-ID와 별 열.

## 다층 입력 충돌 우선순위 ("확정 상태"로 판정)

1. 게이트 통과 확정본(06-운영정책) > 10 디스크립션 > 06-3 매트릭스 placeholder. **단 06-3가
   ⚠️미정이거나 10이 [확인 필요]로 강등한 항목은 12도 [확인 필요]/⚠️ 유지**(디스크립션 단언만으론
   확정 못 함 — 디스크립션 단언이 이기는 건 06 운영정책 확정본일 때만).
2. **03 충돌 이월**: 06-3 미정열에 `(03 충돌 이월)` 표기가 있고 06 운영정책에서 확정된 경우 →
   운영정책 값 채택 + 정책근거표 관련요구사항 열에 충돌 양측 R-ID(예: R9·R10)·해소출처(06
   운영정책) 병기.
3. **상태전이(12-2)·API(12-3)는 상위 1차 원천이 없는 추정 영역** → 각 전이/엔드포인트에 근거
   (06-3 케이스ID 등) 또는 ⚠️AI추정을 병기(유효성/예외 규칙과 동일 강도).
4. **QA 증빙 ≠ 정책 1차 원천.** 11 프로토타입 검증·08-2 `[정책확정]` 플래그는 동작 재현·QA
   증빙일 뿐 정책 1차 원천이 아니다 — 10/06에 케이스 정의가 **없는** 항목을 [확인 필요]→확정으로
   **격상하지 못한다**. 06 운영정책에 케이스 자체가 부재하면(예: "대안 0개 직행") 10의 [확인 필요]
   여부와 무관하게 12는 [확인 필요]/⚠️ 유지.

**회귀 self-check**(도메인 예시이니 본인 케이스ID로 치환): ① 09/10이 `3일·2회`처럼 단언해도 06-3
미정·10 [확인 필요]면 → ⚠️ 유지. ② 위약금율이 06-3 placeholder면 → ⚠️ 유지. ③ **대조** 06-3는
미정이나 운영정책 확정 케이스 → 확정. ④ **"11 검증됨"·"08-2 정책확정"을 확정 근거로 단 행 색출** —
10/06에 케이스 정의가 있어야 확정, 없으면 [확인 필요] 유지. (12는 09를 직접 입력받지 않는다 —
정책 수치 가드는 10이 수행.)

## 08-2 플래그 3종 의미 정규화 승계

- 콜론/공백/화살표 공백을 무시하고 `정책확정` / `정책미정→06환류` / `값환류` **세 의미축**으로
  매칭한다(표면 리터럴 1세트만 매칭 금지 — `[정책미정→06 환류]` 공백/무공백 모두 인식). 케이스ID는
  `[A-Z]+-?\d+` + 복합형(슬래시 분리).
- 처리: `[정책확정]`→예외처리표 동작 반영 / `[정책미정→06환류]`→⚠️ "기획 결정 필요" /
  `[값 환류]`→규칙 형태는 적되 값은 placeholder + ⚠️.
- 정량 대조: **08-2 원본 행ID ↔ 12 반영 항목 1:1 매핑 표**(원본 행명 / 반영 기능ID / 제외 사유).
  행 수 합(5+2=7)만으론 라벨 어긋남(없는 행을 반영에 넣거나 실제 반영 행 누락)을 못 잡는다 — 행 단위 대조.

## 파이프라인

### Stage 0 — 입력확인 & ID 감지 & 입력소스 판별 & 도구 probe & degrade
- 10 필수 확인(없으면 중단). 06 입력은 `06-3 + 06-운영정책_약관초안` 쌍.
- **ID 컨벤션 감지**(위 ID 체계). 화면ID = 10 S-ID 계승. 기능 ID = 감지 스타일(F 충돌 시 FEAT).
- 입력 소스 3분기 판별. 도구 probe(Notion/Context7/Figma read 존재 여부).
- **degrade/중단 1줄 원칙**: 기본 골격(기능목록·화면매핑)을 만들 수 있으면 degrade, 없으면 중단.
  권장 입력별 부재 시 무력화 산출물을 degrade 표로 1:1 매핑.

### 🚦 게이트1 — 기능 목록 + ID 체계 + 템플릿 + 추정 기능 채택/보류
AskUserQuestion(AI 추천 1안). 템플릿 확정도 검수 대상.

### Stage 1 — 기능 단위 추출 → 12-1_기능목록.md
- **화면 단위가 아니라 기능 단위로 분해**(예: 상품 등록 화면 → 사진 업로드 / 카테고리 선택 /
  가격 입력 / 등록 제출). 구성요소 번호 = 12 참조 키 계승.
- **추정 기능 분리**: 관련화면 컬럼이 비거나 10/09-1에 없는 화면을 가리키는 기능 = 환각 의심 →
  추정 기능 섹션 강등 + 사유. (기능↔화면 역추적 1회.)
- **커버리지 표 4열**: 09-1 전체 N / 10 작성 M / 12 명세화 / **10 미작성(차기) K**. 10 미작성
  화면은 "추정 기능"이 아니라 "상위(10) 미작성 — 차기 명세 대기"로 별도 표기(혼동 금지).

### Stage 2 — 입력값/유효성/예외처리 (Must부터 5~10 내부청크) → 기능명세/<기능ID>_*.md
- 각 기능마다 3표: **입력값표**(필드·타입·필수·유효성규칙·기본값) / **예외처리표 6종 전수**
  (빈값·형식·중복·권한·네트워크·서버; 사용자 메시지 문구 그대로) / **정책근거표**(근거 출처 표기,
  AI 추정은 ⚠️, 민감 카테고리는 🔴사람확정).
- **다층 충돌 우선순위 적용** + **10-예외처리_점검 매트릭스·"기획 결정 필요" 조인**(per-screen
  예외표와 둘 다 = 예외 승계 1차 소스) + **08-2 의미정규화 3종 승계** + 10 [확인필요]/06-3 미정 승계.
  - **"기획 결정 필요" 처리 규칙**: 10-예외처리_점검의 "기획 결정 필요" 목록 항목은 06 운영정책
    확정본으로 해소되지 않는 한 정책근거표에서 **[확인 필요]/⚠️로 보존 + 게이트2 잔존 목록 등재**
    (08-2 3분기 처리와 동일 강도 — 조인만 하고 확정으로 빠져나가지 못하게).
- N>40이면 Must/Should만 개별 파일. 완료 기능ID를 12-1에 체크(세션 중단·재개).

### Stage 3 — 상태(state) 정의 → 12-2_상태정의.md
- **상태 목록 표**(상태명 한/영·진입조건·가능 액션·이탈경로) + **Mermaid stateDiagram-v2**.
  Obsidian mermaid 규칙 계승(08 user-flow): `[*]` 초기/종료 전이 명시, state 라벨 한글은 따옴표,
  합성 state 들여쓰기, transition `:` 형식. **stateDiagram-v2 예약어 가드**: state ID로
  `state`/`end`/`class`/`note`/`direction`/`click`/`hide`를 쓰면 파싱이 깨진다 — 영문 식별자 +
  따옴표 별칭(`state "활성" as s_active`)으로 회피.
- **dead-end/unreachable 머신검증**: 상태 목록 표를 SSOT로 python3 인접리스트를 구성해
  **이탈전이 0(dead-end)·진입전이 0(unreachable)** 상태를 산출한다(11 정적점검 선례).
- **충돌 케이스 ≥5**를 질문 형태로 도출(예약중 삭제·결제대기 만료·환불중 재구매 등) → 게이트2.
- 추정 기능 역추적 2회째: 상태머신에서 발견된 추정 기능을 12-1 추정 기능 섹션에 append.

### 🚦 게이트2 — ⚠️ 추정 규칙 + 상태 충돌 + 잔존 미정 + 민감 카테고리 전수 확정
AskUserQuestion(AI 추천 1안). **Stage 3 뒤에 둔다** — 검수 대상(Stage 2 ⚠️ 추정 규칙 + Stage 3
상태 충돌 질문 + Stage 2 승계 [확인 필요]/06-3 미정 잔존분 + 민감 카테고리)이 게이트 시점에 모두
존재해야 한다. **해소 전 API/Notion 차단.**

### Stage 4 — API 목록 초안 → 12-3_API초안.md
- 표(API명·메서드/경로 추정·요청 필드·응답 필드·관련 기능ID). 상단 고지: **"논의용 초안 —
  메서드·경로는 추정이며 개발팀이 변경 가능, 확정 스펙으로 공유 금지."**
- 외부 SDK(결제 PG·소셜 로그인)는 **Context7 2-step**: ①`resolve-library-id`(라이브러리명+질문) →
  ②`query-docs`(질문당 ≤3회). 라이브러리 식별 모호 시 보정 생략(불확실하면 ⚠️).
- 관련 기능ID가 12-1에 모두 존재하는지 역추적(환각 API 차단).

### Stage 5 — (옵트인) Notion DB화
마크다운 검토 완료 후 **사용자 명시 선택 시만**(기본은 마크다운 SSOT에서 멈춤 — 도구 0개로 완성).
- **민감정보 더미 점검**: 실명·연락처·계약/결제 금액·내부 식별자·실제 API 키/엔드포인트를 더미로
  치환(점검 리스트).
- write 대상 = `notion-create-database`/`notion-create-pages`. **되돌리기 어려움 경고** + 생성 후
  검수(레코드 수·민감 필드 샘플 대조).
- 속성: 기능ID(제목)·기능명·관련화면·우선순위(select)·**상태(select: 작성중/검토요청/확정/개발중/
  완료)**·담당(person)·비고. 초기 상태 = 검토요청. 기능 1개 = 레코드, 상세는 페이지 본문.
- degrade: 미인증/미사용 시 마크다운까지(SSOT 손실 0).

### Stage 6 — 마무리
- **환류 write-back**: 기능서에서 발견한 정책 공백→06, 화면 공백→10/07에 **사용자 확인 후 append**
  (거부/대상 부재 시 백로그, **편집은 기획·리서치 폴더 내 한정**).
- **_검증체크리스트** 생성(아래 본문) + 커버리지 표.
- `[확인 필요]`/민감 카테고리 잔존 시 ⚠️ + 사용자 확인 없이 '완료' 보고 금지.

## 도구 정확성

- **Notion MCP**(연결 시) = 외부발행·되돌리기 어려움 → 옵트인·게이트·더미. **마크다운 SSOT가 기본.**
- **Context7 MCP**(연결 시) = 2-step(resolve→query ≤3회/질문), 외부 SDK 환각 감소용.
- **Figma read**(연결 시) = 10이 Figma면 `get_design_context`, **write 도구 금지**(오염·민감정보).
- **Mermaid stateDiagram-v2** = Obsidian 렌더. 문법검증은 `npx -y @mermaid-js/mermaid-cli -i x.mmd
  -o /dev/null`로 파싱오류 확인(미설치 시 stateDiagram-v2 정적 체크리스트 degrade). macOS grep는
  `-P` 미지원 → python3 정규식 사용.

## degrade vs 중단 vs 게이트 블로킹

- **중단**: 10 부재(입력물).
- **degrade**: Figma 미인증→마크다운 / 06 부재→정책근거표·08-2 승계·게이트2 추정판정 전 항목 ⚠️
  잠금 / 11 부재→⚠️플로우검증 미반영(10+06+08-2+03만으로 완성) / 09-1 부재→커버리지 분모 10
  작성분+경고 / Notion 미인증·미사용→마크다운 SSOT / mermaid-cli 없음→정적 체크리스트.
- **게이트 블로킹**: 해소 가능한 ⚠️/[확인 필요]/민감 카테고리.

## 주의

- **AI 추정 유효성을 그대로 확정 금지** — 특히 개인정보·결제·보안은 전부 사람.
- **환각 기능** — 화면설계서에 없는 기능을 끼워 넣지 마라(역추적 검증).
- **API 초안은 논의용** — 확정 스펙처럼 공유하면 갈등의 원인.
- **Notion 전 마크다운 검토 완료** — DB 대량 수정은 번거롭다. .md가 원본, Notion이 공유본.
- 화면ID·구성요소 번호는 **참조 키** — 함부로 바꾸지 마라.
