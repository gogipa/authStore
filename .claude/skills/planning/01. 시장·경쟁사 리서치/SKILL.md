# 시장·경쟁사 리서치 (Market & Competitor Research)

시장 주제 한 줄을 받아 시장·경쟁사 리서치 산출물을 자동 생성한다. 사람 검증 게이트는
**경쟁사 확정 1곳**뿐이고, 나머지 단계는 자동으로 흐른다.

**핵심 원칙**: AI 산출물은 "검증된 사실"이 아니라 "잘 정리된 초안"이다. 시장 수치와
기능 유무는 반드시 출처를 달거나 "확인 불가"/"?"로 남긴다. **추정 금지.**

## 입력

- **필수**: 시장 주제 한 줄. 예) `"국내 반려동물 사료 정기구독 커머스 시장"`
- **선택**:
  - 알려진 경쟁사 힌트 (Stage 0 후보에 합류)
  - 앱 리뷰 등 수동 수집 소스 md 파일 경로 (Stage 3에서 흡수, 없으면 스킵)
  - 비교표 기능 축 커스텀 (없으면 Stage 0에서 도메인 기반 제안)

주제가 주어지지 않았으면 먼저 한 줄로 물어본 뒤 시작한다.

## 출력 위치

결과물은 **`market-research-output/<주제-슬러그>/`** 폴더(현재 작업 디렉토리 기준)에 저장한다:

     예) Obsidian 볼트의 특정 폴더 → "리서치/<주제-슬러그>/" 등 -->

| 파일 | 내용 |

- 출력 폴더가 없으면 생성한다.
- `<주제-슬러그>`는 주제를 짧은 kebab-case로 변환한다 (예: `펫구독-시장`).

## 파이프라인

아래 6단계를 순서대로 실행한다. 각 단계는 독립적으로 degrade한다
(한 단계 실패가 전체를 멈추지 않음 — 단, Stage 1은 예외로 중단).

### Stage 0 — 사전 탐색 & 경쟁사 후보 도출

WebSearch로 주제의 시장 주요 플레이어를 스캔한다.
- **한국어와 영어 검색어를 모두** 사용한다.
- 국내 소스(네이버 뉴스, DART 공시, 혁신의숲/와이즈앱)를 의도적으로 검색에 포함한다
  — 영어권 검색은 국내 시장을 놓친다.

각 경쟁사 후보에 대해 수집한다: ① 서비스명 ② 한 줄 설명 ③ 공식 URL(가격/정책 페이지 우선).
입력에 경쟁사 힌트가 있으면 후보에 합류시킨다.

동시에 도메인에 맞는 **비교표 기능 축(행)** 과 **포지셔닝 맵 X/Y축**을 제안 형태로 준비한다.
(예: 기능 축 = 정기배송·맞춤추천·상담·멤버십·해지정책 / X축 = 가격(저가→프리미엄),
Y축 = 큐레이션(셀프→완전맞춤))

### 🚦 게이트 — 경쟁사 확정 (사람 개입, 필수)

AskUserQuestion으로 사용자에게 제시한다:
- 경쟁사 후보 목록 (각 한 줄 설명 포함)
- 제안 비교축 (기능 행 목록 + 포지셔닝 X/Y축)

사용자가 OK / 추가 / 제거 / 수정한다. **승인 전에는 Stage 1로 넘어가지 않는다.**
확정된 경쟁사 목록과 비교축을 이후 모든 단계의 기준으로 삼는다.

### Stage 1 — 시장 리포트 (deep-research)

> ⚠️ deep-research는 이 파이프라인에서 **가장 무거운 단계**다(수십~수백만 토큰, 5~15분 소요). 비용을 감안해 실행한다.

deep-research 스킬을 호출한다. 프롬프트에 다음을 강제한다:
- 주제 + 확정 경쟁사 목록
- 시장 규모와 최근 3년 성장 추이 (**수치마다 출처 URL 명시**)
- 각 경쟁사의 비즈니스 모델·차별점
- 최근 1년 투자·인수·철수 동향
- 한국어 소스 우선 (네이버/DART/국내 매체)
- **확인 안 되는 수치는 "확인 불가"로 표기하고 추정하지 마라.**
- 출력: 출처 링크 달린 마크다운

결과를 `00-시장리포트.md`에 저장한다.
**실패 시**: 리포트가 핵심 산출물이므로 여기서 중단하고 사용자에게 보고한다.

### Stage 2 — 경쟁사 가격·정책

확정 경쟁사의 가격·정기구독 정책을 수집한다.

> ⚠️ **한국 커머스는 대부분 앱/SPA 기반이라 공식 사이트 WebFetch로는 가격·정책이 거의 안 잡힌다**(정적 HTML만 읽혀 네비게이션만 나옴). 그래서 다음 순서로 시도한다:

1. **WebSearch 우선**: `"<경쟁사> 정기배송 가격"`, `"<경쟁사> 멤버십 혜택 해지 정책"` 등으로
   가격·정책을 다룬 기사·블로그·리뷰를 찾아 거기서 추출한다(출처 명시).
2. **WebFetch 보조**: 공식 가격/정책 페이지 URL을 알면 병렬 WebFetch로 보강한다.
   (SPA 사이트는 실패할 수 있음 — 실패해도 무시하고 진행)

각 서비스의 요금제·배송 주기·건너뛰기/해지 정책을 마크다운 표로 정리한다.
- 어떤 방법으로도 안 잡히는 항목은 "확인 불가"로 남긴다.
- 표 하단에 **조사 날짜(오늘 날짜)** 와 출처 URL, 그리고 "정확한 가격은 각 사 앱 직접 확인 필요"를 적는다.

결과를 `01-가격정책.md`에 저장한다.
**실패 시**: 해당 경쟁사 셀만 "확인 불가"로 남기고 계속 진행한다.

### Stage 3 — NotebookLM 적재 & 질의

**먼저 `server_info`로 `auth_status`를 확인한다. `stale`/`not_configured`이면 노트북 생성을 시도하지 말고 곧바로 이 단계를 스킵**하고 `nlm login`을 안내한다(아래 degrade 규칙).

NotebookLM MCP를 사용한다. 두 서버가 연결돼 있으면 `notebooklm-mcp`(CLI:
`notebook_create`/`source_add`/`notebook_query`)를 우선 쓰고, 없으면 `notebooklm`을 쓴다.

1. `"<주제> 경쟁사 리서치"` 이름으로 노트북을 생성한다(동명이 이미 있으면 재사용).
2. 소스를 추가한다:
   - `00-시장리포트.md` 내용
   - 경쟁사 보도자료/블로그 URL
   - (선택) 입력으로 받은 앱 리뷰 md 파일 — **없으면 이 소스만 스킵한다.**
3. **인덱싱 polling**: 소스 추가 후 인덱싱 완료까지 폴링한다 — 약 10초 간격,
   상한 90초. (NotebookLM은 소스 인덱싱에 5~30초 걸린다.)
4. 노트북에 질의한다:
   > "세 경쟁사가 공통으로 강조하는 가치 제안은 무엇이고, 사용자 리뷰에서 반복되는
   > 불만 상위 3가지는? 각 답마다 출처를 표기해."

질문과 답변(출처 포함)을 `02-notebooklm-질의.md`에 저장한다.

**degrade 규칙:**
- **인증 만료** → 사용자에게 `nlm login` 실행을 안내하고 **이 단계만 스킵**, 나머지는 완주한다.
- **앱 리뷰 파일 없음** → 해당 소스만 스킵(나머지 소스로 진행).
- **인덱싱 90초 초과** → 부분 결과로 질의를 시도하고 답변에 한계를 명시한다.

### Stage 4 — 기능 비교표 + 포지셔닝 맵

앞 단계 산출물을 종합한다(추가 외부 호출 없음).

1. **기능 비교표** (마크다운):
   - 열: 우리 서비스(가칭) + 확정 경쟁사들
   - 행: 게이트에서 확정한 기능 축
   - 셀: `O` / `△` / `X` + 한 줄 비고. **근거 없는 셀은 `?`로 남긴다.**
2. **포지셔닝 맵**: mermaid `quadrantChart` (게이트에서 확정한 X/Y축).
   Obsidian이 mermaid를 기본 렌더링하므로 별도 도구가 필요 없다.

결과를 `03-경쟁사-비교.md`에 저장한다.

### Stage 5 — 검증 체크리스트 첨부 & 마무리

`_검증체크리스트.md`를 아래 템플릿으로 생성한다(`<주제>`/`<날짜>`는 실제 값으로 치환):

```markdown
# 검증 체크리스트 — <주제> (조사일: <날짜>)

> AI 산출물은 검증된 사실이 아니라 "잘 정리된 초안"이다.
> 아래를 사람이 확인해야 보고서에 옮겨 적을 수 있다.

- [ ] 시장 규모·성장률 수치 — 클릭해서 원출처 확인 (00-시장리포트.md)
- [ ] 비교표 O/△/X — 핵심 경쟁사 2~3곳 직접 가입해 검증 (03-경쟁사-비교.md)
- [ ] 가격·정책 — 의사결정 직전 핵심 항목 재확인 (유통기한 짧음, 01-가격정책.md)
- [ ] 국내 소스 누락 여부 — 네이버/DART 보강 필요 점검
- [ ] "?"·"확인 불가" 셀 — 직접 조사로 메우기
```

마지막으로 사용자에게 보고한다:
- 산출물 폴더 경로
- 고지: "이건 검증된 사실이 아니라 잘 정리된 초안입니다. 위 체크리스트를 확인하세요."

## 주의

- 시장 수치를 지어내지 마라. 모르면 "확인 불가".
- Perplexity·Figma는 이 스킬에서 쓰지 않는다(WebSearch / mermaid로 대체).
- 영어권 검색에 쏠리지 마라 — 국내 시장은 국내 소스가 핵심이다.
- 모든 가격·정책 산출물에는 조사 날짜를 박는다(유통기한이 짧다).
