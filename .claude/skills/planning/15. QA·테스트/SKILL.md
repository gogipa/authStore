# QA·테스트 (QA & Test)

QA·테스트는 개발된 기능이 기획 의도대로 동작하는지 **12 기능명세를 기준으로 검증**하는 단계다.
산출물 = ① 테스트케이스(TC) 시트 ② 경계값·예외 보강 ③ **명세 누락 목록(핵심 부산물)** ④ 버그
리포트 ⑤ 결과 집계. **TC는 창작이 아니라 12 명세를 "절차+기대결과"로 재배열하는 변환 작업**이며,
**AI는 변환·체크리스트·포맷팅, 판단(우선순위·정책 확정·탐색적 테스트)은 사람.**

## 핵심 원칙 (계승 우선 — 단 "확정 명세일 때만 기대결과 단정")

- **TC = 변환(창작 금지)**: 각 TC는 12 명세 항목에 **1:1 근거**(명세근거 열 필수). 명세에 없는
  동작을 지어내 TC에 섞지 마라(환각 TC) — 근거 없는 동작은 TC가 아니라 15-2 명세 누락으로.
- **(family 15판) TC 기대결과는 12 정책근거표 판정이 "확정"(근거=06 운영정책 확정본)인 동작만 단정.**
  판정이 `⚠️`/`🔴`/`[확인 필요]`이거나 근거가 12-3 placeholder·06-3 미정을 가리키면 **TC는 만들되
  기대결과 단정 금지**(placeholder + 표기) + **15-2 "명세 누락 — 기획 확인 필요"로 환류**.
  - **reverse-trap(역방향 함정)**: ① 근거표 헤더가 "확정"이라도 그 **행의 근거가 06 운영정책 확정본이
    아니면**(예: 위약금율 = 06-3·운영정책 모두 placeholder) 단정 금지. ② 프로토타입·플로우 같은 **QA
    증빙이 동작을 재현했어도 `[확인 필요]`를 확정으로 격상 못함**(12 캐논 계승). ③ **14-1 추천안을 확정
    기대결과로 오인 금지**(추천 ≠ 확정).
  - **baseline(확정 기준) = 12 정책근거표 판정열 + 12-2 근거열.** 게이트1에서 고정.
- **AI 추천 ≠ 확정**: 우선순위 비즈니스 임팩트·정책 확정은 사람. **🔴 민감(개인정보·결제·보안)은 전수
  사람 확정**(게이트2 통과 조건).
- **명세 누락 발견이 핵심 부산물**: 경계값/예외를 훑다 12에 처리 방침이 없는 항목 = 15-2. QA 단계
  비용보다 싼 시점에 기획 빈틈을 잡는다.
- **탐색적 테스트는 대체 불가(사람)**: "써보니 어색하다"는 TC 밖. 자동화로 번 시간을 여기 쓰는 게 목적.
- **명세-TC 동기화**: 12 변경 시 TC 재생성 신호. 옛 명세 기준 TC는 멀쩡한 기능을 Fail로 만든다.
- **Playwright 안전(E2E 쓸 때)**: 운영 서버 금지·스테이징/테스트 계정 한정·비밀번호 평문 금지(런타임
  입력, 산출물·스크린샷 마스킹). (상세는 주의 + Stage 4.)

## ID·우선순위 (계승, 재발명 금지)

- 기능ID(12 `F<n>`)·화면ID(S-ID)·케이스ID·예외 #번호 계승. TC ID = 기능코드 기반(예: `<코드>-<기능>-001`).
- **우선순위 = 12 MoSCoW/P0~P2를 TC 우선순위로 1:1 계승**(Must=P0/Should=P1/Could=P2). 원본 가이드의
  P1~P3는 **예시(리터럴 금지)**. TC 기본값 = 부모 기능의 12 우선순위.
  - **⚠️ P1 의미충돌 경고**: P0~P2에서 **P1=중간(Should)**, 원본 가이드 P1~P3에서 **P1=최고** — 같은
    토큰이 정반대 등급. 15-1 우선순위 열 **헤더에 체계 라벨 `P0~P2(MoSCoW)` 병기 + 값 옆 원형
    Must/Should/Could 병기**(03→12→15 추적성).
  - **계승은 확정일 때만**: 12 우선순위에 `⚠️`/`[확인 필요]`/"게이트2 확정" 표기가 있으면 그 **잠정
    플래그를 별도 열(⚠️)로 분리 보존**(값과 분리 — 변환·하향에도 희석 금지), 게이트2 회부.
  - **per-TC 하향조정**(예: UI 표기 TC를 낮춤)은 **TC 생성 후** 게이트2 검수 항목(게이트1 아님 — 검수
    대상이 게이트 시점에 존재해야 함).
  - **팀 체계가 P0~P2와 다르면 게이트1에서 변환표 확정**(예: P0→Highest). 변환표는 **번호공간 매핑만**
    바꾸고 `⚠️` 잠정 플래그는 건드리지 않음. 게이트2 "P0 잠정 확정"은 게이트1에서 택한 번호공간 기준.
  - **14가 이미 게이트2에서 우선순위를 확정했으면 재질문 금지·계승만**(게이트 중복 방지).
  - **MoSCoW 미보유 출처(12-2 상태정의·추정기능 등) TC**: 12-2/추정기능엔 P 표기가 없으니 (a) **관련
    기능 우선순위 상속 + 출처 명기**(예: 결제·정산 맥락→`F<n>` P0) 또는 (b) **⚠️[확인 필요]로 게이트2
    회부**. 같은 범주라도 맥락이 다르면 우선순위가 갈릴 수 있으니 분기 사유를 명세근거 열에 보존.

## 파이프라인

### Stage 0 — 입력확인·ID/우선순위 감지·도구 probe·degrade
- 12 필수(없으면 중단). 우선순위 표기 감지(12 P0~P2). **14-1 존재 감지**(있으면 dedup 활성).
  **10 존재 감지**(에러 문구 점검 활성). **baseline(확정 기준) 고정** = 12 정책근거표 판정열 + 12-2 근거열.
- **도구 probe**: Playwright(ToolSearch에서 browser navigate/click/screenshot 류 탐색 — **PlayMCP(인증
  전용)는 Playwright 아님**, 가용은 실제 호출 성공으로만 확정) / Notion. 미연결이면 해당 경로 비활성·미제시.
- TC ID/컬럼·우선순위 체계 확인 준비.

### 🚦 게이트1 — TC ID/컬럼 + 우선순위 체계 확정 (Stage 0 검수 대상만)
AskUserQuestion(AI 추천 1안). TC ID 규칙·컬럼 구성·우선순위 체계(추천=12 계승 P0~P2). 팀 체계 다르면
변환표(번호공간만). **TC 미생성이라 검수 대상은 체계뿐** — 기획 결정 답변·per-TC 하향은 여기서 받지
않는다(게이트2 — 검수 대상이 게이트 시점에 존재해야 한다는 원칙).

### Stage 1 — 12 → TC 초안 → 15-1
- 기능 단위마다 **정상 케이스 먼저**, 명세 정의 **예외(예외처리표 6종 등)도 각각 별도 TC**.
- **명세근거 열 필수**(12 섹션ID: `F<n>` 입력값표/예외#n, 12-2 #n). **환각 TC 0**(근거 없으면 작성 금지).
- 기대결과는 **확정 판정 동작만 단정**(family 15판). ⚠️/🔴/[확인 필요]는 placeholder + 15-2 환류.

### Stage 2 — 경계값·예외 보강 + 명세 누락 → 15-1 추가 + 15-2
- 체크리스트 4범주: **경계값**(최소·최대·0·음수·최대치+1·공백·특수문자) / **상태 충돌**(동시성·중간
  이탈·동시 자원경합) / **네트워크·환경**(지연·끊김·세션 만료) / **권한**(비로그인 직접접근·탈퇴 잔여).
- **2축 판정**(회색지대 명확화 — "환각 금지"와 "확정시만 단정"의 경계):
  - **동작 존재O · 결과 확정O** → 정상/예외 TC(기대결과 단정).
  - **동작 존재O · 결과 미정**(⚠️/[확인 필요]) → **placeholder TC + 15-2 환류**.
  - **동작 자체 부재**(명세에 거동 정의 없음) → **TC 미생성, 15-2만**.
- **15-2 ↔ 14-1 dedup(해결상태 전파)**: 동일 항목은 `14-1 #n과 동일`로 cross-ref(재발견 금지).
  - 14-1 **미해결** → 15-2도 미해결 표기만(추천안 재단정 금지, 게이트2 중복 차단조건서 제외).
  - 14-1 **확정**(게이트2 통과) → 그 값이 **12로 환류된 뒤에만** TC 기대결과 단정(추천안 자체 근거 금지).
  - 14 부재 → 12서 직접 도출(dedup 비활성). 🔴은 14·15 공통 전수 사람 확정.

### Stage 3 — 버그 리포트 양식 + 역질문 → 15-3
- **표준 양식**: 제목/심각도(Critical·Major·Minor)/환경(브라우저·OS·계정)/재현 절차(번호)/기대/실제/
  관련 TC ID/첨부(스크린샷 경로). 모호 표현("가끔"/"멀쩡함")은 **역질문**으로 구체화.
- **양식·템플릿 정립 + 역질문까지만**(pre-gate, 마크다운). **발견분 정리는 Stage 4(E2E) 또는 사용자가
  외부에서 가져온 실제 버그가 있을 때만** — **명세/실행 근거 없는 버그 지어내기 금지**(환각 버그 reverse-trap).

### 🚦 게이트2 — TC 검수 + 명세누락 답변 + P0 잠정 확정 + per-TC 하향 + (옵트인) 승인
AskUserQuestion(AI 추천 1안). **검수 대상(15-1·15-2·15-3)이 게이트 시점에 모두 존재**(상위 캐논).
- **TC 검수**: 환각 TC 0(각 TC 명세근거 확인) + 기대결과 단정이 확정 판정에만 붙었는지.
- **명세 누락 답변**(못 채우면 담당자·기한). **P0 잠정(⚠️) 확정.** **per-TC 우선순위 하향조정** 확정.
- **🔴 민감 전수 확정.** (옵트인) **E2E 실행 승인**(probe 연결 시만 제시 + 대상 URL 확인) + **Notion 발행 승인**.
- **해소 전 Notion 쓰기·E2E 실행 차단.**

### Stage 4 — (옵트인) Playwright E2E
승인 + probe 연결 시만. **대상 URL 확인**(staging/test/dev 아닌 도메인 경고·재확인, 운영/결제 의심 시
기본 차단). 테스트 계정 ID는 적되 **비밀번호는 런타임 입력**(비번 필드 `<런타임 입력→****>`, 15-E2E
기록 account 열은 ID만·pw 열 금지, 스크린샷 입력칸 블러). P0/P1 케이스 절차 수행 → 기대 vs 실제 → 스크린샷 → 15-1 결과열 Pass/Fail + 15-E2E기록.
**Fail은 멈추지 말고 기록 후 다음 TC.** 발견 버그는 15-3에 표준화.

### Stage 5 — (옵트인) Notion 발행
승인 후만. parent/teamspace 확인(루트 오생성 방지). **민감정보 더미**(비밀번호·세션토큰·위약금율·
실제 URL·내부 식별자). 되돌리기 어려움 경고 + 생성 후 검수. degrade: 미사용→마크다운 SSOT.

### Stage 6 — 마무리
- **15-QA패키지**(인덱스 + **결과 집계**: Pass/Fail/Blocked/미수행 + **placeholder(보류)** 카운트·진행률%·
  **미수행 P0 잔여**) + **_검증체크리스트**. **placeholder([확인 필요] 기대결과) TC는 별도 버킷**(명세
  해소 전 Pass/Fail 금지·진행률 분모서 제외).
- **집계 리프레시 진입점(결정적)**: 사람이 결과열 채운 15-1을 다시 입력받아 **집계만 재생성**. 결과열
  도메인(Pass/Fail/Blocked/미수행) 고정·placeholder 보류 버킷·**python3 재집계**(E2E 미수행에도 동작).
- **명세-TC 동기화 가이드**: 12 변경 섹션 ↔ 매핑된 TC만 식별·재생성(양방향 출처 링크).
- 환류 write-back(15-2 발견 공백→12/06; 사용자 확인 후 append, 폴더 한정). 🔴/명세누락 잔존 시 ⚠️ +
  완료 보고 금지.

## 에러/노출 문구 동일성 점검 (13 캐논 계승)
- TC 기대결과의 에러/노출 문구 **1차 원천 = 12 예외처리표(사용자 메시지 열)**. 10/14-3(있으면)은
  **동일성 점검 대상이지 단정 원천 아님**.
- 점검: 12 사용자메시지 ↔ 10 디스크립션 ↔ (14-3 있으면) yaml description 대조. 불일치 → 15-2 "문구
  동기화 필요" 환류. **10이 문구 없이 동작만 적은 항목은 "문구 미확정→기대결과 placeholder+질문" 강등.**

## degrade vs 중단 vs 게이트 블로킹
- **중단**: 12 부재(원천).
- **degrade**: 06 부재→예외 기준 근거 ⚠️ / 14-1 부재→12서 직접 도출(dedup 비활성) / 10 부재→에러 문구
  동일성 점검 비활성 / **03 부재 또는 12에 우선순위 표기 부재→게이트1 inline으로 체계 확정** / 12에
  정책근거표·⚠️/🔴 표기 없으면 모호 항목은 보수적으로 15-2(미정 취급) / Playwright 미연결→E2E 비활성·
  수동 안내 / Notion 부재→마크다운 SSOT.
- **게이트 블로킹**: 게이트2 명세누락 미답·P0 잠정 미확정·🔴 미확정 → Notion/E2E 차단.

## 도구 정확성
- **Playwright MCP**(probe) = E2E 옵트인. ToolSearch에서 browser navigate/click/screenshot 류 탐색,
  **PlayMCP(인증 전용)는 Playwright 아님**, 가용은 호출 성공으로만 확정. 미연결→비활성·수동 안내(설치
  명령 떠먹이기 금지, probe 메시지에 `claude mcp add playwright -- npx @playwright/mcp@latest` 1줄 포인터).
- **Notion MCP**(probe) = TC 시트 옵트인 외부발행. 없으면 마크다운 SSOT.
- 산출물 전부 마크다운 — **yaml 파싱 의존 없음**. 텍스트 점검은 python3로(**grep -P 의존 금지**, macOS 미지원).

## _검증체크리스트 본문 (Stage 6 생성, `<주제>`/`<날짜>` 치환)
```
# 검증 체크리스트 — <주제> QA·테스트 (작성일: <날짜>)
- [ ] TC: 각 TC가 12 명세 항목에 근거(환각 TC 0) — 명세근거 열 확인
- [ ] TC 기대결과: 확정 판정(06 운영정책)인 동작만 단정 / ⚠️·🔴·[확인필요]는 placeholder+15-2 환류
- [ ] 우선순위: 12 P0~P2 계승(헤더 라벨·MoSCoW 병기), 잠정 ⚠️ 별도 보존·게이트2 확정
- [ ] 명세 누락: 14-1 있으면 dedup·해결상태 전파(추천안 재단정 금지) / 🔴 전수 사람 확정
- [ ] 에러 문구: 12 예외처리표 = 1차 원천, 10/14-3과 동일성 점검(불일치는 15-2)
- [ ] 결과 집계: 사람이 결과열 채운 뒤 집계 재생성(미수행 P0 잔여 확인)
- [ ] 탐색적 테스트(사람 전담) 범위 = TC 커버 밖 — 확보 시간 투입
- [ ] (E2E 시) 산출물·스크린샷에 평문 비밀번호 없음 / 대상=스테이징·테스트계정
- [ ] (외부발행 시) Notion 전 비밀번호·세션토큰·위약금율·실 URL 더미
```

## 정량 커버리지 (승계형)
- TC: 기능 N → TC M(정상 + 예외 + 경계값 보강). 각 TC 명세근거(12 섹션ID).
- 명세 누락: 14-1 dedup 후 신규 K(14-1 #n cross-ref 별도 표기).
- 결과 집계: Pass/Fail/Blocked/미수행 + placeholder(보류) + 미수행 P0 잔여.
- **자기검산(python3)**: 유형별 분해합 = distinct TC 총수, **확정단정 + placeholder = 총수**, placeholder
  TC 수 = 기대결과 [확인 필요] 행 전수. 불일치 시 ⚠️·완료 보고 금지(**15-2 추적항목 수 ≠ placeholder TC
  수** — 한 미정 항목이 복수 TC를 placeholder화할 수 있음).

## 주의
- **AI가 만든 TC 그대로 믿지 말 것** — 명세에 없는 동작(환각 TC) 섞임. 각 TC 명세근거 확인.
- **우선순위 비즈니스 판단·탐색적 테스트는 사람** — 12 확정 우선순위는 계승, 잠정만 게이트2.
- **Playwright는 운영 서버 금지** — 실 결제·실 데이터 환경 조작은 사고. 스테이징/테스트 계정 한정,
  대상 URL 확인. **비밀번호 평문 금지**(런타임 입력, 산출물·스크린샷 마스킹).
- **탐색적 테스트 대체 불가** — 자동화로 번 시간을 여기 쓰는 게 이 단계의 진짜 목적.
- **명세-TC 동기화** — 12 바뀌면 TC 재생성. 옛 명세 기준 TC는 멀쩡한 기능을 Fail로 만든다.
- 상태명·기능ID·문구는 명세·TC·(있으면)API에서 **동일** 사용.
