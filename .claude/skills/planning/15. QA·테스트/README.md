# QA·테스트 (QA & Test) 스킬

개발된 기능이 기획 의도대로 동작하는지 **12 기능명세를 기준으로 검증**한다. TC는 창작이 아니라
**12 명세를 "절차+기대결과"로 재배열하는 변환 작업** — AI는 변환·체크리스트·포맷팅, 판단(우선순위·
정책 확정·탐색적 테스트)은 사람이다.

## 1. 무엇을 만드나
- `15-1_TC시트.md` — TC 전수(정상+명세예외+경계값보강). 컬럼: TC ID/대분류/소분류/사전조건/절차/기대결과/우선순위/명세근거/결과
- `15-2_명세누락.md` — **명세 누락 — 기획 확인 필요**(핵심 부산물). 14-1 엣지케이스QA와 dedup·해결상태 전파
- `15-3_버그리포트.md` — 표준 양식(제목/심각도/환경/재현/기대/실제/관련TC/첨부) + 모호표현 역질문
- `15-QA패키지.md`(인덱스 + 결과 집계) / `_검증체크리스트.md` / (옵트인) `15-E2E기록.md`·Notion

> **TC는 변환이지 창작이 아니다.** 각 TC는 12 명세 항목에 1:1 근거. **기대결과는 확정 명세일 때만 단정**
> — ⚠️/🔴/[확인 필요]는 placeholder + 15-2 환류. **마크다운 = SSOT.**

## 2. 설치
```bash
mkdir -p ~/.claude/skills/qa-test-design
cp SKILL.md ~/.claude/skills/qa-test-design/SKILL.md
```
설치 후 `TC 만들어줘` / `테스트케이스 뽑아줘` / `경계값 보강해줘`로 트리거된다.

(선택) E2E를 쓰려면 Playwright MCP:
```bash
claude mcp add playwright -- npx @playwright/mcp@latest
```
연결 안 돼 있으면 스킬이 E2E를 자동 비활성하고 수동 안내한다(떠먹이기 안 함).

## 3. 입력 준비 (계승 우선 — 재발명 금지)
- **필수** — 12 기능명세(원천: 기능목록·각 기능 입력값표/예외처리표/정책근거표·12-2 상태정의).
- **권장** — 06 정책(예외 처리 기준) / 14-1 엣지케이스QA(명세 누락 dedup) / 10 화면설계서(에러 문구 동일성·E2E 대상) / 03(우선순위).
- 12 우선순위·예외처리표는 **계승**(재발명 금지). 12 미정/충돌은 TC 기대결과로 단정하지 말고 15-2로 환류.

## 4. 사람 개입 게이트 (2곳, 스킵 불가)
1. **TC ID/컬럼 + 우선순위 체계 확정** — 추천=12 P0~P2 계승. 팀 체계 다르면 변환표(기획 결정·per-TC 하향은 여기 아님).
2. **TC 검수 + 명세누락 답변 + P0 잠정 확정 + per-TC 하향 + 🔴 전수확정 + (옵트인) E2E/Notion 승인** — 해소 전 Notion/E2E 차단.

## 5. 변경 포인트
| 무엇 | 어디 | 바꾸는 법 |
|---|---|---|
| **E2E·외부발행** | 변경포인트 1 / Stage 4·5 | E2E=Playwright MCP(probe) / 외부발행=Notion MCP / 둘 다 없음=마크다운 |
| **계승 출처** | 변경포인트 2 / `## 입력` | 12/06/14-1/10 경로를 본인 폴더로 |
| **출력 루트** | 변경포인트 3 | `qa-test-design-output/<주제>` → 원하는 폴더 |
| **우선순위 필드** | 변경포인트 4 / ID·우선순위 절 | 12 P0~P2 1:1 계승. 팀 체계 다르면 게이트1 변환표(⚠️ 잠정 별도 보존) |
| **심각도 체계** | 변경포인트 5 / Stage 3 | 버그 Critical/Major/Minor는 예시 — 팀 체계로 교체 |

## 6. degrade / 중단 / 게이트 블로킹
- **중단** — 12 부재(원천).
- **degrade** — 06 부재→예외 기준 ⚠️ / 14-1 부재→직접 도출(dedup 비활성) / 10 부재→문구 점검 비활성 / 03·우선순위 부재→게이트1 inline / Playwright 미연결→E2E 비활성·수동 / Notion 부재→마크다운 SSOT.
- **게이트 블로킹** — 게이트2 명세누락 미답·P0 잠정 미확정·🔴 미확정 → Notion/E2E 차단.

## 7. 주의
- **AI가 만든 TC 그대로 믿지 말 것** — 명세에 없는 동작(환각 TC) 섞임. 각 TC 명세근거 확인.
- **기대결과는 확정 명세일 때만 단정** — ⚠️/🔴/[확인 필요]·placeholder는 단정 금지·15-2 환류. QA 증빙·추천안으로 확정 격상 금지.
- **우선순위 비즈니스 판단·탐색적 테스트는 사람** — 자동화로 번 시간을 탐색적 테스트에 쓰는 게 진짜 목적.
- **Playwright는 운영 서버 금지** — 스테이징/테스트 계정 한정, 대상 URL 확인. 비밀번호 평문 금지(런타임 입력·산출물/스크린샷 마스킹).
- **명세-TC 동기화** — 12 바뀌면 TC 재생성. 옛 명세 기준 TC는 멀쩡한 기능을 Fail로 만든다.
- 12 용어집·13 용어집·14 용어집과 상태명·기능ID·문구를 **동일** 사용.
