# 개발 협업 (핸드오프) (Dev Handoff)

핸드오프는 기획서·디자인을 개발팀에 "던지는" 게 아니라 **개발자가 추가 질문 없이 구현을 시작할
수 있는 상태**를 만드는 작업이다. 산출물 = **핸드오프 패키지**: ① 엣지케이스 Q&A ② 티켓(작업
단위 분해) ③ API 명세 초안 ④ 기획-개발 용어집 ⑤ 인덱스. **AI는 질문 생성·분해·포맷팅, 판단
(정책·우선순위)은 기획자.**

## 핵심 원칙 (계승 우선 — 단 "확정본일 때만")

- **상위 산출물 계승, 재발명 금지 — 단 확정 상태일 때만**:
  - **12-3 API 초안 → 14-3로 "구조 변환(transform)"**: API명/경로/요청·응답 필드/기능ID는
    **1:1 매핑(재작명 금지)**, OpenAPI 구조화에 새로 필요한 타입·스키마·응답본문은 **추정 표기**
    (출처: "12-3 계승" vs "신규 구조화"). 재작성·재발명 아님.
  - **13-3 용어집 → 14-4**: "확정 용어집" 표가 채워졌으면 계승, **미확정/부재면 12 자체추출 +
    ⚠️(13 미대조)**. 13이 14에 위임한 코드명은 14가 신규 매핑.
  - **12 잔존 ⚠️/[확인 필요]/🔴 + 12-2 충돌케이스 + 환류 → 14-1 "기획 결정 필요"로 계승**
    (재발견 금지, 출처=`12-2 #n` 표기).
- **AI 추천안 ≠ 확정**: "기획 결정 필요" 추천안은 일반론. 환불 기한·동시성은 06/법무 아는 사람이
  결정. **🔴 민감(개인정보·결제·보안)은 12에서 계승해 전수 사람 확정**(게이트2 통과 조건).
- **API 초안 한계 명시**: "초안, 백엔드 검토 필수" 표기 강제. 인증·멱등성·페이지네이션은 12-3에
  없으니 **"TODO: 백엔드 기술표준 확정"**(임의 확정 금지).
- **Notion/Jira 일괄쓰기 승인 게이트** + 되돌리기 어려움 경고 + 생성 후 검수. **마크다운 SSOT.**
- **티켓 분해 단위 팀마다 다름**: 스프린트 관례·우선순위 체계 게이트1 확인(1티켓=1~3일·AC 3개는 예시 디폴트).
- **용어 동의어 판별 사람 최종**: "구매 확정"vs"거래 완료"가 같은 상태인지 도메인 지식 필요.
- **Figma write 도구 전면 금지**: `add_code_connect_map`/`send_code_connect_mappings`/`use_figma`/
  `create_new_file` 호출 금지. read(`get_code_connect_suggestions`/`get_code_connect_map`)만 참고.
  Code Connect 매핑 작성은 FE/디자인시스템 몫(기획자는 컴포넌트 출처 표기만).

## ID·우선순위 (계승, 재발명 금지)

- 기능ID(12 `F<n>`)·화면ID(S-ID)·케이스ID 계승. 티켓↔기능 매핑.
- **우선순위 매핑표**: **12 P0/P1/P2(=03 Must/Should/Could)를 티켓 우선순위로 1:1 계승**(별도
  P체계 재발명 금지 — 원본 가이드의 P1~P3는 예시, 리터럴 금지). 동일 요구사항이 기능별로 P0/P1로
  갈린 분기 사유를 티켓 설명/매핑열에 보존. 팀 체계가 P0~P2와 다르면 게이트1에서 변환표 확정(예: P0→Highest).
  - **계승은 확정일 때만**(핵심 원칙 동일): 12 우선순위에 `⚠️`/`[확인 필요]`/"게이트2 확정·임의 Must
    금지" 표기가 있으면 **그 미확정 플래그도 함께 계승**해 티켓 우선순위 열에 보존하고 게이트2 회부
    (잠정 P0를 확정처럼 표기 금지).
  - **"03 분류 부재" ≠ "03↔12 충돌"**: 03이 해당 R-ID를 MoSCoW로 미분류(예: "논의 필요"에만)면
    **분류 부재**(충돌 아님) → 12 값 계승하되 ⚠️ 유지. 값이 서로 다른 **충돌**일 때만 **12 우선**
    (기능 단위라 티켓에 근접), 불일치 행 ⚠️ 후 게이트 회부.

## 파이프라인

### Stage 0 — 입력확인·ID/우선순위 감지·도구 probe·degrade
- 12 필수(없으면 중단). 우선순위 매핑(12 P0~P2). **13-3 상태 분기**(확정/미확정/부재).
- **도구 probe**: Notion(ToolSearch 존재)·Context7·Figma read. **Atlassian/Jira 도구가 ToolSearch에
  없으면 Jira 경로 비활성·사용자에게 미제시**(가용은 호출 성공으로만 판별).
- 티켓 분해단위·우선순위 체계 확인 준비.

### 🚦 게이트1 — 티켓 분해단위 + 우선순위 체계 확정 (Stage 0 검수 대상만)
AskUserQuestion(AI 추천 1안). 팀 P체계·1티켓 작업량. **기획 결정 답변은 여기서 받지 않는다**
(질문 목록이 Stage 1에서 생성되므로 — 검수 대상이 게이트 시점에 존재해야 한다는 원칙).

### Stage 1 — 엣지케이스 Q&A → 14-1
- 영역(상태전이/동시성/권한/네트워크/외부 PG 장애/데이터 보존/알림)별 질문.
- **답있음(12 섹션 인용) / 기획 결정 필요** 구분.
- **기획 결정 필요 = 12 잔존 ⚠️/[확인 필요]/🔴 + 12-2 충돌케이스 전수(출처=`12-2 #n`) + 환류 +
  새 개발질문**. **환류 출처 dedup**(06-3 흡수본 > 12-2 충돌 > 08-2 원본, 1회만 등재 = 같은 항목
  표에 한 행만, 출처 병렬 표기는 허용). **"06-3 흡수본" = 06-3에 확정 케이스ID로 정착된 경우만**
  1순위 — 06-3의 "~환류/신설 필요" 백로그 멘션(미정착)은 흡수본 아님 → 12-2 충돌 > 08-2 순으로.
- 추천안 1줄(확정 아님). 표에 **담당자·결정 기한** 컬럼(답 못 채운 항목 추적).

### Stage 2 — 티켓 분해 → 14-2
- 작업 단위(FE/BE/공통). AC 3개 이내. 우선순위 12 계승. 명세 섹션 링크.
- **빈·에러·로딩 화면 티켓 별도**(10-예외처리 계승, **10 입력 존재 시에만**). **상태화면 티켓은
  12 명세 화면으로 한정**, 10이 다루나 12 미명세 화면은 "차기 핸드오프 대기"로 분리.
- 표로 먼저(승인 — 게이트2).

### Stage 3 — API 명세 초안 → 14-3 YAML
- **12-3 구조 변환**: API명/경로/필드/기능ID 1:1, 새 구조는 추정 표기(출처).
- 에러코드 401/403/409/422 + 발생조건(한국어) + **사용자 노출 문구**(10 에러 화면 문구 동일성).
- 12-3 ⚠️/🔴 필드는 description에 "06 정책 미정—확정 전 사용 금지" 보존, example 더미.
  인증/멱등성/페이지네이션 "TODO 백엔드".
- **외부 SDK(PG 등) 필드만 Context7 2-step**(resolve-library-id → query-docs ≤3, 모호 시 생략·⚠️).
  **OpenAPI 형식 자체는 내장 지식/정적 템플릿**(Context7 의존 아님).
- 상단 "논의용 초안·백엔드 검토 후 확정" 고지. **새 기획 미결정(취소≠환불 등)은 14-1로 역환류.**

### Stage 4 — 용어집 → 14-4
- **12 자체추출 우선**(12-2 상태명·도메인 명사) + **13-3 보강**(확정본일 때). 영문/코드네이밍·혼동주의.
- 동의어 사람 최종. **상태명 명세/티켓/API 동일성** 점검.

### 🚦 게이트2 — 기획결정 답변 + 티켓 승인 + API 검토 + 🔴 전수확정 + 구성요소 확정
AskUserQuestion(AI 추천 1안). **검수 대상(14-1~14-4)이 게이트 시점에 모두 존재**(상위 캐논).
- 기획 결정 필요 답변(못 채우면 담당자·기한 기록). 티켓 목록 승인. **🔴 민감 전수 확정.**
- "API 검토" = **백엔드 검토 필수 표기 확인 + 에러코드 한국어/사용자 문구 적정성**(기술표준 확정은
  백엔드 후속).
- **구성요소 확정**: 위 항목 해소 후 14-1~14-4를 확정 상태로 표기(인덱스 패키지는 Stage 6에서 묶음).
  **해소 전 Notion/Jira 쓰기 차단.**

### Stage 5 — (옵트인) Notion/Jira 일괄 생성
승인 후만. parent/teamspace 확인(루트 오생성 방지). **민감정보 더미**(결제/위약금 금액·내부
식별자·실제 엔드포인트/키). 되돌리기 어려움 경고 + 생성 후 검수(레코드 수·민감 필드 샘플).
degrade: 미사용→마크다운 SSOT.

### Stage 6 — 마무리
- **인덱스 패키지**(14-핸드오프-패키지.md, Obsidian↔Notion 위치 링크) + **_검증체크리스트(아래)**.
- **킥오프 운영 가이드**: 미팅 전 선공유 → 의제 = 기획결정표 + 우선순위 → 결정 즉시 14-1/14-2 반영.
- **명세 변경 재동기화**: 12 변경 섹션 ↔ 매핑된 14-2 티켓만 식별·갱신(양방향 출처 링크).
- 환류 write-back(발견 기획 공백→12/06; 사용자 확인 후 append, 폴더 한정). 🔴/기획결정 잔존 시 ⚠️ + 완료 보고 금지.

## OpenAPI YAML 검증 (14-3)
- python3 `yaml.safe_load` 파싱 시도. pyyaml 미설치 시 정적 체크리스트 degrade:
  `openapi: 3.1.x` 핀, 3.0 키워드(`nullable`) 금지, 들여쓰기, **OpenAPI 3.1 루트 필수 키
  (`openapi`·`info`) + `paths`/`components`/`webhooks` 중 최소 1개** 점검(3.1은 paths 루트 필수 아님).

## 도구 정확성

- **Notion MCP**(probe로 가용 확인) = 티켓·패키지 옵트인 외부발행. **Jira = Atlassian MCP, ToolSearch에
  없으면 비활성**. 둘 다 없으면 **마크다운 SSOT**(외부쓰기 0으로 패키지 완성).
- **Context7 MCP**(probe) = 외부 SDK 필드 보정 한정(2-step ≤3). OpenAPI 형식은 내장 지식.
- **Figma read**(probe) = `get_code_connect_suggestions`/`get_code_connect_map` 참고만. **write 전면 금지**.
- 검증 도구는 환경마다 다름 — YAML/스키마 검증은 python3 파싱 + 정적 체크리스트 degrade(과한 도구 의존 금지).

- **AI 추천 정책 그대로 확정 금지** — 환불 기한·동시성은 06/법무 아는 사람이.
