# 사용자 리서치 분석 (User Research Analysis)

수집된 인터뷰 녹취록·설문 데이터를 받아 질적 코딩 → 어피니티 분석 → 페르소나/JTBD →
설문 분석 → 인사이트 리포트를 생성한다. 사람 검증 게이트는 **코딩 프레임 확정 1곳**뿐이다.

**01 시장 리서치와 다름**: 외부에서 데이터를 수집하지 않는다. **사용자가 이미 모은 데이터를 정리·분석**한다.

**핵심 원칙**:
- 모든 인사이트·인용에 참가자 번호(예: `P3`)와 **원문 그대로**를 붙인다(의역 금지).
- 근거가 없으면 지어내지 말고 **"데이터 부족"**으로 표기한다.
- 설문 수치는 암산하지 말고 **스크립트 실행 결과로만** 답한다.

## 입력

- **필수**: `user-research-output/<주제-슬러그>/녹취록/` 의 인터뷰 md (P1~Pn).
  각 파일 첫머리에 참가자 메타(직군·연차·모집 경로)를 권장.
- **선택**: 같은 폴더의 `설문_결과.csv` (있으면 Stage 3, 없으면 스킵)
- 녹취록이 없으면 위치를 사용자에게 묻고 중단한다.

> 전사(음성→텍스트)는 이 스킬 범위 밖이다. 클로바노트(웹, 한국어 정확) 또는 Whisper(로컬, 보안)로
> 전사해 md로 넣어둔다.

## 출력 위치

결과물은 **`user-research-output/<주제-슬러그>/`** 폴더(현재 작업 디렉토리 기준)에 저장한다:

<!-- 변경 포인트: 다른 위치에 모으려면 이 경로를 바꾸세요.
     예) Obsidian 볼트 → "리서치/<주제-슬러그>/" -->

| 파일 | 내용 |
|---|---|
| `02_어피니티_분석.md` | 질적 코딩 + 어피니티 그룹 + 대표 인용문 |
| `03_페르소나.md` | 페르소나 2~3개 + JTBD |
| `04_설문_분석.md` | 설문 교차분석 (CSV 있을 때) |
| `05_notebooklm-아카이브.md` | NotebookLM 출처 기반 Q&A (인증되면) |
| `06_인사이트_리포트.md` | 종합 인사이트 |
| `_검증체크리스트.md` | 사람이 확인해야 할 항목 |

- 출력 폴더가 없으면 생성한다.
- `<주제-슬러그>`는 주제/프로젝트명을 짧은 kebab-case로 (예: `페이롤리`).

## 파이프라인

아래 6단계를 순서대로 실행한다. Stage 3(설문)·Stage 4(NotebookLM)는 독립적으로 degrade한다.

### Stage 0 — 입력 확인 & 코딩 프레임 제안

`<출력폴더>/녹취록/`의 인터뷰 md(P1~Pn)를 모두 읽는다. 없으면 녹취록 위치를 사용자에게 묻고 중단한다.
`설문_결과.csv` 존재 여부도 확인해 둔다.

녹취록 전체를 훑어 **코드 대분류 체계를 제안**한다.
- 기본 제안: `페인포인트 / 니즈 / 현재 해결책 / 전환 장벽 / 사용 맥락` 5개 대분류.
- 도메인에 맞게 조정 제안을 덧붙인다.

### 🚦 게이트 — 코딩 프레임 확정 (사람 개입, 필수)

AskUserQuestion으로 제시한다:
- 제안한 코드 대분류 체계 → 사용자가 OK / 수정
- **개인정보 경고**: "녹취록을 NotebookLM 등 외부에 올리려면 실명·연락처를 먼저 비식별화하세요."

사용자가 코딩 프레임을 확정하기 전에는 Stage 1로 넘어가지 않는다.
확정한 프레임을 이후 코딩의 기준으로 삼는다.

### Stage 1 — 질적 코딩 + 어피니티 분석

확정된 코딩 프레임으로:
1. 의미 있는 발화 단위마다 코드(태그)를 부여한다. 대분류 아래 자유롭게 세분화.
2. 같은 코드끼리 묶어 어피니티 다이어그램 형태로 정리하고, 그룹마다 **대표 인용문 2~3개를
   참가자 번호(예: `P3`)와 함께 원문 그대로** 인용한다(의역 금지).
3. **3명 이상**에게서 반복된 패턴만 "핵심 인사이트"로 승격하고, 1~2명 언급은 "추가 탐색 필요"로 분리한다.

→ `02_어피니티_분석.md`에 저장한다.

### Stage 2 — 페르소나 / JTBD

`02_어피니티_분석.md`와 녹취록 원문을 근거로:
1. 참가자 행동이 뚜렷이 갈리는 **기준 축 2~3개**를 먼저 제안한다(예: 월 정산 건수, 세무 지식 수준).
2. 그 축으로 페르소나 2~3개를 작성한다. 각 페르소나:
   이름 / 한 줄 정의 / 목표 / 핵심 페인포인트 / 현재 해결책 / 대표 인용문(실제 발화·P번호).
3. 페르소나별 JTBD를 `"(상황)일 때, (동기)하고 싶다, 그래서 (기대 결과)를 얻고 싶다"` 형식으로 3개씩.
4. 근거가 부족한 항목은 지어내지 말고 **"데이터 부족"**으로 표기한다.

→ `03_페르소나.md`에 저장한다.

### Stage 3 — 설문 CSV 분석 (선택적)

`설문_결과.csv`가 **있을 때만** 실행한다(없으면 이 단계 스킵).

- pandas 스크립트를 작성·실행한다. **표를 눈으로 읽고 암산하지 말고, 반드시 스크립트 실행 결과로만 답한다.**
- 내용: ① 문항별 기초 통계(객관식 빈도·비율, 척도형 평균·표준편차, 주관식 키워드 분류)
  ② 핵심 교차표·상관 ③ 페르소나 세그먼트(`03_페르소나.md` 참고)별 응답이 가장 갈리는 문항 Top 5.
- 스크립트는 `scripts/` 폴더에 저장해 재실행 가능하게 한다.

→ `04_설문_분석.md`에 저장한다.

### Stage 4 — NotebookLM 아카이브 (선택적, degrade)

**먼저 `server_info`로 `auth_status`를 확인한다. `stale`/`not_configured`이면 노트북 생성을 시도하지 말고
곧바로 스킵**하고 `nlm login`을 안내한다.

인증되면(두 서버 중 `notebooklm-mcp` CLI 우선):
1. `"<주제> 사용자 리서치"` 노트북 생성(동명 존재 시 재사용)
2. `녹취록/`의 P1~Pn을 각각 소스로 추가. **개인정보 주의: 비식별화되지 않은 녹취록은 올리지 않는다**
   (게이트에서 사용자가 확인하지 않았으면 이 단계를 스킵).
3. 인덱싱 polling(약 10초 간격, 상한 90초)
4. 질의 예: `"참가자들이 가장 자주 언급한 어려움 상위 3가지를 출처(P번호)와 함께 찾아줘."`

→ `05_notebooklm-아카이브.md`에 저장한다.

**degrade**: 인증 만료 → 스킵 + `nlm login` 안내 / 비식별화 미확인 → 스킵.

### Stage 5 — 인사이트 리포트 + 검증 체크리스트

Stage 1~4 결과를 종합해 `06_인사이트_리포트.md`를 만든다(핵심 인사이트 → 근거 인용 → 페르소나 → 설문 교차 검증 순).

이어서 `_검증체크리스트.md`를 아래 템플릿으로 생성한다(`<주제>`/`<날짜>`는 실제 값으로 치환):

```markdown
# 검증 체크리스트 — <주제> 사용자 리서치 (조사일: <날짜>)

> AI 분석은 검증된 결론이 아니라 "잘 정리된 초안"이다. 그룹핑·해석은 리서처의 일이다.

- [ ] 인용문 원문 대조 — 합성·미묘한 변형, 타임스탬프 오류 확인 (02_어피니티_분석.md)
- [ ] 어피니티 그룹 직접 재배열 — "이 묶음이 정말 같은 문제인가" 검토
- [ ] 페르소나는 가설 — "데이터 부족" 표시 유지, 설문/출시 데이터로 재검증 (03_페르소나.md)
- [ ] 설문 수치 — 스크립트(`scripts/`) 검토로 재현성 확인 (04_설문_분석.md)
- [ ] 전사 오류 — 도메인 용어·서비스명·고유명사 교정
- [ ] 개인정보 — 외부 공유 전 비식별화 확인
```

마지막으로 사용자에게 보고한다:
- 산출물 폴더 경로
- 고지: "AI 분석은 초안입니다. 위 체크리스트, 특히 인용 원문 대조와 어피니티 재배열을 꼭 거치세요."

## 주의

- 인용은 **원문 그대로**, 참가자 번호 표기. 의역·합성 금지.
- 설문은 **암산 금지** — 스크립트 실행 결과로만.
- 페르소나는 **가설**이다. "데이터 부족"을 지우지 마라.
- **개인정보**가 최우선 리스크다. 외부 서비스(NotebookLM) 업로드 전 비식별화.
- AI 코딩·그룹핑은 초안이다. 한 번은 사람이 직접 재배열해 관점을 넣는다.
