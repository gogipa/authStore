# 정보구조 설계 (IA) 스킬

기능/요구 목록 → **사이트맵(IA 트리) · 내비게이션 구조 · 메뉴 라벨**을 자동 생성하는 Claude Code 스킬.
초안과 기계적 검증(depth·중복라벨·고아노드·누락)은 AI가, 분류·라벨·전략적 배치 결정은 사람이 한다.

## 1. 무엇을 만드나
- `07-1_IA트리.md` — 들여쓰기 트리(상위 ID 병기·권한 표기·미배치 섹션·차기 로드맵·어드민 별도) + Obsidian mermaid 다이어그램
- `07-2_IA검증리포트.md` — depth4+ 경로·핵심 과업 탭 횟수·중복 라벨·고아 노드·요구 대비 누락·정책-스코프 불일치·(카드소팅 CSV 있으면) 분석
- `07-3_경쟁사IA벤치마크.md` — (선택) 경쟁사 내비 구조 비교
- `_검증체크리스트.md` — 사람이 확인할 항목

## 2. 설치
```bash
mkdir -p ~/.claude/skills/information-architecture
cp SKILL.md ~/.claude/skills/information-architecture/SKILL.md
```
설치 후 `정보구조 설계해줘` / `사이트맵 만들어줘` 같은 말로 트리거된다.

## 3. 입력 준비
- **필수** — 03 요구사항정의 산출물(요구·기능 목록 + ID + MoSCoW 스코프). 한 파일이어도 됨.
- **권장** — 06 정책정의 산출물(권한·상태 정책). 로그인/자격/민감정보 노출 조건(🔒/🩺/🔑)의 근거.
- **선택** — 04 상위기획(전략) / 01 경쟁사(IA 벤치마크) / 02 사용자리서치(라벨 대조) / **카드소팅 결과 CSV**.
- **카드소팅 CSV 형식**(있을 때): long format 권장 — `participant_id, card_id, card_label, category_label`. 헤더가 다르면 스킬이 실제 헤더를 보고 매핑을 물어본다.
- **ID 컨벤션은 감지**한다 — `R1`이든 `US-A3`든 `F-001`이든 입력 문서가 쓰는 ID를 그대로 계승하므로 별도 설정 불필요.

## 4. 사람 개입 게이트 (2곳)
1. **플랫폼·1depth 골격 확정** — 플랫폼 유형(모바일앱/웹/B2B) + 1depth 골격 2안 중 택1. AI 추천안 제시.
2. **미배치 배치 + 검증 반영 결정** — 미배치 기능 배치 + 검증 리포트(중복/depth/카드소팅) 반영. **미배치 0 AND 핵심 과업 경로 검증이 끝나야 통과.**

## 5. 변경 포인트
| 무엇 | 어디 | 바꾸는 법 |
|---|---|---|
| **플랫폼 유형** | Stage 2 주석 | 모바일앱=탭바 / 웹=GNB / B2B콘솔=LNB. 1depth 개수 관례도 조정 |
| **입력 경로** | `## 입력` 주석 | 03·06 산출물이 다른 폴더/Notion DB면 경로 교체 |
| **출력 경로** | `## 출력 위치` 주석 | 기본 `information-architecture-output/` → 원하는 폴더(예: Obsidian 볼트) |
| **Figma 팀** | Stage 5 주석 | `whoami`로 본인이 edit 권한 가진 팀에 생성(View-only 팀 불가) |
| **ID 컨벤션** | (자동) | 감지 기반이라 보통 손댈 필요 없음 |

## 6. degrade 규칙 (없어도 핵심 산출물은 나온다)
- **03 없음** → 핵심 입력이라 위치 묻고 **중단**.
- **06 없음** → 권한 노드를 `🔒?`(미확정)로 표기 + "06 미연동—노출 정책 미검증" 명시(무음 생략 안 함).
- **01 없음** → 경쟁사 벤치마크(07-3) 생략.
- **02 없음** → 라벨 사용자언어 대조 생략(주의 명시).
- **카드소팅 CSV 없음** → 분석 스킵 + "미검증" 명시.
- **Figma 미인증** → FigJam 공유본 스킵(mermaid가 원본이라 무방).

## 7. 산출물 흐름
Stage 0 입력·ID 감지 → 1 요구→화면 분해 → 2 1depth 골격 → **게이트1** → 3 트리(07-1) → 4 검증(07-2) → **게이트2** → 5 확정·mermaid 재생성·(선택)FigJam → 6 정합성·체크리스트

## 8. 주의
- **텍스트 트리가 원본, 다이어그램은 파생물.** mermaid/FigJam은 트리를 고친 뒤 재생성. FigJam에서 직접 고친 건 **07-1에 수동 역반영**(자동 반영 안 됨).
- **라벨은 사람이 최종 확인** — AI 메뉴명은 업계 평균일 뿐. 사용자 언어와 대조.
- **"depth 3 이하"를 절대시하지 마라** — 깊어도 명확 > 얕지만 모호. 검증은 후보 제시일 뿐.
- **IA 확정 전 와이어프레임 시작 금지** — IA가 흔들리면 이후가 전부 재작업. 미배치 0·핵심 경로 검증 후 다음 단계로.
- 도메인 용어가 강한 서비스(B2B·의료·금융)일수록 카드소팅 등 실사용자 검증을 생략하지 마라.
