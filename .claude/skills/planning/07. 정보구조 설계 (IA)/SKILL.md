# 정보구조 설계 (Information Architecture)

03 요구사항정의 + 06 정책정의를 받아 **IA 산출물 1부**(사이트맵 트리 + 내비 구조 + 라벨 + 검증 리포트)를
만든다. 사람 개입 게이트는 **1depth 골격 확정 1곳 + 미배치·검증 반영 결정 1곳, 총 2곳**이다.

**AI의 역할**: **관례 기반 초안·구조화·기계적 검증까지. 분류·라벨·전략적 배치 결정은 사람.** AI 그룹핑은 "업계 평균"이라 그럴듯해 보이지만 우리 타깃의 멘탈모델을 모른다.

**핵심 원칙**:
- **텍스트 트리 = 원본(source of truth), 다이어그램(mermaid/FigJam) = 파생물.** IA는 와이어프레임·플로우 내내 바뀌므로 마크다운 트리를 고치고 다이어그램은 재생성한다.
- **미배치 0 AND 핵심 과업 경로 검증 = 다음 단계(와이어프레임) 진입 전제.** 둘 중 하나라도 미달이면 '완료'로 보고하지 않는다.
- **depth 규칙을 절대시하지 마라.** 깊어도 명확한 경로 > 얕지만 모호한 경로. 검증 리포트는 후보를 제시할 뿐 전부 고쳐야 하는 게 아니다.
- **상위 ID를 계승하라.** 입력 요구사항 문서가 쓰는 ID 컨벤션을 감지해 그대로 쓴다(`F-001` 같은 리터럴 하드코딩 금지).
- **라벨은 사람이 최종 확인.** AI 메뉴명은 무난하지만 서비스 보이스·기존 사용자 용어와 충돌할 수 있다 — 사용자 리서치의 언어와 대조.

- 03이 없으면 위치를 묻고 **중단**한다.

## 파이프라인

### Stage 0 — 입력 확인 & 정규화
03(필수)·06(권장)·04/01/02(선택)을 읽는다. 03 없으면 위치 묻고 중단.
- **ID 패턴 감지**: 요구사항 문서의 ID 열을 읽어 실제 접두사·자릿수·하이픈 유무를 감지(예: `R1`, `US-A3`, `F-001`)하고 그 패턴을 이후 트리 병기·누락검출에 그대로 쓴다. 누락검출 정규식은 하이픈 유무 모두 매칭(`[A-Z]+-?\d+`). **감지 실패 시 1회 질문.** (이 문서에 나온 어떤 ID 예시도 리터럴로 가정하지 마라.)
- **MoSCoW 스코프 분류**: Must/Should/Could = 본 트리 대상, **Won't = 차기 로드맵 대상**(본 트리 미배치).
- **정규화 단위 = 요구사항 ID 우선**: 유저스토리가 요구 ID를 괄호로 포함하면 요구 ID 기준으로 펼치고 US-ID를 동반 병기.
- **06 권한 → 게이트 종류 매핑 준비**: 명시적 권한 매트릭스 파일이 없으면 운영정책 문장에서 추출. 종류 구분 — **🔒 로그인 / 🩺 자격·처방 확인 / 🔑 민감정보 동의**, 불명은 🔒 일반화. 06 케이스ID를 노드 근거로 병기.

### Stage 1 — 요구사항 → 화면 분해
각 요구/스토리를 **1개 이상**의 화면·진입점으로 전개한다(1:N 허용). AC(인수조건)에서 화면 단서를 뽑는다(예: 알림 동의/관리 요구 → 동의 화면 + 관리 화면). **분해 후 화면 수가 요구 수보다 적으면 경고**한다(요구를 1:1로 박으면 앙상한 트리가 된다).
- **정책 → 화면 역추적**: 06 정책 중 **사용자 대면 절차**(환불·반품 신청 / 분쟁·클레임 접수 / 결제 실패 통지·재결제 / 자동갱신 사전 고지 / 해지 완료·환불 안내)는 03 요구에 없어도 화면이 필요하다. 06을 훑어 대응 화면을 전개하되, **03 요구에 없는 신규 화면은 `⚠️정책 파생(06 케이스ID)/요구 없음` 태그**를 달고 게이트2 MVP 포함 결정 대상으로 남긴다(IA가 임의 확정 금지).
- **필수 골격 화면 점검**: 가입·로그인·**온보딩(최초 프로필 입력·필수 동의)**·**empty-state(구독 0건 등 첫 진입)**·(커머스면) 검색/카테고리가 트리에 있는지 체크. 특히 민감정보 동의·프로필이 "마이" 깊숙이만 있으면 신규 유저 동선이 끊긴다 — 온보딩으로 끌어올린다.

### Stage 2 — 플랫폼 유형 + 1depth 골격 제안
**플랫폼 유형**을 먼저 정한다: 모바일앱(하단 탭바) / 웹(GNB) / B2B 콘솔(LNB). 이에 맞춰 1depth 골격 **2안**을 제시한다(근거: 04 전략·01 업계 관례·02 사용자언어). 라벨은 각 골격안에 종속해 함께 제시.

### 🚦 게이트1 — 플랫폼·1depth 골격 확정 (사람 개입, 필수)
AskUserQuestion으로 골격 2안 중 택1(**AI 추천 1안을 먼저** 제시). 1depth는 전략적 선택이라 사람이 정한다(예: "등록 버튼을 탭바 중앙에 둘 만큼 전환이 중요한가"). **확정 전에는 Stage 3으로 넘어가지 않는다.**

### Stage 3 — IA 트리 초안 → 07-1
확정 골격 아래 전 기능을 배치한다.
- 각 노드에 **상위 ID 병기**(Stage 0에서 감지한 컨벤션) + **권한 표기**(🔒/🩺/🔑 + 06 케이스ID).
- **스코프 태그 일관 표기**: 모든 노드에 `[M]`/`[S]`/`[C]`(Must/Should/Could)를 빠짐없이 달고, 하단 mermaid에도 동일하게 반영한다(Could만 달고 Should를 빼면 09 와이어프레임에서 컷 판단 불가). 본문 트리 ↔ mermaid 스코프 정보 불일치 금지.
- **상위 ⚠️미정 플래그 승계**: 03·06 등 상위 문서가 ⚠️미정으로 남긴 항목(미해결 정책 충돌 등)을 IA에서 임의로 '확정'으로 단정하지 마라. IA가 한 안을 가정했으면 `가정(상위 미정)`으로 표기하고 게이트2 결정 대상에 넣는다.
- **미배치 섹션 강제**: 애매한 기능을 아무 데나 욱여넣지 말고 맨 아래 "미배치"에 **사유와 함께** 모은다.
- **차기 로드맵 섹션**: Won't 항목을 본 트리와 분리해 별도 섹션에 둔다.
- **관리자(어드민) 기능은 별도 트리**로 분리.
- 하단에 mermaid flowchart 추가(방향 LR, 1depth 탭별 subgraph, 노드 라벨은 메뉴명만, ID 제외). 텍스트 트리·mermaid는 **이모지 사용 OK**(로컬 렌더). 생성 시 노드 40 초과면 탭별 다이어그램으로 분리(50+는 가독성 한계 — 절대기준이 아니라 "비대하면 분리"라는 구조 기준).
- **06 부재 시**: 권한 추정 노드를 `🔒?`(미확정)로 강제 표기(무음 생략 금지).

### Stage 4 — IA 검증 리포트 → 07-2
트리를 순회·전수검사한다:
1. **구조**: depth 4 이상 경로를 "홈 > 검색 > …" 형식으로 나열 / 핵심 과업 최소 탭 횟수 / 동일·유사 라벨이 다른 위치에 있는 경우 / 고아 노드.
2. **누락·스코프**: 요구 ID 대비 IA에 없는 기능(기계 검출) / **정책 → 화면 역추적**(06의 사용자 대면 정책에 대응 화면이 없으면 플래그) / **정책-스코프 불일치**(06 정책이 Won't 항목을 참조하면 플래그) / **스코프 태그 누락·본문↔mermaid 불일치** 점검.
3. **카드소팅**(CSV 있을 때만): long format 기대(`participant_id, card_id, card_label, category_label`) → 헤더 검증 → 불일치 시 실제 헤더 제시·매핑 질문 → 컬럼 누락 시 **분석 스킵 + "미검증" 명시**. 분석되면 참가자 70%+ 합의 vs 갈린 카드 구분, IA 불일치 항목마다 **"IA 수정 / 라벨만 수정 / 현행 유지" 3선택지** 의견.

### 🚦 게이트2 — 미배치 배치 + 검증 반영 결정 (사람 개입, 필수)
AskUserQuestion으로 ⚠️결정 필요 항목(미배치 기능 배치 + 검증 리포트 반영: 중복 라벨·depth 초과·카드소팅 불일치)을 한 묶음으로 제시(많으면 우선순위/묶음, **AI 추천 디폴트**). **통과 차단 조건: 미배치 0 AND 핵심 과업 경로 검증 완료** — 미달이면 다음 단계로 넘기지 않는다.

### Stage 5 — 확정 반영 + (선택) 공유본
게이트2 결정을 트리에 반영하고 mermaid를 재생성한다.
(선택) **FigJam 사이트맵 공유본** — 게이트2 통과 후 **리뷰·공유가 필요할 때만, 사용자 확인 후** 생성:
- `figma-generate-diagram` 스킬이 있으면 선행 로드, 없으면 MCP instructions 폴백 후 `generate_diagram` 호출.
- `whoami`로 **쓰기 가능한 Dev/edit 팀** 확인 → 회사/공유 워크스페이스 쓰기는 사용자 확인 후 → 미인증/실패 시 스킵.
- **generate_diagram 변환 규칙**(스키마 제약): **이모지 금지·`\n` 금지·노드 텍스트는 따옴표(`["..."]`)·classNames에 'end' 금지.** 🔒/🩺/🔑는 텍스트 라벨(`["회원정보 (로그인필요)"]`)+색상으로 치환. 1depth 탭은 색으로 구분.
- 생성 후 고지: "초안 품질이라 5~10분 수동 정리 필요 / FigJam에서 직접 고친 내용은 **07-1 원본 트리에 수동 역반영**해야 함(자동 반영 안 됨)."

### Stage 6 — 정합성 점검 + 마무리
트리 ↔ 검증 리포트 ↔ 정책 간 정합성을 재점검한다. `_검증체크리스트.md`를 작성하고, **미배치 잔존/핵심 경로 미검증이 있으면 ⚠️ 표기 + 사용자 확인 없이 '완료' 보고 금지**.

`_검증체크리스트.md` 템플릿(`<주제>`/`<날짜>` 치환):

```markdown
# 검증 체크리스트 — <주제> 정보구조(IA) (작성일: <날짜>)

> AI 그룹핑은 "업계 평균"일 뿐 우리 타깃의 멘탈모델이 아니다. 라벨·분류는 사람이 최종 확인.

- [ ] 미배치 0 — 07-1 미배치 섹션이 비었는가 (와이어프레임 진입 전제)
- [ ] 핵심 과업 경로 검증 — 주요 과업 최소 탭 횟수가 납득되는가 (07-2)
- [ ] 라벨 — AI 메뉴명을 사용자 언어와 대조했는가 (서비스 보이스·기존 용어 충돌)
- [ ] depth 초과 후보 — 깊어도 명확하면 유지(절대 규칙 아님), 모호하면 수정 (07-2)
- [ ] 중복/유사 라벨 — 같은 라벨이 다른 위치에 있지 않은가 (07-2)
- [ ] 카드소팅 — (CSV 있으면) 70%+ 합의와 어긋난 분류를 검토했는가 / (없으면) "미검증" 인지
- [ ] 정책 연동 — 06 권한·상태 정책이 노드 노출(🔒/🩺/🔑)에 반영됐는가 / (06 미연동이면) 미검증 인지
- [ ] 정책-스코프 불일치 — 06 정책이 Won't(차기) 항목을 참조하지 않는가 (07-2)

- [ ] 스코프 태그 — 전 노드 [M/S/C] + mermaid 동기화 / 상위 ⚠️미정을 '확정'으로 단정하지 않았는가
- [ ] FigJam — 직접 수정분을 07-1 원본 트리에 역반영했는가 (해당 시)
```

## 주의
- **AI 그룹핑은 그럴듯한 함정이 될 수 있다.** 도메인 용어가 강한 서비스(B2B·의료·금융)일수록 카드소팅·트리테스트 같은 실사용자 검증을 생략하지 마라.
- **라벨은 반드시 사람이 최종 확인.** 사용자 리서치의 사용자 언어와 대조.
- **"depth 3 이하"를 절대시하지 마라.** 깊이보다 각 단계 선택의 명확성이 중요. 검증 리포트는 후보 제시일 뿐.
- **Mermaid 렌더링 한계**: 노드 50+면 읽기 어렵다 — 탭별 분리 조건을 미리 넣어라.
- **FigJam 자동 생성은 초안 품질**: 5~10분 수동 정리 예산. FigJam 직접 수정은 원본 트리에 자동 반영 안 됨 — 07-1에 수동 역반영.
- **흔한 실수**: IA 확정 전 와이어프레임 시작. IA가 흔들리면 09단계 이후가 전부 재작업 — 미배치 0·핵심 과업 경로 검증 후 진행.
- **ID 컨벤션을 가정하지 마라** — 요구사항 문서가 쓰는 실제 ID를 감지해 계승(이 문서의 예시는 예시일 뿐).
