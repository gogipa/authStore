# 비즈니스 모델 설계 (Business Model Design)

04 원페이저(가치제안)를 받아 **BM 캔버스 · 경쟁사 가격정책 · 수익 시뮬레이션(xlsx) · 단위경제(CAC/LTV)**
를 산출한다. 사람 개입 게이트는 **수익원 확정 1곳 + 정량 가정값 확정 1곳, 총 2곳**이다.

**AI의 역할**: 캔버스를 요약·재구성하고 **계산하는 코드를 쓴다**. 가정의 타당성 판단과 의사결정은 사람.

**핵심 원칙**:
- **숫자는 스크립트로만. 암산 금지.** LLM은 36개월 복리·민감도 격자에서 그럴듯하지만 틀린 숫자를 낸다. 채팅 요약은 **스크립트 stdout/ xlsx를 그대로 인용**하고 재계산·재반올림하지 않는다. xlsx가 진실의 기준.
- **캔버스는 생성이 아니라 요약·재구성.** 모든 항목에 출처. 출처 없는 순수 추정엔 ⚠️.
- **가격은 출처 URL + 확인 날짜 강제**, 확인 불가는 추측 금지. 핵심 2~3곳은 사람이 요금 페이지를 직접 대조.
- **가정값엔 근거(벤치마크) 별도 명기.** "깔끔한 xlsx ≠ 맞는 결과."
- 가격·환불·구독의 **법적 제약은 06단계 법무 검토로 이관**(여기서 끝내지 않는다).

### Stage 3 — 수익 시뮬레이션 (스크립트 계산)
`scripts/revenue_sim.py`를 작성·실행한다.
- 가정은 스크립트 **상단에 변수로 분리**하고, 각 변수에 **`# 근거: <출처/벤치마크 또는 추정>` 주석**과 **단위 주석**(예: `SUB_PRICE_MONTHLY`, `CHURN_MONTHLY`)을 단다. 무근거 변수는 xlsx 가정 시트에 ⚠️추정으로 플래그.
- 시나리오 3개(보수/기본/낙관 전환율 등), 36개월 월별: 유료 구독자 수·MRR·누적 매출. 성장은 **월 복리 환산**, 연간결제 할인·비중 반영.
- `openpyxl`로 `revenue_simulation.xlsx` 생성 — **"가정" / "월별 상세" / "시나리오 비교"** 시트.
- 채팅 요약용 핵심 숫자(예: 36개월차 MRR·누적·BEP 도달월)를 **stdout으로 print**한다.
- **계산은 반드시 스크립트 실행으로.** 채팅 요약은 stdout/ xlsx 값을 그대로 인용하고 따로 계산하지 않는다.
- → `scripts/revenue_sim.py` + `revenue_simulation.xlsx` + 요약 `05-3_수익시뮬레이션.md`

### Stage 4 — 단위경제 (CAC/LTV) + 민감도
`scripts/unit_economics.py`를 작성·실행한다.
- **CAC**: 채널별 가중 평균.
- **LTV = (월 ARPU × gross margin%) ÷ 월 churn율** — 단위를 **월로 통일**(ARPU·churn 모두 월). 단위를 섞으면 12배 오차가 난다.
- 산출: LTV / CAC / LTV·CAC 비율 / CAC 회수 기간(개월).
- **민감도 격자**: 이탈률 3%~8%(1%p 간격) × 전환율 3/5/8%. **LTV/CAC < 3 인 셀을 구분 표시**. 격자의 모든 셀과 임계 플래그는 **스크립트가 생성**하고 LLM이 수기로 채우거나 재계산하지 않는다.

- 마지막에 **손익이 무너지는 임계 가정이 무엇인지 한 단락**으로 요약한다.
- → `scripts/unit_economics.py` + `05-4_단위경제분석.md`

## 주의
- **암산 금지.** 채팅에 찍힌 숫자가 아니라 스크립트 출력·xlsx가 기준이다. 요약과 xlsx가 다르면 xlsx가 맞다.
- 의존성(openpyxl/pandas) 미설치 시 **md 수기표로 우회하지 마라** — 설치 후 재실행, 안 되면 중단.
- **디폴트 가정값은 특정 업종 예시다.** 우리 사업 벤치마크로 교체하지 않은 시뮬 결과는 무의미.
- **LTV 공식은 단순화 모델** — 초기 검토용. 출시 후 17단계 실데이터로 갱신.
- 가격·환불·자동갱신 고지·청약철회 등 **법적 제약은 06단계**에서 법무 검토.
- 가격표는 유통기한이 짧다 — 조사 날짜를 박고, 의사결정 직전 직접 재확인.
