## 1. 목표

G4 최종 승인 화면(SCR-08)의 미리보기와 사전 검증을 만든다. `GET …/approval`은 저장된 산출물(③ 판정, ④, ⑥-3, ⑦, ⑧)과 프로필만 읽어 상품명·가격·마진 분해·사이즈 옵션·이미지·상세·고시·태그·요청 JSON 초안을 한 번에 주고, `POST …/pre-validations`는 RG-08 검사 15항목을 돌려 항목별 통과·실패·사유·고칠 단계를 준다. 하나라도 실패하면 '승인·등록' 버튼이 꺼지고 고칠 단계로 가는 링크가 보인다. 흐름에서는 ⑧ 뒤 G4 자리이고, 승인·등록 API는 P4-03이 만든다.

## 4. 핵심 규칙

1. 두 API 모두 후보가 `AWAITING_APPROVAL`일 때만 된다. 아니면 409 `CANDIDATE_STATUS_INVALID`(`details.allowed=['AWAITING_APPROVAL']`), 없는 후보는 404 `CANDIDATE_NOT_FOUND`다. 미리보기는 외부 호출을 하지 않는다. 사전 검증은 상태를 바꾸지 않고 결과를 저장하지 않으며, 부를 때마다 새로 계산해 200을 준다. (05-1 §2.9, 05-2 `getCandidateApproval`·`runCandidatePreValidation` x-decision §7.5-38)
2. 검사 코드는 15개다: `REQUIRED_FIELDS`·`IMAGES`·`OPTIONS`·`TAGS`·`NOTICE_BLOCK`·`ORIGIN`·`JAPAN_WORDING`·`MIN_BLOCK_WORDS`·`NEGATIVE_MARGIN`·`EXTRA_CHARGE_WORDING`·`JUDGEMENT_FRESHNESS`·`REPRESENTATIVE_IMAGE_SOURCE`·`STEP_FRESHNESS`·`CATEGORY`·`DUPLICATE`. 항목 모양은 `{checkCode, passed, severity, reason, stepCode, gateCode}`이고 M1 항목은 모두 `BLOCK`이다. `approvable` = BLOCK 항목 모두 통과. P4-03의 승인 직전 재검증이 같은 서비스를 부른다. (05-3 §5.3, PRD §8.7 RG-08 '하나라도 실패하면 승인 버튼 비활성', F-AP-09)
3. `REQUIRED_FIELDS`: 요청 초안에 name, detailContent, 대표이미지 URL, salePrice, leafCategoryId, stockQuantity, `SHOES` 필수 항목, originAreaInfo(`importer` 포함), afterServiceInfo, deliveryInfo(`deliveryCompany` 포함), customsTaxType, `minorPurchasable`, `naverShoppingRegistration`, `channelProductDisplayStatusType`이 모두 있다. 상품명이 100자를 넘거나 `importer`가 비면 실패다. 글자 수를 세는 방식은 문서에 없음 → 구현 때 Proposed로 정하고 기록. (F-AP-11, US-17 AC1, US-21 AC3)
4. `IMAGES`: 요청 초안과 최종 `detailContent`의 모든 이미지 URL이 `uploaded_image.url`에 있다(UNIQUE `url`로 역조회). 대표 정확히 1장, 추가 9장 이하, 업로드본은 1000×1000, 업로드본의 원천에 `REFERENCE_ONLY` 파일이 없다. (F-AP-12, PRD §8.7 이미지 행, ERD `uploaded_image`)
5. `OPTIONS`: 옵션 사이즈는 모두 재고 > 0이고, 같은 mm 옵션명이 없고, `stockQuantity` = 옵션 재고 합이며, 모든 옵션에서 salePrice + 옵션가 ≥ 10원이다. ⑥-3 `notice_sizes_mm` 집합 = 사양 블록의 사이즈 집합 = 옵션 사이즈 집합이다. (F-AP-13, RG-06, US-20 AC2)
6. `TAGS`: 최종 태그(⑦ 현재 버전)가 10개 이하이고, 승인 화면을 열 때와 승인 직전에 커머스API `restricted-tags`로 다시 확인해 제한 태그가 없다. 조회가 실패하면 그 항목만 `passed=false`에 사유를 적고 전체는 200이다. (F-AP-14, US-20 AC1·AC2, 05-2 x-decision §7.5-37)
7. `NOTICE_BLOCK`: ⑥-3의 `disclosure_blocks` 기록을 믿지 않는다. 최종 `detailContent`에서 고지 블록을 다시 잘라 해시를 내고 앱 내장 템플릿 해시와 비교한다. 블록이 없거나 해시가 다르면(편집) 실패다. 소재가 가죽·'정보 없음'인데 조건부 블록이 없어도 실패다. (F-AP-15, US-16 AC2·AC3, ERD `content_draft_assembly.disclosure_blocks`)
8. `ORIGIN`: 제조국이 근거나 오너 입력으로 확정됐다. 근거 `evidence_url`은 현재 `candidate.item_code`의 페이지이고, 오너 입력이면 `basis_item_code` = 현재 `item_code`다. '재확인 필요'(`recheck_reason` 있음 + `recheck_resolved_at` 없음) 필드가 없다. 원산지 코드가 03·04면 `spec_origin_label`에 실제 국가 표기가 있다. (F-AP-16, PRD §8.7 원산지 행, ERD `content_draft_field`)
9. 문구 검사 셋: `JAPAN_WORDING` — 제조국이 일본이 아니면 상품명·`detailContent`에 '일본 제품'·'일본산'이 없다. `MIN_BLOCK_WORDS` — 상품명·상세에 '반품 불가'·'환불 불가'·'최저가'·'공식'·'정품 100%'가 없다. `EXTRA_CHARGE_WORDING` — 상품명·상세·카피에 '관부가세 별도'·'통관비 별도 청구' 같은 추가 청구 표현이 없고, 배송비가 무료이며 고지의 관부가세·배송 안내와 맞는다. 예시 밖 표현 목록은 문서에 없음 → 설정 사전으로 넓힐지 Proposed. (F-AP-17·18·20, D-11)
10. `NEGATIVE_MARGIN`: 판정 스냅샷(`price_judgement_size`)의 모든 판매 사이즈에서 `profit_b_krw ≥ 0`이고 `profit_a_krw ≥ max(target_margin_rate × size_sale_price_krw, min_profit_krw)`다. (F-AP-19, PRD §8.7 가격 행·§8.3 10, ERD `price_judgement.target_margin_rate`)
11. `JUDGEMENT_FRESHNESS`: 지금 − `price_judgement.rakuten_page_collected_at` ≤ 설정 유효 시간(기본 6시간. 6시간보다 긴 설정은 앱 시작 때 거부). ③만 다시 실행해도 이 시각은 바뀌지 않는다. 실패 항목은 `stepCode=SOURCING`이고 화면은 '재조회'(`POST /candidates/{id}/refetch`, P2-02)를 보인다. (F-AP-21, US-20 AC2, US-25 AC2, PRD §5.3 '판정 유효 시간')
12. `REPRESENTATIVE_IMAGE_SOURCE`: ⑤ 현재 `thumbnail_selection.checklist`가 모두 true다(색상 일치 포함). 레퍼런스 중 출처 앵커 키(`image_asset.source_model_code_norm`·`source_color_code`)가 후보 앵커 키와 다른 것이 있으면 `same_product_color_confirmed_at`이 있어야 한다. (F-AP-22, PRD §5.1 G3, IM-06)
13. `STEP_FRESHNESS`: 필수 단계 9개(②③④⑤⑥-1⑥-2⑥-3⑦⑧)가 모두 `COMPLETED`이고, G2·G3 지문을 지금 값으로 다시 계산해 최신 통과와 같다(P1-06 서비스). URL 후보(`creation_path=RAKUTEN_URL`)는 비교를 했거나 `no_comparison_confirmed_at`이 있다. 최신이 아닌 단계마다 `stepCode`(게이트면 `gateCode`)를 채워 링크를 단다. `CATEGORY`: 리프이고 `gender_path_match=true`이며 `exception_decision`이 `PASS`·`KC_EXEMPT`다(`BLOCKED`면 실패). (F-AP-23·24, US-33 AC6, US-22 AC1)
14. 미리보기: 05-2 `ApprovalPreview`를 채운다. `priceJudgementId`·`uploadResultId`는 현재 버전 id(승인 body의 expected*로 돌아온다), `judgementExpiresAt` = 수집 시각 + 유효 시간이고, URL 후보는 소싱 방식(비교함 / 비교 없이 확정)을 준다. `approveEnabled=false`면 `approveDisabledReason.code`는 승인 API가 돌려줄 409·422 코드와 같다. `?optionType=STANDARD`는 표준형 미리보기다. (F-AP-08, US-06 AC3, US-20 AC1, 05-2 `ApprovalPreview`)
15. 버튼 잠금: BLOCK 실패가 하나라도 있거나 `approveEnabled=false`면 '승인·등록'을 끄고 꺼진 이유를 글로 보인다. 연속 실행·CLI·설정으로 승인을 대신하거나 끄는 길이 없다(⑨ 단계 실행은 422 `INVALID_STEP_CODE`, 연속 실행은 `AWAIT_G4`에서 멈춤). (F-AP-10, US-21 AC3, US-33 AC6, 05-1 표 A)

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).

- 기능 경계: 요청 초안 빌더(F-AP-25·27·35·39·40)와 `DUPLICATE` 항목(F-AP-36)은 P4-03 기능 ID인데 미리보기·사전 검증이 먼저 필요하다. 여기서 빌더와 로컬 중복 검사까지 만들고, P4-03이 SELLER_CODE 교차 조회·표준형 전환·등록 경로를 더한다. 같은 규칙을 두 번 구현하지 않는다.
- 미리보기 상세의 이미지 URL은 shop-phinf(외부)다. 브라우저가 그대로 부르면 '화면은 런타임 외부 호출 없음'에 걸린다. 표시할 때만 `uploaded_image.url` → `/api/v1/image-assets/{imageAssetId}/file`로 바꿔 그리고, 요청 JSON은 URL 그대로 둔다. 렌더링 격리 방식(sandbox iframe 등)은 문서에 없음 → Proposed.
- 시안은 검사 13줄, API는 15코드다('금지어·최소 차단어·추가 청구'를 한 줄, '원산지·일본산'을 한 줄로 묶음). 줄 묶음 대응표를 정해 기록하고 문구는 시안을 따른다.
- 시안의 '20:02가 지나면 승인할 때 자동으로 다시 읽고…'는 M2(F-AP-52) 동작이다. M1은 '재조회' 버튼과 409 `JUDGEMENT_EXPIRED`다. 문구를 M1 동작에 맞춘다.
- 검사 함수 안에서 `new Date()`를 직접 부르지 않는다. 앞 문서가 만든 시계 공급자가 있으면 그것을 쓰고, 없으면 주입 방식을 Proposed로 정한다.
- 차단어 '공식'을 부분 일치로 찾으면 '비공식' 같은 말도 걸린다. 고지 템플릿·사양 블록에 차단어가 섞이지 않았는지 fixture로 확인하고, 일치 방식은 Proposed로 기록한다.
- 사전 검증은 부를 때마다 restricted-tags를 조회한다. SSE로 연달아 다시 돌지 않게 한 번에 하나만 돌리고, 호출은 P1-01 관문·`call_log`를 거친다.
