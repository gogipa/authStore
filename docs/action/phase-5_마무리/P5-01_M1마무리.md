## 4. 핵심 규칙

1. 새 기능·새 API를 만들지 않는다. 테스트가 찾은 결함은 그 기능을 가진 모듈에서 고친다. 명세와 다르면 원본 문서(05-2, 04-3)를 먼저 고친 뒤 코드를 맞춘다. (README 공통 규칙 '설계 문서가 원본이다', 이 문서 2.1)
2. 흐름 A(키워드 경로): ① 붙여넣기 수집 → G1 → ② 검색·앵커·후보 선택 → ③ 국내 기준가 → G2 → ④ → ⑤ 레퍼런스·생성(가짜 `ImageGenProvider`) → G3 → ⑥-1·⑥-2(AI fixture 어댑터) → ⑥-3 → ⑦ → ⑧ → G4 사전 검증 15항목 통과 → 승인. 차단 스위치 켬이면 '검증완료', 끈 뒤 다시 승인하면 '등록됨'과 상품 번호. 첫 등록이라 전시 모드는 `SUSPENSION`이다. (PRD §5 흐름·§17 M1 종료 조건, US-20 AC1~AC5)
3. 흐름 B(URL 경로): 라쿠텐 URL → 색상 선택 → '비교 안 함' 배지 → G2에서 '비교 없이 확정' → … → ⑨ '등록됨'. G4 화면에 소싱 방식 '비교 없이 확정'이 보인다. (PRD §17, US-06 AC3, F-AP-08)
4. 실패 경로도 끝까지 본다: 등록 5xx → '결과확인필요' → '결과 확인'(찾음) → '등록됨'. 등록 4xx → 한국어 오류·추적 번호 → ⑦ 태그 수정 → 재승인. ⑤ 다시 고르기 → ⑧만 '재실행 필요', 승인 버튼 꺼짐과 ⑧ 링크. (US-20 AC4, US-19 AC2, US-33 AC3·AC6)
5. 앱 재시작: ⑨ 등록요청중에 BE를 끄고 켜면 후보는 '결과확인필요', 실행중이던 단계는 '실패(중단됨)'다. 기록 저장 전이거나 차단 스위치가 켜져 있었으면 '승인대기'다. (US-29 AC3, F-BS-18, PRD §5.2)
6. 외부 호출 0건: 흐름 테스트 동안 브라우저 요청은 앱(127.0.0.1)으로만 간다(외부 글꼴·CDN·shop-phinf 이미지 금지). BE는 커머스API·라쿠텐·데이터랩·환율·AI CLI를 모두 가짜로 부른다. 허용 목록 밖 호스트를 부르면 테스트가 실패한다. (README '외부 호출 금지', F-BS-06·07, US-36 AC5)
7. 명세 대조: `pnpm --filter @autostore/be openapi:export`로 `dist/openapi.impl.json`(OpenAPI 3.0)을 만들고 05-2(3.1)의 `x-milestone: M1` 연산과 비교한다. 경로·메서드, operationId, 파라미터·요청 본문 필수 필드, 응답 상태 코드, 응답 스키마 필수 필드를 본다. `nullable` ↔ `type: [x, 'null']`은 같은 것으로 본다. M1 연산은 101개다. 차이는 0건이거나, 남긴 차이마다 이유를 적는다. (2.1, 06-2 §9-5, README '범위 근거')
8. 보안 점검: BE는 127.0.0.1에만 붙는다. `Host`가 틀리면 403 `HOST_NOT_ALLOWED`(SSE·정적 파일 포함), 상태 변경 요청의 `Origin`이 틀리면 403 `ORIGIN_NOT_ALLOWED`, `X-AutoStore-Client`가 없으면 403 `CLIENT_HEADER_REQUIRED`, CORS 헤더가 없다. 비밀정보는 키체인에만 있고 `.env`·로그·DB·API 응답·SSE·AI 프롬프트에 없다. `pnpm secretlint`가 통과한다. 커머스API 토큰 요청에 `account_id`가 없다. (05-1 §1.2, C4 §5, NFR-02, US-27 AC1, PRD §8.7 인증)
9. 안전장치: G4·아동화 차단·실존 인물 차단·중복 방지·원본 업로드 거부를 끄는 설정이 없다. 기준을 완화한 설정 파일(판정 유효 7시간, 아동 단어 삭제 등)은 앱 시작 때 거부된다. 등록 API 차단 스위치 기본값은 켬이다. (US-36 AC4, F-BS-04·05, ERD `registration_switch`)
10. 추적표: 04 §6의 M1 인수조건(Must·CON)마다 그것을 확인하는 테스트 파일·이름을 적는다. 비어 있는 AC가 있으면 테스트를 더하거나 사유를 적는다. (PRD §17 'Must·제약(CON) 태그 AC 전부 통과', 04 §6)
11. M1 리허설은 오너가 한다. Claude는 실제 커머스API·라쿠텐을 부르지 않는다. 리허설 절차(실제 상품 5건 키워드→등록, URL 1건, 처음 10건 전시중지, G5는 스마트스토어센터)와 사전 점검(키 입력, 메타 동기화, 프로필 `importer`, AI 엔진 연결 테스트, 차단 스위치 상태, M0 S3 결과 반영)을 문서로 만든다. (PRD §17, PRD §0 5번, README 'M1 종료 조건')
12. 공통 검사(`pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e && pnpm build`)와 흐름 테스트(`pnpm test:flow`), 명세 대조(`openapi:compare`)가 모두 통과해야 끝난다. (7. 완료 조건, README '끝내기 전')

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- 새 기능 없음. Playwright로 후보 1건이 ①~⑨를 fixture로 끝까지 지나는지 확인하고, 구현 명세(openapi.impl.json)와 05-2를 대조한다.

- 이 문서는 앞 25개 문서가 끝났다는 전제다. 흐름 테스트가 막히면 원인 모듈(P1~P4)을 고치고 그 문서의 완료 조건도 다시 확인한다. 새 기능으로 우회하지 않는다.
- Playwright 브라우저 내려받기가 크다(06 체크리스트에서 미룬 이유). 설치가 안 되면 멈추고 오너에게 알린다. 다른 도구로 바꾸지 않는다.
- 흐름 중에 차단 스위치를 끄는 단계가 있다. 끄기 전에 커머스API·라쿠텐 기본 주소가 127.0.0.1(가짜)인지 단언한다. 실제 스토어 등록은 오너 리허설에서만 한다.
- 흐름 테스트는 `autostore_test`만 쓴다. 개발 DB(`autostore_dev`)를 TRUNCATE하지 않게 DB 이름에 `test`가 있는지 먼저 확인한다(06-4 `TEST_DATABASE_URL` 규칙).
- 구현 명세는 OpenAPI 3.0, 05-2는 3.1이다. `nullable`·`oneOf null`·`exclusiveMaximum` 표기 차이는 결함으로 세지 않는다. 필드 누락과 상태 코드 누락은 결함이다.
- 시각에 기대는 검사(판정 6시간, 하루 조회의 KST 0시 초기화)가 흐름 도중 바뀌지 않게 한다. 밤 12시 근처에 돌리면 조회 한도가 초기화될 수 있다.
- 실제 M1 종료는 M0 S3(커머스API 앱 등록, 판매자관리코드 제한, 고시 0/1 형식, 업로드 응답 모양 등) 결과가 반영된 뒤다. 아직 fixture 가정으로 남은 목록을 리허설 문서의 '사전 점검'에 넣는다.
