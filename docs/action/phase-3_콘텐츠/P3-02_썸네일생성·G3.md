## 1. 목표

이 문서가 끝나면 입력 대기 중인 ⑤에서 레퍼런스와 프롬프트로 AI 썸네일 후보(기본 2장, 1:1, 2K)를 만들고, 다시 만들고, 거부되면 얼굴 노출을 낮춰 다시 시도할 수 있다. 오너는 원본과 후보를 나란히 보고 G3 체크리스트 7개를 모두 체크한 뒤 대표 1장(과 추가 0~9장)을 고른다. 그러면 G3이 통과되고 ⑤가 완료된다. 흐름에서 ⑤의 뒷부분과 G3이고, ⑧ 업로드(P4-01)와 사전 검증(P4-02)이 이 선택본을 읽는다.

## 4. 핵심 규칙

1. 생성 요청(`POST /step-runs/{id}/generation-runs`)은 입력 대기 중인 ⑤에서만 받는다. 아니면 409 `STEP_RUN_NOT_WAITING_INPUT`, ⑤ 실행이 아니면 422 `INVALID_STEP_CODE`, 잠김·제외면 409 `CANDIDATE_LOCKED`·`CANDIDATE_EXCLUDED`. '사람·얼굴 없음'을 확인한 레퍼런스가 없으면 409 `REFERENCES_NOT_CONFIRMED`. (05-1 §2.6, 05-2 `createThumbnailGenerationRuns`, US-12 AC1)
2. `slotNos`는 1..N(N = 설정 후보 수, 기본 2) 안의 중복 없는 값이다. `faceOption`은 3종, `promptAdjustment`는 2000자 이하다. 어기면 422 `VALIDATION_FAILED`. 같은 번호가 생성 중이면 409 `ALREADY_IN_PROGRESS`(`details.job=GENERATION`). (05-2, PRD §16 ③ 썸네일 '후보 2장')
3. 서버가 차단어를 다시 검사한다(조정한 프롬프트 포함, P3-01 `findBlockedTerms`). 걸리면 422 `REAL_PERSON_NAME_BLOCKED`로 막고 `generation_run`을 만들지 않는다. 저장되는 `prompt`는 검사를 통과한 전문뿐이다. (F-TH-10, F-TH-13, US-13 AC1, ERD `generation_run.prompt`)
4. 번호마다 `generation_run` 1행을 `RUNNING`으로 만든다. (F-TH-07, F-TH-08, ERD §3.7 `generation_run`, 05-1 §1.3)
   - `attempt_no` = 그 번호의 최대값 + 1
   - `trigger_type` = 그 번호의 첫 시도면 `INITIAL`, 아니면 `OWNER_RETRY`. M1은 `AUTO_RETRY`를 쓰지 않는다
   - `prompt`, `prompt_adjusted`, `face_option`, `requested_size_px`(기본 2048), `provider`·`model`·`provider_version`, `reference_set_sha256`(P3-01 해시)
   - 응답은 202 + `Location`(첫 시도의 `/api/v1/generation-runs/{id}`) + `GenerationRunAccepted`. 호출마다 새 회차다(비멱등)
5. 생성은 `ImageGenProvider` 포트로만 부른다. 이미지 작업은 동시에 1개, 하드 타임아웃은 15분이다. 성공하면 실제 형식을 판별해 `image_asset`(`kind=GENERATED`, `usage_right=PERMITTED`, `candidate_id` 채움)을 만들고 `status=SUCCEEDED`·`result_image_asset_id`·`finished_at`을 한 번에 채운다. (F-TH-07, AI-05·D-16 R13, AI-03, ERD `ck_gen_result`·`ck_image_asset_right_by_kind`)
6. 콘텐츠 필터 거부는 `status=REFUSED` + `refusal_reason`(필수)이다. 그 밖의 실패는 `FAILED` + 한국어 `error_message`(비밀정보 없음)다. 시도 하나의 결과이므로 ⑤ 단계는 입력 대기 그대로 둔다. 거부되면 화면이 얼굴 노출을 한 단계 낮춘 재시도(`FULL_FACE` → `CHIN_CROP` → `HANDS_UPPER_BODY`)를 묻고, 오너가 받아들이면 같은 API에 낮춘 `faceOption`을 보낸다. (F-TH-09, PRD §8.4, ERD `generation_run.status` '단계 상태가 아님', `ck_gen_refused`)
7. 시도의 상태가 바뀔 때마다 SSE `generation-run.updated`(`slotNo`, `attemptNo`, `triggerType`, `status`, `refusalReason?`, `errorMessage?`, `resultImageAssetId?`)를 보낸다. 앱을 다시 켤 때 `RUNNING`으로 남은 `generation_run`은 `FAILED`로 바꾼다. (05-1 §3, ERD `generation_run` 목적, ERD §5.5 닫힌 뒤 고치는 예외)
8. 조회 두 개. (05-2 `getThumbnailGenerationRun`·`getCandidateThumbnail`)
   - `GET /generation-runs/{id}`: 프롬프트 전문·공급자·모델·거부 사유를 준다. `adopted`(선택본 포함 여부)는 계산한다. 없으면 404 `GENERATION_RUN_NOT_FOUND`
   - `GET /candidates/{id}/thumbnail`: 레퍼런스·생성 후보·G3 선택·G3 유효를 한 번에 주고 프롬프트 전문은 뺀다. `?stepRunId=`로 이전 버전을 준다. 이 후보의 ⑤가 아니면 404 `STEP_RUN_NOT_FOUND`, 미실행이면 404 `STEP_OUTPUT_NOT_FOUND`
9. G3 체크리스트 7개 키 `shoeRatioOver70`, `detailMatch`, `colorMatchesSelectedColor`, `referenceNoPerson`, `noRealPersonResemblance`, `noTextOrPrice`, `singleProductSingleModel`가 모두 true여야 한다. 하나라도 false이거나 빠지면 422 `CHECKLIST_INCOMPLETE`. `thumbnail_selection.checklist`에는 7개 값과 `version` 문자열을 함께 저장한다. (F-TH-14, US-12 AC2, 05-1 표 C, 05-2 `getCandidateThumbnail` x-decision §7.4-30)
10. 레퍼런스 가운데 하나라도 후보 앵커 키(型番 정규화 + 색상 코드)와 다르거나 색상 코드를 모르면 `sameProductColorConfirmed=true`가 있어야 한다. 없으면 422 `SAME_PRODUCT_COLOR_CONFIRMATION_REQUIRED`. 확인 시각은 `same_product_color_confirmed_at`에 둔다. (F-TH-15, PRD §5.1 G3, ERD `image_asset.source_color_code` '모르면 확인으로 대신')
11. 대표 1장과 추가 0~9장은 모두 이 ⑤ 버전 `generation_run`의 `SUCCEEDED` 결과(`kind=GENERATED`)여야 한다. (F-TH-16, F-TH-17, ERD `ck_thumb_sel_img_*`, 05-1 표 C)
    - 원본·참조 전용·다른 실행의 생성본 → 422 `IMAGE_NOT_ALLOWED`
    - 추가 9장 초과 → 422 `IMAGE_COUNT_INVALID`, 생성 중 → 409 `ALREADY_IN_PROGRESS`, ⑤가 실행중·실패 → 409 `STEP_NOT_COMPLETED`
    - 저장: `thumbnail_selection_image` 대표 `REPRESENTATIVE`·`sort_order 0`, 추가 `ADDITIONAL`·`sort_order 1~9`
12. G3 통과는 한 트랜잭션이다: `thumbnail_selection`(+image) 저장 → ⑤ `COMPLETED` → `gate_pass`(G3, 지문 = 레퍼런스 파일 해시 + 선택본 파일 해시 + 앵커 키) → 후보 상태 자동 전이. 응답 201에 `thumbnailSelectionId`·`thumbnailStepRunId`를 넣는다. 게이트 기록은 웹 화면 요청만 받는다. (C4 §4, 05-1 표 C·§1.2, F-TH-16)
13. ⑤ 완료 뒤 G3을 다시 고르면 ⑤의 OWNER_EDIT 새 버전과 새 선택 행을 만든다. ⑤를 다시 실행하면 이전 버전 생성본을 가져가지 않고 새로 만든다. 레퍼런스·선택본·앵커 키 중 하나라도 바뀌면 G3 지문이 달라져 다시 통과해야 한다(SSE `gate.invalidated`). (05-2 x-decision §7.4-31, ERD §7.2-4, F-TH-16, PRD §5.1 게이트 지문)
14. G3 선택본만 바뀌면 그 값을 읽는 ⑧만 '재실행 필요'가 되고 ⑥·⑦은 '완료'로 남는다(⑥-3 HTML은 자리표시자라 영향이 없다). (US-33 AC3, PRD §5.3 ⑥-3 HTML 규칙)
15. 이미지 생성 공급자는 M0 S1에서 하나로 정한다(`provider` ∈ `AGY`·`GEMINI_API`·`OPENAI_API`·`CODEX`). 정하기 전에는 가짜 공급자로만 돈다. 공급자는 선택 AI 엔진과 섞지 않는다. 그래서 M1 ⑤의 `step_run.ai_engine`은 NULL이다. (PRD §8.4 공급자, IM-09, D-16 R1, ERD `ck_gen_provider`)

## 6. 테스트

테스트 공통: ESM Jest라 가짜 공급자는 `overrideProvider(IMAGE_GEN_PROVIDER)`로 넣는다. e2e는 `autostore_test`, 정리는 `TRUNCATE … RESTART IDENTITY CASCADE`. 실제 이미지 생성 테스트는 P1-10에서 정한 실제 호출 스위치(환경변수)가 켜졌을 때만 돈다.

**단위**

| 대상 | 확인할 것 |
|---|---|
| 회차 계산 | 번호 1 첫 요청 → `attempt_no=1`, `INITIAL`. 다시 → `2`, `OWNER_RETRY`. 번호 2는 따로 센다 |
| `reference_set_sha256` | P3-01 해시와 같은 값. 레퍼런스 순서와 관계없다 |
| 얼굴 노출 낮추기 | `FULL_FACE` → `CHIN_CROP` → `HANDS_UPPER_BODY` → 더 없음(null) |
| G3 검사기 | 7개 키를 하나씩 false로 → `CHECKLIST_INCOMPLETE`. 型番이 다른 레퍼런스 + 확인 없음 → `SAME_PRODUCT_COLOR_CONFIRMATION_REQUIRED`. 색상 코드 없는 레퍼런스도 확인을 요구한다. 원본을 대표로 → `IMAGE_NOT_ALLOWED`. 다른 ⑤ 버전 생성본 → `IMAGE_NOT_ALLOWED`. 추가 10장 → `IMAGE_COUNT_INVALID` |
| 형식 판별 | 공급자가 `.jpg` 이름으로 PNG를 주면 `mime_type=image/png`로 저장한다 |

**e2e**

- `{slotNos:[1,2], faceOption:"FULL_FACE"}` → 202, `Location: /api/v1/generation-runs/{id}`, 2행 `RUNNING`. 가짜가 끝나면 `SUCCEEDED`, `image_asset`은 `GENERATED`·`PERMITTED`. ⑤는 계속 `WAITING_INPUT`.
- 레퍼런스 확인 전 → 409 `REFERENCES_NOT_CONFIRMED`. N=2에서 `slotNos:[3]` → 422 `VALIDATION_FAILED`. 조정 문구에 차단어 → 422 `REAL_PERSON_NAME_BLOCKED`, `generation_run` 0행. 같은 번호 생성 중 → 409 `ALREADY_IN_PROGRESS`.
- 거부 시나리오 → `REFUSED` + `refusal_reason`. `CHIN_CROP`으로 다시 → `attempt_no=2`, `OWNER_RETRY`, `face_option=CHIN_CROP`.
- 타임아웃 시나리오(테스트 설정 짧게) → `FAILED` + `error_message`.
- 재시작 복구: `RUNNING` 행을 넣고 복구 → `FAILED`, `finished_at` 채움.
- G3(P1-06 `POST …/gates/G3/pass`): 7개 모두 true + 대표 1 → 201. ⑤ `COMPLETED`, `gate_pass` G3 1행, 대표 `sort_order=0`. 키 하나 빠짐 → 422 `CHECKLIST_INCOMPLETE`. 추가 10장 → 422 `IMAGE_COUNT_INVALID`. 생성 중 → 409 `ALREADY_IN_PROGRESS`.
- 완료 뒤 다른 후보로 다시 고름 → ⑤ 새 버전(`OWNER_EDIT`), 새 `gate_pass`. 시드에서 완료였던 ⑧만 `RERUN_REQUIRED`가 되고 COPY·TAGS는 `COMPLETED`(US-33 AC3).
- `GET …/thumbnail?stepRunId=`에 다른 후보의 실행 id → 404 `STEP_RUN_NOT_FOUND`. `GET /generation-runs/9999` → 404 `GENERATION_RUN_NOT_FOUND`. 선택본에 든 시도는 `adopted=true`.

**FE**

- `G3Checklist`: 7개를 모두 체크하기 전에는 버튼이 꺼져 있다. '같은 상품·색상' 체크는 `sameProductColorRequired=true`일 때만 보인다.
- `CandidateGrid`: `REFUSED` 칸은 사유와 '낮춰 다시 만들기'를 보인다. `SUCCEEDED`가 아닌 칸은 대표로 고를 수 없다. '신발 비중' 글자가 없다(M2).

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- 이미지 생성 경로는 M0 S1에서 정한다. 그 전에는 ImageGenProvider 포트와 테스트용 가짜 공급자로 만든다.

- ⑤는 생성하는 동안에도, G3 전까지도 `WAITING_INPUT`이다. 시도마다 ⑤를 `RUNNING`·`FAILED`로 바꾸지 않는다. 한 후보·단계에 열린 실행은 하나다(`uq_step_run_one_open`).
- `generation_run`은 삭제 금지이고 `RUNNING` 행을 한 번만 마감한다. `thumbnail_selection`(+image)은 `trg_output_frozen` 대상이라, ⑤를 `COMPLETED`로 닫기 **전에** 같은 트랜잭션에서 써야 한다.
- 완료 뒤 G3을 다시 고르는 OWNER_EDIT 버전에는 자기 `generation_run`이 없다. 그래서 '이 실행의 생성본' 판정은 바탕 버전(`base_step_run_id`)의 생성 결과로 한다. 문서에 없는 해석이라 Proposed로 기록한다. 닫힌 ⑤에는 새 시도를 더할 수 없으니 새로 만들려면 ⑤를 다시 실행한다.
- G3 지문의 '선택본 파일 해시'가 대표만인지 대표 + 추가 전체인지 PRD가 모호하다. ERD는 `thumbnail_selection_image` 목록 전체로 읽힌다. P1-06과 같은 함수 하나로 계산해 두 곳이 어긋나지 않게 한다.
- M0 S1 전이다. agy는 크기 지시를 무시하거나 확장자와 실제 형식이 다를 수 있다. 저장할 때 늘 내용으로 형식을 판별한다. 1000×1000 JPEG 정규화는 P4-01 몫이니 여기서 줄이거나 바꾸지 않는다.
- 이미지 생성은 실제 비용·쿼터를 쓴다. 테스트·개발에서 실제 공급자를 부르지 않는다. 이미지 작업은 동시에 1개라 병렬로 띄우지 않는다.
- P4-02 대표이미지 출처 검사(F-AP-22)는 `thumbnail_selection.checklist`, `same_product_color_confirmed_at`, 레퍼런스 `image_asset`의 `source_item_code`·앵커 필드를 읽는다. P4-01은 `thumbnail_selection_image` 순서를 읽는다. 이 값들을 빠짐없이 채운다.
