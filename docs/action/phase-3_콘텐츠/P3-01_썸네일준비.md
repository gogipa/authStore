## 1. 목표

이 문서가 끝나면 ⑤ 썸네일 단계를 실행했을 때 고른 라쿠텐 상품의 원본 이미지가 출처 정보와 함께 '참조 전용'으로 저장되고, ⑤는 '입력 대기'로 멈춘다. 오너는 SCR-05에서 신발만 나온 컷 1~3장을 고르고 '사람·얼굴 없음'을 체크하며, 얼굴 노출 수준과 프롬프트 조정을 넣어 실존 인물 차단어 검사를 거친 프롬프트를 미리 본다. 흐름상 ④ 카테고리 뒤 ⑤의 앞부분이다. 실제 생성·비교·G3 선택은 P3-02가 이어서 만든다.

## 4. 핵심 규칙

1. ⑤ 실행(`POST …/steps/THUMBNAIL/runs`, P1-05)은 ② 현재 버전이 '완료'이고 소싱 선택 `itemCode`가 있어야 시작한다. 없으면 409 `STEP_START_CONDITION_UNMET`. 원본 목록 조회는 ② 선택 전이면 409 `SOURCING_SELECTION_REQUIRED`. (PRD §5.3 필수 시작 조건·⑤ 행, 05-1 §2.6, 05-3)
2. ⑤ 입력 지문(시작 조건)은 설정 두 키 `settings.thumbnail.promptTemplate`·`settings.thumbnail.faceOptionDefault`(`source_type=SETTINGS`)뿐이다. ② `itemCode`·원본 목록은 지문에 넣지 않는다. 같은 앵커 키 안에서 샵만 바꾸면 ⑤와 G3은 그대로여야 한다. 실행 body의 `ownerInputs.faceOption`·`promptAdjustment`는 실행 중 오너 입력이라 지문에서 뺀다. (ERD `generation_run` '⑤ 입력 기록 규칙', PRD §5.2 작업 단위, 05-1 표 A THUMBNAIL)
3. 원본 받기: 현재 ② 버전 `rakuten_item.image_urls`(`media.images[]`)를 모두 원본 해상도로 받는다. 목록이 비면 API 이미지 URL의 `_ex` 값을 키워 받는다. 키울 값과 API URL을 읽을 곳은 문서에 없음 → 구현 때 Proposed로 정하고 기록. 형식은 확장자가 아니라 파일 내용으로 판별해 `mime_type`에 적는다. 받기 실패는 ⑤ `FAILED`(`failureKind=EXTERNAL_API`). (F-TH-01, US-11 AC1, IM-01, ERD `image_asset.mime_type`)
4. 원본 1장 = `image_asset` 1행: `kind=ORIGINAL`, `usage_right=REFERENCE_ONLY`, `source_section=PRODUCT_IMAGE`, `candidate_id=NULL`. `source_url`·`source_item_code`·`source_shop_code`·`collected_at`·`width`·`height`·`byte_size`·`sha256`(소문자 hex 64자)을 채우고, 아는 경우 `source_model_code_norm`·`source_color_code`도 채운다. 같은 `(source_item_code, sha256)`은 새 행 없이 기존 행을 쓴다. (F-TH-02, US-11 AC1·AC2, ERD §3.6 CHECK `ck_image_asset_*`, `uq_image_asset_original`)
5. 원본 목록 API는 현재 ② `itemCode`의 ORIGINAL만 준다(페이징 없음, 1~20장). `sourceSection`으로 거를 수 있고, 틀린 값은 422 `INVALID_QUERY_PARAMETER`. 로컬 경로는 주지 않고 `fileUrl`(`/api/v1/image-assets/{id}/file`)을 준다. `isSameAnchor`는 이미지의 型番·색상 코드와 후보 앵커 키를 비교해 계산한다. (F-TH-03, 05-1 §2.6·§1.2 '로컬 경로를 내보내지 않는다', 05-2 `listCandidateSourceImages`)
6. 원본을 받은 ⑤는 `WAITING_INPUT`으로 멈춘다(`pendingInputs`에 레퍼런스). 후보의 최신 `thumbnail_reference_input`(최대 `input_no`)이 있고 모두 현재 `itemCode` 원본이면 이 버전의 `thumbnail_reference`로 복사해 기본값으로 둔다. ⑤는 G3 선택까지 입력 대기다. (F-TH-04, ERD `thumbnail_reference_input` '다시 실행 기본값', ERD §7.2-4)
7. 레퍼런스 저장(`PUT /step-runs/{id}/thumbnail-references`)은 아래를 검사한다. (05-2 `putThumbnailReferences`, 05-3, US-12 AC1)
   - 1~3장이 아니면 422 `IMAGE_COUNT_INVALID`
   - `noPersonConfirmed`가 true가 아니면 422 `NO_PERSON_CONFIRMATION_REQUIRED`
   - 현재 `itemCode`의 `ORIGINAL`·`PRODUCT_IMAGE`가 아니면 422 `IMAGE_NOT_ALLOWED`, 없는 이미지 404 `IMAGE_ASSET_NOT_FOUND`
   - ⑤ 실행이 아니면 422 `INVALID_STEP_CODE`, 입력 대기가 아니면 409 `STEP_RUN_NOT_WAITING_INPUT`, 생성 중이면 409 `ALREADY_IN_PROGRESS`(`details.job=GENERATION`), 잠김·제외면 409 `CANDIDATE_LOCKED`·`CANDIDATE_EXCLUDED`
8. 저장은 한 트랜잭션이다: `thumbnail_reference_input`에 새 `input_no`(max + 1)로 1~3행 추가(`no_person_confirmed_at`=지금) → 열린 ⑤의 `thumbnail_reference`를 이 선택으로 교체 → `step_run_input`의 `owner.referenceSelection`(`OWNER_INPUT`, `is_start_condition=false`) 해시 갱신. 해시 = 고른 파일 SHA-256들을 정렬해 이은 값의 SHA-256(`generation_run.reference_set_sha256`과 같은 정의). 같은 선택을 다시 보내면 새 행 없이 200. (F-TH-04, ERD `thumbnail_reference`·`thumbnail_reference_input`, 05-1 §1.7 PUT 멱등)
9. '사람·얼굴 없음' 확인은 웹 화면 요청으로만 기록된다(Origin·`X-AutoStore-Client` 가드를 통과한 PUT). FE는 이 체크를 미리 켜 두거나 자동으로 보내지 않는다. (F-TH-05, 05-1 §1.2 웹 화면 전용 기록, PRD §5.3 안전 규칙)
10. 완료된 ⑤의 레퍼런스는 이 API로 바꿀 수 없다(409 `STEP_RUN_NOT_WAITING_INPUT`). 바꾸려면 ⑤를 다시 실행하고 새 입력 대기에서 고른다. 화면 안내 문구 '레퍼런스를 바꾸면 ⑤를 다시 실행해야 합니다'를 그대로 쓴다. (05-1 §2.6 '완료 뒤 레퍼런스 변경은 다시 실행', 시안 Thumbnail.dc.html)
11. 프롬프트 = 설정의 영어 골격에 `{resolution}`(기본 2K = 2048px)과 `{face_option}`을 채우고 오너 조정 문구(최대 2000자)를 붙인 것이다. 골격에는 '실존 인물과 닮지 않은 가상의 한국 남성 아이돌 스타일 모델', 신발 비중 70% 이상, 로고·색상·밑창 보존, 문구·가격·워터마크 없음이 들어 있다. (F-TH-06, PRD §8.4 기본 프롬프트 골격, §16 ③ 썸네일 2K, 05-2 `ThumbnailPromptPreviewRequest`)
12. 얼굴 노출: `FULL_FACE`(전체, 기본) / `CHIN_CROP`(턱 아래 크롭) / `HANDS_UPPER_BODY`(손·상반신만). 골격 주석의 `full face` / `crop at chin (face not shown)` / `hands and upper body only` 문장으로 바꾼다. 그 밖의 값은 422 `VALIDATION_FAILED`. (F-TH-11, US-13 AC2, PRD §8.4, §16 ①-4, ERD `ck_gen_face`)
13. 차단어 검사는 골격·해상도·얼굴 옵션·조정 문구를 채운 **전체 프롬프트**에 대해 한다. 사전 = 앱 내장 목록 ∪ 설정 추가분. 걸리면 `realPersonNameDetected=true`, `blockedTerms[]`, `generationAllowed=false`. 미리보기 API는 저장 없이 200만 준다. 실제로 막는 곳은 생성 요청(P3-02, 422 `REAL_PERSON_NAME_BLOCKED`)의 서버 재검사다. (F-TH-10, US-13 AC1, 05-2 `createThumbnailPromptPreview`)
14. 비교 방식(대소문자·NFKC·공백 무시)과 내장 목록의 실제 내용은 문서에 없음 → 구현 때 Proposed로 정하고 기록(목록은 오너 검토). 내장 목록은 설정으로 뺄 수 없다. 뺀 설정은 P1-03이 앱 시작 때 거부하고, 이 모듈은 항상 내장 ∪ 설정으로 검사한다. (F-TH-10, F-BS-05, US-36 AC4)
15. `generationAllowed` = 차단어 없음 AND 이 ⑤ 버전에 '사람·얼굴 없음'을 확인한 레퍼런스 1~3장이 있음. (05-2 `ThumbnailPromptPreview.generationAllowed`, US-12 AC1)

## 6. 테스트

테스트 공통: Jest는 ESM 모드라 `jest.mock` 끌어올리기가 안 된다. 가짜는 Nest DI(`overrideProvider`)로 바꾼다. e2e는 `autostore_test`에서 돌고, 정리는 `TRUNCATE … RESTART IDENTITY CASCADE`로 한다(삭제 금지·추가만 트리거).

**단위**

| 대상 | 확인할 것 |
|---|---|
| `prompt-builder` | 세 얼굴 옵션이 각각 정해진 영어 문장으로 들어간다. `{resolution}` = 2048. 조정 문구가 뒤에 붙는다. 기본 골격만으로 만든 프롬프트는 차단어에 걸리지 않는다 |
| `real-person-guard` | 내장 단어와 설정 추가 단어 모두 걸린다. Proposed 정규화(대소문자·전각·공백)가 적용된다. 걸린 단어가 `blockedTerms`에 나온다 |
| `reference-set-hash` | 같은 파일을 순서만 바꿔도 같은 값. 한 장만 달라도 다른 값 |
| `source-image.downloader` | `png-named.jpg` → `mime_type=image/png`. `image_urls`가 비면 `_ex` 대체 경로를 탄다. 같은 `(itemCode, sha256)`은 행을 새로 만들지 않는다 |
| `thumbnail-step.runner` | 시작 조건 키가 설정 두 개뿐이다. ② `itemCode`만 다른 새 버전을 줘도 ⑤ 지문이 같다(규칙 2) |

**e2e (가짜 라쿠텐 이미지 어댑터)**

- ⑤ 실행 → 202. 끝나면 ⑤ `WAITING_INPUT`이고, 원본 목록 200에 6장이 나온다. 모두 `REFERENCE_ONLY`·`PRODUCT_IMAGE`이고 응답 어디에도 로컬 경로가 없다.
- ② 선택 전 원본 목록 → 409 `SOURCING_SELECTION_REQUIRED`. `sourceSection=FOO` → 422 `INVALID_QUERY_PARAMETER`.
- 레퍼런스 저장 오류: 0장·4장 → 422 `IMAGE_COUNT_INVALID`. `noPersonConfirmed=false` → 422 `NO_PERSON_CONFIRMATION_REQUIRED`. 생성본·다른 `itemCode` 원본 → 422 `IMAGE_NOT_ALLOWED`. 완료된 ⑤ → 409 `STEP_RUN_NOT_WAITING_INPUT`. `X-AutoStore-Client` 없음 → 403 `CLIENT_HEADER_REQUIRED`.
- 레퍼런스 2장 저장 → 200 `inputNo=1`. 같은 선택을 다시 보내면 `inputNo=1`이고 `thumbnail_reference_input` 행 수가 그대로다. 다른 선택 → `inputNo=2`.
- 다시 실행하면 새 ⑤ 버전의 `thumbnail_reference`가 최신 선택으로 미리 채워진다.
- 프롬프트 미리보기: 기본값 → `realPersonNameDetected=false`, `requestedSizePx=2048`. 조정 문구에 차단어 → 200 + `generationAllowed=false` + `blockedTerms`. 레퍼런스 확인 전 → `generationAllowed=false`.
- DB: `image_asset` UPDATE·DELETE가 트리거로 거부된다.

**FE (Vitest + Testing Library, fetch는 가짜 응답)**

- `SourceImagesPanel`: 이미지마다 '참조 전용' Chip이 보인다. 4번째 레퍼런스를 고를 수 없다. 레퍼런스 1~3장 + '사람·얼굴 없음' 체크 + `generationAllowed` 전에는 생성 버튼이 꺼지고 이유 글이 보인다.
- `GenerationOptionsPanel`: 기본 선택이 '전체'다. 차단어가 있으면 걸린 단어와 이유를 보여 준다. 없으면 '실존 인물 이름 없음'을 보여 준다.
- M2 패널('생성 순서와 비용')이 없다.

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).

- 원본 이미지 호스트는 `call_log.target` CHECK(`RAKUTEN_PAGE` 등)에 이미지용 값이 없다. `RAKUTEN_PAGE`로 기록하면 하루 페이지 상한(110)을 이미지가 써 버린다. 대상 값·허용 목록·상한 포함 여부를 Proposed로 정하고, CHECK를 바꾸면 ERD부터 고친 뒤 새 마이그레이션을 만든다.
- ⑤ 지문에 ② `itemCode`나 원본 목록을 넣으면 같은 모델·색상 안에서 샵만 바꿔도 ⑤·G3이 무너진다(PRD §5.2). 원본은 읽되 지문은 설정 키만 쓴다.
- `image_asset`·`thumbnail_reference_input`은 추가만 된다(트리거). 메타를 고치는 코드를 만들지 않는다. 같은 파일은 `uq_image_asset_original`로 재사용한다.
- `thumbnail_reference`는 `trg_output_frozen` 대상이다. ⑤가 열려 있을 때만 교체할 수 있다. 완료 뒤 변경 경로는 '다시 실행'뿐이다. ERD의 '완료 뒤 썸네일 화면에서 고르면 재실행 필요'는 이를 받는 API가 없어 M1에서 쓰지 않는다.
- 원본의 `usage_right=REFERENCE_ONLY`는 P4-01 업로드 거부(F-BS-45)와 P4-02 이미지 검사의 근거다. 원본을 다른 값으로 저장하는 경로를 만들지 않는다.
- ⑤는 M1에서 선택 AI 엔진을 쓰지 않는다. 그래서 `step_run.ai_engine`은 NULL이고 `AI_ENGINE_UNAVAILABLE`로 막지 않는다. G2 전 실행의 `PRE_G2_AI_COST` 경고는 step-engine(P1-05)이 붙인다.
- `buildPrompt`·`findBlockedTerms`·`reference-set-hash`는 P3-02가 생성 요청 때 다시 쓴다. 모듈 안 공개 함수로 두고, 미리보기와 생성이 서로 다른 구현을 갖지 않게 한다.
