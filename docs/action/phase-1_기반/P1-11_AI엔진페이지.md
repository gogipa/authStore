## 1. 목표

이 작업이 끝나면 사용자는 SCR-13 'AI 엔진'(`/settings/ai-engine`)에서 세 엔진(`claude`·`agy`·`codex`)의 설치·로그인·연결 테스트 상태를 보고, 엔진 하나와 텍스트·비전 모델을 골라 저장한다. 저장은 고른 엔진·텍스트 모델로 10분 안에 연결 테스트를 통과했을 때만 된다. 저장하면 설정 JSON `ai` 섹션과 새 설정 스냅샷이 생긴다.
SCR-11 시스템 상태에는 'AI 도구 상태' 패널과 첫 실행 'AI 엔진 고르기' 항목이 붙는다. 4개 API(`getAiEngineSettings`·`updateAiEngineSettings`·`getLatestAiCliChecks`·`createAiCliCheck`)가 05-2와 같게 동작한다.
①~⑨ 흐름 밖의 설정 작업이다. ②·⑤·⑥의 AI 단계를 실제로 돌리기 전에 끝나야 한다. 이 작업이 없으면 기본값 `CLAUDE`(`sonnet`)로만 돈다.

## 4. 핵심 규칙

1. **설정 조회** `GET /settings/ai-engine`: 원본은 P1-03 로더가 읽은 설정 JSON의 `ai` 섹션이다. DB 테이블은 없다. 응답은 `{ selectedEngine, models, engines[3], settingsSnapshotId, updatedAt }`이고 `engines` 순서는 `CLAUDE`·`AGY`·`CODEX`다. `updatedAt`은 현재 스냅샷의 `last_loaded_at`이다. 로드된 스냅샷이 없으면 503 `SETTINGS_INVALID`. 설치·로그인 상태는 여기 넣지 않는다. (05-2 `getAiEngineSettings`, PRD §8.9 R3·R12)
2. **엔진 안내 상수**(`AiEngineOption`): 아래 값을 앱 상수로 둔다. 비밀은 없다. (PRD §8.9 R12·R14, F-ST-30, F-ST-32, 시안 AiEngine.dc.html)

   | engineCode | displayName | binName | modelOptions | allowCustomModel | defaultModels(text/vision) | loginCommand | termsNote |
   |---|---|---|---|---|---|---|---|
   | `CLAUDE` | Claude Code | `claude` | `sonnet`·`opus`·`haiku` | false | `sonnet` / `sonnet` | `claude` 실행 후 `/login` | Claude 구독의 약관·쿼터 책임은 사용자에게 있습니다. |
   | `AGY` | Antigravity CLI | `agy` | `agy models` 결과 | false | `gemini-3.8-flash-medium` / `gemini-3.8-flash-high`(M0 S7에서 확정) | 처음 실행할 때 로그인 창이 뜹니다 | Google 구독의 약관·쿼터 책임은 사용자에게 있습니다. |
   | `CODEX` | Codex | `codex` | `[]` | true | `null` / `null`(M0 S7에서 확정) | `npm install -g @openai/codex` 다음 `codex login` | ChatGPT 구독의 약관·쿼터 책임은 사용자에게 있습니다. |

3. **모델 검사**: `CLAUDE`는 `sonnet`·`opus`·`haiku`만, `AGY`는 `agy models` 결과 안의 값만 받는다. `CODEX`는 1~100자 직접 입력이다. 벗어나면 422 `AI_MODEL_INVALID`, `fieldErrors`에 `models.{엔진}.text` 또는 `models.{엔진}.vision`을 넣는다. 선택 엔진의 모델이 `null`이어도 422다. `agy models`를 부를 수 없을 때(미설치 등) `AGY` 값 검사는 문서에 없음 → 구현 때 Proposed로 정하고 기록. (F-ST-30, 05-3 `AI_MODEL_INVALID`, R12)
4. **저장 조건(10분)**: `ai_cli_check`에 조건을 모두 만족하는 행이 있어야 저장한다: `engine_code = selectedEngine`, `model = models[selectedEngine].text`, `smoke_status = 'PASSED'`, `checked_at ≥ 지금 − 10분`. 없으면 409 `AI_ENGINE_NOT_VERIFIED`, `details: { engineCode, model }`. 비전 모델은 이 조건에 들지 않는다. (PRD §8.9 R8, F-ST-31, ERD §3.14, 05-3, US-38 AC2)
5. **저장 동작** `PUT /settings/ai-engine`: 본문 `{ selectedEngine, models }`이고 추가 필드는 422 `VALIDATION_FAILED`다. 값이 현재와 같으면 새 스냅샷·SSE 없이 200 + 현재 설정을 준다. 다르면 설정 파일 `ai` 섹션을 원자적으로 쓴다(같은 폴더 임시 파일 → rename). 그다음 새 `settings_snapshot`을 만들고 SSE `settings.reloaded { settingsSnapshotId, changedKeys, valid: true, errors: [], rerunRequiredStepCount: 0 }`를 보낸 뒤 200 + 새 설정을 준다. 검사 순서(형식 → 모델 → 같은 값 → 10분 조건)는 문서에 없음 → Proposed로 기록. (05-2 `updateAiEngineSettings`, 05-1 §1.7, F-ST-31)
6. **전환 영향**: 새 엔진은 저장 뒤 새로 시작하는 AI 단계부터 쓴다. 진행 중 실행은 시작 때 고정한 엔진으로 끝난다(P1-10). 이미 만든 결과는 그대로다. 저장해도 어떤 `candidate_step`도 `RERUN_REQUIRED`가 되지 않는다. `ai.*` 키는 입력 지문·재실행 전파에서 뺀다. (PRD §8.9 R9, F-ST-31, US-38 AC2)
7. **감지**: 페이지를 열 때와 [다시 감지]를 누를 때 `POST /ai-cli-checks { smokeTest: false, trigger: 'MANUAL' }`로 세 엔진을 감지한다. 감지는 `--version`·실행 파일 경로·로그인 상태만 본다(`claude auth status`, `codex login status`, `agy`는 `UNKNOWN` = '연결 테스트로 확인'). 호출 비용이 없는 명령만 쓰고, 로그인 정보·토큰 파일은 읽지 않는다. 페이지를 열 때의 계기 코드는 문서에 없다 → `MANUAL`로 Proposed. (PRD §8.9 R6, F-ST-28, CON-11, US-38 AC1)
8. **연결 테스트**: 사용자가 [연결 테스트]를 누를 때만, 누른 엔진만 부른다. `smokeTest=true`인데 `engineCodes`가 없으면 422 `VALIDATION_FAILED`. 모델은 `models[엔진]`이고, 없으면 설정의 그 엔진 텍스트 모델이다. 그것도 비었으면(CODEX 기본) 422 `AI_MODEL_INVALID`. 화면·앱은 선택하지 않은 엔진을 스스로 테스트하지 않는다(구독 쿼터 보호). (PRD §8.9 R7, F-ST-29, 05-2 `createAiCliCheck`, US-38 AC2)
9. **점검 API** `POST /ai-cli-checks`: 202 + `Location: /api/v1/ai-cli-checks/latest` + `{ engineCodes, smokeTest, trigger, status: 'RUNNING', acceptedAt }`. 엔진마다 `ai_cli_check` 1행을 추가만 하고, SSE `ai-cli-check.completed`를 1건씩 보낸다. 점검 중에 또 오면 409 `ALREADY_IN_PROGRESS`, `details.job = 'AI_CLI_CHECK'`(메모리 잠금, 작업 행 없음). `trigger`는 `MANUAL`·`BEFORE_SAVE`·`FIRST_RUN`만 받고, `STARTUP`은 422다. 미설치 엔진은 `smoke_status=SKIPPED`다(`ck_ai_cli_check_not_installed`). (05-2 `createAiCliCheck`·`AiCliCheckRequest`, ERD §3.14 CHECK)
10. **최신 점검 조회** `GET /ai-cli-checks/latest`: 엔진마다 `checked_at DESC, id DESC` 첫 행을 준다. 점검한 적 없으면 `latest: null`이다. `selected`와 `selectedEngine`은 P1-03 로더의 `ai.engine`에서 읽는다. 로컬 경로 중 `binPath`만 예외로 내보내고, SSE에는 넣지 않는다. (05-2 `getLatestAiCliChecks`, 05-1 §1.2·§3)
11. **SCR-13 화면**: 시안 구성·문구 그대로 만든다.
    - 엔진 카드 3개는 `role="radiogroup"` 안의 진짜 `<input type="radio" name="ai-engine">`다.
    - 칩: '사용 중'(저장된 엔진), '저장 전'(골랐지만 저장 안 함), '설치 안 됨'.
    - 미설치 카드는 라디오·모델·[연결 테스트]를 끄고 "설치되지 않아 고를 수 없습니다"를 보인다. 카드는 숨기지 않는다.
    - 안내 띠 2개와 최근 점검 이력 표를 둔다.
    - 하단 저장 바는 바뀐 것이 없으면 두 버튼이 모두 꺼진다. [저장]을 눌렀는데 10분 안에 통과한 기록이 없으면 `trigger: 'BEFORE_SAVE'` 연결 테스트를 먼저 하고, 통과하면 PUT한다.

    (F-ST-27, F-ST-32, 화면시안_명세 §6 SCR-13, US-38 AC1)
12. **'실험적' 표시**: M0 S7 기준(스키마 통과율 ≥ 95%, 호출당 ≤ 120초)에 못 미친 엔진 카드에 '실험적'을 붙인다. S7 전에는 측정값이 없고, 05-2 `AiEngineOption`에 이 필드가 없다. 문서에 없음 → Proposed로 정하고 기록(예: 앱 상수. 필드를 더하면 05-2부터 고친다). (F-ST-27, PRD §8.9 R15)
13. **SCR-11 AI 도구 상태**: '텍스트·비전 AI 엔진' 묶음에 세 엔진의 설치·버전·로그인·형식 점검('OK') 결과·걸린 시간을 보인다. 선택 엔진에는 '선택됨' 칩을 붙인다. 패널 머리에 'AI 엔진 설정으로' 링크(`/settings/ai-engine`)를 둔다. `versionSupported=false`면 경고를 보이고 같은 링크를 둔다. 이미지 생성 CLI 줄은 M1 API에 조회할 곳이 없다 → Proposed로 정하고 기록. (F-SY-13, US-28 AC2)
14. **첫 실행 AI 엔진 고르기**: 첫 실행 점검 목록에 'AI 엔진 고르기' 항목과 [AI 엔진] 링크를 둔다. 추천은 설치됐고 최신 연결 테스트가 `PASSED`인 엔진 가운데 `CLAUDE → CODEX → AGY` 순서의 첫 번째다. 사용자가 저장해야 확정된다. 확정 전 설정 파일 기본값은 `CLAUDE`(`sonnet`/`sonnet`)다. 첫 실행 중 점검의 계기 코드는 `FIRST_RUN`이다. '확정 여부·시각'(캡션 'Claude Code (sonnet)로 확정 · 09:12')을 둘 곳이 M1에 없다(`install_info`는 M2). 문서에 없음 → Proposed로 정하고 기록. (F-SY-23, PRD §8.9 R3·R4, US-38 AC1)

- **앱이 스스로 연결 테스트를 부르지 않는다(R7).** 화면을 열 때, 첫 실행 추천을 만들 때, 모델을 바꿀 때 자동으로 `smokeTest: true`를 보내면 쓰지도 않을 엔진의 구독 쿼터를 쓴다. 추천은 이미 있는 PASSED 기록으로만 계산한다. 자동 점검은 앱 시작 때 선택 엔진 1개뿐이다(P1-10).
- **10분 계산의 시계를 하나로 한다.** `checked_at`은 DB `now()`로 찍힌다. 앱 시계와 섞어 비교하면 경계에서 어긋난다. FE의 `hasRecentPass`는 버튼 상태 표시에만 쓴다. 최종 판정은 BE(409)가 한다.
- **settings ↔ system 순환 의존**: settings(저장 조건)가 system(`ai_cli_check`)을 부르고, system은 선택 엔진을 설정에서 읽는다. `forwardRef`로 덮지 말고, P1-03의 읽기 전용 설정 제공자를 순환 없는 곳에서 주입받는다. 필요하면 떼어 낸다.
- **설정 파일을 직접 고친 경우가 열려 있다.** 오너가 JSON의 `ai` 섹션을 직접 고치고 다시 읽으면 10분 규칙을 건너뛴다(05-1 §7 #51, 미결). 이 작업에서 몰래 정하지 말고 결과 보고의 '오너 검토'에 올린다. 앱 시작 계약 테스트는 그래도 돈다.
- **잠금은 메모리에만 있다.** `ALREADY_IN_PROGRESS` 잠금은 작업 행 없이 메모리로 한다. 예외가 나도 `finally`에서 풀어야 다음 점검이 막히지 않는다. 앱이 다시 켜지면 잠금은 없다.
- **`agy models`도 CLI 호출이다.** P1-10 러너의 격리 규약으로 부르고, 화면 입력마다 부르지 않는다. `agy`가 없거나 목록을 못 받으면 AGY 값 검사를 어떻게 할지는 규칙 3의 Proposed 결정을 따른다.
- **로컬 경로는 `binPath`만 내보낸다.** `binPath`는 `GET /ai-cli-checks/latest`에만 넣고 SSE·로그·오류 `message`에는 넣지 않는다. 로그인 명령 안내는 문자열 상수이고, CLI를 실행해 만든 값이 아니다.
- **스캐폴딩 코드를 바꾼다.** 기존 e2e(`test/app.e2e-spec.ts`)는 스냅샷에서 선택 엔진을 읽는 스캐폴딩 동작을 확인한다. P1-03 로더로 바꾸면 그 테스트도 새 원본(설정 파일)에 맞게 고친다.
