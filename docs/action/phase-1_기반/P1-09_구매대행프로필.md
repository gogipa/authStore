## 1. 목표

이 작업이 끝나면 SCR-10 설정의 '구매대행 프로필' 탭에서 해외 출고지·반품지·택배사·반품비·교환비·상호·A/S·수입자(`importer`)·고시 고정 문구·주문당 최대 수량을 한 번 저장해 모든 상품에 쓴다. 해외 출고지는 동기화한 주소록(P1-08)의 해외 주소만 고를 수 있다. 관부가세 포함·개인통관·무료배송 같은 고정값은 코드 상수로 두고, ⑨ 요청 본문의 배송·A/S 조각을 만드는 함수로 묶어 둔다. ⑥-3 고시·고지(P3-04), G4 사전 검증(P4-02), ⑨ 등록(P4-03)이 이 프로필을 읽고, 값을 바꾸면 그 단계들이 '재실행 필요'가 된다.

## 4. 핵심 규칙

1. 프로필은 설치본당 1행이다(`singleton_key=1`, `ck_pap_singleton`). `GET`은 행이 없으면 빈 기본값으로 200을 준다: `id`·`createdAt`·`updatedAt` null, `deliveryFeeKrw=0`, `maxPurchaseQuantityPerOrder=1`, `noticeFixedTexts={}`, 나머지 null. 행은 지우지 않는다(`trg_forbid_delete`). (05-2 getPurchaseAgencyProfile, ERD `purchase_agency_profile`)
2. 기본 템플릿·코드·시드에 개인 값(상호, 연락처, 주소, 반품비, `importer`)을 넣지 않는다. `importer`는 비워 두고 사용자가 넣는다. (F-ST-07, F-BS-03, US-37 AC3, PRD §16 ③ `importer`)
3. `PUT`은 전체 교체다. 05-2 `PurchaseAgencyProfileInput`의 12개 키가 모두 있어야 한다(값은 null 허용). 키가 빠졌거나, 정의 밖 필드가 있거나, 형식이 틀리면 422 `VALIDATION_FAILED`: 반품비·교환비는 0 이상 정수, `maxPurchaseQuantityPerOrder`는 1 이상 정수, 길이는 상호 100·A/S 연락처 40·A/S 안내 1000·`importer` 100·발송 택배사 코드 40, `noticeFixedTexts`는 값이 문자열인 객체. (05-2, `ck_pap_fees`, `ck_pap_qty`, 06-2 ValidationPipe)
4. 배송비는 받지 않고 0으로 고정한다. 본문에 `deliveryFeeKrw`가 오면 정의 밖 필드라 422다. M1은 무료배송만 지원한다. (F-ST-10, `ck_pap_free_delivery`, 05-2 replacePurchaseAgencyProfile)
5. 해외 출고지는 `commerce_addressbook`에 있고 `removed_at`이 NULL이어야 한다(아니면 404 `ADDRESSBOOK_NOT_FOUND`). 그리고 `is_overseas=true`여야 한다(아니면 422 `ADDRESS_NOT_OVERSEAS`). 반품·교환지도 없거나 사라졌으면 404 `ADDRESSBOOK_NOT_FOUND`. (F-ST-08, US-21 AC1, 05-3 설정·시스템)
6. 발송 택배사 코드는 현재 설정 스냅샷의 코드 목록(코드·이름·출처) 안에 있어야 한다(아니면 422 `DELIVERY_COMPANY_NOT_ALLOWED`). 반품 택배사는 동기화 목록(`commerce_return_delivery_company`, `removed_at` NULL)에서만 고른다. 목록 밖 id에 쓸 오류 코드는 문서에 없음 → Proposed. (F-ST-09, US-21 AC1, 05-3)
7. `GET /dispatch-delivery-companies`: DB 테이블 없이 현재 `settings_snapshot.content`의 목록을 `{ items: [{ code, name, source }] }`로 준다(페이징 없음). 로드된 스냅샷이 없으면 503 `SETTINGS_INVALID`. 설정 키 이름과 기본 목록은 문서에 없음 → Proposed(해외 출고에 쓸 코드는 M0 S3). (05-2 listDispatchDeliveryCompanies, RG-03)
8. 고정값 `customsTaxType=INCLUDED`, `businessCustomsClearanceSaleYn=false`, `minorPurchasable=true`, 무료배송은 코드 상수다(열·설정 아님). 주문당 최대 수량 기본값은 1이다. 이 상수와 프로필로 ⑨ 요청 본문의 배송·A/S 조각을 만드는 함수를 둔다(P4-03이 쓴다). 구매수량 제한 필드 이름은 M0 S3. (F-ST-10, F-AP-25, US-21 AC2, ERD `purchase_agency_profile` 목적, PRD §8.7 요청 골격)
9. `missingFields`: GET·PUT 응답에 비어 있는 필수값 이름을 준다. 최소 `businessName`·`afterServicePhone`·`importer`·`overseasShippingCommerceAddressbookId`(05-2 예). 전체 목록과 빈 문자열을 null로 볼지는 문서에 없음 → Proposed. 빈칸이 있어도 저장은 된다(값 null 허용). (05-2 `PurchaseAgencyProfile.missingFields`, F-CT-24, F-AP-11)
10. `addressWarnings`(막지 않음): 프로필이 가리키는 주소록이 최신 동기화에서 사라졌으면 `ADDRESSBOOK_NOT_FOUND`, 해외 출고지가 더는 해외 주소가 아니면 `ADDRESS_NOT_OVERSEAS`를 `field`와 함께 준다. (05-2 `PurchaseAgencyProfileAddressWarning`, ERD `commerce_addressbook.removed_at`)
11. 저장 결과는 200 `{ profile, rerunRequiredStepCount }`다. 값이 바뀌면 이 값을 읽는 ⑥-3(`NOTICE_HTML`)·⑧(`UPLOAD`)·⑨(`REGISTER`) 후보 단계를 P1-05 전파로 '재실행 필요'로 바꾸고 바뀐 입력 이름을 남긴다. 자동으로 다시 실행하지 않는다. `user_action_log`에 `SETTING_CHANGED` 1행(detail은 바뀐 키 이름만). 같은 값이면 기록·전파 없이 200, `rerunRequiredStepCount=0`. (05-1 §2.12·§1.7, 05-2 replacePurchaseAgencyProfile, F-BS-21, ERD `user_action_log`)
12. 프로필 저장·재실행 필요 전파·감사 기록은 한 트랜잭션이다(문서에 없음 → Proposed, 03-2 §4 단계 완료 원칙과 같게).
13. `importer`·상호·A/S 정보가 비면 ⑥-3이 시작하지 않고(409 `PROFILE_INCOMPLETE`, P3-04), `importer`가 비면 G4 사전 검증이 막는다(P4-02). 이 작업은 두 검사가 쓸 읽기 함수(`getCurrent()`, `missingFields`)를 제공한다. (F-CT-24, F-AP-11, US-21 AC3, 05-3 `PROFILE_INCOMPLETE`)
14. 화면: '구매대행 프로필' 탭은 보드 문구 그대로 '출고·반품', '배송비·반품비·수량', '판매자·고시' 세 묶음이다. 해외 출고지 선택지는 `overseas=true` 주소록만이다. 배송비 칸은 '무료배송' 읽기 전용('판매가에 포함합니다 · 고정'). `importer`가 비면 탭에 '수입자 입력 필요' 칩과 '수입자가 비어 있어 ⑥-3을 시작할 수 없습니다. 수입자를 넣고 저장해 주세요. 기본값은 없습니다.' 안내가 뜬다. (F-ST-07~09, Settings.dc.html)

## 5. 만들 것

**BE** (`apps/BE/src/modules/settings/purchase-agency-profile/`)

- `purchase-agency-profile.controller.ts`: `getPurchaseAgencyProfile`·`replacePurchaseAgencyProfile`. `@ApiTags('settings')`, `operationId`는 05-2 그대로.
- `dto/`: `PurchaseAgencyProfileDto`, `PurchaseAgencyProfileInputDto`(12개 키 모두 `@IsDefined()` + null 허용 검증), `PurchaseAgencyProfileSaveResultDto`, `PurchaseAgencyProfileAddressWarningDto`.
- `purchase-agency-profile.service.ts`: `getCurrent()`, `replace(input)`(검증 → 바뀐 키 계산 → 트랜잭션: `singletonKey` upsert + step-engine 전파 + `user_action_log`), `computeMissingFields()`, `computeAddressWarnings()`. 주소록·반품 택배사 조회는 P1-08 `CommerceMetaCacheService`(integrations export)로 한다. C4에 settings → integrations 화살표가 없으니 Proposed로 적는다.
- `profile-input-keys.ts`: 단계가 읽는 입력 이름 `profile.<필드>`(예 `profile.importer`)와 읽는 단계(⑥-3·⑧·⑨). 단계 모듈이 프로필을 읽을 때 `step_run_input`(`source_type=SETTINGS`)에 이 이름과 값 해시를 남기게 P1-05의 입력 선언 방식에 맞춘다. 전파는 P1-05 step-engine이 주는 함수로 부른다(이름은 P1-05 결과를 따른다). 이 작업은 단계 모듈이 아니라 step-engine에 등록하지 않는다.
- `profile-fixed-values.ts`: `PROFILE_FIXED_VALUES = { customsTaxType: 'INCLUDED', businessCustomsClearanceSaleYn: false, minorPurchasable: true, deliveryFeeType: 'FREE' }`.
- `profile-registration-fragment.ts`: `buildProfileFragment(profile, addressbooks, returnCompany)` → `deliveryInfo`(`deliveryType: 'DELIVERY'`, `deliveryCompany`, 무료 `deliveryFee`, `claimDeliveryInfo`의 `shippingAddressId`·`returnAddressId`·반품·교환 배송비, `businessCustomsClearanceSaleYn`), `customsTaxType`, `minorPurchasable`, `afterServiceInfo`. 주소는 로컬 `id`가 아니라 `address_book_no`(숫자)로 바꾼다. 필드 이름은 R04 §2.11 골격을 따르고, 확인 안 된 필드(구매수량 제한, 반품 택배사 필드)는 M0 S3 표시를 남긴다.
- `apps/BE/src/modules/settings/dispatch-delivery-companies/`: `dispatch-delivery-companies.controller.ts`(`listDispatchDeliveryCompanies`) + P1-03 설정 서비스에서 현재 스냅샷을 읽는 service.
- P1-03 설정 JSON Schema와 기본 템플릿에 발송 택배사 목록 키를 더한다(이름 Proposed, 예 `delivery.dispatchCompanies: [{ code, name, source }]`). 출처가 없는 코드는 기본 템플릿에 넣지 않는다.
- `common/errors/error-codes.ts`: `ADDRESSBOOK_NOT_FOUND`(404), `ADDRESS_NOT_OVERSEAS`(422), `DELIVERY_COMPANY_NOT_ALLOWED`(422), `SETTINGS_INVALID`(503, P1-03에 없으면)를 05-3 문구로 더한다.

- ERD §7.2-18(배송기간·교환 정책은 설정 파일)은 바꾸지 않는다.

## 6. 테스트

**단위** (Jest ESM, 가짜 캐시·전파는 DI로)

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).

- 프로필은 로컬 `commerce_addressbook.id`를 저장하지만, ⑨ 요청의 `shippingAddressId`·`returnAddressId`는 네이버 주소록 번호(`address_book_no`, int64)다. 조각 함수에서 바꾸고 테스트로 고정한다. 잘못 넣으면 실제 스토어에 엉뚱한 출고지로 등록된다.
- 전파 부작용: 프로필을 한 번 저장하면 진행 중 후보 여럿의 ⑥-3·⑧·⑨가 '재실행 필요'가 된다. 값이 실제로 바뀐 키만 전파하고, 같은 값 저장은 아무것도 바꾸지 않는다.
- `importer` 표기(상호 vs 실구매자)는 법률 확인(E-3) 전이다. 기본값을 채우거나 상호를 자동으로 복사하지 않는다.
- 발송 택배사의 해외 출고용 코드, 구매수량 제한 필드, 고시 0/1 입력 형식은 M0 S3 전이다. 추측한 코드를 기본 템플릿에 넣지 않고 출처가 있는 값만 둔다.
- 배송기간(기본 10~20영업일)·교환 정책 문구는 프로필이 아니라 설정 파일에 있다(ERD §7.2-18). 오너 결정 없이 프로필 열을 더하지 않는다.
- 선택지는 P1-08 캐시에 기댄다. 캐시가 비어도 폼이 깨지지 않게 하고, 테스트는 동기화 대신 시드로 채운다.
- SCR-10은 P1-03(설정 파일 검사)·P2-04(요금표·환율)와 같이 쓴다. 탭 하나만 더하고 페이지 틀을 갈아엎지 않는다.
- `purchase_agency_profile`은 삭제 금지 트리거가 있다. 테스트 정리는 `deleteMany`가 아니라 `TRUNCATE … CASCADE`다.
