## 4. 핵심 규칙

1. 부품 하나에 폴더 하나를 쓴다(`shared/ui/<Name>/<Name>.tsx` + `<Name>.module.css`). 밖으로는 `shared/ui/index.ts`로만 낸다. CSS에는 `tokens.css` 변수만 쓴다. 토큰이 없는 치수는 숫자로 쓰고 주석을 단다 (04-3 §1, 04-2 §5).
2. 변형 prop 하나(문자열 유니언)가 CSS 클래스 하나가 된다. 상태 prop은 API 코드 그대로 받고, 글자로 바꾸는 일은 부품이 한다. `StatusChip`의 글자는 아래와 같다.

   | 코드 | 글자 |
   |---|---|
   | `COMPLETED` | 완료 |
   | `RUNNING` | 실행중 |
   | `WAITING_INPUT` | 입력 대기 |
   | `RERUN_REQUIRED` | 재실행 필요 |
   | `FAILED` | 실패 |
   | `NOT_RUN` | 미실행 |

   아이콘은 상태마다 하나로 고정한다. `detail` prop을 주면 `FAILED`의 글자를 '실패(중단됨)'으로 바꾼다(`failureKind=INTERRUPTED`일 때) (04-3 §1·§3, 공통부품 §C, 05-1 §1.1).
3. `GateBadge`는 게이트 이름을 `GATE_LABEL`에서 가져온다(G1 키워드 선택·G2 판정 확정·G3 썸네일 선택·G4 최종 승인·G5 전시 켜기). 상태별 모양은 아래와 같다.

   | `state` | 붙는 글자 | 색 | 마름모 |
   |---|---|---|---|
   | `passed` | ` · 통과` | done | 채움 |
   | `pending` | ` · 확인 필요` | waiting | 채움 |
   | `locked` | ` · 잠김` | idle | 테두리만 |

   (04-3 §3, 공통부품 §D).
4. `Num`과 `shared/lib/format.ts`는 `167,300원`·`¥12,000`·`255mm`·`10%`·`14:02` 모양으로 쓴다. 시각은 Asia/Seoul로 쓴다. 글꼴은 mono에 `tabular-nums`, 표 안에서는 오른쪽 정렬이다 (공통부품 §J, PRD §9 시간대).
5. 접근성 약속:
   - `IconButton`: `aria-label` 필수. 타입으로 강제한다.
   - `Switch`: `role="switch"`와 `aria-checked`.
   - `ProgressBar`: `role="progressbar"`.
   - `Tabs`: `role="tablist"`·`tab`과 `aria-selected`.
   - `FilterToggleGroup`: `aria-pressed`.
   - `Disclosure`: `aria-expanded`.
   - `TextField`: 오류일 때 `aria-invalid`, 라벨은 `<label for>`.
   - 꺼진 버튼 옆에는 `DisabledReason`으로 꺼진 이유를 보이는 글로 쓴다.

   (04-3 §2, 화면시안_명세 §1·§3).
6. 공통 부품은 데이터를 부르지 않는다. API 코드 값만 받는 부품(`StatusChip`·`GateBadge`)은 도메인 말을 알아도 shared에 둔다. `Meter`·`Dialog`는 M2라 만들지 않는다. 시안에만 있는 M2 부분도 만들지 않는다 (04-3 §1·§2).
7. 레이어 경계는 03-2 §5의 `no-restricted-imports` 초안을 `apps/FE/eslint.config.js`에 넣어 지킨다.
   - shared → app·pages·features: 금지
   - features → app·pages, 다른 feature의 내부 파일: 금지
   - pages → app, 다른 pages, feature 내부 파일: 금지

   (03-2 §4·§5).
8. API는 `shared/api/client.ts`의 `api` 하나로만 부른다. `fetch`를 직접 부르지 않는다. 예외는 SSE와 이미지 `<img src>` 두 가지다. `X-AutoStore-Client: 1`은 미들웨어가 붙인다 (03-2 §6.2, 05-1 §1.2).
9. queryKey는 `[태그, operationId, 파라미터?]`다(예: `['integrations', 'getCallUsage']`). 훅은 `features/<OpenAPI 태그>/api/`에 두고, 화면은 훅만 부른다. 오류는 05-3 봉투로 받는다. 화면은 `code`로 갈라 처리하고 `message`를 그대로 보여 준다 (03-2 §3·§6.2, 05-3 §2).
10. SSE 규칙:
    - 앱 전체에 `EventSource('/api/v1/events')`는 하나다.
    - 이벤트가 오면 관련 쿼리를 무효화만 한다. 캐시에 값을 직접 쓰지 않는다.
    - 연결이 끊겼다가 다시 붙으면 활성 쿼리를 모두 다시 읽는다. 서버가 놓친 이벤트를 다시 보내지 않기 때문이다.
    - 202 작업의 결과를 폴링하지 않는다.

    (03-2 §6.3, 05-1 §1.3, 05-2 `streamProgressEvents` x-decision).
11. 서버 값은 TanStack Query에만 둔다. 전역 클라이언트 스토어는 두지 않는다. 고른 탭·필터처럼 새로 고침 뒤에도 남아야 하는 값은 URL search params에 둔다 (03-2 §6.1).
12. 내비 상태 상자는 '오늘 페이지 조회 {count}/{dailyLimit}'를 `RAKUTEN_PAGE` 항목으로 보여 준다. 조회에 실패하면 `—`를 보인다(지금 코드의 빈 값 표시, Proposed). 등록 차단 칩은 `getRegistrationSwitch`(P4-03)가 붙을 때까지 지금 문구를 둔다. 문구는 공통부품 §A를 글자 그대로 쓴다 (05-2 layout §3, 공통부품 §A).
13. `AppLayout` 아래에 경로 없는 layout route를 하나 두고 `ErrorBoundary`를 붙인다. 오류가 나도 내비는 남는다. 본문에는 오류 봉투의 `message`와 '다시 시도' 버튼을 보인다. 없는 경로(`*`)에는 "없는 화면입니다"와 대시보드 링크를 보인다 (05-2 layout §4-2·§6).
14. 화면 하나를 route `lazy` 청크 하나로 나눈다. `AppLayout`·`AppNav`·`CandidateLayout`·`StepRail`·`NotFoundPage`·`shared`는 나누지 않는다(eager) (05-4 §1·§2).
15. 실행 중에 밖을 부르지 않는다. 글꼴·아이콘을 CDN에서 받지 않는다. 아이콘은 인라인 SVG(24 격자, 선 1.5px)다. 라이트 테마만 만든다 (README 공통 규칙, D-13, 04-3 `Icon`).

## 6. 테스트

FE는 Vitest + Testing Library(jsdom)다. jsdom에는 `EventSource`가 없어서 `src/test/fakeEventSource.ts`를 넣는다. BE 코드는 바꾸지 않지만 `pnpm test:e2e`는 그대로 통과해야 한다.

**부품 (`shared/ui/**/*.test.tsx`)**
- `StatusChip`: 코드 6개 → 글자·클래스가 규칙 2의 표와 같다. `status="FAILED" detail="INTERRUPTED"` → "실패(중단됨)".
- `GateBadge`: `gate="G2" state="passed"` → "G2 판정 확정 · 통과". `G3`·`locked` → "G3 썸네일 선택 · 잠김"이고 마름모 `fill="none"`. `G4`·`pending` → "G4 최종 승인 · 확인 필요".
- `Num`·`format`: `167300` krw → `167,300원`, `12000` yen → `¥12,000`, `255` mm → `255mm`, `10` pct → `10%`, `2026-09-27T05:02:00Z` time → `14:02`.
- `IconButton`: `aria-label`이 없으면 타입 오류다. `// @ts-expect-error` 줄을 두어 `pnpm typecheck`로 확인한다.
- `Switch`: 클릭·Space로 `aria-checked`가 바뀐다.
- `Tabs`: 누른 탭만 `aria-selected="true"`.
- `Disclosure`: `aria-expanded`가 바뀐다.
- `FilterToggleGroup`: `aria-pressed`가 바뀐다.
- `TextField`: `error`가 있으면 `aria-invalid="true"`이고, 라벨로 칸을 찾을 수 있다.
- `Banner`: tone 3개 → 클래스 3개. `DataTable`: 숫자 열은 오른쪽 정렬, `selected` 행에 `.selected`.
- 토큰 검사(`shared/ui/tokens-only.test.ts`): `shared/ui/**/*.module.css`에 `#[0-9a-fA-F]{3,8}`·`rgb(` 글자가 없다.

**API·SSE (`shared/api/*.test.ts`)**
- `unwrap`: 409 봉투(`{code:'DAILY_LIMIT_REACHED',…}`)를 받으면 `ApiRequestError`를 던진다. `code`·`status`·`message`가 봉투 그대로다.
- `qk('step-engine','getCandidate',{candidateId:12})` → `['step-engine','getCandidate',{candidateId:12}]`.
- `connectProgressEvents`:
  - provider가 둘이어도 `EventSource` 인스턴스는 1개이고, URL은 `/api/v1/events`다.
  - `call-usage.changed`가 오면 `invalidateQueries`가 `['integrations','getCallUsage']`로 불린다. 모르는 이벤트는 무시한다.
  - `fail()` 뒤 `reopen()`이면 활성 쿼리 전체를 무효화한다.
  - 언마운트하면 `close()`가 불린다.

**앱 틀 (`app/*.test.tsx`)**
- `AppNav`: API 가짜가 `RAKUTEN_PAGE` 38/110을 돌려주면 "오늘 페이지 조회 38/110"이 보인다. 이벤트 뒤 39를 돌려주면 "39/110"으로 바뀐다. API가 실패하면 "—"가 보인다.

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- 기능 ID가 없는 화면 공통 작업이다. docs/dev/FE/04_디자인토큰컴포넌트/04-3_컴포넌트계층.md의 M1 부품을 만든다.

- 시안끼리 문구가 다르다. 공통부품 §A는 "오늘 페이지 조회 38/110"·"등록 API 차단 켜짐 · 드라이런"이고, 화면시안_명세 §3은 "하루 페이지 조회"·"등록 API 차단 스위치 켜짐"이다. 공통부품이 '글자 그대로 복사' 규칙이므로 공통부품을 따르고, 차이를 결과 보고에 적는다.
- `StepStatusBar`·`StepTable`·`StepDots`(`features/step-engine`)와 후보 머리의 실제 값은 후보·단계 API가 있어야 만든다. P1-04·P1-05에서 만든다. 여기서 만들면 다음 문서와 겹친다.
- 이벤트 → 무효화 표(`EVENT_INVALIDATIONS`)에는 이 문서에서 `call-usage.changed` 하나만 넣는다. 나머지 21개는 해당 도메인 훅을 만드는 실행 문서가 같은 표에 더한다. 화면마다 `EventSource`를 새로 열지 않는다.
- `schema.d.ts`·`tokens.css`는 생성물이다. 손으로 고치지 않는다. 명세가 바뀌면 `pnpm api:gen`, 토큰이 바뀌면 `pnpm --filter @autostore/fe tokens:gen`을 돌린다.
- 오류 필드 형식이 문서끼리 다르다. 05-2 `FieldError`는 `{ field, message, rejectedValue? }`, 05-3 §2 예시는 `reason`이다. FE는 생성 타입(05-2)을 따른다(06-2 §9-4에서 열린 문제).
- `lazy`로 바꾸면 기존 동기 테스트가 깨질 수 있다. 경로 테스트는 `await screen.findBy…`로 바꾼다. 단계 화면끼리 오갈 때 `CandidateLayout`이 다시 받아지지 않게 eager로 둔다(05-4 §4).
- Chip tone 가운데 '템플릿 제안'·'임시'·'수동'은 보드에서 읽은 값이고 디자인 사전에는 없다(04-3 §3). 04-3 §4의 오너 확인 세 건도 아직 열려 있다. 그대로 구현하되 결과 보고의 '오너 검토'에 올린다.
