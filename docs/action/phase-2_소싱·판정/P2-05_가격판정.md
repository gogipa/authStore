## 1. 목표

②에서 고른 라쿠텐 상품의 사이즈별 가격으로 ③ 판정이 돈다. 사이즈마다 원가·면세·배대지·관부가세·수수료·부가세를 계산하고, 최소 판매가(P_min)·판매 가능 여부·판매가를 정해 판정 스냅샷으로 남긴다. 오너는 판정 화면(SCR-04)에서 국내 기준가를 넣고(네이버쇼핑 링크 포함), URL 후보면 '비교 없이 확정'을 체크한 뒤 G2(소싱 확정)를 통과한다. 흐름에서는 ② 소싱 다음, ④ 카테고리 앞이며, 연속 실행은 G2 전까지 여기서 멈춘다.

## 4. 핵심 규칙

1. **시작 조건과 입력 대기**: ③은 ② 현재 버전이 '완료'일 때만 시작한다. 읽는 값은 재고 있는 목표 사이즈의 SKU가(`taxIncludedPrice`, 쿠폰 전), 일본 내 송료와 '송료 추정' 여부, 쿠폰, 후보 성별, 판정 설정, 환율 3종, 활성 요금표다. 환율 3종 중 하나라도 없으면 시작 때 409 `FX_RATE_UNAVAILABLE`이다. 국내 기준가 행이 없으면 `WAITING_INPUT`(`pendingInputs`에 `owner.domesticPrice`)으로 멈추고, 있으면 최신 행을 기본값으로 쓴다. 연속 실행은 G2 전에는 ③에서 멈춘다(`AWAIT_G2`). (F-PJ-14, PRD §5.3 ③, 05-1 표 A, ERD §1.4)
2. **쿠폰**: 비교를 한 후보는 ② 선택 행의 `coupon_yen`을 쓴다. 비교하지 않은 URL 후보(`comparison_performed=false`)는 화면 쿠폰 칸(엔, 기본 0)을 실행 body `ownerInputs.couponYen`(0 이상 정수)으로 받아 `pricing_coupon_input` 새 행으로 넣고, 최신 행을 시작 조건 `owner.coupon`으로 읽는다. 비교를 한 후보가 `couponYen`을 보내면 422 `COUPON_NOT_ALLOWED`다. (F-PJ-01, ERD `pricing_coupon_input`·§7.2-19, 05-3)
3. **상품원가**: `C_goods_i = (Y_item_i + Y_ship − Coupon) × FX_base × (1 + 2.5%)`. 쿠폰은 이 식에만 쓰고, 면세 판정과 과세가격에는 넣지 않는다. (F-PJ-03, US-08 AC1, PRD §8.3 1))
4. **면세 판정**: `V_usd_i = (Y_item_i + Y_ship) × FX_cJPY / FX_cUSD`(쿠폰 전, 국제운임 빼고). `V_usd_i ≤ 150 − 5 = 145`면 면세다. `2 × V_usd_i > 145`면 '2켤레 주문 시 과세 전환', `142.5 ≤ V_usd_i ≤ 157.5`(150달러 ±5%)면 '경계' 배지다. 면세 경계 엔화 `duty_free_limit_yen = floor(145 × FX_cUSD / FX_cJPY)`(내림은 Proposed, 예 ¥22,490). (F-PJ-08, F-PJ-11, US-08 AC2)
5. **관부가세와 과세 사이즈**: 과세 사이즈는 `CV_i = (Y_item_i + Y_ship) × FX_cJPY + C_ship_intl`, `C_tax_i = CV_i × t + (CV_i + CV_i × t) × 10%`다. `t`는 6401 8%, 6402~6405 13%이고, 상품별 HS 판정 방법은 문서에 없음(ERD §7.1-8) → 구현 때 Proposed로 정하고 기록(적용 값은 `params`). 간이세율 18%는 설정(기본 꺼짐), FTA·RCEP는 쓰지 않는다. 과세 사이즈 판매 설정(F-ST-02)이 꺼져 있으면(M1 기본) 과세 사이즈는 예상액만 보여 주고 `unsellable_reason=TAXABLE`로 뺀다. 면세면 `c_tax_krw=0`(`ck_pjs_duty_free_tax`). (F-PJ-09, F-PJ-10, US-08 AC2, PRD §8.3 3))
6. **배대지 비용**: 신발 박스 기본값 33×22×12cm·1.2kg으로 청구무게 = max(실무게, 부피무게 = 33×22×12 / 나눗수)를 잡는다(부피무게 적용 조건은 요금표 열). 활성 요금표에서 `weight_max_kg ≥ 청구무게`인 가장 작은 구간 요금이 `C_ship_intl`이고, 엔화면 `FX_base`로 바꾼다. 검수·포장비는 설정(기본 포함)이며 금액 설정 키는 문서에 없음 → Proposed. 셀러라이프 쿠폰(F-ST-05)을 켜면 뺀 금액을 `fwd_coupon_krw`에 남긴다. 활성 요금표가 없으면 `C_fwd = 15,000`, `fwd_assumed=true`, `forwarder_rate_table_id=NULL`(`ck_pj_fwd_assumed`). 가장 큰 구간을 넘는 무게와, 요금표가 없을 때 CIF에 쓸 `C_ship_intl`은 문서에 없음 → Proposed. (F-PJ-06, F-PJ-07, US-09 AC4)
7. **순이익과 최소 판매가**: `C_mkt = P × 3.0% + P × 3.63%`(고객 배송비 0). 모드 A `VAT_A = (P − C_goods − C_fwd − C_tax)/11 − C_mkt/11`, 모드 B `VAT_B = P/11 − C_mkt/11`, 모드 C 0. `Π(P) = P − C_goods − C_fwd − C_tax − C_mkt − VAT − 3,000`, 마진율 = Π/P. `P_min_i`는 `Π_A(P) ≥ max(10% × P, 5,000)`인 가장 작은 P를 이분 탐색으로 찾아 100원 단위로 올린다. 원 단위 반올림 시점은 문서에 없음 → 항목마다 원 단위 반올림(half-up)을 Proposed로 한다(PRD 예시를 그대로 낸다). (F-PJ-04, F-PJ-05, US-08 AC1, PRD §8.3 4)~7))
8. **1차 판정**: `P_min_i ≤ P_ref × (1 − 1%)`면 판매 가능, 아니면 `P_MIN_OVER_REF`로 판매 불가다. `P_ref`는 '판매가 + 고객 배송비' 총액이다. (F-PJ-15, US-08 AC3, PRD §8.3 8))
9. **판매가 책정**: 기본 `REF_MINUS_1PCT` = `floor100(P_ref × 0.99)`. 설정으로 `REF_MINUS_100` = `P_ref − 100`, `MAX_SKU_SINGLE` = 가장 비싼 사이즈 기준 단일가(max `P_min_i`로 해석, Proposed), `OPTION_PRICE` = `salePrice = min(P_min_i)`, `옵션가_i = ceil100(max(0, P_min_i − salePrice))`. 단일가 규칙은 `salePrice ≥ max(판매 가능 P_min_i)`를 지킨다. 사이즈별 판매가 = `salePrice + 옵션가_i`(단일가면 옵션가 0). (F-PJ-16, US-08 AC3, PRD §8.3 9))
10. **모드 B 게이트**: 판매 가능 사이즈마다 사이즈별 판매가로 계산한 `Π_B < 0`이면 `MODE_B_NEGATIVE`로 뺀다. 빠진 사이즈 때문에 하한(max 또는 min `P_min_i`)이 바뀌면 9부터 다시 계산하고, 더 빠지는 사이즈가 없을 때까지 반복한다. 저장은 마지막 결과만 한다. (F-PJ-17, US-08 AC3, PRD §8.3 10)·11))
11. **최종 판정과 후보 제외**: 게이트 뒤 판매 가능 사이즈 수 ≥ 최소 기준(설정, 기본 3)이면 판매 후보다. 모자라면 `is_sale_candidate=false` + `exclusion_reason`(한국어 사유)이고, ③은 `COMPLETED`, 후보는 같은 완료 트랜잭션에서 `EXCLUDED`(`excluded_reason`·이력 사유 `NOT_SALE_CANDIDATE`)가 된다. 제외된 후보는 단계 실행·국내 기준가 입력이 409 `CANDIDATE_EXCLUDED`라, 다시 판정하려면 `POST /candidates/{id}/reopen`(REOPENED)부터 한다. (F-PJ-18, US-08 AC3, PRD §5.2, ERD `ck_pj_exclusion`·`ck_pj_sale_sizes`)
12. **판정 스냅샷과 기준 시각**: 판정마다 `price_judgement` 1행(`step_run_id` UNIQUE) + 재고 있는 목표 사이즈마다 `price_judgement_size` 1행을 만든다. `sku_price_source=STEP2`, `rakuten_item_id`·`rakuten_page_collected_at`(② `rakuten_item.collected_at` 사본, 복합 FK), `domestic_price_id`, 환율 3종 id, 요금표 id, `vat_mode`, `pricing_rule`, `target_margin_rate`, `min_profit_krw`를 열로, 나머지 기준값은 `params`로 둔다. ③만 다시 실행해도 수집 시각은 ② 버전 값 그대로다. `pageValidUntil = rakuten_page_collected_at + 6시간`(설정, 6시간 초과 불가)이고, 넘으면 연속 실행은 ③을 건너뛰지 않고 ② 재조회부터 한다. 실행이 닫히면 스냅샷을 고칠 수 없다(`price_judgement_frozen`). (F-PJ-21, F-PJ-22, F-BS-05, ERD §3.4)
13. **국내 기준가 API**: `POST …/domestic-prices`는 `pRefKrw`(0보다 큰 정수)·`sourceLabel`(100자)·`sourceUrl`(URI, 2048자)로 새 행(추가만)을 만들고 201 + `pricingStepStatus`를 준다. ③이 국내 기준가를 기다리면 이어서 계산하고(`RUNNING`), 완료였으면 `RERUN_REQUIRED`(바뀐 입력 `owner.domesticPrice`), 실행 중이면 409 `STEP_LOCKED_BY_RUNNING_STEP`, 잠긴 후보는 409 `CANDIDATE_LOCKED`다. M1은 `sourceKind=MANUAL`만 받는다(SELLAFINDER 거부 방식은 Proposed). 이력은 `enteredAt,desc` 페이징이다. (F-PJ-13, US-07 AC2, 05-1 §2.4, 05-2 `createDomesticPrice`)
14. **네이버쇼핑 링크**: 저장 없이 0~2개를 준다. `SOURCE_KEYWORD` = 출처 키워드 원문(`keyword.keyword`), `MODEL_CODE` = 앵커 型番(`candidate.anchor_model_code`), 값이 있는 것만이다. 검색 URL 형식은 문서에 없음 → Proposed. 링크는 국내 기준가 입력 영역에만 두고 라쿠텐 가격이 보이는 영역에는 두지 않는다. 새 탭으로 연다. (F-PJ-12, US-07 AC1, CON-14, 05-2 x-decision §7-28)
15. **'비교 없이 확정'과 G2**: `PUT …/no-comparison-confirmation`은 ② 현재 버전이 `comparison_performed=false`인 URL 후보만 받고, 아니면 409 `CONFIRMATION_NOT_APPLICABLE`이다. 이미 체크돼 있으면 기존 시각으로 200, 새로 체크하면 `user_action_log`(OWNER_CONFIRMED)를 남긴다. `DELETE`는 204, G2 통과 뒤면 409 `GATE_ALREADY_PASSED`다. G2 통과는 ③ 현재 버전이 완료·최신(409 `STEP_NOT_COMPLETED`), 판매 후보(409 `NOT_SALE_CANDIDATE`), URL 후보면 체크 있음(409 `NO_COMPARISON_NOT_CONFIRMED`)이어야 한다. G2 지문 = 소싱 itemCode·색상 + 판매 여부 + 판매 사이즈 + 사이즈별 판매가·옵션가이고, ③을 다시 돌려도 이 값이 같으면 G2는 유효하다. (F-PJ-02, F-PJ-20, F-CW-02, US-06 AC3, 05-1 표 C)

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- PRD §8.3 계산 예시(¥12,000 · 환율 8.76 → 상품원가 107,748 · 배대지 15,000 · P_min 153,100 · 판매가 167,300 · 모드 A 부가세 3,042 · 순이익 27,418(16.4%) · 모드 B 순이익 16,259)를 테스트 기대값으로 고정한다.

- **소수·반올림**: 6,072.99원 같은 값이 생긴다. 금액·환율은 `Prisma.Decimal`로 계산하고, 원 단위 반올림은 `money.ts` 한 곳에서만 한다. 반올림 위치를 바꾸면 PRD 예시(27,418원·16,259원)가 1원씩 틀어진다.
- **수집 시각은 사본이다**: `rakuten_page_collected_at`에 `now()`를 쓰면 ③만 다시 돌릴 때 6시간 유효 시간이 늘어나 오래된 가격으로 등록된다(F-PJ-22). ② 버전의 `rakuten_item.collected_at`을 복사한다.
- **입력 대기 중에는 스냅샷이 없다**: `price_judgement.domestic_price_id`가 NOT NULL이라 국내 기준가가 없으면 행을 만들 수 없다. 이때 `GET …/price-judgement`는 404이고, 화면은 입력 패널과 대기 상태만 보인다. 판정은 국내 기준가 입력으로 재개된 뒤 한 번에 저장한다.
- **쿠폰은 시작 조건이다**: `ownerInputs`는 원래 입력 지문에서 빠지지만, URL 후보 쿠폰은 `pricing_coupon_input` 행으로 넣은 뒤 `owner.coupon`으로 지문에 넣는다(ERD §7.2-19). 순서가 바뀌면 쿠폰을 바꿔도 '재실행 필요'가 안 생긴다.
- **G2 지문 안정성**: 사이즈를 `size_mm` 순으로 정렬하고 정수 값만 넣는다. 정렬이 흔들리면 같은 판정인데 G2가 무효가 된다.
- **후보 제외 부작용**: 판매 후보 아님이면 후보가 바로 `EXCLUDED`가 된다. 재조회(`POST …/refetch`) 뒤 재판정도 같다. 제외된 후보는 `reopen` 없이는 다시 돌릴 수 없다.
- **P4-02가 기대는 것**: 최종 승인 검사(F-AP-19 역마진, RG-08 판정 유효 시간)는 저장된 `profit_b_krw`·`target_margin_rate`·`min_profit_krw`·`rakuten_page_collected_at`을 읽는다. 열 뜻을 바꾸지 않는다.
- **M1은 면세만 판다**: 과세 사이즈도 `C_tax`와 `P_min`은 계산해 보여 주지만 판매 사이즈에 넣지 않는다. 과세 판매 설정(F-ST-02)은 E-2 확인 전까지 꺼 둔다.
