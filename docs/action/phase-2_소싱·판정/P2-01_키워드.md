## 1. 목표

데이터랩 인기검색어를 '수집' 버튼(여성·남성 cid 차례, 상위 100·500위)이나 순위 붙여넣기로 모아 키워드 묶음으로 저장하고, 아동화 키워드를 기본으로 뺀 목록에서 오너가 키워드를 골라(G1) 라쿠텐 검색어 확인으로 넘길 수 있다.
흐름 ①~⑨의 맨 앞 ①이다. 고른 키워드는 후보의 '출처 키워드'(정보용)와 ② 검색어 기본값이 된다.
키워드·검색어·URL 세 경로가 함께 쓰는 아동화 공통 판별 규칙(F-BS-12)도 여기서 만들고, P2-02·P2-06이 그대로 쓴다.

## 4. 핵심 규칙

1. **수집 대상·순서**: 버튼 수집은 `50000173`(여성신발) → `50000174`(남성신발) 순서로 cid마다 따로 요청한다. 한 요청에 cid 하나만 보내고, 콤마가 든 cid는 어댑터가 호출 전에 막는다. `requestedCids`·`filters`는 M2 필드라 M1 화면은 보내지 않고, 서버는 없으면 기본 2개를 쓴다. (PRD §8.1, F-KW-01, F-BS-33, 05-2 `KeywordButtonCollectionRequest`)
2. **범위**: `rankLimit` 100(기본) = cid당 page 1~5, 합계 10요청. 500 = cid당 page 1~25, 합계 50요청. `count=20` 고정. (F-KW-01, F-KW-02, ERD `ck_kws_rank_limit`)
3. **요청 형식**: `POST https://datalab.naver.com/shoppingInsight/getCategoryKeywordRank.naver`, `application/x-www-form-urlencoded`, form `cid`·`timeUnit=date`·`startDate`·`endDate`·`age`·`gender`·`device`(M1은 빈 값 = 전체)·`page`·`count=20`. 헤더 `Referer: https://datalab.naver.com/shoppingInsight/sCategory.naver`, 앱 고유의 정직한 UA(브라우저 위장 금지). URL·Referer·UA·페이지 크기·최대 페이지는 설정 파일 값이다. 날짜 형식은 `YYYY-MM-DD`(M0 S4에서 확정). (PRD §8.1, F-BS-33, F-BS-08, R01-NFR-04)
4. **실행 조건·간격**: 오너가 '수집'을 누를 때만 1회 돈다. 요청은 하나씩, 사이 간격 2초 이상. 예약·자동 반복·병렬 수집은 없다. 수집 중 두 번째 BUTTON 요청은 409 `ALREADY_IN_PROGRESS`(`details.job=KEYWORD_COLLECTION`). (F-BS-33, F-BS-09, US-01 AC1, 05-2 `createKeywordSnapshot`)
5. **기간**: 종료일 = 어제(Asia/Seoul), 시작일 = 종료일 − 1개월(달력 기준), `timeUnit=date`. 응답 `range`(예: `2026.08.23. ~ 2026.09.23.`)를 파싱해 요청 기간과 대조하고 `response_range`·`range_matched`에 남긴다. 불일치 때 멈출지와 월말(3/31 − 1개월) 계산은 문서에 없음 → 구현 때 Proposed로 정하고 기록(기본안: 멈추지 않고 표시만). (F-KW-03, US-01 AC1, R01-NFR-03)
6. **정상·이상 구분**: `ranks: []`는 그 cid의 정상 종료다. 이상 8종(`NO_RANKS_KEY`·`HTTP_404`·`NOT_JSON`·`RETURN_CODE`·`COUNT_MISMATCH`·`HTTP_403`·`HTTP_418`·`HTTP_429`)이면 자동 재시도 없이 즉시 멈추고 묶음을 `ABORTED` + `abort_reason` + `http_status`로 닫는다. Content-Type이 `text/html`이어도 본문을 JSON으로 읽는다. '건수 불일치'의 정확한 기준은 문서에 없음 → Proposed. (F-KW-04, US-01 AC2, PRD §8.1, ERD `ck_kws_abort_reason`·`ck_kws_abort_pair`)
7. **경고·24시간 쉼**: 이상 8종 모두 붙여넣기 입력란을 연다. `structureChangeSuspected`는 앞 5종(키 없음·404·JSON 아님·returnCode·건수)일 때만 true이고 화면에 '데이터랩 구조 변경 의심' 경고를 띄운다. 403·418·429 뒤에는 `call_log`(target=DATALAB) 기준 24시간 쉰다. 그동안 BUTTON은 409 `EXTERNAL_CALL_COOLDOWN`(`details.target=DATALAB`·`blockedUntil`, `Retry-After`)이고 붙여넣기는 된다. 쉼 판단은 `call_log`만 본다. (F-KW-04, F-BS-10, ERD 결정 ⑦, 05-2 `getKeywordSnapshot`)
8. **수집 기록·진행 알림**: 요청마다 P1-01 외부 호출 관문이 `call_log` 1행(target=`DATALAB`, 보내기 직전 삽입, 응답 코드·건수 채움)을 남긴다. BUTTON은 202 + `Location: /keyword-snapshots/{id}` + `{ keywordSnapshotId, status: RUNNING, rankLimit, requestedCids }`. 진행은 SSE `keyword-collection.progress`(페이지마다)·`.completed`·`.aborted`. (F-BS-11, 05-1 §1.3·§3, ERD `ck_kws_status`)
9. **붙여넣기**: `method=PASTE`, `text` 1~100,000자(넘으면 413 `PAYLOAD_TOO_LARGE`), `cid` = `50000173`·`50000174`·null(모름, 기본). 줄 단위로 '순위 + 키워드'를 읽어 곧바로 201. 형식 불일치·같은 순위 중복은 422 `IMPORT_PARSE_FAILED`(fieldErrors에 줄), 읽을 줄 0개는 422 `IMPORT_EMPTY`. 붙여넣기 묶음은 `period_*`·`rank_limit`이 null이다. 정확한 줄 형식은 M0 S4 복사 텍스트로 정한다(Proposed). (F-KW-05, US-01 AC3, 05-2 `KeywordPasteRequest`, ERD `ck_kws_button`)
10. **스냅샷·목록**: 버튼·붙여넣기 모두 `keyword_snapshot` 1행 + `keyword` N행이다. 두 표는 삭제 금지다. `GET /keyword-snapshots`는 `page`(0부터)·`size`(기본 20, 최대 100), `sort`는 `collectedAt`만(기본 `collectedAt,desc`), 필터 `method`·`status`. `keywordCount`·`excludedCount`는 집계값이다. `GET …/keywords`는 `sort=rank`만(기본 `rank,asc`), 필터 `cid`·`excluded`, `candidateIds`는 `candidate.source_keyword_id` 역참조. 허용 밖 값은 422 `INVALID_QUERY_PARAMETER`. (F-KW-06, 05-1 §1.4, ERD §1.3 `trg_forbid_delete`)
11. **아동화 키워드 제외**: 수집·붙여넣기 직후 아동 단어가 든 키워드는 `excluded_reason='CHILD'`로 저장한다(지우지 않음). 목록은 기본 `excluded=false`, `excluded=true`면 제외된 것만. 기본 단어는 키즈·주니어·아동·キッズ·ジュニア·ベビー(`builtIn=true`)다. `POST /child-keyword-terms`로 더하기만 되고 삭제 API는 없다. 같은 단어 409 `CHILD_TERM_ALREADY_EXISTS`, 빈 값·100자 초과 422 `VALIDATION_FAILED`. 더하면 설정 파일을 다시 쓰고 새 `settings_snapshot`을 만들며(201 `settingsSnapshotId`), 이미 수집한 묶음에는 다시 적용하지 않는다. 단어 비교 정규화(NFKC·대소문자)는 문서에 없음 → Proposed. (F-KW-07, US-02 AC1, 05-2 `addChildKeywordTerm` x-decision)
12. **아동화 공통 판별(F-BS-12)**: 아동 단어 검사, 장르가 설정 genreId(558885 靴) 하위인지, 전체 사이즈 최댓값 ≤ 설정값(기본 235mm, 235 미만 설정 불가), 바퀴 달린 운동화·고령자용 신발 제외를 순수 함수 한 곳에 둔다. 키워드(P2-01)·검색어·URL(P2-02)·카테고리(P2-06)가 같은 함수를 부른다. 끄는 설정은 없다. 바퀴·고령자 신발을 가려낼 단어 목록은 문서에 없음 → Proposed 설정값. (F-BS-12, CON-08, F-BS-04, F-SO-05)
13. **G1 키워드 고르기**: `PUT /keywords/{id}/selection`은 멱등(이미 골랐으면 `selectedAt` 유지), 제외 키워드 409 `KEYWORD_EXCLUDED`(DB `ck_keyword_excluded_not_selected`), 없는 id 404 `KEYWORD_NOT_FOUND`. `DELETE`는 204(비어 있어도 204), 그 키워드를 출처로 만든 후보가 있으면 409 `KEYWORD_IN_USE`. 고를 때 `user_action_log`(`GATE_PASSED`, `gate=G1`, `candidate_id` NULL)를 남긴다. 하나 이상 골라야 소싱 버튼이 켜진다. (F-KW-08, US-02 AC2, 05-2 `selectKeyword`·`unselectKeyword`, ERD `user_action_log` 목적)
14. **수집 상태**: `GET /keyword-collection-status`는 `collecting`·`runningKeywordSnapshotId`·마지막 묶음(id·시각·상태·중단 사유)·`blockedUntil`·`requestIntervalSeconds`(설정 2)·`disabledReasonCode`(`ALREADY_IN_PROGRESS`·`EXTERNAL_CALL_COOLDOWN`·null)를 계산해 준다. 화면 머리 '마지막 수집 13:30 · 2초 간격 · 이상 없음'과 '수집' 버튼의 꺼진 이유가 이 값이다. (F-KW-01, F-KW-04, 05-2 `KeywordCollectionStatus`)
15. **후보로 넘기기**: 소싱 버튼은 `POST /candidates`(`creationPath=KEYWORD`, `sourceKeywordId`, `rakutenQuery` 반각 128자, 기본값 = 키워드 원문)로 후보를 만들고 ② 화면으로 간다. 고르지 않은 키워드 409 `KEYWORD_NOT_SELECTED`, 제외 키워드 409 `KEYWORD_EXCLUDED`. 후보에는 고른 키워드만 출처 키워드로 남고 단계가 아니다. (F-KW-06, F-KW-08, 05-1 §2.1 표 D, 05-2 `getRakutenQuerySuggestion` 'M1은 키워드 원문')

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- 데이터랩 실제 호출 금지. 응답 fixture로만 개발·테스트한다.

- 데이터랩은 robots가 막은 비공식 내부 주소다. '오너가 누를 때 1회·2초 간격·직렬' 밖의 경로(예약, 자동 재시도, 병렬, 백오프)를 만들지 않는다. 라쿠텐 API의 429 백오프(P2-02)와 섞지 않는다.
- `keyword_snapshot.status`에 RUNNING이 있지만, 수집 중 앱이 꺼지면 RUNNING이 남아 `ALREADY_IN_PROGRESS`로 계속 막힌다. `abort_reason` CHECK에 '중단' 값이 없어 ABORTED로 닫을 수도 없다. 처리 방법을 Proposed로 정하고(예: 새 마이그레이션으로 사유 추가) 오너 검토에 올린다.
- `keyword`·`keyword_snapshot`은 삭제 금지 트리거가 있다. 아동 단어를 더해도 기존 행을 지우거나 다시 표시하지 않는다(05-2 x-decision). 테스트 정리는 `TRUNCATE`만 쓴다.
- 붙여넣기에서 cid가 null인 행은 UNIQUE(keyword_snapshot_id, cid, rank)가 중복을 못 잡는다(PG14 NULL). 파서가 막는다.
- 날짜는 서버 시간대가 아니라 Asia/Seoul로 계산한다. KST 0시~9시에 UTC 날짜를 쓰면 '어제'가 하루 틀린다.
- 아동화 공통 규칙을 keywords 안에 두면 sourcing(P2-02)·category(P2-06)가 import할 수 없다(단계 모듈끼리 호출 금지). 순수 함수를 공용 위치에 두고, 끄는 옵션을 만들지 않는다(F-BS-04).
- SCR-02의 검색어 형식 표시(`validateRakutenQuery`)와 SOURCING 실행기는 P2-02에서 생긴다. 여기서는 `createCandidate`까지 확실히 하고, `startCandidateStepRun` 실패는 ② 화면에서 오류로 보이게 둔다. `createCandidate`(KEYWORD)는 P1-04 코드라 실제 keyword 행으로 409 검사가 도는지 e2e로 확인만 한다.
- M0 S4에서 정직한 UA로 수집이 안 되면 붙여넣기가 기본 경로가 된다. 버튼 수집이 실패하거나 쉬는 중에도 붙여넣기 패널은 늘 쓸 수 있어야 한다.
