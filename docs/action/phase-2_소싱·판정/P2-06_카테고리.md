## 1. 목표

④ 카테고리 단계가 돈다. ② 장르·상품유형과 후보 성별로 네이버 리프 카테고리 후보를 뽑고, 오너가 판정 화면(SCR-04 `#category`)에서 하나를 고르면 후보에 `leafCategoryId`·전체 경로가 저장된다. 성별 불일치·아동 인증·판매 제외 품목은 막고, 성인 KC 예외는 'KC 면제 성인용 확인'으로만 통과시키며, 판단은 모두 감사 로그에 남는다. 연속 실행에서는 G2 바로 뒤, 단계 실행으로는 ② 뒤 언제든 돌고, 결과는 ⑦ 태그 필터와 상품명이 쓴다.

## 4. 핵심 규칙

1. **시작 조건**: ② 현재 버전이 '완료'이고 후보 성별(`MALE`·`FEMALE`)이 있어야 한다. 성별이 없으면 409 `STEP_START_CONDITION_UNMET`(`fieldErrors`에 `candidate.gender`)이다. ② 장르(`genre_id`)·상품유형(`product_type`)은 없어도 실행한다(URL 후보). ③ 완료는 필요 없다. 연속 실행에서는 G2 직후에 돌고, G2 전에는 단계 실행으로만 돈다. (F-CA-01, US-30 AC2, PRD §5.3 ④, F-CW-15)
2. **메타 캐시 필요**: `commerce_category`(P1-08)가 비어 있으면 시작 때 409 `COMMERCE_META_NOT_SYNCED`(`details.target`)다. 카테고리 ID는 코드에 박지 않고 이 캐시에서만 쓴다. `removed_at`이 찍힌 행은 후보에서 뺀다. (05-1 표 A, 05-3, F-BS-48, ERD `commerce_category`)
3. **매핑표로 후보 뽑기**: 설정 매핑표(라쿠텐 장르·상품유형 → 네이버 리프 후보)로 후보를 뽑고, `whole_category_name`이 성별 경로(`패션잡화>남성신발>…` / `패션잡화>여성신발>…`)로 시작하는 것만 남긴다. `candidate_source=MAPPING`. 매핑표의 설정 키·형식은 P1-03 설정 스키마에 없으면 Proposed로 더한다. (F-CA-02, PRD §8.7 카테고리 확정 1)
4. **매핑 못 한 URL 후보**: 장르가 없거나 매핑표에 없는 장르면 성별 경로의 신발 리프 전체(아동 카테고리 빼고)를 후보로 둔다. `candidate_source=GENDER_PATH_ALL`. (F-CA-04, US-06 AC5)
5. **후보 목록 저장**: `category_options`에는 `{ leafCategoryId, wholeCategoryName }`만 넣고(아동 카테고리는 넣기 전에 뺀다), 조회 응답의 `kcExemptionRequired`·`blocked`는 `GET` 때 `commerce_category.exceptional_categories`로 계산한다. (05-1 §2.5, ERD `category_decision.category_options`)
6. **입력 대기와 자동 완료**: 후보가 여럿이거나 KC 확인이 필요하면 `WAITING_INPUT`으로 멈추고 `PUT …/selection`으로 이어 간다. 후보가 하나이고 막힘·KC가 없을 때 바로 완료할지는 표 A('여럿·KC 확인 필요 → selection')의 해석이라 Proposed로 정하고 기록. 고를 수 있는 후보가 하나도 없을 때의 처리도 문서에 없음 → Proposed. (05-1 표 A, F-CA-03)
7. **고르기 검사와 오류**: `PUT /category-decisions/{id}/selection`은 결정 없음 404 `CATEGORY_DECISION_NOT_FOUND`, 실행이 입력 대기가 아님 409 `STEP_RUN_NOT_WAITING_INPUT`, 보여 준 목록에 없음 422 `CATEGORY_NOT_IN_OPTIONS`, 아동 409 `CATEGORY_CHILD_BLOCKED`, 제외 품목 409 `CATEGORY_EXCLUDED_ITEM`, 성별 불일치 409 `CATEGORY_GENDER_MISMATCH`, KC 확인 없음 409 `KC_EXEMPT_CONFIRMATION_REQUIRED`, 잠긴 후보 409 `CANDIDATE_LOCKED`를 준다. 검사 순서는 이 목록 순서로 한다(Proposed). (05-1 §2.5, 05-2 `selectCategoryDecisionLeaf`, 05-3)
8. **성별 불일치 차단**: 후보 성별과 카테고리 경로의 성별이 다르면(예: `MALE`인데 `…여성신발…`) 막고 `gender_path_match=false`를 남긴다. 최종 승인 검사(P4-02)가 같은 판정을 다시 한다. (F-CA-06, US-22 AC1)
9. **아동 인증 차단**: 카테고리 예외 유형에 `CHILD_CERTIFICATION`이 있거나 아동 카테고리면 무조건 고를 수 없다(`blocked=true`). '아동 카테고리'를 경로 이름으로 가르는 기준은 문서에 없음 → Proposed(설정 목록, 더하기만). (F-CA-07, US-30 AC3, US-22 AC3, PRD §8.7 3)
10. **KC 면제**: 성인 카테고리에 `KC_CERTIFICATION`이 걸리면 `kcExemptAdultConfirmed=true`(웹 화면 체크)로만 고를 수 있다. 통과하면 `exception_decision=KC_EXEMPT`, `kc_exempt_adult_confirmed_at`, `certification_exclude_content = { kcCertifiedProductExclusionYn: "KC_EXEMPTION_OBJECT", kcExemptionType: "OVERSEAS" }`를 함께 저장한다(`ck_cd_kc_exempt`). 예외가 없으면 `PASS`다. ②의 '성인용 상품 확인'과는 따로 기록한다. (F-CA-08, US-30 AC3, US-22 AC3, PRD §8.7 3, ERD `category_decision`)
11. **판매 제외 품목 차단**: 아동화·바퀴 달린 운동화·고령자용 신발(CON-08)은 ④에서 한 번 더 막는다(409 `CATEGORY_EXCLUDED_ITEM`, `block_reason`). 카테고리로 제외 품목을 가르는 기준은 문서에 없음 → Proposed(설정 목록, 더하기만). (F-CA-09, CON-08, PRD §8.7 3)
12. **완료 트랜잭션**: 고르기가 통과하면 `category_decision`(`leaf_category_id`·`whole_category_name`·`gender_path_match`·`exception_decision`·`decided_at`) + ④ `step_run` 완료 + 후보 `leaf_category_id`·`whole_category_name` 갱신(step-engine) + `user_action_log`(`CATEGORY_DECISION`) + 뒷단계 '재실행 필요'를 한 트랜잭션으로 한다. ⑦ 완료 버전이 있으면 ⑦이 '재실행 필요'가 되고 응답 `staleDownstreamSteps`에 `TAGS`가 들어간다. 응답은 200 `CategorySelectionResult`다. (F-CA-01, F-CA-03, F-CA-10, US-30 AC2, 05-1 §2.5, 03-2 §4)
13. **판단 감사 기록**: 확정과 예외 판단(차단·KC 면제·통과)을 `user_action_log`(`CATEGORY_DECISION`)에 남긴다. 차단으로 409를 줄 때도 그 판단을 남긴다(롤백되는 트랜잭션 밖에서). 차단 시도를 `category_decision.exception_decision=BLOCKED`로 언제 쓰는지는 문서에 없음 → Proposed. (F-CA-10, PRD §8.7 3 '판단 결과는 감사 로그')
14. **성별 재확인**: ④가 입력 대기일 때 `PUT /candidates/{id}/gender`(P1-04)로 성별을 바꾸면, 같은 실행 안에서 `category_decision.gender`를 바꾸고 `gender_changed_in_run=true`로 두고 후보 목록을 다시 뽑는다. 후보 성별은 `gender_source=OWNER`가 되고, ③·⑥-3·⑦(`PRICING`·`NOTICE_HTML`·`TAGS`)이 '재실행 필요'가 된다. ④ 자신은 '재실행 필요'로 바꾸지 않는다. 같은 성별이면 아무것도 하지 않는다. (F-CA-05, 05-1 §2.1 `PUT …/gender`, ERD `gender_changed_in_run`)
15. **완료 뒤 바꾸기**: ④가 끝나면 산출물을 고칠 수 없다(`category_decision_frozen`, `trg_output_frozen`). 다른 카테고리로 바꾸려면 ④를 다시 실행해 새 버전을 만든다. `GET …/category-decision`은 현재 버전, `?stepRunId=`로 이전 버전을 주고, 다른 후보·단계 id는 422 `INVALID_QUERY_PARAMETER`, 실행 전은 404 `STEP_OUTPUT_NOT_FOUND`(`details.stepCode=CATEGORY`)다. (ERD §1.3, 05-2 `getCategoryDecision`)

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).

- **성별 재확인과 입력 지문**: 성별은 ④의 시작 조건이다. 입력 대기 중 시작 조건이 바뀌면 원래 '재실행 필요'가 되지만(F-CW-18), ④의 성별 재확인은 같은 실행에서 이어 가는 예외다(F-CA-05). 이 실행의 입력 기록(`candidate.gender`)을 새 값으로 바꾸지 않으면, 끝날 때 지문이 달라 방금 고른 ④가 '재실행 필요'로 남는다.
- **전파 부작용**: 성별을 바꾸면 ③까지 '재실행 필요'가 되고, ③을 다시 돌려 판매 사이즈가 바뀌면 G2 지문이 달라져 G2를 다시 통과해야 한다. 성별 변경은 가볍지 않다는 것을 화면 안내 문구 그대로 보여 준다.
- **캐시는 값 복사**: `category_decision`은 `commerce_category`에 FK가 없다. 재동기화로 캐시가 바뀌어도 결정의 경로·예외 원문(`exceptional_categories`)은 그때 값 그대로 남아야 한다. 고르기 때 예외 판단은 캐시의 현재 값으로 다시 한다.
- **단계 모듈끼리 import 금지**: 성별 경로 판정은 P4-02(F-AP-24)도 쓴다. category 모듈 안에만 두면 registration이 category를 import하게 되니 공용 규칙 파일로 둔다.
- **웹 전용 확인**: 'KC 면제 성인용 확인'은 웹 화면에서 누른 것만 기록한다(05-1 §1.2). ②의 '성인용 상품 확인'을 여기 값으로 재사용하지 않는다.
- **⑥-3 상품명과의 관계**: 상품명이 ④ 경로를 쓰지만 ⑥-3 시작 조건에는 ④가 없다(ERD §7.1-10). 이 문서는 F-CA-01대로 ⑦만 '재실행 필요'로 둔다. ⑥-3까지 전파할지는 P3-04와 함께 정하고 기록한다.
- **큰 후보 목록**: `GENDER_PATH_ALL`은 성별 경로 리프 전체라 수백 개일 수 있다. `category_options` jsonb에 id·이름만 넣고, 화면은 스크롤 목록으로 보여 준다.
