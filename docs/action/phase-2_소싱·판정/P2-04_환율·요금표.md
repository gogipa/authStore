## 1. 목표

원가 환율(한국수출입은행)과 과세환율(관세청 엔·달러)이 자동으로 쌓이고, 수집이 실패하면 마지막 값을 쓰면서 경고를 띄운다. 오너는 설정 화면(SCR-10)과 판정 화면(SCR-04)에서 환율을 직접 넣고, 배대지 요금표 CSV를 버전으로 가져와 하나를 활성으로 둔다. ①~⑨ 흐름의 단계는 아니지만, 여기서 만든 환율 3종과 활성 요금표가 ③ 판정(P2-05)의 시작 조건이다. 값이 바뀌면 그 값을 읽은 ③이 '재실행 필요'가 된다.

## 4. 핵심 규칙

1. **원가 환율 자동 수집**: 수출입은행 `deal_bas_r`의 엔화 값을 KST 영업일 11시 이후 하루 1회 받는다. `fx_rate`에 `rate_kind=COST`, `currency=JPY`, `source=KEXIM`으로 넣는다. `rate_value`는 고시 원값 그대로 두고, 통화 표기가 `JPY(100)`이면 `unit=100`이다. 계산용 값은 언제나 `rate_value / unit`(예: 876 / 100 = 8.76원/엔)이다. `reference_at`은 고시일 11시(KST)다. (F-BS-40, PRD §8.3 `FX_base`, ERD `fx_rate`)
2. **과세환율 자동 수집**: 관세청(data.go.kr) 관세환율을 주 1회 받아 `rate_kind=CUSTOMS`, `source=CUSTOMS_SERVICE`로 JPY·USD 두 행을 넣는다. 응답 화폐단위명이 100엔이면 JPY는 `unit=100`, USD는 항상 `unit=1`이다. `reference_at`은 적용 주의 시작 시각이다. (F-BS-41, PRD §8.3 `FX_cJPY`·`FX_cUSD`, ERD `fx_rate`)
3. **키와 호출 기록**: 인증 키는 키체인의 `KOREAEXIM_API_KEY`·`CUSTOMS_SERVICE_KEY`만 쓴다. 호출은 P1-01 외부 호출 관문을 거쳐 `call_log`(`target=FX_KOREAEXIM`·`FX_CUSTOMS`)에 남긴다. `raw_response`·`call_log`·오류 메시지에 `authkey`·`serviceKey`를 넣지 않는다(`ck_fx_no_secret`). (NFR-02, 05-2 `SecretKey`, ERD `fx_rate`·`call_log`)
4. **중복 수집 막기**: 같은 종류·통화·출처·기준 시각의 자동 수집 행은 한 번만 들어간다(`uq_fx_rate_auto`). 재시도로 같은 고시를 다시 받으면 새 행 없이 성공으로 본다. 수동 입력은 여러 번 허용한다. (ERD `uq_fx_rate_auto`)
5. **수집 실패**: 실패하면 새 행을 만들지 않고 마지막 행을 계속 쓴다. `GET /fx-rates/latest`의 `warnings[]`에 `FX_FETCH_FAILED`를 넣고, SSE `fx-rate.updated`(`warningCode=FX_FETCH_FAILED`)를 보낸다. 실패 여부는 `call_log`의 최근 실패로 계산한다. 막지는 않는다. (F-BS-42, US-09 AC3, 05-2 `getLatestFxRates`)
6. **원가·과세 차이 경고**: 최신 과세환율(엔)과 최신 원가 환율이 `|FX_cJPY / FX_base − 1| > 0.20`이면 `FX_DIVERGENCE` 경고를 준다. 정확히 20%는 경고하지 않는다. 막지는 않는다. (F-BS-43, PRD §8.3, 05-3 §5.2)
7. **최신값 조회**: 종류·통화별 `reference_at`이 가장 큰 행이 최신값이다. `GET /fx-rates/latest`는 페이징 없이 `{ items[COST/JPY, CUSTOMS/JPY, CUSTOMS/USD], warnings[] }`를 주고 `raw_response`는 뺀다. `rateValue`는 JSON number다. (F-BS-44, 05-1 §2.4, 05-2 x-decision §7-4)
8. **수동 입력**: `POST /fx-rates`는 `rateKind`·`currency`·`rateValue`(> 0)·`unit`(1·100)·`referenceAt`·`sourceNote`(200자 이하)를 받아 `source=MANUAL` 새 행을 만들고 201을 준다. USD인데 `unit=100`이거나 `rateValue ≤ 0`이면 422 `VALIDATION_FAILED`다. 기존 행은 고치지 않는다(`fx_rate_append_only`). (F-ST-06, US-09 AC2, ERD `ck_fx_unit`)
9. **이력 조회**: `GET /fx-rates`는 `page`(0부터)·`size`(기본 20, 최대 100)·`sort`(`referenceAt`·`collectedAt`, 기본 `referenceAt,desc`)와 필터 `rateKind`·`currency`·`source`를 받는다. 응답은 `{ content[], page }`, 허용 밖 값은 422 `INVALID_QUERY_PARAMETER`다. (05-1 §1.4)
10. **③ 재실행 필요 전파**: 새 최신 환율이 생기면(수동 입력 포함) 그 값을 읽은 ③을 P1-05 전파 규칙대로 '재실행 필요'로 바꾸고 SSE를 보낸다. 자동으로 다시 실행하지 않는다. 전파 대상 범위(진행 중 후보만인지)는 문서에 없음 → 구현 때 Proposed로 정하고 기록. (05-1 §2.4 `POST /fx-rates`, F-BS-21)
11. **요금표 CSV 형식**: 열은 `weight_max_kg, fee, currency, volumetric_divisor, volumetric_applies_when`이다. `weight_max_kg > 0`(소수 3자리), `fee`는 0 이상 정수, `currency`는 `JPY`·`KRW`, `volumetric_divisor`는 비우거나 0보다 큰 정수다. 같은 무게 구간이 두 번 나오거나 열·숫자·통화가 틀리면 422 `IMPORT_PARSE_FAILED`(`fieldErrors`에 행·열), 데이터 행이 0개면 422 `IMPORT_EMPTY`, CSV가 아니면 422 `UNSUPPORTED_FILE_TYPE`, 5MB를 넘으면 413 `PAYLOAD_TOO_LARGE`다. (F-ST-04, PRD §8.3 기본 파라미터, 05-2 `importForwarderRateTable`)
12. **요금표 버전**: 새 파일(SHA-256)이면 `forwarder_rate_table` 1행 + `forwarder_rate_tier` N행을 만들고, 기존 활성을 끈 뒤 새 버전을 켠다. 이 전부가 한 트랜잭션이고 201 + `Location: /forwarder-rate-tables/{id}`다. 같은 해시면 새 행 없이 기존 버전을 다시 활성화하고 200 + `reused=true`다. 활성은 하나뿐이다(`uq_forwarder_rate_table_one_active`). 요금표는 지우지 않는다(`forwarder_rate_table_no_delete`, 구간은 추가만). (ERD §3.11, 05-1 §1.7)
13. **요금표 활성 변경 전파**: 활성 버전이 바뀌면 ③을 '재실행 필요'로 전파하고, 응답 `rerunRequiredStepCount`에 그 수를 준다. 활성 버전이 없으면 ③은 기본 15,000원 가정값을 쓴다(P2-05). (05-1 §2.12, F-PJ-07)
14. **엔화 요금**: 구간 요금은 CSV 통화 그대로 저장한다. 엔화 요금을 원으로 바꾸는 것은 가져올 때가 아니라 판정 때 그 판정의 `FX_base`로 한다. (F-ST-04, PRD §8.3)
15. **요금표 조회**: `GET /forwarder-rate-tables`는 `active` 필터와 `sort=importedAt`(기본 `importedAt,desc`) 페이징, `GET /forwarder-rate-tables/{rateTableId}`는 구간을 `weightMaxKg` 오름차순으로 준다. 없는 id는 404 `RATE_TABLE_NOT_FOUND`다. 원본 CSV 경로(`source_file_path`)는 응답에 넣지 않는다. (05-2 `listForwarderRateTables`·`getForwarderRateTable`, 05-1 §1.2)

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- 환율 출처 실제 호출 금지. fixture로 검증한다.

- **100엔 단위**: `rate_value`는 고시 원값(예: 876)이다. 계산하는 곳마다 `/ unit`을 따로 쓰면 한 곳만 빠져도 100배 틀린다. 계산값은 `perUnit()` 한 함수로만 얻고, P2-05도 이 함수를 쓴다.
- **숫자 파싱**: 환율 응답 값은 문자열이고 천 단위 쉼표가 올 수 있다(`1,358.72`). 부동소수점으로 계산하지 말고 `Prisma.Decimal`로 다룬다. 저장 열은 `numeric(12,4)`다.
- **키가 URL에 들어간다**: `authkey`·`serviceKey`는 요청 쿼리에 실린다. 호출 관문의 URL 기록·오류 메시지·`raw_response`에서 가린다. DB CHECK는 `raw_response` 최상위 키만 본다.
- **시간대**: '영업일 11시'와 '이번 주'는 서버 시간대와 상관없이 `Asia/Seoul`로 계산한다. 앱이 11시에 꺼져 있었으면 켤 때 오늘 몫을 받는다. 공휴일·11시 전에는 빈 응답이 올 수 있으니 fixture로 처리를 고정한다(Proposed).
- **추가만 하는 표**: `fx_rate`·`forwarder_rate_tier`는 고칠 수 없고 `forwarder_rate_table`은 지울 수 없다. 수동 입력 오타도 새 행으로 바로잡는다(ERD §7.2-20).
- **활성 교체 순서**: `uq_forwarder_rate_table_one_active` 때문에 같은 트랜잭션에서 기존 활성을 먼저 끄고 새 버전을 켠다. 순서가 바뀌면 UNIQUE 오류가 난다.
- **매일 재실행 필요**: 환율은 ③의 시작 조건이다. 자동 수집이 매일 새 행을 만들면 진행 중인 모든 ③이 매일 '재실행 필요'가 되고, 승인대기 후보가 작업중으로 돌아갈 수 있다. 전파 범위를 Proposed로 정하고 결과 보고의 '오너 검토'에 올린다. G2는 판매가·사이즈가 같으면 그대로 유효하다(F-CW-02).
- **P2-05가 기대는 것**: `getLatestForJudgement()`(환율 3종 + id), `perUnit()`, 활성 요금표 조회. 이 이름과 반환 형태를 바꾸면 P2-05 문서의 전제가 깨진다.
