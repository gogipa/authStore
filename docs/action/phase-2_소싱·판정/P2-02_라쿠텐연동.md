## 1. 목표

라쿠텐 Item Search·IchibaGenre API와 상품 페이지 JSON을 읽는 연동 계층과, ② 소싱 단계 실행기(`SOURCING` StepRunner)의 뼈대가 fixture로 동작한다.
검색어 형식 검사, 호출 간격·캐시·하루 페이지 상한·24시간 쉼, EUC-JP 페이지 파싱, 아동화 차단(제외어·장르·사이즈·'성인용 상품 확인'), 라쿠텐 URL 입구('바로 후보 만들기')와 재조회가 된다.
흐름 ②의 앞부분이다. 비교표·앵커·재고 판정·실질가·최종 선택은 P2-03이 이 위에 붙이고, 재조회는 ③(P2-05)·연속 실행(P1-06)·승인 화면(P4-02)이 부른다.

## 4. 핵심 규칙

1. **Item Search 호출**: `GET https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701`, `applicationId` + `accessKey`(키체인, 없으면 ② 시작 전 409 `SECRET_NOT_CONFIGURED`). 구 도메인 `app.rakuten.co.jp`는 쓰지 않는다. 기본 파라미터: `genreId=558885`(설정), `sort=+itemPrice`, `hits=30`, `availability=1`, `imageFlag=1`, `field=1`, `formatVersion=2`, `purchaseType=0`, `carrier=0`, `minPrice`(설정), `NGKeyword`(설정 `中古 インソール 靴紐 シューレース 箱のみ キッズ ジュニア ベビー`). (PRD §8.2 RK-01, F-BS-34, US-04 AC1)
2. **호출 규칙·캐시**: 직렬, 1.5초 이상 간격. 429·503은 HTTP 상태 코드로 판정해 지수 백오프로 최대 3회 다시 한다. 같은 쿼리는 `rakuten_search_cache`에 6시간 둔다: `query_hash` = 키 정렬 JSON(page 포함, 비밀값 제외)의 SHA-256, 200 응답만 저장, `expires_at = fetched_at + 6h`인 행만 적중. '다시 실행'도 캐시를 쓴다. `request_params`에 키가 섞이면 `ck_rsc_no_secret`이 막는다. (F-BS-34, PRD §5.3 외부 호출, ERD `rakuten_search_cache`)
3. **라쿠텐 오류 안내**: 400 'must be present' → 키 누락, 403 'Invalid Access Key' → 키 오류, 403 `CLIENT_IP_NOT_ALLOWED` → 허용 IP 아님, 429·503 → 한도 초과·점검으로 바꿔 보여 준다. 비동기 ② 실행 중 실패는 HTTP 오류가 아니라 `step_run.status=FAILED`, `failureKind=EXTERNAL_API`, `errorCode`(원래 코드), 한국어 `errorMessage`와 SSE로 알린다. (F-SO-03, 05-1 §1.3)
4. **검색어 형식**: 전체 반각 128자 이내, 단어(공백 구분)마다 반각 2자 또는 전각 1자 이상, 히라가나·가타카나·기호 단어는 2자 이상. `POST /rakuten-query-validations`는 저장 없이 200 `{ rakutenQuery, valid, halfWidthLength, maxHalfWidthLength: 128, violations[{ rule: TOO_LONG·WORD_TOO_SHORT, word, message }], genreId, ngKeywords }`이고 본문 누락만 422 `VALIDATION_FAILED`. 후보 만들기·② 시작은 같은 검사기로 422 `RAKUTEN_QUERY_INVALID`. 전각 1자를 반각 몇 자로 셀지는 문서에 없음 → Proposed(기본안 2자). (F-SO-02, F-SO-01, US-03 AC1, 05-2 `RakutenQueryValidation`, 05-1 표 A·D)
5. **검색 결과 아동화 거르기**: 키워드에서 왔든, 검색어를 직접 넣었든, URL 후보의 '검색·비교'든 모든 검색에 장르와 제외어를 붙인다. 결과 상품명에 아동 단어(P2-01 공통 규칙)가 있으면 비교표 행으로 저장하지 않는다. (F-SO-04, US-04 AC5, ERD `sourcing_comparison_row` 목적)
6. **상품 페이지 요청**: 하나씩, 3초 이상 간격, 앱 고유 UA. 페이지는 캐시하지 않는다(재조회는 늘 새로 받음). 보내기 직전 `call_log`(target=`RAKUTEN_PAGE`) 행을 넣는다. 403·418·429면 그 작업을 즉시 멈추고(재시도 없음) 24시간 쉰다. 쉬는 동안 페이지를 읽는 요청은 409 `EXTERNAL_CALL_COOLDOWN`(`details.target`·`blockedUntil`, `Retry-After`). (F-BS-36, F-BS-09, F-BS-10, PRD §8.2 RK-04)
7. **페이지 조회 순서·중단**: 앵커와 일치한 행을 `itemPriceMin3` + 송료 추정(`postageFlag=0`이면 0, 아니면 기본 송료) 오름차순으로 세워 차례로 읽는다. 재고 기준을 통과한 행이 3개(K)가 되거나 10페이지(M)를 읽으면 멈춘다. 하루 상한·쉼에 걸리면 그 자리에서 멈춘다. 끝나면 SSE `sourcing.page-fetch-finished`(`stopReason` `ENOUGH_CANDIDATES`·`PAGE_CAP`·`DAILY_LIMIT`·`BLOCKED`). 재고 통과 판정은 P2-03 규칙을 받아 쓴다. (F-SO-12, US-04 AC2, 05-1 §3)
8. **하루 페이지 상한**: 신규 소싱 조회, URL 입구(건당 1), '재고 확인', '재조회'를 모두 `call_log`의 (kst_date, `RAKUTEN_PAGE`) 집계로 센다. 상한(설정, M1 기본 110)에 닿으면 409 `DAILY_LIMIT_REACHED`(`details.target=RAKUTEN_PAGE`, `Retry-After` = 다음 KST 0시). 한국 시간 0시에 초기화된다. 화면은 페이지를 읽는 버튼을 끄고 사유를 보여 준다. 카운터 표를 따로 두지 않는다. (F-SO-16, US-06 AC4, PRD §8.8, ERD 결정 ⑦)
9. **페이지 JSON 읽기**: 본문 바이트를 EUC-JP로 풀어 `<script type="application/json" id="item-page-app-data">`를 JSON으로 읽는다. 루트는 `newApi.itemInfoSku`, 없으면 `api.data.itemInfoSku`. SKU는 `newApi.purchaseInfo.variantMappedInventories[]`를 `variantId`로 조인하고 짝 없는 재고 행은 버린다. SKU별 `taxIncludedPrice`·`hidden`·`articleNumber`·`shipping.postageIncluded`·`attributes`, 이미지 전체(`media.images[]`), `backOrderFlag`·`unlimitedInventoryFlag`·`standardPrice.identical`, 장르 ID·설명 HTML·세일 기간(경로 M0 S2)을 뽑아 `rakuten_item` + `rakuten_sku`에 추가만 한다. `collected_at`, 원본 파일 경로·SHA-256·크기를 함께 둔다. JP cm → mm(24.5 → 245), cm가 아닌 라벨은 `size_mm = NULL`. (F-SO-13, PRD §8.2 RK-04 표, ERD `rakuten_item`·`rakuten_sku`)
10. **점검 페이지·방어적 파싱**: HTTP 200이어도 본문에 'ページが表示できません'이 있으면 실패다. URL 입구(동기)면 502 `EXTERNAL_API_ERROR`(`details.target=RAKUTEN_PAGE`·`reason`). 키가 빠져도 멈추지 않고 읽은 것만 저장하며 `manual_check_required=true`·`manual_check_note`(빠진 키)로 넘긴다. 파싱 자체가 실패하면 `rakuten_item` 행을 만들지 않는다. (F-SO-14, ERD `rakuten_item` 목적)
11. **URL 입구**: `POST /rakuten-items` `{ sourceUrl }` → 동기 201 + `Location` + `{ rakutenItem, checks }`(`entry_source=MANUAL`, `fetch_reason=URL_ENTRY`, 하루 상한 1건). 라쿠텐 상품 주소가 아니면 422 `RAKUTEN_URL_INVALID`. `itemCode`는 URL 조각이 아니라 페이지 JSON에서 얻어 `샵코드:상품ID`로 맞춘다. 두 경로 키가 다르면(M0 S2) URL의 샵 코드 + 型番·상품명으로 Item Search를 불러 `itemUrl`이 같은 항목의 `itemCode`를 쓰고, 못 찾으면 후보를 만들지 않는다. 허용 URL 형식과 보완 실패 오류 코드는 문서에 없음 → Proposed(05-3에 먼저 추가). (F-SO-31, F-SO-32, F-BS-37, US-06 AC1, 05-2 `fetchRakutenItem`)
12. **URL 아동화 신호**: 응답 `checks` = `excludedWords[]`·`genreScope`(`IN_SCOPE`·`OUT_OF_SCOPE`·`NOT_FOUND`)·`childSizeSuspect`·`adultConfirmationRequired`. 여기서는 막지 않고 알리며 후보·행을 만들 때 다시 검사한다. 제외어(中古·インソール·靴紐·シューレース·箱のみ·キッズ·ジュニア·ベビー)가 상품명에 있으면 후보·행을 만들지 않는다(422 `RAKUTEN_ITEM_EXCLUDED_WORD`). 장르는 페이지 JSON → 없으면 `itemCode`로 Item Search(`genre_source` `PAGE_JSON`·`ITEM_SEARCH`·`NOT_FOUND`). 하위 판정은 `rakuten_genre.id_path LIKE '/558885/%'`(IchibaGenre 캐시, 호출 경로·갱신 주기 M0 S2 → Proposed). 전체 사이즈 최댓값 ≤ 설정값(기본 235, 235 미만 설정은 검증 오류)이면 아동화 의심. (F-SO-05, F-SO-07, F-SO-33, F-BS-35, US-06 AC1, 05-2 x-decision §7-23)
13. **성인용 상품 확인**: `PUT /sourcing-comparisons/{id}/adult-product-confirmation`(본문 없음) → 200 `{ sourcingComparisonId, stepRunId, adultProductConfirmedAt, stepStatus }`. 아동화 의심·장르 문제가 아니면 409 `CONFIRMATION_NOT_APPLICABLE`, ② 버전이 입력 대기가 아니면 409 `STEP_RUN_NOT_WAITING_INPUT`. 이미 체크했으면 기존 시각(멱등). `sourcing_comparison.adult_product_confirmed_at` + `user_action_log`(`OWNER_CONFIRMED`)를 남기고 멈춘 ②를 잇는다. ④ 'KC 면제 성인용 확인'과 필드·기록을 나눈다. 웹 화면 요청만 받는다. (F-SO-06, US-04 AC5, US-06 AC1, 05-1 §1.2, ERD 결정 ⑨)
14. **URL로 바로 후보 만들기**: `POST /candidates`(`creationPath=RAKUTEN_URL`, `rakutenItemId`, `selectedColor`) → 201 WORKING + ② `URL_CREATE` 버전(`comparison_performed=false`, `anchor_input_method=URL_ITEM`, `selected_rakuten_item_id`, `shipping_yen`·`shipping_source`, 비교표 행 0개)을 한 트랜잭션. 성인용 확인·성별이 필요하면 ②는 입력 대기, 아니면 완료. 진행 중 후보에 같은 itemCode+색상이 있으면 409 `CANDIDATE_DUPLICATE`(`details.existingCandidateId`) → 화면이 그 후보를 연다. '비교 안 함' 배지. URL 후보에서 ②를 '검색·비교'로 다시 실행하면 그 상품이 앵커다. (F-SO-35, F-SO-36, US-06 AC3, 05-1 §2.1 표 D, ERD `ck_sc_url_no_compare`·`ck_sc_selection_uncompared`)
15. **재조회**: `POST /candidates/{id}/refetch` → 202 `StepRunAccepted`(② 새 버전). 소싱 선택이 없으면 409 `SOURCING_SELECTION_REQUIRED`. 고른 상품 페이지 1건만 새로 읽어(`fetch_reason=REFETCH`, 1건 차감) ② `REFETCH` 버전을 만들고, 앞 버전의 행과 행별 쿠폰·배율을 복사한다. ③을 실행한 적이 있으면 지문과 관계없이 이어서 ③을 실행한다(`execution_mode=STEP`). 재판정이 재고 부족·판매 후보 아님이면 후보가 '제외'된다. 그 밖 409: `DAILY_LIMIT_REACHED`, `EXTERNAL_CALL_COOLDOWN`, `STEP_ALREADY_RUNNING`, `STEP_LOCKED_BY_RUNNING_STEP`, `CANDIDATE_LOCKED`, `CANDIDATE_EXCLUDED`. '성인용 상품 확인'을 새 버전에 가져갈지는 문서에 없음 → Proposed. (F-SO-17, US-20 AC2, US-25 AC2, PRD §5.3 ② 세 동작, 05-2 `refetchCandidate` x-decision, ERD §1.4)

## 8. 주의

- 공통 규칙은 [README §공통 규칙](../README.md#공통-규칙)을 따른다(실행 환경, 외부 호출 금지, 비밀정보, 커밋 안 함).
- 라쿠텐 실제 호출 금지(API·상품 페이지 모두). EUC-JP 페이지 fixture와 API 응답 fixture로 검증한다.

- EUC-JP: `response.text()`는 UTF-8로 풀어 일본어가 깨진다. 바이트로 받아 `new TextDecoder('euc-jp')`로 푼다(Node 24 full ICU). 원본 파일은 받은 바이트 그대로 저장·해시한다. 새 의존성(iconv-lite 등)이 필요하면 `-E`로 고정하고 보고한다.
- 두 종류의 429를 섞지 않는다. 라쿠텐 API(공식)의 429·503은 최대 3회 백오프, 상품 페이지(비공식)의 403·418·429는 재시도 없이 멈추고 24시간 쉰다.
- `rakuten_item`·`rakuten_sku`는 추가만 된다(트리거). 재조회·재고 확인은 새 행이다. `sourcing_comparison`·`_row`는 `trg_output_frozen`이라 ② StepRun이 실행중·입력 대기일 때만 고칠 수 있다. 성인용 확인은 열린 버전에만 쓴다.
- 하루 상한·쉼의 원본은 `call_log` 하나다(ERD 결정 ⑦). 요청 직전에 행을 넣어야 실패한 요청도 센다. 앵커 뒤 반복·재고 확인·재조회·URL 입구가 같은 직렬 페이지 큐를 써야 '세고 → 보내기'가 경합하지 않는다.
- `applicationId`·`accessKey`는 키체인에서만 읽는다. 요청 URL에 들어가므로 `call_log.url_masked`·로그·캐시 사본에 원문이 남지 않는지 먼저 테스트한다(CHECK도 막는다).
- 재조회는 ③ 실행기(P2-05 전에는 없음)를 step-engine을 거쳐 시작한다. pricing 모듈을 직접 import하지 않고, 여기서는 가짜 PRICING 실행기로 검증한다. P1-06 연속 실행(6시간 넘은 판정)과 P4-02 '재조회' 버튼이 이 API에 기댄다.
- 이 문서와 P2-03은 경계를 나눠 쓴다. `sourcing_comparison`은 P2-03 소유 표지만 URL_CREATE·REFETCH·성인용 확인은 여기서 쓴다. 페이지 조회 순서(F-SO-12)는 P2-03의 앵커 분류·재고 판정을 주입받는다. 둘 다 같은 `SOURCING` 실행기 안에 둔다.
- M0 S2 전 가정(두 경로 itemCode 같음, 장르 ID·설명 HTML·세일 기간 경로, 색상 코드 출처, 정직한 UA로 페이지가 열림)은 파서 경로 상수와 fixture 한 곳에 모아 두고 S2 결과로 바꾼다.
