# 열린 질문 — 실행 문서별

실행 문서를 채우며 설계 문서(PRD·ERD·API·시안)에서 찾은 빈칸과 어긋남이다.

- **구현하는 Claude**: 해당 문서를 실행할 때 이 목록을 먼저 본다. 문서가 정하지 않은 것은 가장 무리 없는 값으로 정하고, 해당 설계 문서에 Proposed로 적고, 결과 보고의 오너 검토에 올린다.
- **오너**: 먼저 정해 두고 싶은 것이 있으면 여기에 답을 적어 두면 된다. 적지 않으면 구현 때 추천값으로 정한다.
- 06 개발 환경 단계에서 이미 고친 것(`fieldErrors` 형식 05-2 ↔ 05-3)은 뺐다.

## [P1-01](phase-1_기반/P1-01_공통기반.md) 공통 기반: 외부 호출 관문·진행 알림(SSE)·이미지 파일·감사 기록

- 라쿠텐 이미지 내려받기 호스트와 그 기록 대상(`CallLogTarget`)이 정해지지 않았다. `RAKUTEN_PAGE`로 세면 하루 페이지 조회 몫(110)을 쓴다. P3-01 전에 정한다.
- `call_log`에 `fetch_reason` 열이 없다. 그래서 조회 사유별 집계는 `rakuten_item.fetch_reason`으로 세야 하고, 합계가 전체 건수보다 작을 수 있다.
- 일부 진행 알림(`sourcing.row-updated`, `sourcing.page-fetch-finished`)에 `candidateId`가 없다. `/events?candidateId` 필터를 쓰려면 발행할 때 후보 id를 따로 넘겨야 한다.
- 05-2 `streamProgressEvents`에 404 응답이 있는데 언제 쓰는지 적혀 있지 않다.
- 허용 목록 밖 호스트로 가는 요청에 쓸 오류 코드가 05-3에 없다.
- 문서에 없다: 데이터랩 하루 상한 값, UA 문자열 형식, 최소 간격을 요청 시작과 끝 중 어디서 재는지, `GET /call-usage`가 보여 줄 대상.
- 앱 데이터 폴더 기본값이 저장소 루트 `.data`라 F-BS-02 '설치 폴더 밖'과 맞지 않는다. 배포본 기본 경로가 정해지지 않았다.
- CON-04(Referer 위장 금지)와 PRD §8.1(데이터랩은 Referer 필요)이 부딪친다. 문서는 데이터랩에만 Referer를 허용했다.
- 환율 API 호스트(한국수출입은행, 관세청·data.go.kr)가 PRD·ERD·API 어디에도 없다. P2-04에서 정한다.

## [P1-02](phase-1_기반/P1-02_FE공통부품.md) FE 공통 부품·앱 셸·API 훅·진행 알림 구독

- 왼쪽 내비 상태 상자 문구가 공통부품 §A와 화면시안_명세 §3에서 다르다. 공통부품의 '글자 그대로 복사' 규칙에 따라 공통부품을 따랐다.
- 화면별 코드 분할(lazy) 시점이 FE 05-4(화면 구현 때)와 06-3 §9(번들이 커지면)에서 다르다. 문서는 지금 적용하라고 적었다.
- 대시보드·후보 작업의 실제 데이터 부품(StepStatusBar, StepTable, StepDots, CandidateHeader)은 P1-04·P1-05 몫이다.
- FE 04-3 §4에 오너 확인 항목 3개가 열려 있다. '템플릿 제안·임시·수동' 칩 색은 시안 보드에서만 읽었다.

## [P1-03](phase-1_기반/P1-03_설정파일.md) 설정 파일 로더·검증·설정 스냅샷

- ERD §3.11은 고지 배송기간 기본값(영업일 10~20일)을 설정에 두지만, F-BS-03·US-37 AC3은 이것을 사람마다 다른 값(자리표시자)으로 본다.
- 05-1 §7.5-51이 열려 있다. 설정 파일의 `ai` 섹션을 직접 고치고 다시 읽으면 10분 연결 테스트 규칙(R8)을 건너뛴다. P1-11이 이 결정에 기댄다.
- 문서에 없다: 설정 파일 구성(ERD §7.4-1), 섹션·키 이름, 비율 표기(2.5와 0.025 중 무엇), 숫자 정밀도(05-1 §7.1-4).
- 문서에 없다: 내장 실존 인물 차단어 목록, 필수 고지 블록 ID와 해시 대상 텍스트.
- 설정 화면 시안에 '설정 파일 다시 읽기' 버튼이 없어, 설정 스냅샷 만들기를 화면 어디서 부를지 정해지지 않았다.
- 셀러라이프 배대지 쿠폰의 월 사용 한도 기본값이 없다.
- 다시 읽기가 실패했을 때도 `settings.reloaded` 알림을 보내는지 정해지지 않았다.

## [P1-04](phase-1_기반/P1-04_후보·상태.md) 후보 만들기·목록·상태 전환·이어 하기(대시보드)

- 성별을 바꿀 때 영향받는 단계 목록(PRICING·NOTICE_HTML·TAGS)에 CATEGORY가 없다. PRD §5.3은 성별을 ④ 시작 조건으로 둔다. 05-2대로 쓰고 오너 검토로 올렸다.
- 후보 상세 응답에 `resumeStepCode`가 없어 화면이 레일·목록 데이터로 계산해야 한다.
- 후보 표시 이름의 원천 열이 없다(05-1 §7.2-10). 대시보드 단계 점에서 ⑥ 묶음을 어떻게 합칠지, M1에서 직접 입력 입구를 어떻게 처리할지도 없다.
- 대시보드 시안의 조치 필요 표에는 필드 단위 '재확인 필요' 행(⑥-2 원산지)이 있다. 05-2 결정 §7.2-18은 필드 재확인을 이 목록에서 뺀다.
- URL로 후보를 만들 때의 ② 버전은 P2-02 소싱 로직이 필요하다. P1-04에서는 확장 자리만 둔다.

## [P1-05](phase-1_기반/P1-05_단계실행.md) 단계 실행 엔진: 실행·버전·입력 지문·재실행 필요 전파

- 입력 대기 중인 단계를 다시 시작할 때 응답이 정해지지 않았다(ERD §7.1-15: 열린 실행 유일 제약이 막고, 닫는 상태가 없다).
- 실행기가 아직 없는 단계 코드의 오류 코드, ⑥ 묶음(⑥-1→⑥-3) 중간 실패·대기 때 동작, 이전 버전 복원 때 지문을 다시 비교하는지가 없다.
- 상품명은 ④를 읽는데 ⑥-3 시작 조건에 ④가 없다(ERD §7.2-10). 재실행 전파에서 ⑥-3←④ 관계가 모호하다.
- 설정이 바뀌었을 때 재실행 필요를 어디까지 퍼뜨릴지(잠긴·제외·등록된 후보를 건너뛰는지) 정해지지 않았다.
- ⑨ 재시작 복구(F-BS-18)는 P4-03의 등록 로직에 기댄다. 실행기 훅(`onInterrupted`)으로 설계했다.

## [P1-06](phase-1_기반/P1-06_연속실행·게이트.md) 연속 실행·게이트(G1~G4) 통과 기록

- 05-1 §2.1은 연속 실행 조회에 '건너뛴 단계 기록 없음 ⚠️'이라고 적었지만, ERD·05-2는 이미 기록한다. 05-1을 맞추라고 적었다.
- 후보당 열린 연속 실행이 하나뿐이라는 규칙을 DB가 막지 않는다(ERD §7.2-12). 앱에서 행 잠금으로 지킨다.
- 정해지지 않았다: 입력 대기·실패로 멈출 때 기록할 멈춘 단계, 재실행 필요 반복의 상한, 키워드 없이 시작한 후보의 G1 표시, 멈춘 이유 문구(시안 없음).
- 6시간 규칙은 P2-05의 페이지 수집 시각과 P2-02 재조회가 필요해, 선택형 실행기 메서드로 두고 가짜로만 테스트한다.

## [P1-10](phase-1_기반/P1-10_AI실행기.md) AI 실행기와 엔진 어댑터 3개(claude·agy·codex)

- agy 사용자 MCP가 올라왔는지 검사하는 방법이 없고, 그 경고를 남길 곳도 없다(ai_cli_check에 경고 열이 없다).
- F-BS-76은 SCR-12에 'AI 엔진 설정으로' 링크를 요구하는데, 헤더는 '화면 없음(BE 전용)'이다. 그래서 작은 FE 작업(StepStatusBar 링크·aiEngine.ts)을 만들 것에 넣었다.

## [P2-01](phase-2_소싱·판정/P2-01_키워드.md) ① 키워드: 데이터랩 수집·아동화 제외·키워드 선택(G1)

- ⑥-2 값을 한국어로 정리하는 방법(사전인지 AI인지)이 문서에 없다.
- 스펙 이미지 선택 규칙(M0 S2)과 그 설정 키가 정해지지 않았다.
- 색상 표기(F-CT-17)와 주의 문구의 fact 필드 키 이름이 없다(05-2 x-decision: M0 뒤에 정함).
- 완료 뒤 '재확인 필요'를 푸는 방식이 새 OWNER_EDIT 버전인지 recheck_resolved_at 수정인지 05-1 §7.4-32 제안 상태다.
- F-CT-17·F-CT-21은 ⑥-2가 만드는 값인데 P3-04 범위에 있다. 그래서 ⑥-2 구현이 두 문서로 나뉜다. P3-03에는 추출기를 필드 추가형으로 두라고 적었다.
- (구현 중 추가) ⑥-2 입력 지문의 '스펙 이미지(파일 해시)'는 시작 때 알 수 없다(이미지는 ⑥-2가 AI가 필요할 때 받는다). 시작 조건에는 설명 HTML에서 고른 **주소 목록**을 넣었다 — 같은 주소의 내용이 바뀌면 잡지 못한다(ERD §7.2-25).
- (구현 중 추가) 스펙 이미지가 없으면 AI를 글만으로 부르는데(텍스트 모델), `step_run.ai_model`은 시작 때 고정한 비전 모델로 남는다(엔진 규약상 한 실행에 모델 하나).
- (구현 중 추가) 사실 필드(fact.*)의 '나란히 고르기'(`choose`)는 고른 AI 값의 근거(원문 발췌)를 남길 칸이 없어 받지 않았다. 다시 실행한 새 추출 값은 `generated_value`로 나란히 보이고, 오너는 값을 다시 넣거나(근거 URL) 재확인한다.
- (구현 중 추가) 시안 Content.dc.html은 소재를 '갑피 … / 밑창 …' 한 줄로 그리지만 필드는 겉감·안감·밑창 셋이라, 한 칸 안에 세 줄로 보였다. 또 ⑥-1·⑥-2만 따로 실행할 버튼이 보드에 없어 구획 머리에 더했다.

## [P3-04](phase-3_콘텐츠/P3-04_고시·HTML·상품명.md) ⑥-3 고시 매핑·구매대행 고지·원산지 코드·상세 HTML·상품명

- 상품명 템플릿이 읽는 ② 입력(브랜드·시리즈·모델명·상품유형·並行輸入品)이 PRD §5.3 ⑥-3 시작 조건에 없다. 브랜드·시리즈의 한국어 표기 출처도 없다(브랜드 사전은 M2).
- 상품명 경고 코드가 05-3 §5.2에 없다. 05-2 ProductNameWarning에는 '05-3에서 확정'이라고만 적혀 있다.
- 이미지 자리표시자 형식과 고지 블록 해시 정의(무엇을 정규화해 해시하는지)가 없다. P4-01·P4-02와 계약으로 정해야 한다.
- 가죽 판정 단어 목록, '소재 정보 없음'의 범위(한 칸인지 전부인지), '굽 재료를 쓰는 여성화' 판정 방법이 문서에 없다.
- 끊긴 사이즈 표기(250~265·275mm)는 시안에만 있다. PRD 예시는 연속 범위뿐이다.
- notice.* 필드에 '재확인 필요'가 남았을 때 ⑥-3 상태가 모호하다. F-CT-15는 '확인해야 완료'라고 하고, 표 A의 NOTICE_HTML에는 입력 대기가 없다.
- 고지의 배송기간·교환 정책은 ERD §7.2-18에 따라 프로필이 아니라 설정 파일에 둔다(시안 프로필 화면에 칸이 없다).
- (구현 중 추가) 상품명이 ② 모델 정보(型番 원문·並行輸入品·브랜드 속성)를 읽어 ⑥-3의 필수 앞 단계에 ②를 더했다(`STEP_GRAPH.NOTICE_HTML.requires`, 입력 `sourcing.modelInfo`). ③이 이미 ②를 요구해 실행 가능 여부는 같지만, ② 새 버전의 모델 정보가 바뀌면 ⑥-3이 직접 재실행 필요가 된다(05-1 §7.4 P3-04).
- (구현 중 추가) 고지 `{배송기간_*}`은 설정 파일 값(기본 null — F-BS-03)이라 비어 있으면 ⑥-3을 409 `PROFILE_INCOMPLETE`로 막았다(`missingFields`에 `notice.values.deliveryDaysMin·Max`). 오너가 설정 파일을 직접 고쳐야 한다(화면 칸 없음 — ERD §7.2-18). 반품비(`{반품비}`)도 같은 검사에 넣었다.
- (구현 중 추가) 시안은 HTML 미리보기를 레일 아래에 그렸지만 후보 작업 틀의 레일 칸은 모든 단계가 같이 써서 ⑥-3 구획 아래에 두었다. 고시 표에 '색상' 줄을 더했다(오너가 고칠 수 있는 칸). 원산지 코드 고르기(03·04) 화면은 두지 않았다 — API(owner-edits `notice.origin_area`)만 받는다.

## [P3-05](phase-3_콘텐츠/P3-05_태그.md) ⑦ 태그: 추천·경쟁 태그·정제·검증·최종 10개

## [P4-01](phase-4_승인·등록/P4-01_이미지업로드.md) ⑧ 이미지 업로드: 정규화·순차 전송·URL 재사용

- 이미지 자리표시자 형식이 PRD·ERD에 없다. P3-04가 정해야 하고, P4-01은 그 형식을 공통 상수로 쓴다고 적었다.
- 정사각이 아닌 원천 이미지 처리(자르기/채우기)와 업로드 도중 실패 때 이미 받은 URL을 남길지가 문서에 없다. 둘 다 Proposed로 적었다.
- 커머스 이미지 업로드 응답 모양과 shop-phinf URL 유효기간은 M0 S3 확인 전이다(ERD §7.3-7). 해시 재사용 규칙이 이것을 전제로 한다.
- 05-1 표 A는 TEMP_CANDIDATE_NOT_ALLOWED를 (M2)로 적었다. F-AP-01(M1)은 임시 후보 실행 차단을 요구한다.
- (구현 중 추가) 업로드 응답의 URL 수가 보낸 파일 수와 다르면 어느 파일의 URL인지 알 수 없다. 받은 URL을 저장하지 않고 ⑧을 실패(`EXTERNAL_API_ERROR`·`URL_COUNT_MISMATCH`)로 두었다(Proposed — M0 S3에서 응답에 파일 이름·순번이 있는지 본다).
- (구현 중 추가) 시안 Approval.dc.html의 ⑧ 줄에는 업로드 이미지 목록이 없는데 작업 지시는 업로드 이미지 미리보기를 요구한다. 상태 줄 아래 '업로드한 이미지' 띠를 더했다(화면시안_명세 SCR-08).

## [P4-03](phase-4_승인·등록/P4-03_등록.md) ⑨ 등록: 요청 본문·중복 방지·사이즈 옵션·차단 스위치·결과 확인
