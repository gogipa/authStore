# FE 설계 — 스마트스토어 정복 로컬 웹앱

API 명세([05](../05_API/05-1_엔드포인트표.md)) 다음, 화면 구현 전에 정한 FE 구조다. 절차는 프로젝트 스킬 `.claude/skills/frontend` 03~05이고, 스킬의 Next.js·Tailwind·Figma 전제를 이 스택(Vite SPA · React Router 8 · TanStack Query · openapi-fetch · CSS 변수 + CSS Modules · 라이트 테마만)에 맞게 줄였다. 맞지 않는 항목은 각 `_검증체크리스트.md`의 '해당 없음'에 이유와 함께 적었다.

실제 코드는 `apps/FE`이고 구축 기록은 [06-3 FE 스캐폴딩](../06_개발환경/06-3_FE스캐폴딩.md)이다. 경로·폴더·토큰 방식은 이 문서들과 같다(2026-09-27 대조).

## 설계 중 찾은 어긋남 (오너·디자인·API 담당 확인)

| # | 어긋남 | 정한 것(Proposed) | 문서 |
|---|---|---|---|
| C1 | SCR-12 시안은 목록 + 고른 후보 단계 **표**가 한 화면인데, 공통 명세 §3은 `/candidates/:candidateId`를 "현재 단계로 이동"으로 정했다 | 경로는 명세대로. 목록 화면이 `?candidateId=`로 단계 표를 연다 | 05-2 §4-1 |
| C2 | F-CW-22 '입력 고르기'(단계 화면을 후보 없이 열기)에 맞는 경로가 명세 §3에 없다 | `/candidates?runnableStep=<StepCode>`(`listCandidates` 필터) | 05-1 §3 |
| C3 | 후보 머리 오른쪽 버튼이 디자인 문서마다 다르다: 공통부품 §F '후보 목록' · 화면시안_명세 §3 '여기부터 연속 실행' · SCR-12 보드 '후보 제외' | 단계 화면 틀 '후보 목록', 목록 화면 '후보 제외'. 버튼은 슬롯 | 04-3 §4 |
| C4 | 내비 상태 상자 문구가 다르다: 공통부품 §A '등록 API 차단 켜짐 · 드라이런'·'오늘 페이지 조회' / 화면시안_명세 §3 '…차단 스위치 켜짐…'·'하루 페이지 조회' | 공통부품 §A("글자 그대로 복사")를 따른다 | 05-2 §3 |

- 스택 자체(React + Vite)는 D-14 **Accepted**다.
