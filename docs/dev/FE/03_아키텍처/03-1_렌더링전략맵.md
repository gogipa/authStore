## 1. 이 앱의 전제

- 설치 사용자 1명이 이 PC(127.0.0.1)에서만 연다. 로그인이 없다(GEN-01, 02-ADR-001 C1).
- 검색 엔진에 노출할 화면이 없다. 모든 화면이 개인 작업 화면이다.
- 운영에서는 BE(NestJS)가 `apps/FE/dist`를 내보내고, `/api` 밖 경로는 `index.html`로 돌린다(03-ADR-003 결정 1).
- 그래서 판단 기준 가운데 "공개·SEO → SSR/SSG/ISR"에 드는 화면이 없다. **14개 화면 모두 CSR**이다(D-29로 SCR-14 사용 안내를 더했다).

## 2. 화면별 전략

공개 여부는 모두 "로컬 1인(로그인 없음)"이고 SEO는 모두 "불필요"라 열에서 뺐다. 신선도 열의 SSE는 `GET /events`(05-1 §3) 알림을 받아 조회 API를 다시 읽는다는 뜻이다.

## 3. 클라이언트 경계

- **`'use client'` 경계 — 해당 없음.** 서버 컴포넌트(RSC)가 없다. 앱 전체가 브라우저 번들이다.
- 이 앱에서 경계에 해당하는 것은 **번들 분할 경계**다. 화면(page)마다 lazy로 나눈다 → [05-4](../05_라우팅/05-4_코드스플리팅경계.md).

## 4. 쓰지 않는 전략

| 전략 | 판단 | 이유 |
|---|---|---|
| SSR | 해당 없음 | SEO·첫 화면 속도 요구가 없다. 로컬 1인 앱이다(§3 스캐폴딩 명세). 스택도 Vite SPA로 정해졌다(D-14) |
| SSG | 해당 없음 | 정적 콘텐츠 화면(약관 등)이 없다. 첫 실행 이용 고지(GEN-09)는 M2이고 앱 안 화면이다 |
| ISR | 해당 없음 | 서버 캐시 재생성이 필요한 공개 목록이 없다 |
| CSR + 실시간 채널 | **채택(부분)** | 긴 단계 실행은 SSE로 알린다(02-ADR-001). SSE는 "무엇이 바뀌었는지"만 알리고 화면은 조회 API로 다시 읽는다 |
