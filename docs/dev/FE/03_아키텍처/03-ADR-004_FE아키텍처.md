## 맥락

- 로컬 1인 앱이다. 127.0.0.1에서만 열리고 로그인이 없다(GEN-01).
- 화면 13장이 모두 개인 작업 화면이다. 공개·SEO 화면이 없다.
- 스택은 React + Vite로 정해졌다(D-14). 데이터는 TanStack Query + openapi-fetch, 라우팅은 React Router, 스타일은 토큰 → CSS 변수 + CSS Modules다(02-ADR-001, Proposed).
- 단계 실행이 길어(수십 초~수 분) 진행은 SSE로 온다(02-ADR-001).
- BE는 모듈 경계를 규칙으로 지킨다(03-ADR-003). FE도 같은 이름으로 나누면 API와 화면 코드를 함께 찾기 쉽다.

## 결정

1. **렌더링**: 모든 화면 CSR(SPA). 개발은 Vite 서버(127.0.0.1:5173, `/api` 프록시), 운영은 BE가 `dist`를 내보낸다.
2. **폴더**: `app / pages / features / shared` 4층. 의존은 위에서 아래로만(03-2 §4).
3. **feature 이름**: OpenAPI 태그와 1:1(`step-engine`, `keywords`, … `system`). 폴더는 그 도메인을 쓰는 첫 화면을 만들 때 만든다.
4. **경계 강제**: ESLint `no-restricted-imports` 초안(03-2 §5). 적용은 06.
5. **서버 상태**: TanStack Query 전담. queryKey는 `[태그, operationId, 파라미터]`.
6. **클라이언트 상태**: React state + URL search params. 전역 스토어는 두지 않는다.
7. **실시간**: SSE 연결 하나를 앱이 공유하고, 이벤트는 쿼리 무효화만 한다.
8. **API 타입**: 05-2 OpenAPI가 원본. `api:gen`으로 `schema.d.ts`를 만들고 손으로 타입을 쓰지 않는다.

## 근거

- CSR: SEO·SSR이 필요 없고 BE 한 프로세스가 정적 파일까지 내보내면 설치가 단순하다(스캐폴딩 명세 §3, 03-ADR-003 결정 1).
- OpenAPI 태그 1:1: 05-1·05-2·BE 모듈과 같은 말을 쓰면 재작명 비용이 없다.
- 전역 스토어 없음: 화면 상태 대부분이 서버 상태다. 남는 것은 탭·펼침·폼 입력처럼 화면 안 상태다.
- SSE 무효화: 05-1 §3이 "이벤트는 무엇이 바뀌었는지만 알린다"로 정했다. 캐시를 직접 고치면 조회 API와 어긋날 수 있다.

## 기각안

| 안 | 기각 이유 |
|---|---|
| SSR/SSG 프레임워크(Next.js 등) | D-14로 React + Vite가 정해졌다. SEO 화면이 없어 얻는 것도 없다 |
| 화면(page) 단위로만 폴더 나누기 | 단계 레일·후보 머리처럼 여러 화면이 쓰는 도메인 코드가 흩어진다 |
| Zustand 등 전역 스토어 | 지금 담을 전역 클라이언트 상태가 없다. 서버 값을 복사하면 SSE 갱신과 어긋난다 |
| 폴링으로 진행 확인 | 단계가 길어 요청이 많다. 02-ADR-001이 SSE를 골랐다(폴링은 대체 경로) |

## 영향

- 폴더: 03-2 트리대로 06-3 스캐폴딩이 만든다. `features/`는 비워 두고 README 한 줄만 둔다.
- 캐싱: 모든 조회는 Query 기본값(retry 1, refetchOnWindowFocus false)을 쓴다. 신선도는 SSE 무효화로 맞춘다.
- 라우팅·분할: 05에서 화면마다 lazy로 나눈다.
- 감수하는 것: 첫 화면이 JS를 받은 뒤 그려진다. 로컬이라 체감이 작다.

- 여러 화면이 같이 쓰는 클라이언트 상태(예: 일괄 선택 바구니)가 생기면 → context 또는 스토어를 다시 본다.
