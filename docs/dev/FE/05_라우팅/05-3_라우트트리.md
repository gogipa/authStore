## 1. 지금 경로 표 (routes.tsx 요약)

```tsx
// apps/FE/src/app/routes.tsx — 요약. 경로·순서는 05-1 표와 같다
export const routes: RouteObject[] = [
  {
    path: '/',
    element: <AppLayout />,                        // 왼쪽 내비 + <main><Outlet/></main>
    children: [
      { index: true, element: <DashboardPage /> }, // SCR-01
      { path: 'keywords', element: <KeywordsPage /> },          // SCR-02
      { path: 'candidates', element: <CandidatesPage /> },      // SCR-12 목록
      {
        path: 'candidates/:candidateId',
        element: <CandidateLayout />,                            // SCR-12 틀: 후보 머리 + 단계 레일
        children: [
          { index: true, element: <CandidateIndexRedirect /> }, // 현재 단계로 replace(지금은 sourcing)
          { path: 'sourcing', element: <SourcingPage /> },       // SCR-03
          { path: 'judgement', element: <JudgementPage /> },     // SCR-04 (④ #category)
          { path: 'thumbnail', element: <ThumbnailPage /> },     // SCR-05
          { path: 'content', element: <ContentPage /> },         // SCR-06
          { path: 'tags', element: <TagsPage /> },               // SCR-07
          { path: 'approval', element: <ApprovalPage /> },       // SCR-08
        ],
      },
      { path: 'products', element: <ProductsPage /> },          // SCR-09 (M2)
      { path: 'settings', element: <SettingsPage /> },          // SCR-10
      { path: 'settings/ai-engine', element: <AiEnginePage /> },// SCR-13
      { path: 'system', element: <SystemPage /> },              // SCR-11
      { path: '*', element: <NotFoundPage /> },
    ],
  },
];
```

- 경로 표를 `routes.tsx`에 따로 두는 이유: 앱은 `createBrowserRouter`, 테스트는 `createMemoryRouter`로 **같은 표**를 쓴다.
- 단계 화면 경로 조각은 `shared/lib/steps.ts`의 `StepScreen`과 같아야 한다.
- 지금은 모든 화면을 바로 import한다(lazy 없음). 06-3 §9에 "번들이 커지면 나눈다"로 남겨 두었다.

## 2. 지금 모양 (P1-02에서 적용)

> 적용 차이: 오류 화면은 `pages/route-error/RouteErrorPage.tsx`가 아니라 **`app/RouteErrorBoundary.tsx`**에 두었다(P1-02 실행 문서가 정한 위치, 경로를 아는 앱 조립층이라 app에 둔다). 첫 진입 fallback은 경로 없는 layout route의 `hydrateFallbackElement: <></>`다(루트에 두면 내비까지 가려진다). '다시 시도'는 같은 주소로 `navigate(..., { replace: true })`하고 Query 오류 상태를 푼다(RR 8은 위치가 바뀌면 오류 경계를 푼다. `revalidate()`는 loader가 없어 경계를 풀지 못했다).

바뀌는 것은 두 가지다. **경로는 그대로다.**
1. 화면마다 `lazy`(05-4).
2. 경로 없는 layout route에 `ErrorBoundary`(05-2 §4-2 옵션 B) — 오류가 나도 내비가 남는다.

```tsx
// 목표 모양 초안. React Router route 객체의 lazy는 { Component }를 돌려준다 ⚠️ RR 8 문법은 적용 때 확인
import type { ComponentType } from 'react';

const page =
  <M,>(load: () => Promise<M>, pick: (m: M) => ComponentType) =>
  async () => ({ Component: pick(await load()) });

export const routes: RouteObject[] = [
  {
    path: '/',
    element: <AppLayout />,
    hydrateFallbackElement: null,           // 첫 진입 때 lazy 화면을 받는 동안(⚠️ 경고 방지용, 확인 필요)
    children: [
      {
        ErrorBoundary: RouteErrorPage,      // 경로 없음. 오류를 <main> 안에서 보여 준다
        children: [
          { index: true, lazy: page(() => import('@/pages/dashboard/DashboardPage'), (m) => m.DashboardPage) },
          { path: 'keywords', lazy: page(() => import('@/pages/keywords/KeywordsPage'), (m) => m.KeywordsPage) },
          { path: 'candidates', lazy: page(() => import('@/pages/candidates/CandidatesPage'), (m) => m.CandidatesPage) },
          {
            path: 'candidates/:candidateId',
            element: <CandidateLayout />,   // 단계 화면 6개가 모두 쓰는 틀이라 바로 import
            children: [
              { index: true, element: <CandidateIndexRedirect /> },
              { path: 'sourcing', lazy: page(() => import('@/pages/sourcing/SourcingPage'), (m) => m.SourcingPage) },
              { path: 'judgement', lazy: page(() => import('@/pages/judgement/JudgementPage'), (m) => m.JudgementPage) },
              { path: 'thumbnail', lazy: page(() => import('@/pages/thumbnail/ThumbnailPage'), (m) => m.ThumbnailPage) },
              { path: 'content', lazy: page(() => import('@/pages/content/ContentPage'), (m) => m.ContentPage) },
              { path: 'tags', lazy: page(() => import('@/pages/tags/TagsPage'), (m) => m.TagsPage) },
              { path: 'approval', lazy: page(() => import('@/pages/approval/ApprovalPage'), (m) => m.ApprovalPage) },
            ],
          },
          { path: 'products', lazy: page(() => import('@/pages/products/ProductsPage'), (m) => m.ProductsPage) },
          { path: 'settings', lazy: page(() => import('@/pages/settings/SettingsPage'), (m) => m.SettingsPage) },
          { path: 'settings/ai-engine', lazy: page(() => import('@/pages/ai-engine/AiEnginePage'), (m) => m.AiEnginePage) },
          { path: 'system', lazy: page(() => import('@/pages/system/SystemPage'), (m) => m.SystemPage) },
          { path: '*', element: <NotFoundPage /> },
        ],
      },
    ],
  },
];
```

- 페이지는 지금처럼 **이름 있는 export**(`export function SourcingPage`)를 유지한다. `pick`이 이름을 고른다.
- 바꾼 뒤 `routes.test.tsx`는 `findBy…`(비동기)로 바꿔야 한다.
- route `loader`는 쓰지 않는다. 데이터는 화면 안 TanStack Query 훅이 읽는다(03-2 §6).

## 3. Next 특수 파일 ↔ 이 프로젝트

| Next App Router | 이 프로젝트 | 위치 |
|---|---|---|
| `layout.tsx` | layout route의 `element` + `<Outlet/>` | `app/AppLayout.tsx`, `pages/candidate/CandidateLayout.tsx` |
| `page.tsx` | route `element`(목표: `lazy`) | `pages/<화면>/<Name>Page.tsx` |
| `loading.tsx` | 화면 안 Query `isPending` 표시(05-2 §6) | 각 화면 |
| `error.tsx` | `ErrorBoundary`(§2) | `app/RouteErrorBoundary.tsx`(P1-02) |
| `not-found.tsx` | `path: '*'` / 없는 후보는 틀 안 안내 | `pages/not-found/NotFoundPage.tsx`, `CandidateLayout` |
| `generateStaticParams`·`dynamic` | 해당 없음(CSR) | — |
| `'use client'` | 해당 없음(전부 클라이언트) | — |
