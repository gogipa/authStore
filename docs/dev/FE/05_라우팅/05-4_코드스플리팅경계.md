# 05-4. 코드 스플리팅 경계

| 항목 | 내용 |
|---|---|
| 버전 | 0.1 (2026-09-27) |
| 상태 | **Proposed** (D-11). 13단계(성능 최적화) 입력 |
| 스킬 대응 | `next/dynamic`·`ssr` 옵션 **해당 없음** — Vite + React Router route `lazy`(동적 `import()`)로 나눈다. SSR이 없어 `ssr: false`도 필요 없다 |

## 1. 기본 규칙

- **화면(page) 하나 = 청크 하나.** route `lazy`로 나눈다(05-3 §2). App Router처럼 저절로 나뉘지 않으므로 직접 적는다.
- **나누지 않는 것(첫 청크)**: `AppLayout`·`AppNav`, `CandidateLayout`·`StepRail`, `NotFoundPage`, `shared/ui`, `shared/api`, `tokens.css`·`global.css`. 모든 화면이 쓰거나 아주 작다.
- 적용 시점: 08 화면 구현 때. 지금 스캐폴딩은 자리표시자라 나눌 이득이 없다(06-3 §9).
- 로컬 앱이라 네트워크 비용이 거의 없다. 분할의 목적은 **첫 화면을 빨리 그리는 것**과 **화면별 번들 크기를 보이게 하는 것**이다.

## 3. 앞으로의 후보 (생기면 라우트 안에서 한 번 더 나눈다)

| 후보 | 생길 곳 | 언제 | 분할 방식 |
|---|---|---|---|
| 차트 라이브러리 | 대시보드 오늘 처리량·판매 비중, 시스템 AI 사용량 | M2 | 차트 부품만 `React.lazy` + `<Suspense>` |
| HTML 정화기(DOMPurify 등) | ⑥-3 HTML 미리보기, ⑨ 전체 미리보기 | M1 구현 때 판단 | 미리보기 패널만 lazy. `getContentAssemblyPreview`를 `<iframe sandbox>`로 보여 주면 라이브러리가 필요 없다(권장) |
| 이미지 크롭·배경 제거 편집기 | ⑤ 썸네일(`createImageBackgroundRemoval`) | M2 | 편집 대화상자만 lazy |
| CSV·엑셀 파서 | 판매상품비중 CSV, 셀라파인더 엑셀 | M2 | 지금 명세는 BE가 파일을 읽는다(`importSalesRatioRecordCsv`·`importDomesticPriceFile`). FE 파서를 들이면 그때만 |
| 코드·JSON 보기 | ⑨ 요청 JSON 내려받기 | M2 | 내려받기만이면 필요 없음 |

## 4. 과분할 경고

- 작은 부품(칩·버튼·표)을 lazy로 나누지 않는다. 요청만 늘고 깜빡임이 생긴다.
- 단계 화면끼리 오갈 때 틀(`CandidateLayout`)이 다시 받아지면 안 된다 → 틀은 eager.
- 한 화면 안 탭(설정 탭 등)은 나누지 않는다. 탭 전환이 느려진다.
- 13단계에서 `vite build` 결과의 청크 크기를 보고, 50KB(gzip)를 넘는 화면만 안쪽 분할을 검토한다(기준값은 Proposed).
