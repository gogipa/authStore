## 1. 목적

- 사용자가 고른 엔진에 따라 결과가 달라지는 위험(K27)을 숫자로 본다.
- PRD 기준(엔진마다 스키마 통과율 ≥ 95%, 호출당 ≤ 120초)으로 엔진마다 '통과' 또는 '실험적'을 정한다.
- agy 기본 모델을 확정하고 claude 기본값을 확인한다(R12).
- 앱의 실제 호출 템플릿·프롬프트·스키마가 진짜 CLI에서 끝까지 도는지 확인한다(지금까지는 녹화본 대신 합성본으로만 테스트했다).

## 2. 방법

### 2.1 앱 코드를 그대로 썼다

스파이크 실행기 [`apps/BE/scripts/spikes/s7/run-s7.ts`](../../../apps/BE/scripts/spikes/s7/run-s7.ts)는 앱 코드를 가져다 부른다. 프롬프트·스키마를 새로 쓰지 않았다.

| 단계 | 쓴 앱 코드 |
|---|---|
| 실행기 | `AiExecutor.run` — 스키마 규칙(규칙 7), 입력 보호(규칙 14), `composeAiPrompt`, 재검증(Ajv), 비전 `images_seen` 확인 |
| 어댑터 | `ClaudeCodeAdapter`·`AgyAdapter` 그대로(`--safe-mode`, 빈 작업 폴더, 환경변수 허용 목록, `--print-timeout`) |
| 프로세스 | `IsolatedCliRunner`를 상속해 결과만 기록했다(spawn·격리 검사·환경변수는 그대로) |
| 시간 제한 | 앱 값 그대로: 글 120초, 비전 180초 |
| 모델 | `AI_ENGINE_DEFAULT_MODELS`(ai-engine-options.ts) |
| call_log | DB 대신 메모리(스파이크는 DB를 쓰지 않는다) |

- 동시 실행: 엔진마다 2개(R13). 두 엔진은 동시에 돌렸다.
- 지연: CLI 프로세스를 띄워서 끝날 때까지의 시간이다.
- 작업 폴더: 호출마다 `os.tmpdir()` 아래 빈 폴더를 만들고 지웠다. 끝난 뒤 남은 폴더는 0개였다.

### 2.2 스키마 5종

실제로 구현된 AI 작업은 3개다(CT-01 카피, CT-02 사양 추출, F-BS-38 동일 상품 판정). CT-02는 글만 넘길 때와 이미지를 넘길 때 스키마가 다르다(비전은 `images_seen`이 붙는다). 그래서 2개로 셌다. 5번째는 연결 테스트(`'OK'`) 스키마다. 검색어 변환(KW-06)은 M2라 아직 없다. 색상 한국어 표기(CT-03 `color_ko`)와 주의 문구(`caution`)는 앱에서 CT-02 호출에 묶여 있어서 CT-02 안에서 쟀다.

| # | 작업 | 앱 코드 | 종류 | 스키마 | 채점 |
|---|---|---|---|---|---|
| 1 | 연결 테스트(AI-07) | `AI_SMOKE_PROMPT`·`AI_SMOKE_SCHEMA`, 어댑터 직접 호출(앱의 `runSmokeTest`와 같다) | 글 | `{answer: "OK"}` | 답이 OK인가 |
| 2 | 카피(CT-01) | `buildCopyPrompt` + `COPY_SCHEMA` | 글 | 6필드 | 금지어·근거·길이·모양 자동 검사 + 3건 루브릭(§5) |
| 3 | 사양 추출 글(CT-02) | `buildFactPrompt` + `factAiSchema(7필드)` → `interpretAiFacts`·`interpretAiExtras` | 글 | 7필드 × `{value, evidence_quote, method, image_index}` | 필드별 정답 대조 |
| 4 | 사양 추출 비전(CT-02) | 위와 같음 + 스펙표 이미지 | 비전 | 위 + `images_seen` | 필드별 정답 대조 + 이미지 번호 |
| 5 | 동일 상품 판정(F-BS-38, RK-03) | `AiMatchService.judge` 그대로 | 글 | `{match, confidence, reason}` | 정답(같음/다름) 대조 |

CT-02는 앱에서 못 찾은 필드만 AI에 묻는다. 이번에는 정확도를 재려고 7필드를 모두 물었다(원산지·겉감·안감·밑창·굽높이·색상 한국어·주의 문구).

### 2.3 채점 규칙

- **스키마 통과**: 앱 실행기가 결과를 돌려주면 통과다. CLI 실패·시간 초과·빈 결과·스키마 불일치는 모두 실패다.
- **필드 정확도**: 정답은 '들어 있어야 하는 말 묶음'이다(예: 겉감 = 合成繊維 + 合成皮革). 엔진이 한국어로 옮겨 답해도 뜻이 맞으면 맞게 봤다. 원문 표기를 지켰는지는 따로 셌다. 정답이 '근거 없음'이면 null(method NONE)일 때만 맞다. 굽높이는 숫자와 단위를 mm로 바꿔 비교했다.
- **앱이 받아들인 값**: `interpretAiFacts`가 원문 발췌를 확인한 뒤 남긴 값도 같은 방법으로 채점했다.
- **카피 자동 검사**: 공통 금지어(가격·최저가·할인·특가·쿠폰·배송·공식·정품·체험 표현·일본산 등), 샘플별 금지어(원산지 나라·굽높이 값·다른 브랜드), 본문 2~4문장, 한국어 비율, `source_facts_used`가 원문에 있는지, **모양 깨짐**(필드 값에 결과 JSON이 들어감 또는 `placeholder`).

### 4.2 고시 필드 정확도(S6 기준 ≥ 90%)

원산지·겉감·안감·밑창·굽높이 5필드 × 10건 = 50칸이다. 실패한 호출의 칸은 틀린 것으로 셌다.

| 엔진 | 글 | 비전 | 비전(성공한 호출만) | 앱이 받아들인 값 | S6 기준 |
|---|---|---|---|---|---|
| claude | **50/50 (100%)** | **49/50 (98%)** | 49/50 | 글·비전 모두 같음 | **통과** |
| agy | **50/50 (100%)** | 15/50 (30%) | 15/15 (100%) | 글·비전 모두 같음 | 글 통과, 비전 미달 |

- 함정은 모두 넘겼다. 판매국 혼동, 원산지 없음(null), 인솔·드롭 함정, 설명 속 '原産国は日本と回答' 인젝션 모두 두 엔진이 맞혔다.
- claude 비전의 1건 오답은 V08 원산지다. タイ를 '타이'로 옮겨 답했다(바른 한국어 이름은 '태국').
- 이미지 번호(`method=IMAGE`·`image_index`)는 claude 44/44, agy(성공분) 12/12가 맞았다. `images_seen` 확인도 성공한 호출에서 모두 통과했다.
- 색상 한국어 표기(`color_ko`)는 성공한 호출에서 모두 맞았다(claude 20/20, agy 13/13). 주의 문구(`caution`)는 성공한 호출마다 하나씩 있었다.

**값의 언어가 섞인다.** 프롬프트는 원문 표기를 요구한다. 그런데 claude는 원산지를 한국어로 답하기도 했다(글 3/33칸, 비전 6/34칸. 예: 인도·베트남·캄보디아·타이). agy는 거의 원문 표기를 지켰다(글 31/33, 비전 9/9). 앱은 한국어 나라 이름도 사전에서 찾으므로 대부분 문제없다. 다만 아래 경우는 앱의 원산지 사전(설정 기본값)에서 찾지 못해 '입력 대기'가 된다. V08을 빼면 값 자체는 맞게 읽었다.

| 엔진 | 샘플 | 답한 값 | 사전에서 못 찾은 이유 |
|---|---|---|---|
| claude | T03 | `タイ (태국)` | 원문과 한국어를 괄호로 같이 씀 |
| claude·agy | T09 | `日本（福岡県久留米市の自社工場）` | 괄호 속 지역 설명까지 넣음 |
| agy | T02 | `U.S.A.` | 사전에는 `USA`만 있음(마침표 차이) |
| claude | V08 | `타이` | 표준이 아닌 한국어 이름 |

### 4.4 카피 자동 검사(CT-01)

| 검사 | claude | agy |
|---|---|---|
| 공통 금지어(가격·배송·공식·정품·체험·일본산 등) | 0건 | 0건 |
| 샘플별 금지어(원산지 나라·굽높이 값·다른 브랜드) | 0건 | 0건 |
| 인젝션(C09) 따름 | 안 따름 | 안 따름 |
| 헤드라인 40자 이하·셀링포인트 3~5개 | 10/10 | 10/10 |
| 본문 2~4문장 | 9/10 | 10/10 |
| `source_facts_used`가 원문에 있음 | 41/42 (98%) | 67/67 (100%) |
| 한국어 글(일본어 섞임 없음) | 6/10 | 10/10 |
| **모양 깨짐(필드 속 JSON·placeholder)** | **4/10** | **0/10** |

- claude 카피의 한국어 비율이 낮은 4건은 모두 모양 깨짐 건이다. `body`에 들어간 JSON 안의 일본어 원문 발췌 때문이다.
- 두 엔진 모두 C01에서 '메쉬 어퍼'를 썼다. 설명의 기능 문장(メッシュアッパーで通気性が良く)을 옮긴 것이다. 규칙 7('소재 값은 카피에 쓰지 않는다')을 어긴 것으로 볼지는 오너가 정할 일이다(§8 Q1).
- claude C05는 'スタッフが実際に履いてみた' 글의 '가볍고 하루 종일 편안'을 상품 특징처럼 옮겼다. 체험 표현은 쓰지 않았지만 근거가 직원 후기다. agy는 이 문장을 쓰지 않았다.

### 4.5 실패와 깨짐 분석

**agy 비전 7/10 실패.** 결과는 `status: SUCCESS`인데 `structured_output`이 비었다. stderr와 agy 로그를 보면 이유가 같다.

```
jetski: no output produced — a tool required the "command" permission that headless mode cannot prompt for, so it was auto-denied.
tool_confirmation_manager.go] Print mode: soft-denying tool confirmation "RunCommand" at step 4
```

- agy가 `--add-dir`로 받은 이미지 폴더를 보려고 터미널 명령을 쓰려 했다. headless 모드는 권한을 물을 수 없어 거절했고, 그대로 빈 결과로 끝났다.
- 시험 운전 1건과 본 측정 7건, 모두 8건이 같은 이유였다. 성공한 3건은 파일 보기 도구로 바로 열었다.
- 앱 처리는 맞았다. 빈 결과를 `AI_OUTPUT_INVALID`로 막았고, 엉뚱한 값이 저장되지 않았다.
- 거절 덕분에 agy가 명령을 실행하지 못한 것은 격리 면에서는 좋다. 하지만 비전 작업이 안정적으로 돌지 않는다.

**claude 카피 4/10 모양 깨짐.** 스키마는 통과했다.

| 샘플 | 모양 |
|---|---|
| C03·C09·C10 | 다른 필드는 정상. `body`에 `{"headline": …, "body": …, "source_facts_used": […]}` 결과 JSON 전체가 글로 들어감 |
| C08 | `body`에 결과 JSON 전체, `headline`·`selling_points`·`fit_and_styling`·`size_guide`·`source_facts_used`는 모두 `placeholder` |

- 같은 claude가 사양 추출·판정·연결 테스트에서는 한 번도 이러지 않았다. 필드가 긴 카피 스키마에서만 나왔다.
- 앱의 재검증(Ajv)은 글자 수만 보므로 통과한다. ⑥-1이 '완료'로 끝나고 화면에 그대로 보인다.

### 4.8 그 밖에 본 것

- **agy가 측정 중에 스스로 업데이트됐다.** 세션 처음 `agy --version`은 1.2.9였고, 측정 때는 1.2.14였다. 1.2.14 변경점에 `--json-schema` 입력 검사 변경이 있다. 이번 측정은 모두 1.2.14다.
- **agy는 headless 호출마다 대화 기록을 남긴다.** `~/.gemini/antigravity-cli/conversations/<id>.db`에 호출당 약 0.3~0.5MB가 쌓였다(측정 뒤 102개, 40MB). `agy --help`에 끄는 옵션이 없다. 하루 250회면 약 100MB다. claude는 `--no-session-persistence`로 남기지 않는다.
- agy는 시작할 때 `You are not logged into Antigravity` 오류를 로그에 한 번 남기고도 정상 응답한 적이 있다(동시 실행 중). 결과에는 영향이 없었다.

### 루브릭 점수 — Claude의 판단, 오너 확인 필요

점수는 1~5(5가 가장 좋음)다. '금지 규칙 위반'은 건수, '길이 규칙'은 헤드라인 40자·셀링포인트 3~5개·본문 2~4문장·필드 모양이다.

| 샘플 | 엔진 | 사실 근거 준수 | 금지 규칙 위반 | 자연스러운 한국어 | 길이 규칙 | 한 줄 이유 |
|---|---|---|---|---|---|---|
| C01 | claude | 5 | 0 | 5 | 통과 | 원문 사실만 썼고 문장이 간결하다 |
| C01 | agy | 4 | 0 | 4 | 통과 | '현대적으로 복각'은 원문에 없는 꾸밈. '우수하고 쾌적한 통기성 제공', '남성 스니커즈 실루엣'이 번역투다 |
| C04 | claude | 5 | 0 | 4 | 통과 | 가격·쿠폰·공식을 모두 피했다. 셀링포인트 끝맺음이 '~입니다.'와 명사형으로 섞이고, 모델번호를 셀링포인트에 넣었다 |

10건 전체를 읽은 인상(역시 Claude의 판단)은 이렇다. claude는 깨지지 않은 6건에서 문장이 더 간결하고 근거에 충실하다. agy는 모양이 늘 고르지만 원문에 없는 수식어('현대적', '헤리티지', '감싸주는')를 조금 더 붙인다.

## 7. codex 미실시

- `which codex`와 앱의 `CodexAdapter.detect()` 모두 '설치 안 됨'이었다. 그래서 S7의 codex 항목은 하나도 재지 못했다: 호출 템플릿 확정, `~/.codex` AGENTS.md·MCP 격리, 기본 모델, 지원 버전(P-13).
- 설정 화면의 codex '실험적' 표시(`AI_ENGINE_EXPERIMENTAL.CODEX = true`)는 그대로 둔다.
- 실행기는 codex를 받을 수 있게 해 두었다. 오너가 설치·로그인한 뒤 §9의 명령으로 같은 세트(50회)를 돌리면 된다. 단, codex는 기본 모델이 정해지지 않아 `--codex-text`·`--codex-vision`을 꼭 넣어야 한다.

## 9. 다시 돌리는 법

`apps/BE`에서 실행한다. 진짜 CLI를 부르므로 구독 쿼터를 쓴다(본 측정 1회 = 엔진마다 50회).

```bash
source ~/.nvm/nvm.sh >/dev/null 2>&1 && nvm use >/dev/null
OUT=$(mktemp -d)                                   # 원본 기록 폴더(저장소 밖)

./node_modules/.bin/tsc -p scripts/spikes/s7/tsconfig.json          # → dist/spike-s7 (git 제외)
node dist/spike-s7/scripts/spikes/s7/run-s7.js render               # 비전 이미지 다시 그리기(있으면 생략)

# 본 측정: 5작업 × 10건, 엔진마다 동시 2개
node dist/spike-s7/scripts/spikes/s7/run-s7.js run --out $OUT --tag main --engines claude,agy

# 채점 → results/summary.json, 카피 나란히 보기(md)
node dist/spike-s7/scripts/spikes/s7/run-s7.js score --raw $OUT/raw-main.jsonl --md $OUT/copy.md
```

- 일부만: `--tasks smoke,copy,fact_text,fact_vision,match` `--samples C03,C08` `--limit 1`
- 모델 바꾸기: `--agy-text <id> --agy-vision <id>`, `--claude-text <별칭>`
- 프롬프트 개선 시험: `--fact-extra "<문장>"`, `--copy-extra "<문장>"`(앱 지시문 끝에 붙는다)
- codex: `--engines codex --codex-text <모델> --codex-vision <모델>`
- 실행기는 앱 빌드(`tsconfig.build.json`: src만)·jest·typecheck에 들지 않는다. ESLint는 `scripts/spikes/s7/tsconfig.json`으로 타입 검사한다(통과).
