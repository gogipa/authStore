## 1. 원칙 (12-Factor III '설정은 환경에')

- 환경마다 다른 값(DB 주소, 포트, 로그 수준)만 환경변수로 둔다. 코드에 박지 않는다.
- **비밀정보는 환경변수에 두지 않는다.** 커머스API 키·토큰·쿠키는 macOS 키체인에만 있다(03-2 §5). `.env`에도 넣지 않는다.
- 키 목록과 설명은 `apps/BE/.env.example`에만 둔다(커밋한다). 실제 값은 `apps/BE/.env`(커밋하지 않는다, 루트 `.gitignore`의 `.env`·`.env.*`).
- 셸에 있는 값이 `.env`보다 앞선다. 테스트가 `DATABASE_URL`을 바꿀 수 있는 이유다.
- BE는 시작할 때 값을 검사한다(`src/common/config/env.validation.ts`). 틀리면 어느 키가 왜 틀렸는지 적고 뜨지 않는다. 빈 값(`KEY=`)은 없는 것으로 보고 기본값을 쓴다.
- 코드는 `process.env`를 직접 읽지 않고 `AppConfigService`로 읽는다(설정 파일·테스트 도구 제외).
- 앱의 업무 설정(마진율, 선택 AI 엔진 등)은 환경변수가 아니다. 설정 JSON(`APP_DATA_DIR` 안)과 `settings_snapshot`이 원본이다(D-16).

### 2.1 `APP_DATA_DIR` 하위 폴더 (Proposed, P1-01 — 오너 검토)

| 폴더 | 내용 | 만드는 곳 |
|---|---|---|
| `images/<sha256 앞 2자>/<sha256>.<ext>` | 이미지 파일(원본·레퍼런스·생성본·업로드본). 내용 주소라 같은 파일은 한 번만 둔다. ext는 파일 내용으로 판별한 `jpg`·`png`·`webp`·`gif` | P1-01 `FileStorageService`·`ImageAssetsService` |
| `rakuten/pages/<sha256 앞 2자>/<sha256>.html` | 라쿠텐 상품 페이지 원본(받은 EUC-JP 바이트 그대로). 내용 주소라 같은 페이지는 한 번만 둔다. `rakuten_item.raw_file_path`(상대 경로)·`raw_file_sha256`·`raw_file_bytes`가 가리킨다. P2-02(Proposed) | P2-02 `RakutenItemRepository`(`FileStorageService.writeIfAbsent`) |

| (예정) `logs/` | 파일 로그 | system 모듈 |

- DB(`image_asset.file_path`)에는 이 폴더 기준 **상대 경로**(`/` 구분)만 쓴다. 응답·SSE·로그에는 절대 경로를 내보내지 않는다(05-1 §1.2).
- 쓰기는 같은 폴더의 임시 파일(`.<난수>.tmp`)에 쓴 뒤 rename한다. `..`·절대 경로로 폴더 밖을 가리키면 거부한다.
- **운영 기본값**(`NODE_ENV=production`이고 비었을 때, F-BS-02 '설치 폴더 밖'): macOS `~/Library/Application Support/autoStore`, Windows `%APPDATA%\autoStore`, 그 밖 `$XDG_DATA_HOME/autoStore`(없으면 `~/.local/share/autoStore`). 운영에서 저장소 안 경로를 주면 시작하지 않는다.
- e2e는 `os.tmpdir()/autostore-e2e-*` 임시 폴더를 쓰고 끝나면 지운다(`test/setup-env.cjs`).

**표기**
- 비율은 **퍼센트 수**(2.5 = 2.5%, 0.025가 아니다). 키 이름 끝 `Pct`. 소수는 셋째 자리까지(`multipleOf 0.001`). JSON number로 둔다(05-1 §7.1-4): 계산하는 쪽(P2-05)은 정수 천분율(`Math.round(pct × 1000)`)이나 decimal로 바꿔 계산해 부동소수 오차를 피한다.
- 금액은 키 끝에 단위(`Krw` 원 정수, `Yen` 엔 정수, `Usd` 달러). 사이즈 `Mm`(KR mm 정수), 시간 `Hours`.
- 모든 객체가 모르는 키를 막는다(`additionalProperties: false`). 비밀 키(API 키·시크릿·토큰)는 들어갈 자리가 없고, 이름이 비밀처럼 보이면 '키체인에 넣어 주세요' 안내를 준다. 오류 응답에 값(`rejectedValue`)은 넣지 않는다.
- 빠진 키는 기본 템플릿 값으로 채워 검사한다(`useDefaults`). 뒤 실행 문서가 키를 더해도 있던 파일이 깨지지 않는다.

**개인 값 자리표시자**(F-BS-03, US-37 AC3): 기본 템플릿에는 개인 값을 넣지 않는다. 고지 문장의 `{상호}`·`{최대수량}`·`{반품비}`·`{A/S 안내}`는 구매대행 프로필(P1-09, DB)에서, `{배송기간_최소}`·`{배송기간_최대}`는 `notice.values`(기본 **null** = 오너가 넣는다)에서, `{교환정책}`·`{템플릿_기준일}`은 `notice.values.exchangePolicy`·`notice.basisDate`에서 ⑥-3이 채운다. 상호·A/S·배대지 주소·요금표·importer·파일 경로 키는 설정 파일에 없다. ⚠️ ERD §3.11은 배송기간 기본 10~20영업일을 적었다(오너 검토: 기본값을 넣으려면 템플릿의 null만 바꾼다).

**내장 안전 목록**(F-BS-05, `apps/BE/src/modules/settings/safety/builtin-safety-lists.ts`) — 파일은 더할 수만 있고, 빼거나 기준을 풀면 422 `SAFETY_SETTING_RELAXATION_REJECTED`(시작 때는 그 파일을 쓰지 않는다). 비교는 NFC + 앞뒤 공백 제거.
- 아동 키워드(KW-01, `safety.childKeywords`): 키즈·주니어·아동·キッズ·ジュニア·ベビー. 키워드·상품명과 비교할 때(P2-01)는 NFKC → 소문자 → 앞뒤 공백 제거로 맞춰 '포함'을 본다(원본 `common/child-shoe/child-shoe.rules.ts`)
- 바퀴 달린 운동화 단어(`safety.wheeledShoeWords`, P2-01 Proposed — 문서에 목록 없음): 바퀴·롤러·힐리스·heelys·ローラー·ヒーリーズ·車輪
- 고령자용 신발 단어(`safety.seniorShoeWords`, P2-01 Proposed): 실버화·효도화·효도신발·노인화·介護·高齢者·シニア·リハビリ. '실버'만 쓰면 색 이름(실버 운동화)과 겹쳐 신발 낱말이 붙은 표기만 넣었다
- NGKeyword 아동 단어(`sourcing.ngKeywords`): キッズ·ジュニア·ベビー
- 실존 인물 차단어(`safety.personBlockWords`, Proposed): 방탄소년단·BTS·블랙핑크·BLACKPINK·트와이스·세븐틴·스트레이 키즈·Stray Kids·에스파·aespa·뉴진스·NewJeans·르세라핌·LE SSERAFIM·아이브·엔하이픈·ENHYPEN·에이티즈·ATEEZ·ITZY·차은우·장원영·카리나. 흔한 낱말·색 이름과 겹치는 표기(IVE·TWICE·Red Velvet·있지 등)는 오탐을 피하려고 뺐다.
- 구매대행 고지 필수 블록(Proposed): `AGENCY`·`DELIVERY`·`CUSTOMS_DUTY`·`COMBINED_TAX`·`PERSONAL_CUSTOMS_CODE`·`WITHDRAWAL`·`ORIGIN`(늘 넣음), `LEATHER_SAFETY`(조건 `LEATHER_OR_UNKNOWN_MATERIAL`)·`AI_IMAGE`(조건 `AI_IMAGE_LABEL`). 같은 ID·같은 조건·문장(NFC + 앞뒤 공백 제거)의 SHA-256이 앱 상수와 같아야 한다. 해시 범위는 블록 문장 하나(자리표시자 포함, PRD §8.5 초안 그대로). 필수가 아닌 블록: `HEADER`·`EXCHANGE`·`AFTER_SERVICE`·`PRICE_BREAKDOWN`(조건 `MODE_A_PRICE_BREAKDOWN`)·`BASIS_DATE`. 법률 검토(E-3)로 문장이 바뀌면 템플릿과 해시를 앱 업데이트로 함께 바꾼다.
- 하한·상한: 아동화 의심 기준 `CHILD_SHOE_MAX_MM_FLOOR = 235`(235 통과), 판정 유효 시간 `JUDGEMENT_VALIDITY_HOURS_CEIL = 6`(6 통과).

## 3. FE 환경변수 (apps/FE)

| 키 | 값 | 비고 |
|---|---|---|
| (없음) | — | FE는 환경변수를 쓰지 않는다 |

- 포트·프록시는 `apps/FE/vite.config.ts`에 고정했다: 개발 서버 `127.0.0.1:5173`(strictPort), `/api` → `http://127.0.0.1:3100`(`changeOrigin: true`). 로컬 1인 앱이라 환경마다 바뀌지 않는다.
- API 주소는 상대 경로 `/api/v1`이다. 개발은 Vite 프록시가, 운영은 같은 BE 프로세스가 받는다. 그래서 `VITE_API_BASE_URL` 같은 값이 필요 없다.
- 나중에 `VITE_` 변수를 더하면 **빌드 결과(브라우저)에 그대로 들어간다**. 비밀정보는 절대 넣지 않는다.

## 4. `apps/BE/.env.example`

```dotenv
# apps/BE 환경변수 예시. 복사해 .env로 쓴다(.env는 커밋하지 않는다).
# 값은 모두 이 PC 안(127.0.0.1·localhost)을 가리킨다. 비밀정보는 여기 넣지 않는다(키체인에 둔다).

# development | production | test
NODE_ENV=development
# BE 포트. 항상 127.0.0.1에만 붙는다
PORT=3100
# 개발 DB(필수)
DATABASE_URL=postgresql://<사용자>@localhost:5432/autostore_dev
# 테스트 DB(e2e·db:migrate:test가 쓴다)
TEST_DATABASE_URL=postgresql://<사용자>@localhost:5432/autostore_test
# 앱 데이터 폴더(설정 JSON·이미지·로그). 비우면 개발·테스트는 저장소 루트의 .data,
# 운영은 OS 사용자 데이터 폴더(06-4 §2.1). apps/ 안은 쓸 수 없다
APP_DATA_DIR=
# fatal | error | warn | info | debug | trace | silent
LOG_LEVEL=info
# 개발에서만 허용하는 FE 개발 서버 Origin(쉼표 구분)
DEV_FE_ORIGINS=http://127.0.0.1:5173,http://localhost:5173
# 커머스API 메타데이터 하루 1회 자동 동기화(on | off)
COMMERCE_META_AUTO_SYNC=on
```

```bash
cp apps/BE/.env.example apps/BE/.env   # <사용자>를 이 PC의 PostgreSQL 사용자로 바꾼다

```

## 5. 로컬 전용 값

| 값 | 왜 이 PC 안에만 있는가 |
|---|---|
| BE 바인딩 `127.0.0.1` | 코드 상수다(`main.ts`의 `BIND_HOST`). 환경변수로 바꿀 수 없게 했다(03-2 §5, GEN-01) |
| DB `localhost:5432` | PostgreSQL도 localhost에서만 받는다. 로컬 trust 인증이라 URL에 비밀번호가 없다 |
| `autostore_dev` · `autostore_test` | 개발·테스트 DB를 나눈다. e2e는 DB 이름에 `test`가 없으면 멈춘다(개발 DB를 TRUNCATE하지 않게) |
| FE 개발 서버 `127.0.0.1:5173` | Vite `host: '127.0.0.1'`, `strictPort: true` |
| `APP_DATA_DIR`(`.data`) | 개발·테스트만 저장소 안(git 제외, 루트 `.gitignore`의 `.data/`). 운영은 OS 사용자 데이터 폴더(§2.1) |

- 오너 PC의 실제 `.env`는 `DATABASE_URL=postgresql://pyo@localhost:5432/autostore_dev`, `TEST_DATABASE_URL=…/autostore_test`이고 나머지는 예시와 같다(2026-09-27 확인).

## 6. 확인한 것 (2026-09-27)

- `DATABASE_URL`이 없으면 시작 실패, `PORT=abc`·`PORT=70000`·`NODE_ENV=staging`·`LOG_LEVEL=verbose`는 거부, 빈 `APP_DATA_DIR`은 저장소 루트 `.data` 절대 경로 — 단위 테스트(`env.validation.spec.ts`) 통과.
- `prisma.config.ts`가 `.env`를 읽어도 셸의 `DATABASE_URL`이 앞선다 — 셸에서 `autostore_test`를 주고 `migrate deploy`를 돌려 테스트 DB에 적용됨을 확인.
- 개발(`NODE_ENV=development`)에서는 `Origin: http://127.0.0.1:5173` POST가 통과하고, 운영(`production`)·테스트(`test`)에서는 403 `ORIGIN_NOT_ALLOWED` — curl·e2e로 확인.
