## 1. 한 줄 요약

화면은 전부 CSR(SPA)이다. 로컬 1인 앱이라 SEO·SSR이 필요 없다. 개발에서는 Vite 개발 서버(127.0.0.1:5173)가 `/api`를 BE(127.0.0.1:3100)로 넘긴다. 운영에서는 BE가 `apps/FE/dist`를 내보낸다.

지금은 뼈대만 있다. 모든 경로에 자리표시자 화면(제목·화면 ID·설명 한 줄)이 있고, 왼쪽 내비와 후보 작업의 단계 레일이 시안 모양대로 그려진다. 실제 데이터는 아직 부르지 않는다.

## 2. 폴더 구조

```
apps/FE/
├─ index.html              lang="ko", 제목 '신발 자동등록'
├─ vite.config.ts          포트·프록시·별칭(@/ → src)
├─ vitest.config.ts        jsdom + jest-dom (vite.config.ts를 합쳐 쓴다)
├─ eslint.config.js        ESLint 9 flat config
├─ tsconfig.json           참조만: tsconfig.app.json(src) + tsconfig.node.json(설정 파일)
├─ scripts/gen-tokens.mjs  tokens.json → tokens.css
└─ src/
   ├─ main.tsx             진입점: 공급자 + RouterProvider, 토큰·전역 CSS 불러오기
   ├─ app/                 앱 틀
   │  ├─ routes.tsx        경로표(RouteObject[]). 테스트도 이 표를 그대로 쓴다
   │  ├─ router.tsx        createBrowserRouter(routes)
   │  ├─ providers.tsx     QueryClientProvider
   │  ├─ AppLayout.tsx     왼쪽 내비 + <main><Outlet/></main>
   │  └─ AppNav.tsx        왼쪽 내비(NavLink)
   ├─ pages/<화면>/        화면별 페이지. 지금은 자리표시자
   │  └─ candidate/        후보 작업 틀: 후보 머리 + 단계 레일 + <Outlet/>
   ├─ features/            도메인 기능(훅·폼·표). 지금은 비어 있다
   ├─ shared/
   │  ├─ ui/               공통 부품(CSS Modules): PageHeader, Button·ButtonLink, ScreenPlaceholder
   │  ├─ styles/           tokens.css(생성물), global.css
   │  ├─ api/              schema.d.ts(생성물), client.ts, queryClient.ts
   │  └─ lib/steps.ts      단계 코드 ↔ 화면 경로 대응표, 단계 레일 행
   └─ test/                setup.ts(jest-dom), renderRoute.tsx(메모리 라우터로 경로 그리기)
```

- 화면(`pages`)은 도메인 기능(`features`)과 공통 부품(`shared`)을 가져다 조립만 한다.
- `features`끼리는 서로 가져오지 않는다. 공통으로 쓰는 것은 `shared`로 올린다.
- 경로 별칭은 `@/` → `src/` 하나다(vite.config.ts `resolve.alias`, tsconfig.app.json `paths`).

## 3. 스크립트

모든 명령은 저장소 루트에서 `source ~/.nvm/nvm.sh && nvm use` 뒤에 실행한다(Node 24.21.0).

| 명령 | 하는 일 |
|---|---|
| `pnpm --filter @autostore/fe dev` | Vite 개발 서버. `127.0.0.1:5173`, 포트가 차 있으면 멈춘다(strictPort) |
| `pnpm --filter @autostore/fe build` | `tsc -b`로 타입 검사 후 `vite build` → `apps/FE/dist` |
| `pnpm --filter @autostore/fe preview` | 빌드 결과 미리 보기(`127.0.0.1:4173`) |
| `pnpm --filter @autostore/fe test` | Vitest 한 번 실행(jsdom). `test:watch`는 감시 모드 |
| `pnpm --filter @autostore/fe lint` | ESLint |
| `pnpm --filter @autostore/fe typecheck` | `tsc -b --noEmit` (앱 코드 + 설정 파일) |
| `pnpm --filter @autostore/fe api:gen` | 05-2 openapi.yaml → `src/shared/api/schema.d.ts` (루트 `pnpm api:gen`도 같다) |
| `pnpm --filter @autostore/fe tokens:gen` | tokens.json → `src/shared/styles/tokens.css`. 뒤에 `--check`를 붙이면 파일이 최신인지 검사만 한다(다르면 종료 코드 1) |

- 생성물 두 개(`schema.d.ts`, `tokens.css`)는 커밋한다. 원본(05-2, tokens.json)이 바뀌면 다시 만든다. 손으로 고치지 않는다.
- `schema.d.ts`는 Prettier·ESLint 검사에서 뺀다(루트 `.prettierignore`, `eslint.config.js`). `tokens.css`는 Prettier 모양 그대로 나오게 만들어서 커밋 때 바뀌지 않는다.

### 4.1 왼쪽 내비

- 순서·라벨·아이콘은 `공통부품_마크업.md` §A 그대로다: 대시보드 → 키워드 → 후보 작업 → 등록 상품 → 설정 › AI 엔진 → 시스템 상태.
- `NavLink`가 현재 항목에 `aria-current="page"`를 달고 현재 항목 모양(accent-soft 바탕, accent 글자, 600)을 입힌다.
- '대시보드'와 '설정'은 경로가 정확히 같을 때만 현재 항목이다(`end`). 그래서 `/settings/ai-engine`에서는 'AI 엔진'만 현재 항목이다.
- '후보 작업'은 `end`가 없다. 단계 화면(`/candidates/:id/...`)에서도 현재 항목이다.
- 내비 맨 아래 안전장치 상자(등록 API 차단·페이지 조회 수)는 모양만 있다. 값은 설정·시스템 API를 붙일 때 채운다(지금은 '확인 전', '—').

### 4.2 후보 작업 틀과 단계 레일

- `/candidates/:candidateId`로 들어오면 현재 단계 화면으로 보낸다. 지금은 후보 API가 없어 첫 단계 `sourcing`으로 보낸다. 후보 API를 붙이면 목록·상세의 `resumeStepCode`로 바꾼다.
- 단계 코드 ↔ 화면 대응표는 `src/shared/lib/steps.ts`에 있다. 코드는 ERD·OpenAPI `StepCode`와 같다(타입을 `schema.d.ts`에서 가져와 어긋나면 타입 오류가 난다).

| 단계 코드 | 레일 이름 | 화면 경로 조각 |
|---|---|---|
| `SOURCING` | ② 소싱 | `sourcing` |
| `PRICING` | ③ 판정 | `judgement` |
| `CATEGORY` | ④ 카테고리 | `judgement#category` |
| `THUMBNAIL` | ⑤ 썸네일 | `thumbnail` |
| `COPY` | ⑥-1 카피 | `content` |
| `NOTICE_RAW` | ⑥-2 원산지·소재 | `content` |
| `NOTICE_HTML` | ⑥-3 고시·HTML | `content` |
| `TAGS` | ⑦ 태그 | `tags` |
| `UPLOAD` | ⑧ 이미지 업로드 | `approval` |
| `REGISTER` | ⑨ 등록 | `approval` |

- 레일 행 순서는 `공통부품_마크업.md` §G를 따른다. ⑥ 상세 콘텐츠는 묶음 행이고 ⑥-1~⑥-3은 들여쓴 하위 행이다. 게이트 줄은 ③ 아래 G2, ⑦ 아래 G3, ⑧ 아래 G4다.
- 현재 화면을 맡는 **첫 행**에 `aria-current="step"`을 단다. 판정 화면이면 ③, 콘텐츠 화면이면 ⑥, 최종 승인 화면이면 ⑧이다.
- 단계 상태 칩, 게이트 통과 여부, '재실행 필요 단계 모두 실행' 버튼은 후보 API를 붙일 때 넣는다. 지금 게이트 줄은 잠김(idle) 모양이다.

## 5. 토큰 흐름

```
docs/design/design-system/tokens.json  (원본, 디자인 소유)
        │  pnpm --filter @autostore/fe tokens:gen   (scripts/gen-tokens.mjs)
        ▼
apps/FE/src/shared/styles/tokens.css   (생성물, :root CSS 변수, 라이트만)
        │  main.tsx에서 한 번 불러온다
        ▼
global.css · *.module.css              var(--color-…) 등 변수만 쓴다
```

| tokens.json | CSS 변수 | 예 |
|---|---|---|
| `color.tokens[].value.light` | `--color-<이름>` | `--color-accent: #2447b8` |
| 참조 값 `{accent}` | `var(--color-<이름>)` | `--color-running: var(--color-accent)` |
| `type.families` | `--font-sans`, `--font-mono` | |
| `type.groups[].styles[]` | `--type-<이름>`(font 단축 값) + `-size`·`-line-height`·`-weight`·`-letter-spacing` | `font: var(--type-title)` |
| `spacing.tokens` | `--space-1`~`--space-8` | `--space-4: 16px` |
| `radius.tokens` | `--radius-sm`·`-md`·`-lg` | |
| `shadow.tokens[].value.light` | `--shadow-pop` | |

- 라이트 테마만 만든다(D-13). 다크 값은 tokens.json에 남겨 두고 읽지 않는다. 다크를 붙일 때는 생성기에 테마 블록만 더하면 되고 화면 코드는 고치지 않는다.
- 컴포넌트는 CSS Modules와 토큰 변수만 쓴다. 색 값을 직접 적지 않는다(`src` 전체에서 16진 색·rgb 0건 확인). UI 키트·Tailwind는 쓰지 않는다.
- 토큰에 없는 크기(내비 폭 220px, 버튼 높이 36·32px, 내비 하위 항목 13px 등)는 시안 값을 그대로 적었다. 색이 아니라 배치 값이다.
- 글꼴은 외부에서 받지 않는다(GEN-01). `--font-sans`는 `'IBM Plex Sans KR', 'Apple SD Gothic Neo', 'Malgun Gothic', system-ui`다. 이 PC에 IBM Plex가 없으면 시스템 한글 글꼴로 보인다. 빌드 결과물에 외부 글꼴·CDN 주소가 없음을 확인했다.

## 6. API 클라이언트

- 타입: `pnpm --filter @autostore/fe api:gen`이 05-2 openapi.yaml로 `schema.d.ts`(`paths`, `components`)를 만든다. 원본은 항상 05-2다.
- 클라이언트: `src/shared/api/client.ts`의 `api`를 쓴다. `openapi-fetch`의 `createClient`, `baseUrl: '/api/v1'`이다.
- 미들웨어: POST·PUT·PATCH·DELETE에 `X-AutoStore-Client: 1`을 붙인다. GET에는 붙이지 않는다. BE는 이 헤더가 없으면 403 `CLIENT_HEADER_REQUIRED`로 막는다(05-1 §1).
- 05-2는 상태를 바꾸는 작업마다 이 헤더를 **필수 파라미터**로 적는다. 미들웨어가 붙이므로 `client.ts`의 `ApiPaths` 타입이 호출부에서 이 헤더를 선택 사항으로 바꾼다. 호출할 때 헤더를 적지 않아도 된다. 다른 파라미터·본문 타입 검사는 그대로다.
- 오류 봉투: `ApiError` 타입(`components['schemas']['ErrorResponse']`, 05-3 `{ code, message, status, timestamp, path, fieldErrors, details }`)과 `isApiError()` 검사 함수를 둔다.
- TanStack Query 기본값(`queryClient.ts`): `retry: 1`, `refetchOnWindowFocus: false`, 변경 요청은 다시 시도하지 않는다.
- 개발 프록시: `/api` → `http://127.0.0.1:3100`, `changeOrigin: true`(Host 헤더를 `127.0.0.1:3100`으로 바꿔 BE Host 검사를 통과). BE CORS는 켜지 않는다.

## 9. 결정과 남은 일

- **Proposed** — 경로 조각 이름(`sourcing`·`judgement`·`thumbnail`·`content`·`tags`·`approval`)과 `/candidates/:candidateId` 기본 이동 규칙. FE 설계 05 라우팅과 같게 유지한다.
- **Proposed** — 화면 코드 분할(`lazy`)은 아직 하지 않았다. 화면이 채워져 번들이 커지면 경로 단위로 나눈다.
- **Proposed** — 화면 제목은 React 19의 `<title>` 요소로 `PageHeader`가 정한다(`<제목> · 신발 자동등록`).
- 남은 일: 후보 API(`resumeStepCode`, 단계 상태, 게이트)로 레일·후보 머리 채우기, 내비 안전장치 상자 값 연결, 상태 칩·표·패널·안내 띠 같은 공통 부품은 화면을 만들 때 필요한 만큼 `shared/ui`에 더한다.
