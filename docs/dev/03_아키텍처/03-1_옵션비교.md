# 03-1. 아키텍처 옵션 비교

근거: [02-ADR-001](../02_기술스택/02-ADR-001_기술스택.md), [PRD §5.3 단계 실행](../../prd/03-PRD초안.md), [04 기능 리스트](../../prd/04_기능리스트.md).

## 배포 단위

| 옵션 | 장점 | 단점 | 이 앱에 맞는가 |
|---|---|---|---|
| **모듈러 모놀리식(권장)** | 프로세스 하나(NestJS)라 설치·실행이 단순하다(GEN-09). 모듈 경계는 Nest 모듈로 나눈다. 단계 완료·재실행 전파를 한 DB 트랜잭션으로 묶을 수 있다 | 모듈 경계를 지키는 규율이 필요하다 | 사용자 1명·로컬 1대(GEN-01)라 가장 맞다 |
| 단순 모놀리식 | 시작이 가장 빠르다 | 단계 모듈 15개와 외부 연동 7개가 한데 엉키기 쉽다 | 규모가 커서 부적합 |
| MSA | 모듈별 배포 | 로컬 앱에 프로세스 여러 개는 설치·운영 부담만 크다 | 부적합 |

## 내부 구조

| 옵션 | 장점 | 단점 | 이 앱에 맞는가 |
|---|---|---|---|
| 레이어드(controller → service → repository) | Nest 관례와 같다 | 외부 연동을 테스트 fixture로 바꿔 끼우기가 불편할 수 있다 | 대부분의 모듈 |
| **혼합(권장)**: 레이어드 + 외부 연동만 포트·어댑터 | 커머스API·라쿠텐·데이터랩·환율·AI CLI를 인터페이스(포트) 뒤에 두어 fixture·목으로 바꿔 끼운다(NFR-06). 실제 스토어라 샌드박스가 없으므로 이 분리가 필요하다 | 인터페이스가 하나 더 는다 | 권장 |
| 헥사고날 전면 | 도메인 순수성 | 1인 로컬 앱에 과설계 | 부적합 |

## 권장안

모듈러 모놀리식 + 레이어드, 외부 연동만 포트·어댑터. 단계(②~⑨)마다 `run(후보, 입력) → 산출물` 모듈을 두고 단계 실행 엔진이 부른다(PRD §18). 선택은 오너 검토 대상이다(D-11).
