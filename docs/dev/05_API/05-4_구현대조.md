## 1. 무엇을 보나

05-2에서 `x-milestone: M1`인 연산과 구현 명세의 연산을 `operationId`로 짝짓고, 짝마다 다음을 본다.

| 항목 | 결함으로 세는 것 |
|---|---|
| 연산 | 05-2 M1 연산이 구현에 없음 / 구현 연산이 05-2 M1에 없음 |
| 경로·메서드 | 메서드가 다름, 경로 틀이 다름(`/api/v1` 접두는 뺀다), 경로 변수 이름이 다름 |
| 파라미터 | path·query·header 파라미터가 빠지거나 더 있음, 필수 여부가 다름 |
| 요청 본문 | 본문 유무·필수 여부, 본문 형식(content type), 필드 누락·추가, 필수 필드 차이, nullable·기본 타입 차이(중첩까지) |
| 응답 상태 코드 | 05-2의 코드가 구현에 없음 / 구현에만 있음 |
| 성공 응답 스키마 | 2xx 응답의 필드 누락·추가, **필수 필드 누락**, nullable·기본 타입 차이(중첩까지) |

남긴 차이는 이 문서 §4 표에 차이 키와 이유가 있어야 한다. 표에 없는 차이가 하나라도 있거나, 표에만 있고 실제로는 사라진 차이가 있으면 명령이 exit 1로 실패한다(문서가 낡지 않게).

## 2. 같은 것으로 보는 표기 차이(정규화)

| 규칙 | 이유 |
|---|---|
| `nullable: true`(3.0) = `type: [x, 'null']`(3.1) = `oneOf`/`anyOf: [X, {type: 'null'}]` = `allOf: [X]` + `nullable` | 06-2 §9-5. 3.0과 3.1의 null 표기 차이 |
| `const: v` = `enum: [v]`, `exclusiveMaximum` 숫자(3.1) = 불리언(3.0), `integer` ≈ `number` | 같은 뜻의 버전별 표기 |
| `$ref` 이름은 보지 않는다(구현은 `…Dto` 접미사) | 이름이 아니라 모양을 본다 |
| 05-2가 `x-milestone: M2`로 표시한 속성·파라미터·`oneOf` 갈래는 구현에 없어도 되고 있어도 된다 | M1 범위 밖. 구현은 M2 칸을 null로 두거나 받지 않는다(422) |
| 05-2가 모양을 정하지 않은 자유 JSON(`{}`)은 구현 표기를 보지 않는다 | 원문 JSON 칸(라쿠텐 attributes·필드 값 등) |
| 판별자(`oneOf`)로 나뉜 **요청 본문**은 갈래들을 합쳐 비교한다: 필드 = 갈래 필드의 합집합, 필수 = 모든 갈래가 필수인 필드 | 구현은 한 DTO로 받고 갈래 검사는 손 파서(`parseOwnerEditBody`·`parseGatePassBody`·`parseAnchorRequest`·키워드 본문 등)가 한다 — class-validator로 `oneOf`를 표현하지 않는다 |
| 오류 응답(4xx·5xx)은 상태 코드만 본다 | 모두 05-3 공통 봉투(`ErrorResponse`)다. 구현 명세는 설명(코드 목록)만 둔다 |
| `text/event-stream` 응답은 형식만 본다 | 프레임 모양(이벤트 이름별 `oneOf`)은 05-2 `ProgressEventFrame`이 원본이다(구현 명세는 글 스트림) |
| `X-AutoStore-Client` 헤더 파라미터도 일반 헤더로 비교한다 | 05-2의 상태 변경 연산은 모두 이 헤더를 필수로 적는다(03-2 §5). 구현도 같은 데코레이터를 단다 |

## 3. 호환 차이(세지 않음 — 계약을 깨지 않는다)

`--verbose`로 목록을 본다.

| 종류 | 건수 | 뜻 |
|---|---|---|
| 응답 `required-extra` | 140 | 05-2가 선택으로 둔 칸을 구현은 늘 보낸다(값이 null이어도 키가 있다). 많은 곳: `fetchRakutenItem`·`getRakutenItem` 29, `getPriceJudgement` 27, 키워드 묶음 연산 37, `getCategoryDecision` 9 |
| 응답 `optional-field-missing` | 13 | 05-2의 선택 칸을 구현이 보내지 않는다. 12건은 설명이 '(M2)'인 칸(`directInputId`·`personDetected`·`autoRecommended`·`classification`·`brandPolicy`·`regularPriceYen`·`warnings`·`regularPricePMinKrw`), 1건은 설정 검사 오류의 `rejectedValue`(P1-03 결정 — 오류에 입력값을 싣지 않는다) |

요청 본문에서는 호환 규칙을 두지 않는다. 05-2의 선택 칸을 구현이 받지 않으면 클라이언트 요청이 422가 되므로 결함이다(그래서 아래 §5처럼 M2 칸을 05-2에 표시했다).
