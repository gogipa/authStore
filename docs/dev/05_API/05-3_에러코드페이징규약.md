## 2. 오류 응답

```json
{
  "code": "STEP_START_CONDITION_UNMET",
  "message": "시작에 필요한 값이 없습니다: 국내 기준가.",
  "status": 409,
  "timestamp": "2026-09-27T14:02:11+09:00",
  "path": "/api/v1/candidates/12/steps/PRICING/runs",
  "fieldErrors": [{ "field": "owner.domesticPrice", "message": "국내 기준가를 넣어 주세요." }],
  "details": { "stepCode": "PRICING" }
}
```

- `code`: 대문자 스네이크 도메인 코드(§5). `message`: 한국어, 셀러가 아는 말. 비밀정보를 넣지 않는다.
- `fieldErrors[]`: `{ field, message, rejectedValue? }`(05-2 `FieldError`와 같다). 값 검증(422)과 빠진 입력(409 `STEP_START_CONDITION_UNMET`)에 쓴다.
- `details`(선택, **규약 확장 제안 ⚠️ §7.1**): 코드별 추가 정보. 예: `blockedUntil`·`target`(24시간 쉼), `existingCandidateId`(중복 후보), `missingFields[]`(프로필 빈칸), `checks[]`(사전 검증), `stepCode`·`gate`·`job`.
- 24시간 쉼·하루 상한(409)에는 `Retry-After` 헤더도 붙인다.
- **409와 422 가르기**: 요청 값은 맞지만 지금 상태에서 할 수 없으면 409(상태가 바뀌면 같은 요청이 통과한다). 요청 값 자체가 규칙에 맞지 않으면 422(값을 고쳐야 한다). 본문 체크 항목이 빠진 것(`CHECKLIST_INCOMPLETE`)은 422, 앞서 해야 할 확인 동작을 안 한 것(`ADULT_CONFIRMATION_REQUIRED`)은 409다.
- **경고(막지 않음)**: 성공 응답에 `warnings[{ code, message }]`로 준다(§5.2). 예: G2 전 AI 비용 경고(F-CW-17).

## 3. 상태 코드 매핑

| 코드 | 쓰는 때 | 예 |
|---|---|---|
| 200 | 조회, 동기 처리·상태 전이 결과, 같은 내용 재요청을 기존 기록으로 돌려줄 때 | 모든 GET, PUT, `POST …/exclude`, 같은 파일 다시 올리기 |
| 201 | 새 기록을 만들었을 때(`Location`) | `POST /candidates`, 게이트 통과, 오너 수정, 국내 기준가 입력 |
| 202 | 오래 걸리는 작업을 받았을 때(`Location` = 진행 조회) | 단계 실행, 연속 실행, 키워드 버튼 수집, G4 승인 |
| 204 | 삭제, 돌려줄 값이 없는 성공 | DELETE, `PUT /secrets/{secretKey}`, 이어 할 곳 없음 |
| 400 | 요청을 읽을 수 없음, 필수 헤더 없음 | `MALFORMED_REQUEST`, `IDEMPOTENCY_KEY_REQUIRED` |
| 403 | 로컬 보안 가드 | `HOST_NOT_ALLOWED`, `ORIGIN_NOT_ALLOWED`, `CLIENT_HEADER_REQUIRED` |
| 404 | 대상 없음(경로·본문의 id), 없는 주소 | `CANDIDATE_NOT_FOUND`, `STEP_OUTPUT_NOT_FOUND`, `ROUTE_NOT_FOUND` |
| 409 | 충돌·상태 위반·막힌 이유 | `STEP_START_CONDITION_UNMET`, `GATE_NOT_PASSED`, `DAILY_LIMIT_REACHED`, `EXTERNAL_CALL_COOLDOWN` |
| 413 ⚠️ | 파일·본문이 너무 큼 | `PAYLOAD_TOO_LARGE` |
| 422 | 검증 실패 | `VALIDATION_FAILED`, `CHECKLIST_INCOMPLETE` |
| 500 | 예상 못 한 서버 오류 | `INTERNAL_ERROR` |
| 502 ⚠️ | 동기로 부른 외부 API 실패 | `EXTERNAL_API_ERROR`, `COMMERCE_AUTH_FAILED` |
| 503 ⚠️ | 이 PC의 의존물을 쓸 수 없음 | `KEYCHAIN_UNAVAILABLE`, `SETTINGS_INVALID` |

- ⚠️ 400·413·502·503은 주어진 규약 목록(201·202·204·409·422·404)에 없어 더했다. 확인 필요(§7.1).

## 4. 멱등성

| 종류 | 규칙 | 해당 |
|---|---|---|
| GET·PUT·DELETE | 멱등. PUT은 전체 교체·목표 상태 지정, 같은 값이면 부작용 없음 | 전부 |
| POST 생성 | 기본 비멱등 | 후보 만들기, 오너 수정, 수동 환율 입력 등 |
| Idempotency-Key 필수 | 헤더 `Idempotency-Key`(UUID). 같은 키 재요청은 첫 응답을 다시 준다. 같은 키에 다른 본문은 422 `IDEMPOTENCY_KEY_REUSED`. 서버는 판매자관리코드(`RKT:{itemCode}:{colorCode}`)와 `registration` 부분 UNIQUE로 이중 등록을 한 번 더 막는다. 키 저장 위치 ⚠️ §7.6 | `POST /candidates/{candidateId}/registrations`, (M2) `POST /registration-batches`, `POST /registrations/{registrationId}/retry` |
| 화면이 본 버전 확인 | 요청에 화면이 본 버전 id를 넣고, 현재 버전이 아니면 409 `VERSION_NOT_CURRENT` | `baseStepRunId`(오너 수정), `basisStepRunId`(게이트), `expectedUploadResultId`·`expectedPriceJudgementId`(G4) |
| 같은 내용이면 기존 기록 | 새 행 없이 200 + 기존 기록 | 같은 파일 해시(요금표·판매상품비중 CSV·셀라파인더), 게이트 지문이 최신 통과와 같음(⚠️ §7.2), 같은 고지 버전 동의, 같은 설정 파일 다시 읽기 |
| 진행 중 중복 | 409 | 같은 단계 실행 중 `STEP_ALREADY_RUNNING`, 같은 작업 진행 중 `ALREADY_IN_PROGRESS`, 후보의 열린 연속 실행 `CONTINUOUS_RUN_ALREADY_OPEN` |
| '다시 실행' | 입력이 같아도 새 버전(F-BS-19). 결과 캐시를 쓰지 않는다 | `POST …/steps/{stepCode}/runs` |

## 5. 오류 코드

- 화면 문구는 `message`의 기본값이다. `{…}`는 `details`로 채운다. 셀러가 아는 말로 쓰고, 내부 용어(지문·StepRun)는 쓰지 않았다.
- 05-3 규약과 BE 전역 예외 핸들러가 이 표를 같이 쓴다.

**커머스API 인증 실패 원인 분류(P1-07, Proposed 2026-09-30 — 오너 검토)**

`COMMERCE_AUTH_FAILED`의 `details.causeCategory`와 `GET /auth-status`의 `causeCategory`는 마지막 토큰 발급 호출의 `(call_log.http_status, call_log.error_code)`로 정한다. 위에서부터 처음 맞는 줄을 쓰고, 맞는 줄이 없으면 `UNKNOWN`이다. 공식으로 확인된 것은 `GW.IP_NOT_ALLOWED` 하나뿐이고 나머지 코드 이름은 M0 S3(실제 앱 등록) 전 추정이다. 실제 응답을 받으면 이 표·`apps/BE/src/modules/integrations/naver-commerce/commerce-auth-cause.ts`·fixture(`apps/BE/test/fixtures/commerce/auth`)를 함께 고친다.

|---|---|---|---|
| `IP_NOT_ALLOWED` · 호출 IP 불일치 | 무관 | `GW.IP_NOT_ALLOWED`, `CLIENT_IP_NOT_ALLOWED` | R04 A8 공식 · 05-2 getAuthStatus 예시(2차 관찰값) |

### 5.3 사전 검증 항목 코드(`checks[].checkCode`)

`REQUIRED_FIELDS`, `IMAGES`, `OPTIONS`, `TAGS`, `NOTICE_BLOCK`, `ORIGIN`, `JAPAN_WORDING`, `MIN_BLOCK_WORDS`, `NEGATIVE_MARGIN`, `EXTRA_CHARGE_WORDING`, `JUDGEMENT_FRESHNESS`, `REPRESENTATIVE_IMAGE_SOURCE`, `STEP_FRESHNESS`, `CATEGORY`, `DUPLICATE`, (M2) `BRAND_POLICY`, `DIRECT_INPUT_JUDGEMENT`. 각 항목은 `{ checkCode, passed, severity(BLOCK·WARN), reason, stepCode, gateCode }`. 코드 상수(스키마 밖)이고 결과는 승인 때 `registration.validation_result`에 남는다.
