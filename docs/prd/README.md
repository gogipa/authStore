# docs/prd — 요구사항 정의

신발 해외구매대행(라쿠텐 → 네이버 스마트스토어) 자동등록 로컬 웹앱의 요구사항 문서 모음이다. 외부 사실은 모두 2026-09-24 기준이며, 마지막 개정은 v0.4.8(2026-10-03, D-25 저장 공간 표시)이다. 오너가 먼저 쓰고, 지인·동료 셀러에게 무료로 나눠 각자 자기 PC에 설치해 쓴다.

## ⚠️ 먼저 할 일

1. **커머스API '내 스토어 애플리케이션'을 등록한다.** [PRD §0](03-PRD초안.md) 5번이다. 라쿠텐 Developers 앱(6번)은 이미 있는지 확인한다. 1~4번(사업자·전자상거래업자부호·해외상품판매 권한·주소록)은 이미 갖췄다(D-10).
2. 결정 시트(PRD §16)는 모두 추천대로 정했다(D-11). 완성본을 보며 고칠 곳을 짚으면 된다.
3. 전문가 확인 E-1~E-10은 오너가 할 일로 남는다(PRD §16 E).
4. **Codex를 쓰려면 `codex`를 설치하고 로그인한다.** 오너 PC에는 아직 없다. M0 S7(세 AI 엔진 비교)에 필요하다(D-16, [PRD §17](03-PRD초안.md)).
5. **쓰는 AI 계정의 학습 설정을 끈다**(D-20). claude.ai 개인정보 설정 'Help improve Claude', Antigravity 설정 › 계정 › 'Enable Telemetry', ChatGPT 데이터 제어 'Improve the model for everyone'. 앱은 계정 설정을 대신 바꾸지 않는다([PRD §8.9 R16](03-PRD초안.md)).

- 초안 v0.2: 5관점 검토에서 나온 116건을 반영했다.
- 초안 v0.3: 단계를 따로 실행하는 방식을 반영했다(GEN-02·03 개정, GEN-07·08 신설, PRD §5.3). 오너 결정 시트에 답하면 확정한다.
- 초안 v0.3.1: 오너 결정 D-07(②-16 추천안)을 반영했다. RK-02를 Must로 올려 Must가 42개(40.8%, 과적 경고)가 됐다.
- 초안 v0.4: 동료 셀러가 각자 설치해 쓰는 방식을 반영했다(GEN-01 개정, GEN-09 신설, CON-10 개정, §0 정리). 요구사항 104개, Must 40.4%.
- v0.4.1: 결정 시트를 모두 추천대로 정했다(D-11). Must 44개(42.3%).
- 다음 단계(D-12): 기능 리스트 → 디자인 → 개발(M1, Must 44).
- 화면은 라이트 테마만 먼저 만든다(D-13). 다크 테마는 나중이다.
- 기능 리스트 v0.1: 기능 442개. 요구사항 104개와 인수조건 124개가 모두 기능에 이어진다. PRD v0.4.2(CT-07 표기, US-08 AC2 정리).
- 디자인 v0.1: 화면 시안 12장을 캔버스에 올렸다([docs/design](../design/README.md)). 다음은 오너 검토 뒤 개발(M1)이다.
- 개발 스펙(D-14): apps/BE NestJS · apps/FE React+Vite · PostgreSQL. 개발 전에 ERD → API 명세를 만든다(D-15, [docs/dev](../dev/README.md)).
- v0.4.3(D-16): 사용자가 텍스트·비전 AI 엔진을 Claude Code(`claude`)·Antigravity CLI(`agy`)·Codex(`codex`) 중에서 고른다. 고르는 곳은 설정 아래 별도 페이지(SCR-13 'AI 엔진')다. AI-10 [Must]과 US-38을 더해 요구사항 105개, Must 45개(42.9%)가 됐다. 오너가 정하지 않은 세부(전역 엔진 1개, 기본 claude, 저장 전 연결 테스트, 쓸 수 없으면 멈춤 등)는 추천안(D-11)이고 PRD §8.9에 있다. `codex`는 오너 PC에 없어 M0 S7에서 설치·실측한다([원천자료 08](원천자료/08_AI엔진선택_2026-09-27.md)).
- v0.4.4(D-17~D-20, 2026-10-02): M0 S6·S7 뒤 오너 결정. ⑥-1 카피는 검증 실패 때 같은 엔진·모델로 1회 바로 다시 부른다(AI-04 일부를 M1으로, 기능 `F-CT-41`, 분류는 그대로). AGY는 계속 고를 수 있고 오너 본인 사용의 약관 위험은 '중'이다(배포본 기본값은 M2에서 E-10 뒤). 썸네일 생성 경로는 agy `generate_image`다(Gemini API 키 없음). 학습은 허용하지 않는다([원천자료 09](원천자료/09_M0결정_2026-10-02.md)).
- v0.4.5(2026-10-02): M0 S1 결과(agy `generate_image` 실측)를 반영했다. 늘 JPEG 1024×1024, 권한 플래그 불필요, 사람 채점 기준은 미측정이다.
- v0.4.6(D-21, 2026-10-03): S1 Q1 오너 결정. 썸네일 생성 해상도 기본값을 2048에서 1024로 바꿨다(agy는 늘 1024를 낸다). 업로드 때 1000×1000 JPEG로 맞추는 처리는 그대로다. 썸네일은 엔진 선택과 관계없이 agy가 만들어 엔진별 크기 문구는 두지 않는다. 이미 있는 설정 파일의 값은 앱이 바꾸지 않는다([원천자료 10](원천자료/10_S1결정_2026-10-03.md)).
- v0.4.7(D-22~D-26, 2026-10-03): S1 Q2~Q6 오너 결정. '70%' 지표는 신발 길이(신발 박스 긴 변 ÷ 같은 방향 이미지 변 ≥ 0.70)로 잰다. 지금 생성 결과가 목표라 프롬프트는 그대로다. G3 문구는 '신발 길이가 화면 폭의 70% 이상'이다. 생성 하드 타임아웃 기본은 300초다. 얼굴 노출은 품질 기준이 아니다. agy 기록은 앱이 지우지 않고 AI 엔진 설정 화면(SCR-13)에 용량을 보인다. StitchMCP는 그대로 둔다([원천자료 10](원천자료/10_S1결정_2026-10-03.md)).
- v0.4.8(D-25, 2026-10-03): agy 기록 용량 표시의 세부. AI 엔진 화면(SCR-13) 맨 아래 읽기 전용 '저장 공간' 패널에 agy 기록 폴더·앱 이미지 폴더의 크기·파일 수와 디스크 남은 공간을 보인다(PRD §8.9 R17, 기능 `F-ST-33`). 앱은 크기만 재고 지우지 않는다.
