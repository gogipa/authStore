# 원천자료 10 — M0 S1 결정: 썸네일 생성 해상도 (2026-10-03)

- 일자: 2026-10-03
- 발언자: 오너
- 채널: Claude Code 세션 대화
- 비고: 원문 그대로 보존한다('업로드할떄'는 '업로드할 때'의 오타다). 인용은 `원천10 Q26`~`Q27`, 결정은 `D-21`로 참조한다(Q 번호는 원천자료 09의 Q25에 이어 붙인다).
- 이어 적기: S1 보고서의 남은 질문 Q2~Q6([S1_썸네일생성](../../dev/07_M0스파이크/S1_썸네일생성.md) §8)은 오너가 답하는 대로 **이 파일 끝에 이어 적는다**. Q 번호는 Q28부터, 결정 번호는 D-22부터 붙인다.
- 맥락: M0 S1 보고(2026-10-02) 뒤 Claude가 '오너 확인이 필요한 것' Q1~Q6을 물었고, 오너는 하나씩 정하기로 했다. 먼저 Q1(해상도)이다. S1 Q1은 이랬다: "agy는 늘 1024×1024입니다. 설정 기본 2048을 1024로 바꿀까요, 아니면 요청값은 두고 화면에 실제 크기를 보일까요? 업로드는 1000×1000이라 화질 차이는 없습니다."
  - 오너가 'LLM에 따라 크기 문구를 넣자'고 하자 Claude는 이렇게 답했다.
  - 썸네일은 고른 텍스트·비전 엔진과 상관없이 agy가 만든다. `claude`는 이미지를 만들지 못해서 D-16 때 이미지 생성을 엔진 선택에서 뺐다(PRD §8.9 R1). 썸네일 경로는 agy다(D-19).
  - 1000×1000을 바로 만드는 모델은 없다(R06 사전 조사). agy는 1024×1024만 낸다(S1 실측). Gemini API는 1K·2K·4K(1024·2048·4096, NB2는 512도)다. Codex(`gpt-image-2`)는 1024×1024·1536×1024 같은 고정 크기나 16의 배수라 1000을 만들 수 없다(Codex는 설치돼 있지 않아 직접 확인하지 못했다).
  - 앱은 업로드(⑧) 직전에 고른 썸네일을 1000×1000 JPEG로 바꾼다(P4-01, 이미 구현됨). 1024 → 1000이라 화질 차이는 거의 없고 한 장에 약 0.01초다(S1 §4.3).
  - 추천: 설정 해상도 기본값을 2048에서 1024로 바꾼다. 업로드 때 1000×1000으로 줄이는 처리는 그대로 둔다. 나중에 Codex로 이미지를 만들게 되면 크기는 프롬프트 문구가 아니라 Codex 어댑터의 크기 값으로 정한다.

## 결정

| ID | 결정 | 근거 |
|---|---|---|
| D-21 | 썸네일 **생성** 해상도 기본값(`thumbnail.resolutionPx`)을 **1024**로 한다(전에는 2048). 고칠 수 있는 범위 512~4096은 그대로다. **업로드**(⑧) 때 고른 썸네일을 **1000×1000 JPEG**로 맞추는 처리는 그대로 둔다(P4-01, RG-05). 텍스트·비전 엔진별로 크기 문구를 따로 두지 않는다. 썸네일은 엔진 선택과 관계없이 agy가 만든다. 프롬프트 골격의 `{resolution}` 자리는 그대로 두고 1024가 들어간다. 나중에 Codex 등 다른 이미지 공급자를 붙이면 크기는 프롬프트 문구가 아니라 그 어댑터의 크기 값으로 정한다 | Q26·Q27, S1 §0·§4.3(늘 1024², 2048 요청 7회도 1024), R06 §2.4, PRD §8.9 R1(D-16), D-19 |

### 바뀐 것

- **설정 기본값**: `apps/BE/src/modules/settings/defaults/settings.default.json`의 `thumbnail.resolutionPx` 2048 → 1024. 설정 fixture(템플릿 사본 7개)와 ⑤ 설정 조각도 같이 바꿨다.
- **화면**: ⑤ '썸네일 후보' 요약 줄이 '2K' 대신 '1K'를 보인다(요청값 1024). 업로드 화면의 '1000×1000 JPEG'는 그대로다.
- **이미 있는 설치본**: 앱은 저장된 설정 파일을 고치지 않는다. 파일에 `"resolutionPx": 2048`이 적혀 있으면 계속 2048을 요청한다(agy 결과는 어차피 1024, 업로드는 1000×1000). 키가 빠진 파일만 새 기본 1024로 채운다. 오너 PC의 개발 설정 파일도 2048이다(2026-10-03 확인) — 오너가 설정 파일에서 1024로 고치고 SCR-10 '설정 파일 다시 읽기'를 누르면 된다(썸네일 설정 화면 `F-ST-21`은 M2). 이 값은 ⑤ 입력 지문이 아니라서 바꿔도 '재실행 필요'가 생기지 않는다.
