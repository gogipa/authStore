## 1. 평가 기준

### 1.1 오너 확정 기준 (D-01)

| 번호 | 기준 |
|---|---|
| ① | 핵심 가치(자동 소싱 → 등록)에 직접 기여하는가 |
| ② | 없으면 한 건도 등록할 수 없는가 |
| ③ | 나중에 추가해도 작업 흐름이 크게 깨지지 않는가 |

### 1.2 적용 규칙 (원천자료 02에 기록된 원문)

| 분류 | 조건 |
|---|---|
| Must | ②를 만족한다. 또는 ①을 만족하면서 ③을 만족하지 못한다 |
| Should | ①을 만족하고 ③도 만족한다. MVP 직후 우선 추가한다 |
| Could | ①에 간접 기여한다(편의·효율). ③을 만족한다 |
| Won't | ①에 기여하지 않거나, 1인 로컬 사용이라는 전제와 맞지 않는다 |

> 원천자료 04(D-08) 이후 '1인 로컬 사용'은 '설치본 하나를 1명이 로컬에서 쓴다'로 읽는다. 동료 셀러가 각자 설치해 쓰는 것은 이 전제에 맞는다.

### 1.3 AI가 제안한 확장 규칙 (D-11로 승인)

아래 두 규칙은 원천자료 02에 없다. AI가 리서치를 바탕으로 덧붙였다. 오너가 D-11로 [PRD §16 ②-10](03-PRD초안.md)의 추천(모두 승인)을 채택했다.

- **Won't 확장**: 명시된 요구라도 준수 제약(CON)과 충돌하면 Won't로 둔다. 해당 항목은 KW-08, PR-11, RK-12, TG-07이다.
  - CON 자체도 리서치에서 도출한 것이라 오너가 아직 확정하지 않았다.
- **③의 해석(법·플랫폼 준수 기능)**: 다음 두 종류는 Must로 분류했다. 나중에 넣으면 이미 등록한 상품을 모두 소급 수정해야 하거나 되돌릴 수 없어서, ③을 만족하지 못한다고 보았다.
  - 모든 상품에 매번 적용되는 법정·플랫폼 요건: 구매대행 고지, 어린이 인증 카테고리 차단, 실존 인물 가드레일, 원산지 확정
  - 되돌릴 수 없는 제재를 막는 장치: 중복 등록 방지
  - 가끔 생기는 오류를 잡는 검출 장치(문구 린터, 가품 플래그)는 Should로 두었다. 오너 검토가 1차 통제이기 때문이다.

> ⚠️ **Must 과적 경고**: 45/105 = 42.9%로 기준 40%를 넘는다. D-16으로 AI-10(AI 엔진 선택)이 Must로 더해졌다(v0.4.1은 44/104 = 42.3%). 그 전에 D-11로 ②-7 추천(PR-03 환율 자동, CT-07 상품명 자동)을 채택해 2개가 올랐다(v0.4는 42/104 = 40.4%, v0.3.1은 42/103 = 40.8%).
>
> - **초과 사유(v0.3.1)**: 오너가 PRD §16 ②-16에서 추천안을 골랐다(D-07, 2026-09-27, 원문 "추천대로 하자"). 라쿠텐 URL 입구를 MVP에 넣기로 해서 RK-02를 Should에서 Must로 올렸다. D-01 규칙만 보면 Should(③ 충족)지만, MVP 범위는 오너가 정한다.
> - v0.3에서는 41/103 = 39.8%로 기준 안이었다. 다만 v0.2(41/101 = 40.6%, 과적 경고)보다 **Must 범위가 줄어서가 아니라, 요구사항 수가 늘어서(GEN-07·GEN-08) 낮아진 것**이었다. GEN-02·03의 M1 구현량은 오히려 늘었다.
>
> - **v0.2 과적의 원인**
>   - 오너의 프로세스가 9단계 파이프라인이라, 단계마다 최소 기능이 하나씩은 있어야 한다.
>   - 검토에서 드러난 역마진·초상권·중복 위험을 막으려고, 새 Must ID를 만들지 않고 기존 Must 항목의 M1 범위를 넓혔다. 이 방식으로 강화한 항목은 PR-06, RK-06, IM-03, RG-08, RG-09다.
>   - TG-02(추천 태그)를 Must로 올렸다.
> - **v0.3(원천자료 03)도 새 Must ID를 만들지 않았다.** 단계 실행의 골격(연속 실행·단계 실행, 단계 상태, 입력 지문, '재실행 필요' 전파)은 기존 Must인 GEN-02·GEN-03의 범위를 넓혀 담았다. 나중에 넣으면 상태 모델과 데이터 모델을 다시 만들어야 해서 ③을 만족하지 못한다. 그만큼 M1 구현량은 늘었다. 직접 입력 입구(GEN-07)는 Should, CLI(GEN-08)는 Could다.
> - **v0.4(원천자료 04)도 새 Must ID를 만들지 않았다.** 동료 셀러 배포에 대비한 설계 제약(오너 값 분리, 안전장치 끌 수 없음, 사용자 데이터 외부 전송 없음)은 기존 Must인 GEN-01의 범위를 넓혀 담았다. 나중에 넣으면 설정·데이터 구조를 다시 짜야 해서 ③을 만족하지 못한다. 배포 패키지·설치 안내(GEN-09)는 Should다.
> - **v0.4.3(원천자료 08)은 새 Must ID(AI-10)를 만들었다.** 오너가 엔진 선택과 별도 설정 페이지를 직접 요청했다(D-16). 엔진을 고를 수 없으면 `claude` 구독이 없는 동료 셀러는 앱을 쓸 수 없다. 작업별 엔진 지정·자동 대체는 AI-09(Should)에 남겼다.
> - **안전장치는 내리지 않는다**: 비율을 맞추려고 되돌릴 수 없는 제재를 막는 장치(RG-12, IM-07 등)를 내리지는 않는다.
> - D-11로 §5의 안건은 모두 추천대로 정해졌다. 비율을 낮추거나 M1 구현량을 줄이려면 [§4 재검토 후보](#4-must-재검토-후보)를 본다.
