## E1. 키워드 발굴

### US-01 데이터랩 신발 인기검색어 수집
- **As a** 오너, **I want** 데이터랩 여성신발·남성신발 인기검색어(최근 1개월)를 버튼 한 번이나 붙여넣기로 모으고, **So that** 지금 수요가 있는 신발 키워드를 빠르게 찾을 수 있다.
- AC
  1. '수집'을 누르면 선택한 cid마다 기본 상위 100위를 순서대로 모은다. 기간은 어제(KST)가 종료일인 1개월이고, 요청 간격은 2초 이상이다. `[KW-01/Must]`
  2. 응답에 키가 없거나 404, JSON 아님, 403·418·429가 나오면 즉시 멈추고 '데이터랩 구조 변경 의심' 경고와 붙여넣기 입력란을 보여 준다. 빈 `ranks`는 정상 종료로 처리한다. `[KW-01/Must]`
  3. 데이터랩 화면에서 복사한 '순위 + 키워드' 텍스트를 붙여 넣으면 같은 형식의 키워드 목록이 만들어진다. `[KW-01/Must]`
- 관련: KW-01, KW-02, CON-03, CON-05

### US-02 키워드 선별
- **As a** 오너, **I want** 키워드를 일반어·브랜드·브랜드+모델로 나누고 국내 전용 브랜드와 아동화 키워드를 걸러 보고, **So that** 라쿠텐에서 같은 상품을 찾을 수 있는 키워드만 고를 수 있다.
- AC
  1. 아동화 키워드(키즈·주니어·아동 등)는 기본적으로 목록에서 빠지고, '제외됨' 필터로만 볼 수 있다. `[CON-08/제약]`
  2. 키워드 목록에서 시작할 때는 키워드를 하나 이상 골라야 '라쿠텐 소싱으로' 버튼이 켜진다. 키워드 없이 검색어를 직접 넣어 시작하는 방법은 US-04에 있다. `[KW-05/Must]`
  3. 키워드마다 분류 태그가 붙는다. 브랜드 사전에서 '국내 전용'이나 '판매 제외'인 키워드는 흐리게 표시된다. `[KW-04/Should]`
- 관련: KW-03, KW-04, KW-05, CON-08

### US-03 라쿠텐 검색어 변환
- **As a** 오너, **I want** 고른 한국어 키워드가 라쿠텐 검색어(브랜드 일본어·영문 + 型番)로 바뀌어 제안되기를 원하고, **So that** 일본어를 몰라도 라쿠텐 검색을 바로 시작할 수 있다.
- AC
  1. 검색어 편집 칸이 있고, 오너가 직접 입력하거나 고친 뒤 검색할 수 있다. `[RK-01/Must]`
  2. 브랜드 사전에 있는 브랜드는 사전 표기로 바꿔 제안한다(예: 뉴발란스 → ニューバランス). `[KW-06/Should]`
- 관련: KW-06, RK-01, CON-13

## E2. 소싱·가격 판정

### US-04 라쿠텐 최저가 후보 비교
- **As a** 오너, **I want** 기준 상품(앵커)과 같은 모델·색상만 남긴 라쿠텐 후보를 실질가와 목표 사이즈 재고로 비교하고, **So that** 재고 있는 가장 싼 상품을 고를 수 있다.
- AC
  1. 검색 결과에서 기준 상품 1개와 색상을 고르거나 型番+색상 코드를 입력하면, 나머지 결과가 '일치 / 확인 필요 / 불일치'로 나뉜다. 일치가 20개보다 적으면 2페이지까지 본다. `[RK-01·RK-03/Must]`
  2. 일치 후보를 API 가격순으로 차례로 페이지 조회한다. 재고 기준을 통과한 후보가 3개가 되거나 10페이지에 닿으면 멈춘다. 조회하지 않은 행은 '미검증'으로 표시되고 고를 수 없다. 그 행에서 '재고 확인'을 누르면 그 페이지만 조회한다. `[RK-04/Must]`
  3. 검증을 마친 행만 실질가(SKU가 + 송료 − 쿠폰 − 포인트 × k_rank) 오름차순으로 다시 정렬되고, 각 항목이 분해돼 보인다. `[RK-06·RK-09/Must]`
  4. 선택 색상에서 목표 사이즈 재고가 최소 기준(기본 3개 사이즈)보다 적은 후보는 '재고 부족'으로 빠진다. `[RK-05/Must]`
  5. 키워드를 고르지 않고 검색어를 직접 넣어도 같은 검색·비교를 시작할 수 있다. 이 경로에도 `genreId`·`NGKeyword`와 상품명 아동화 필터가 적용된다. 고른 상품의 전체 사이즈 최댓값이 235mm(설정) 이하면 '아동화 의심'으로 멈추고, '성인용 상품 확인'을 받아야 진행된다(CON-08). `[RK-01/Must]`
- 관련: RK-01, RK-03, RK-04, RK-05, RK-06, RK-09, RK-10, RK-11, NFR-05

### US-05 쿠폰·송료 반영
- **As a** 오너, **I want** 후보마다 쿠폰과 송료를 반영하고, **So that** API에 없는 할인과 비용까지 넣어 최저가를 정확히 판단할 수 있다.
- AC
  1. 후보 행마다 쿠폰 금액(엔) 입력 칸이 있다. 입력하면 실질가와 순위가 즉시 다시 계산된다. `[RK-06/Must]`
  2. 송료 별도(`postageFlag=1`이면서 `postageIncluded=false`) 상품에는 기본 송료가 적용되고 '송료 추정' 배지가 붙는다. 0으로 계산되지 않는다. `[RK-06/Must]`
  3. 쿠폰 %·최소 금액·병용 여부와 송료를 직접 입력할 수 있다. `[RK-07·RK-08/Should]`
- 관련: RK-06, RK-07, RK-08

### US-06 라쿠텐 URL로 소싱
- **As a** 오너, **I want** 라쿠텐 사이트에서 직접 찾은 상품 URL을 붙여 넣어 후보로 쓰고, **So that** API를 쓸 수 없을 때도, 이미 찾아 둔 상품을 바로 작업하고 싶을 때도 소싱을 이어 갈 수 있다.
- AC
  1. URL을 붙여 넣으면 API 후보와 같은 형식으로 사이즈별 재고·가격·속성을 가져오고, 식별자는 `itemCode` 형식으로 정규화된다. 아동화 신호(상품명·사이즈 범위·장르)를 검사하고, 전체 사이즈 최댓값이 235mm(설정) 이하면 '아동화 의심'으로 멈춘다. 상품명에 제외어(中古·箱のみ 등)가 있으면 후보가 만들어지지 않는다. 장르가 신발(靴) 밖이거나 장르를 얻지 못하면 '성인용 상품 확인'을 체크해야 진행된다. `[RK-02/Must]`
  2. 비교표에 넣은 URL 행은 출처가 '수동'으로 표시된다. `[RK-02/Must]`
  3. '바로 후보 만들기'를 고르고 색상을 고르면 그 상품을 앵커로 후보가 만들어지고, '비교 안 함' 배지가 붙는다. 이 후보에서 원하는 단계(예: 썸네일)를 바로 실행할 수 있다. ② 소싱을 '검색·비교'로 다시 실행하면 이 상품을 앵커로 비교한다. G2는 비교를 했거나 '비교 없이 확정'을 체크해야 통과하고, 이 선택은 최종 승인 화면에 보인다. `[RK-02/Must]`
  4. URL 입구와 재조회의 페이지 조회는 하루 조회 상한에 합산된다. `[RK-02/Must]`
  5. 장르를 얻지 못한 URL 후보도 ④에서 성별에 맞는 신발 리프 카테고리 목록(아동 카테고리 제외)에서 골라 진행할 수 있다. `[RG-04/Must]`
- 관련: RK-02, RK-04, RG-04, GEN-07, CON-08

### US-07 국내 기준가 입력
- **As a** 오너, **I want** 직접 확인한 국내 최저가(또는 셀러라이프 셀라파인더 결과)를 넣고, **So that** "국내보다 싸면 판다"는 판정을 할 수 있다.
- AC
  1. 키워드·모델별 네이버쇼핑 검색 링크가 새 탭으로 열린다. 이 링크는 라쿠텐 데이터가 보이는 영역과 분리된 입력 영역에 둔다. `[PR-05/Must, CON-14]`
  2. 오너가 입력한 기준가(판매가 + 배송비 총액)에는 출처 URL과 입력 시각이 함께 저장된다. `[PR-05/Must]`
  3. 셀라파인더 엑셀을 올리면 型番이 맞는 국내 상품 후보가 나오고 오너가 하나를 고른다. `[PR-05 확장/Should]` (M0에서 샘플을 확보한 뒤 구현)
- 관련: PR-05

### US-08 마진 판정과 권장 판매가
- **As a** 오너, **I want** 사이즈별로 원가·배송비·관부가세·수수료·부가세를 반영한 최소 판매가와 권장 판매가를 보고, **So that** 어느 사이즈에서도 역마진 없이 팔 수 있다.
- AC
  1. 비용 분해표(원가, 배대지, 관부가세, 판매·Npay 수수료, 부가세 모드 A·B, 기타)와 순이익·마진율이 보인다. 가정값(기본 배대지 비용·송료)을 쓴 항목에는 배지가 붙는다. `[PR-01·PR-02·PR-06/Must]`
  2. 사이즈마다 면세·과세가 따로 판정되고, 과세 사이즈에는 관부가세 예상액이 원가에 들어간다. '2켤레 주문 시 과세 전환' 여부도 표시된다. M1은 과세 사이즈를 팔지 않으므로(D-11 ①-1) 과세 사이즈는 예상액만 보여 주고 판매 불가로 뺀다. `[PR-04/Must]`
  3. `P_min_i ≤ P_ref × (1 − δ_judge)`인 사이즈만 '판매 가능'이다. 판매가는 가격 책정 규칙대로 정해지며 모든 판매 가능 사이즈의 `P_min_i` 이상이다. 모드 B 기준 순이익이 0 미만인 사이즈는 판매 불가로 빠지고, 남은 사이즈 수가 최소 기준보다 적으면 후보가 '제외'된다. 제외 사유가 표시된다. `[PR-06/Must]`
- 관련: PR-01, PR-02, PR-04, PR-06, PR-07

### US-09 비용 파라미터·환율 관리
- **As a** 오너, **I want** 수수료율, 배대지 요금표, 카드 가산율, 목표 마진, 환율을 관리하고, **So that** 정책이나 환율이 바뀌어도 코드를 고치지 않고 판정을 맞출 수 있다.
- AC
  1. MVP에서는 설정 JSON을 고치면 앱을 켤 때 스키마로 검증된다. 오류가 있으면 화면에 어느 값이 틀렸는지 나온다. `[PR-02/Must]` (전체 설정 화면은 GEN-04, Should)
  2. 환율은 값, 단위, 출처, 기준 시각과 함께 저장되고, 수동으로 입력할 수 있다. `[PR-02/Must]`
  3. 환율은 자동으로 수집된다. 실패하면 마지막 값을 쓰고 경고가 뜬다. `[PR-03/Must]`
  4. 배대지 요금표를 CSV로 가져오면 무게 구간별 요금과 요금표 버전이 반영된다. `[PR-02/Must]`
- 관련: PR-02, PR-03, PR-10, OP-06, GEN-04

### US-10 판매가 시뮬레이션
- **As a** 오너, **I want** 판매가를 바꿔 보며 마진을, 목표 마진을 넣어 판매가를 계산하고, **So that** 가격 전략을 빠르게 정할 수 있다.
- AC
  1. 판매가를 입력하면 순이익과 마진율이 즉시 바뀐다. `[PR-08/Should]`

### US-30 성별·카테고리 확정

### US-12 AI 썸네일 생성

## E4. 태그

### US-18 manuTag 기반 태그 10개 선정

- AC
  1. 시드 키워드·모델명·상품유형으로 `recommend-tags` 결과가 자동으로 나온다. `[TG-02/Must]`
  2. 셀라파인더 엑셀이나 붙여 넣은 텍스트·JSON에서 태그를 뽑아 입력 순서(빈도가 있으면 빈도순)로 보여 준다. 원본 붙여넣기는 저장되지 않는다. `[TG-01/Must]`

  4. 태그마다 점수가 표시되고, 기준 점수 미만은 제외된다. `[TG-03/Should]`
  5. 경쟁 태그를 넣지 않아도 추천 태그만으로 최종 태그가 만들어진다. `[TG-04/Must]`
- 관련: TG-01, TG-02, TG-03, TG-04

## E5. 승인·등록

### US-20 최종 승인 후 등록
- **As a** 오너, **I want** 등록될 상품 전체를 한 화면에서 확인하고 승인할 때만 스마트스토어에 등록되게 하고, **So that** 내 승인 없이 잘못된 상품이 판매되지 않게 할 수 있다.
- AC
  1. 이미지 업로드(⑧) 단계를 실행하면 이미지가 직렬로 업로드되고(이미 올린 같은 이미지는 다시 올리지 않음), 자리표시자가 업로드 URL로 바뀐 최종 상세 미리보기가 그려진다. 승인 화면을 열 때와 승인 직전에 최종 태그가 `restricted-tags`로 다시 검증된다. `[RG-05·TG-04/Must]`
  2. 로컬 검증(필수 필드, 옵션 재고 합·중복 옵션명 없음, 태그 10개 이하, 고지 블록 해시, 원산지 확정, 판매국·제조국 혼동 문구 없음, 모드 B 역마진 없음, 판매가·배송비 밖 비용 청구 표현 없음, 판정에 쓴 라쿠텐 페이지를 받은 뒤 6시간 이내, 단계 최신성, 대표이미지 출처·색상 확인, 고시 사이즈 = 옵션 사이즈, 원산지 근거가 현재 상품의 것)을 통과해야 '승인·등록' 버튼이 켜진다. 6시간을 넘었으면 '재조회' 버튼으로 페이지를 다시 읽고 다시 판정해야 한다. 판정만 다시 실행해서는 이 시간이 초기화되지 않는다. `[RG-08/Must]`
  3. 승인하면 이미 업로드한 URL로 상품 등록 API가 호출된다. 성공하면 상품 번호가 저장되고, 실패하면 한국어 오류와 Trace-ID가 보인다. `[RG-09/Must]`
  4. 응답이 타임아웃이나 5xx면 자동으로 재시도하지 않고 '결과 확인 필요'가 된다. 다시 등록하기 전에 판매자관리코드로 조회해, 이미 등록됐으면 그 상품을 연결한다. `[RG-09/Must]`
  5. 처음 10건은 전시중지로 등록되고 이후로는 즉시 전시된다. 전시중지 상품은 M1에서는 스마트스토어센터에서 켠다. `[RG-09/Must]` 앱에서 켜는 기능은 이후 단계에 추가된다. `[RG-10/Should]`
- 관련: RG-05, RG-06, RG-08, RG-09, RG-10, CON-02

## E7. 기반(설정·AI·안정성)

### US-27 온보딩과 사전조건 점검

  1. 처음 실행할 때 키 입력 화면(또는 CLI 명령)으로 비밀정보를 받아 macOS 키체인에 저장한다. `.env`에는 비밀정보가 없다. `[NFR-02/Must]`

  3. 항목마다 '확인됨 / 미확인 / 실패'와 해결 방법 링크가 보이고, 자격증명 만료 30일 전과 7일 전에 경고한다. `[GEN-05/Should]`
  4. 공인 IP가 커머스API·라쿠텐 등록 IP와 다르면 경고가 뜬다. `[RG-02/Should]`
- 관련: GEN-05, NFR-02, RG-01, RG-02

### US-28 AI 엔진 설정과 상태
- **As a** 오너, **I want** 각 AI CLI의 상태와 사용량을 보고 작업마다 어떤 AI를 쓸지 정하고, **So that** 구독 한도나 장애에 맞춰 엔진을 바꿀 수 있다. 앱 전체에 쓰는 AI 엔진 하나를 고르는 방법은 US-38에 있다.
- AC
  1. 모든 AI 호출은 전용 빈 작업 디렉터리와 환경변수 화이트리스트로 실행되고, 결과는 스키마로 검증된다. `[AI-01·AI-02/Must]`
  2. 앱을 켜면 CLI마다 설치 여부, 버전, 인증, 스모크 테스트 결과가 표시된다. `[AI-07/Should]`
  3. 작업 유형별 우선순위를 바꾸면 다음 호출부터 적용된다. 1순위가 실패하면 2순위로 넘어간다. `[AI-09/Should]`
  4. 일일 호출·이미지·비용 상한에 닿으면 큐가 멈추고 알림이 뜬다. `[AI-06/Should]`
- 관련: AI-01~AI-09

### US-29 작업 이어 하기
- **As a** 오너, **I want** 앱을 껐다 켜도 후보마다 멈춘 곳부터 이어서 하고, **So that** 긴 작업을 여러 번에 나눠 할 수 있다.
- AC
  1. 후보 목록에서 후보마다 단계별 상태가 보이고, '이어 하기'를 누르면 '입력 대기'이거나 아직 완료되지 않은 첫 단계의 화면이 열린다. `[GEN-03/Must]`
  2. 연속 실행과 '이어 하기'는 '완료'이고 최신인 단계를 다시 만들지 않는다. 오너가 '다시 실행'을 누르면 입력이 같아도 새로 만든다(새 버전). `[GEN-03/Must]`
  3. 앱이 꺼질 때 실행 중이던 단계는 다시 켜면 '실패(중단됨)'로 보이고, 그 단계만 다시 실행할 수 있다. ⑨ 등록 중이었으면 등록 기록에 따라 '결과 확인 필요'(판매자관리코드 조회부터) 또는 '승인 대기'가 된다. `[GEN-03/Must]`
- 관련: GEN-02, GEN-03, AI-05

### US-33 원하는 단계만 실행
- **As a** 오너, **I want** 후보마다 원하는 단계만 골라 실행하거나 다시 실행하고, **So that** 전체를 처음부터 다시 돌리지 않고 필요한 부분만 고칠 수 있다.
- AC
  1. 후보 작업 화면(SCR-12)에 ②~⑨ 단계(⑥은 ⑥-1~⑥-3을 묶어 표시)와 단계별 상태(미실행·실행중·입력 대기·완료·실패·재실행 필요)가 보인다. 필수 시작 조건이 모두 '완료'인 단계는 흐름 순서와 관계없이 '실행'할 수 있고, 단계 실행은 다음 단계를 자동으로 시작하지 않는다. `[GEN-02/Must]`
  2. '여기부터 연속 실행'을 누르면 고른 단계를 실행한 뒤, 이미 '완료'이고 최신인 단계는 건너뛰며 흐름 순서대로 이어서 실행한다. G2를 통과하기 전에는 판정(③)에서 멈추고, 이 버튼은 ②·③에서만 켜진다. G2 뒤에는 오너 입력을 기다리거나 실패한 단계의 결과를 읽는 단계만 멈추고 나머지는 계속 실행하며, G3·G4에서 멈춘다. `[GEN-02/Must]`
  3. 앞 단계를 다시 실행해 값이 바뀌면, 그 값을 읽은 뒷단계만 '재실행 필요'로 바뀌고 바뀐 입력 이름이 표시된다. 자동으로 다시 실행되지 않는다. 예: 썸네일을 다시 만들어 다른 후보를 고르면 이미지 업로드만 '재실행 필요'가 되고, 카피·태그는 '완료'로 남는다. 국내가만 고쳐 재판정했는데 판매 사이즈가 그대로면 고시·사양 블록은 '완료'로 남는다. `[GEN-03/Must]`
  4. 어떤 단계가 실행 중이면, 그 단계의 결과를 읽는 단계와 그 단계가 읽는 앞 단계의 '실행'·수정 버튼이 꺼지고 사유가 보인다. `[GEN-03/Must]`
  5. 오너가 고친 카피·고시 문구·태그 추가·삭제는 그 단계를 다시 실행해도 지워지지 않는다. 다시 적용한 태그도 규칙 필터와 `restricted-tags` 검증을 다시 거친다. 상품 사실에서 나온 필드(원산지·고시 사이즈 등)의 예외는 US-35에 있다. `[GEN-03/Must]`
  6. 필수 단계 중 미실행·실행중·입력 대기·실패·재실행 필요가 하나라도 있거나, G2·G3 게이트 지문이 바뀌었으면 최종 승인 버튼이 꺼지고 해당 단계로 가는 링크가 보인다. `[RG-08/Must]`
- 관련: GEN-02, GEN-03, RG-08, TG-04

### US-34 직접 입력으로 시작
- **As a** 오너, **I want** 키워드 수집 없이 엔화 가격, 내가 가진 신발 이미지, 상품 설명, 시드 키워드 같은 값을 직접 넣어 원하는 단계를 바로 실행하고, **So that** 궁금한 부분만 빠르게 확인하거나 처리할 수 있다. 라쿠텐 URL로 시작하는 방법은 US-06에 있다.
- AC
  1. 판정 화면에서 사이즈별 엔화 가격·쿠폰·국내 기준가를 직접 넣어 계산할 수 있다. 라쿠텐 상품에 연결하기 전 결과는 '계산 전용'으로 표시된다. 연결한 뒤에도 등록 전에는 라쿠텐 페이지 값으로 다시 판정해야 한다. 성별(목표 사이즈 범위)과 국내 기준가도 넣어야 계산된다. `[GEN-07/Should]`
  2. 직접 올린 이미지는 권리 용도 '참조 전용'으로 저장되고, '사람·얼굴 없음'을 체크해야 레퍼런스로 쓸 수 있다. 이 이미지 자체는 어떤 경로로도 업로드되지 않는다(CON-07). 라쿠텐 상품에 연결하면 G3에서 '같은 상품·색상'을 확인해야 한다. `[GEN-07/Should]`
  3. 설명 텍스트를 붙여 넣을 때 출처 URL을 넣어야 하고, 원산지 근거 발췌는 그 텍스트에서 뽑는다. 원산지를 확정하지 못하면 진행할 수 없다. `[GEN-07/Should]`
  4. 시드 키워드를 직접 넣어 태그 추천을 받을 수 있고, 카테고리를 검색해 고를 수 있다(아동 카테고리는 목록에 없고, 고른 카테고리도 성별 검사를 거친다). `[GEN-07/Should]`
  5. 임시 후보를 라쿠텐 상품에 연결할 때 직접 넣은 값마다 '② 값으로 바꿈'과 '오너 입력으로 유지'를 고른다(엔화 가격은 유지 불가). '오너 입력으로 유지'한 값은 최종 승인 화면에 모아 표시된다. `[GEN-07/Should]`
- 관련: GEN-07, PR-01, IM-01, IM-03, CT-02, TG-02, RG-04, CON-07, CON-08

### US-35 따로 돌려도 어긋나지 않게
- **As a** 오너, **I want** 단계를 따로, 여러 번 다시 실행해도 상품 정보가 서로 어긋난 채 등록되지 않기를 원하고, **So that** 단계별 실행의 편리함 때문에 잘못된 상품을 올리지 않는다.
- AC
  1. 후보 안에서는 다른 型番·색상을 고를 수 없고, 고르려 하면 새 후보 만들기를 안내한다. 같은 모델·색상 안에서 샵을 바꾸면 G2를 다시 통과해야 한다. `[GEN-03/Must]`
  2. 진행 중인 후보에 같은 `itemCode`·색상이 있으면 새 후보를 만들거나 연결하지 않고 그 후보가 열린다. 앵커 키만 같으면 경고가 뜬다. `[GEN-03/Must]`
  3. ⑥-1 카피가 '재실행 필요'이면 바뀐 입력의 차이를 보고 '그대로 유지'를 고를 수 있다. 원산지(⑥-2)·판정·업로드에는 이 선택이 없다. `[GEN-03/Must]`
  4. 샵이나 판매 사이즈가 바뀌면, 오너가 고쳤던 원산지·고시 사이즈 값에 '재확인 필요'가 붙고 다시 확인해야 완료된다. `[GEN-03/Must]`
  5. 판정(G2) 전에 썸네일·카피·원산지 추출을 실행하면 AI 비용 경고가 뜬다(실행은 된다). `[GEN-02/Must]`
  6. SCR-12에서 이전 버전을 보고 다시 고를 수 있고, 고르면 새 버전으로 저장되어 그 값을 읽는 뒷단계에 전파된다. `[GEN-03/Must]`
- 관련: GEN-02, GEN-03, RG-08, RG-12

### US-36 동료 셀러가 내 PC에 설치해 쓰기
- **As a** 동료 셀러, **I want** 오너가 나눠 준 앱을 내 PC에 설치하고 내 스토어·키·AI 구독으로 설정해 쓰고, **So that** 오너와 같은 방식으로 신발 상품을 등록할 수 있다.
- AC
  1. 설치 안내만 보고 설치하고 첫 실행 점검(사전 조건·키·AI CLI 로그인)을 마칠 수 있다. 빠진 사전 조건은 무엇을 어디서 해야 하는지와 함께 표시된다. `[GEN-09/Should]`
  2. 첫 실행 때 이용 고지(무료 배포, 약관·법규 준수와 계정 책임은 사용자에게 있음, 생성형 AI 사용 사전 고지, 기본값이 받아들인 잔여 리스크 목록)를 보고 동의해야 쓸 수 있다. `[GEN-09/Should]`
  3. 오너의 키·설정·작업 데이터가 설치본에 없다. 내 값은 내 PC의 사용자 데이터 폴더와 비밀정보 저장소(NFR-02)에만 저장된다. `[GEN-01/Must]`
  4. 안전장치(최종 승인, 아동화 차단, 실존 인물 차단, 중복 방지, 원본 업로드 거부)를 끄는 설정이 없다. 설정 파일을 고쳐도 내장 차단 목록을 빼거나 기준(아동화 사이즈 기준, 판정 유효 시간)을 완화할 수 없고, 그런 설정은 앱을 켤 때 거부된다. `[GEN-01/Must]`
  5. 앱은 내 데이터를 오너나 다른 곳으로 보내지 않는다. 외부 호출 대상은 허용 목록(커머스API, 라쿠텐, 데이터랩, 환율 API, AI CLI 등)뿐이고, AI CLI는 내 전역 훅·MCP 설정을 읽지 않고 실행된다. M1은 테스트로 호출 대상 호스트와 CLI 실행 인자를 확인한다. `[GEN-01/Must]`
  6. 외부 호출 로그 화면에서 호출 대상을 볼 수 있다. `[NFR-03/Should]`
  7. 새 버전으로 바꿔도 내 설정·작업 데이터가 그대로 남고, 설정 파일은 자동으로 새 형식으로 옮겨진다. 실패하면 이전 상태로 되돌려진다. `[GEN-09/Should]`
- 관련: GEN-01, GEN-05, GEN-09, AI-01, NFR-02, NFR-03, CON-10

### US-37 나눠 줄 설치본 만들기
- **As a** 오너, **I want** 동료에게 줄 설치본에 내 키·설정·작업 데이터가 섞이지 않고 버전이 표시되기를 원하고, **So that** 안심하고 나눠 주고 문제가 생기면 어느 버전인지 알 수 있다.
- AC
  1. 배포 패키지를 만들 때 비밀정보·설정·작업 데이터·로그와 테스트 fixture·녹화 응답이 들어 있지 않은지 검사하고, 들어 있으면 만들지 않는다. `[GEN-09/Should]`
  2. 앱 화면에 버전과 변경 내역이 보이고, 새 버전을 확인하는 방법이 안내된다. 자동 확인은 사용자가 켤 때만 한다. `[GEN-09/Should]`
  3. 오너 개인 값(키·계정, 상호·연락처, 배대지·창고 주소, 요금표, 고지의 배송기간·반품비, 프로필 `importer`, 파일 경로)은 코드와 설치본에 들어가지 않고, 사용자가 첫 실행 때 넣는다. 일반 기본값(PR-02 비용 파라미터 등)은 들어가도 된다. `[GEN-01/Must]`
- 관련: GEN-01, GEN-09, NFR-02

### US-38 AI 엔진 고르기
- **As a** 오너(또는 동료 셀러), **I want** 앱이 쓸 AI 엔진을 Claude Code·Antigravity CLI·Codex 중에서 고르고, **So that** 내가 가진 구독으로 앱을 쓸 수 있다.
- AC
  1. 설정 아래 'AI 엔진' 페이지(SCR-13)에서 세 엔진의 설치·로그인·연결 테스트 상태를 보고, 엔진 하나와 모델을 고른다. `[AI-10/Must]`
  2. 연결 테스트를 통과한 엔진만 저장되고, 저장 뒤 새로 시작하는 AI 단계부터 그 엔진을 쓴다. 진행 중인 실행과 이미 만든 결과는 그대로다. `[AI-10/Must]`
  3. 선택한 엔진을 쓸 수 없으면 AI 단계는 다른 엔진으로 넘어가지 않고 멈추며, AI 엔진 페이지로 가는 길을 보여 준다. `[AI-10/Must]`
  4. 결과마다 어떤 엔진·모델·CLI 버전으로 만들었는지 남는다. `[AI-10/Must]`
- 관련: AI-10, AI-01, AI-02, AI-05, AI-07, CON-11, GEN-09
