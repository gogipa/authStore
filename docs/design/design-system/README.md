라쿠텐에서 신발을 골라 네이버 스마트스토어에 올리는 1인 셀러의 **작업대**다. 화면은 읽는 곳이 아니라 확인하고 누르는 곳이다. 사장님은 가격표·사이즈표·단계 상태를 빠르게 훑고, 멈춘 곳만 손본다. 그래서 장식보다 정확한 칸을, 색보다 단어를 먼저 쓴다.

## 글

- 화면의 말은 한국어로, 셀러가 아는 말로 쓴다. 개발 용어 대신 "재실행 필요", "입력 대기", "최종 승인", "국내 기준가"처럼 쓴다.
- 버튼은 무엇이 일어나는지 동사로 쓴다: "실행", "다시 실행", "여기부터 연속 실행", "승인·등록", "재조회". 결과 알림은 끝난 일로 쓴다: "등록했습니다", "3개 사이즈를 다시 판정했습니다".
- 오류는 무엇이 막혔고 어떻게 푸는지 쓴다: "국내 기준가가 비어 있어 판정할 수 없습니다. 국내 기준가를 넣어 주세요." 사과하거나 흐리게 쓰지 않는다.
- 꺼진 버튼은 꺼진 이유를 **보이는 글**로 버튼 옆에 쓴다: "판정(G2)을 통과해야 승인할 수 있습니다". 툴팁에만 숨기지 않는다.
- 숫자 표기: 원은 `167,300원`, 엔은 `¥12,000`, 사이즈는 `255mm`, 비율은 `10%`, 시각은 `14:02`. 가격·수량은 `num` 스타일로 쓰고 표에서는 오른쪽 정렬한다.
- AI가 만든 결과(썸네일 후보, 카피 초안, 규칙으로 못 찾아 AI가 뽑은 원산지·소재 값, 색상 한국어 표기 보조, AI가 바꾼 검색어)에는 항상 'AI 생성' 칩을 붙인다. 템플릿이나 규칙으로 만든 값(상품명 제안, 상품 속성에서 읽은 원산지)에는 붙이지 않는다. 상품명 제안에는 '템플릿 제안' 칩을 쓴다.
- 이모지는 쓰지 않는다.

## 색

- 지금은 **라이트 테마만** 쓴다. 다크 테마는 나중에 만든다. `tokens.json`의 다크 값은 그때 쓰려고 남겨 둔 것이다. 화면 코드에는 색 값을 직접 적지 말고 토큰 이름으로만 쓴다. 그래야 다크 테마를 붙일 때 화면 코드를 고치지 않는다.
- 바닥은 `bg`, 카드·표·패널·입력칸은 `surface`, 표 머리·잠긴 입력칸·ID 칩은 `surface-sunk`다. 구분선은 `line`, 입력칸 테두리는 `line-strong`이다.
- 글자는 `ink`(본문·제목), `ink-muted`(보조), `ink-faint`(캡션·시각·단위)를 쓴다. `ink-faint`는 `bg`와 `surface` 위에만 올린다.
- `accent`는 한 화면의 주 버튼 하나, 링크, 선택 표시, 포커스 링, '실행중' 상태에만 쓴다. 채운 `accent` 위의 글자는 `on-accent`다.
- 단계 상태는 여섯 가지이고, **색·단어·아이콘**을 항상 함께 쓴다.

| 상태 | 글자·아이콘 | 칩 바탕 | 아이콘 |
|---|---|---|---|
| 완료 | `done` | `done-soft` | 체크 |
| 실행중 | `running` | `accent-soft` | 도는 원호 |
| 입력 대기 | `waiting` | `waiting-soft` | 멈춤 막대 두 개 |
| 재실행 필요 | `rerun` | `rerun-soft` | 되돌림 화살표 |
| 실패 | `failed` | `failed-soft` | 느낌표 삼각형 |
| 미실행 | `idle` | `surface-sunk` | 빈 원 |

- 역마진·차단된 검사·삭제는 `failed`, 경고(오래됨·확인 필요)는 `waiting`이다. 통과한 검사는 `done`이다. 초록과 빨강을 색으로만 구분하지 않는다.

## 글자

- 화면 글자는 `sans`(IBM Plex Sans KR) 하나로 쓰고, 가격·수량·ID·코드는 `mono`(IBM Plex Mono)로 쓴다.
- 화면 제목은 `title`, 패널 제목은 `heading`, 본문과 표 셀은 `body`, 강조와 버튼 글자는 `body-strong`, 시각·출처는 `caption`, 필드 라벨·표 머리·상태 칩은 `label`이다.
- 가격·수량·비율은 `num`, itemCode·앵커 키·기능 ID는 `id`다. `display`는 대시보드의 요약 수치 한두 개에만 쓴다.

## 간격과 모양

- 4px 격자를 쓴다. 패널 안쪽은 `space-4`, 섹션 사이는 `space-6`, 화면 가장자리는 `space-8`, 표 셀 좌우는 `space-3`이다.
- 표 행 높이는 40px로 촘촘하게 둔다. 주요 버튼은 높이 36px, 표 안 버튼은 32px이다.
- 모서리는 칩·입력칸·표 안 버튼에 `radius-sm`, 버튼·패널·카드에 `radius-md`, 대화상자에 `radius-lg`를 쓴다.
- 그림자는 메뉴·대화상자처럼 떠 있는 것에만 `shadow-pop`을 쓴다. 패널은 `line` 테두리로 나눈다. 카드 왼쪽에 색 띠를 두르지 않는다.

## 화면 틀

- 왼쪽 내비(폭 220px)는 대시보드, 키워드, 후보 작업, 등록 상품, 설정, 시스템 상태 순서다.
- 후보 작업 화면은 세 부분이다. 위쪽 후보 머리(상품명, 앵커 키, 게이트 통과 상태), 왼쪽 단계 레일(② 소싱 ~ ⑨ 등록), 오른쪽 단계 본문이다.
- 단계 본문 맨 위에는 상태 줄(상태 칩, 마지막 실행 시각, 입력 출처)과 '실행'·'다시 실행' 버튼을 둔다. '재실행 필요'이면 바뀐 입력 이름을 같은 줄에 쓴다.
- 게이트(G1~G5)는 마름모 기호와 이름으로 표시한다. 통과 전에는 다음 버튼 옆에 막힌 이유를 한 줄로 쓴다.
- 오너가 고친 값에는 '직접 입력' 칩을, 다시 확인해야 하는 값에는 `waiting` 색의 '재확인 필요' 칩을 붙인다.

## 아이콘

- 24px 격자에 선 굵기 1.5px인 선 아이콘을 쓰고, 16px 또는 20px로 줄여 쓴다. 채운 일러스트와 이모지는 쓰지 않는다.
- 로고는 아직 없다. 앱 이름 '신발 자동등록'을 `heading` 글자로 쓴다.

## 접근성

- 포커스 링은 `accent` 2px 실선이고, 요소에서 2px 떨어뜨린다.
- 누르는 것은 모두 진짜 `button`, `a`, `input`으로 만든다. 아이콘만 있는 버튼에는 `aria-label`을 단다.
- 글자는 바탕 위 4.5:1 이상, 입력칸 테두리와 의미 있는 아이콘은 3:1 이상이다.
