## 2. 디자인 방향

- '작업대': 사장님이 가격표·사이즈표·단계 상태를 빠르게 훑고, 멈춘 곳만 손보는 도구. 장식보다 정확한 칸, 색보다 단어.
- **라이트 테마만** 만든다(D-13). 다크 테마 값은 [tokens.json](design-system/tokens.json)에 나중용으로 남겨 두었다.
- 글꼴: IBM Plex Sans KR(화면 글), IBM Plex Mono(가격·수량·ID).
- 단계 상태 6가지(완료·실행중·입력 대기·재실행 필요·실패·미실행)는 색·단어·아이콘을 항상 함께 쓴다.
- AI가 만든 결과에는 'AI 생성' 칩을 붙인다. 템플릿이나 규칙으로 만든 값(상품명 제안, 상품 속성에서 읽은 원산지)에는 붙이지 않는다.
- 자세한 원칙: [design-system/README.md](design-system/README.md)

## 3. 화면 구조

- 모든 화면: 왼쪽 내비(220px, 맨 위 앱 이름 '스마트스토어 정복' — D-28) + 본문. 화면 제목 옆에 화면 ID(SCR-xx)를 보이지 않는다(D-27). 화면 ID는 문서에서만 쓴다. 내비 순서는 대시보드 → 키워드 → 후보 작업 → 등록 상품 → 설정 → 시스템 상태 → 사용 안내. '설정' 바로 아래에 들여쓴 하위 항목 'AI 엔진'(SCR-13)이 있다. 맨 아래 '사용 안내'(SCR-14)는 D-29로 더했고 보드에는 없다([명세 §8](spec/화면시안_명세.md)).
- 단계 화면(② ~ ⑨): 위에 후보 머리(상품명·앵커 키·게이트), 왼쪽에 단계 레일(260px), 오른쪽에 단계 본문. 단계 화면은 내비가 아니라 후보 작업 → 단계 레일에서 연다. 내비의 현재 항목은 '후보 작업'이다.
- 단계 본문 맨 위에는 상태 줄(상태 칩, 마지막 실행, 입력 출처, '다시 실행'·'여기부터 연속 실행')이 있다.
- 공통 부품 마크업(내비, 후보 머리, 단계 레일, 상태 칩, 게이트, 버튼): [spec/공통부품_마크업.md](spec/공통부품_마크업.md)

## 5. 예시 데이터

시안 속 상품·가격·재고·시각은 모두 예시다. 실제 상품이나 판매 기록이 아니다. 값은 [spec/화면시안_명세.md](spec/화면시안_명세.md) §4에 있고, 가격 계산은 PRD §8.3의 '테스트 기대값'과 같다.

- 단계 화면 여섯 장은 모두 같은 후보(아식스 젤카야노 14 · 크림/블랙)가 최종 승인 직전인 상태다: ②~⑧ 완료, ⑨ 미실행, G2·G3 통과, G4 확인 필요.
- 후보 작업 화면만 다른 후보(뉴발란스 530, ③ 판정 입력 대기)를 골라 둔 상태다. '입력 대기'와 게이트 잠금 모양을 보여 주려는 것이다.
- 판매가 167,300원(국내 기준가 169,000원 × 0.99), 최소 판매가 153,100원, 순이익 27,418원 · 16.4%(모드 A), 모드 B 순이익 16,259원.
- AI 엔진(오너 PC 실측, 2026-09-27): Claude Code `claude` 2.1.269 사용 중(텍스트·비전 `sonnet`, 로그인됨, 연결 테스트 통과 12.7초), Antigravity CLI `agy` 1.2.9(로그인은 연결 테스트로 확인, 아직 테스트 안 함, 텍스트 `gemini-3.8-flash-medium`·비전 `gemini-3.8-flash-high`), Codex `codex` 설치 안 됨.

## 6. 시안을 그리며 정한 것

PRD에 적혀 있지만 화면으로 옮기며 해석이 필요했던 곳이다. 오너 위임(D-11)에 따라 정했고, 고칠 곳이 있으면 짚어 주면 된다.

| # | 정한 것 | 근거 |
|---|---|---|
| 1 | 승인대기 후보는 ⑧ 이미지 업로드까지 끝난 상태다. 최종 승인 화면의 미리보기는 업로드한 이미지로 만든 최종본이다 | PRD §8.7 차단 스위치 설명("이미지는 ⑧에서 이미 올라가 있다"), 승인대기 조건(필수 단계 ②~⑧ 완료) |
| 2 | 등록 API 차단 스위치가 켜진 채 승인하면 등록하지 않고 요청 내용과 검증 결과만 저장해 '검증완료'로 둔다. 시안의 후보는 아직 승인 전이다 | PRD §5.2 후보 상태도, §8.7 |
| 3 | 목표 마진은 부가세 모드 A로 계산하고, 모드 B(총액 과세) 순이익이 0원 이상인지 따로 검사한다. 판정 화면과 설정 화면이 같은 말을 쓴다 | PRD §8.3 파라미터 표(셀러 부가세 모드) |
| 4 | '러닝화'처럼 카테고리 리프 이름과 같은 태그는 규칙으로 빠진다. 예시 최종 태그는 '조깅화'로 바꾸고, 뺀 태그 목록에 '러닝화'를 보였다 | PRD §8.6 규칙 필터(카테고리 경로 토큰) |
| 5 | 상품명 제안에는 'AI 생성'이 아니라 '템플릿 제안' 칩을 붙인다. 상품 속성에서 읽은 원산지·소재에도 AI 칩을 붙이지 않는다 | PRD §5.3 ⑥-3 "AI를 쓰지 않는다", F-CT-09 규칙 추출 |
| 6 | 썸네일의 얼굴 노출 옵션은 '전체(기본) / 턱 아래 크롭 / 손·상반신만'이다 | PRD §16 ①-4, F-TH-11 |
| 7 | 후보 작업 화면의 후보 머리 오른쪽 버튼은 '후보 목록' 대신 '후보 제외'다(같은 화면을 가리키는 링크가 되므로) | F-CW-06 |
| 8 | 좁은 표 칸에서는 꺼진 버튼의 이유를 행마다 쓰지 않고 바로 위 게이트 줄에 한 번 쓴다 | 디자인 시스템 README(꺼진 이유는 보이는 글로) |
| 9 | 시스템 상태 화면의 키 입력 칸은 값을 보여 주지 않고 '키체인에 저장됨'과 '다시 넣기'만 둔다 | NFR-02, 보안 제약 |
| 10 | 'AI 엔진'은 모든 보드의 내비에서 '설정' 아래 들여쓴 하위 항목(높이 32px, 13px)이다. AI 엔진 화면에서는 이 하위 항목만 현재 항목이다 | D-16 R4 |

| 13 | 설치되지 않은 엔진(예시: Codex)은 카드는 보이되 라디오·모델 칸·[연결 테스트]를 끄고, 꺼진 이유와 설치·로그인 명령을 카드 안에 쓴다 | D-16 R5, F-ST-32 |
| 14 | 시스템 상태 화면은 AI 도구 상태(세 엔진 + 이미지 생성)와 첫 실행 점검 패널이 늘어 보드 높이를 1100 → 1200px로 키웠다 | F-SY-13, F-SY-23 |

## 7. 그리지 않은 것

- 단계 화면을 후보 없이 열었을 때 나오는 '입력 고르기' 패널(F-CW-22, M1). 개발 때 후보 머리 자리에 둔다.
- 실행중·실패·재실행 필요 상태의 단계 화면. 이 상태들은 후보 작업·대시보드 목록에서만 보인다. 상태 줄과 칩 모양은 같다.
- 오류·중복 등록 때의 최종 승인 화면(F-AP-31·33·37).
- 첫 실행 이용 고지 화면(GEN-09, M2).
- AI 엔진을 쓸 수 없어 멈춘 AI 단계(F-BS-76). 상태 줄의 실패 칩 옆에 'AI 엔진 설정으로' 링크를 둔다.
- AI 엔진 카드의 연결 테스트 실행중·실패 상태. 카드의 '연결 테스트' 줄에 실행중·실패 칩과 오류 이유를 쓴다.
- 'AI 생성' 칩에 엔진 이름을 붙인 표기(예: 'AI 생성 · Claude Code', D-16 R11). 기존 보드의 칩은 아직 'AI 생성'만 적었다.
- AI 엔진 화면 맨 아래의 읽기 전용 '저장 공간' 패널(D-25, `F-ST-33` — agy 기록·앱 이미지 폴더 크기, 디스크 남은 공간). 보드는 캔버스 사본이라 고치지 않았다. 자리·문구·상태는 [화면시안_명세](spec/화면시안_명세.md) SCR-13 D-25 절에 있다.

## 8. 개발에서 쓰는 법

- 색·글자·간격은 [tokens.json](design-system/tokens.json)의 이름으로만 쓴다. 코드에 색 값을 직접 적지 않는다(나중에 다크 테마를 붙이기 위해, D-13).
- 화면 요소가 어떤 기능인지는 [04 기능 리스트](../prd/04_기능리스트.md)의 화면 열로 찾는다. M1 개발에서는 §4 표의 '시안 속 M2 부분'을 빼고 만든다.
- 시안 파일(.dc.html)은 캔버스용 형식이다. 앱 코드로 그대로 쓰지 않고, 배치·문구·상태 표현의 기준으로 쓴다.
- 시안은 폭 1440px 기준이다.
